# sympy/utilities -- Catalog

> Part of [SymPy](../catalog.md). General utilities: iterables, decorators, code generation helpers, lambdify, memoization, testing.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package init that re-exports key public utilities such as `flatten`, `lambdify`, `source`, `threaded`, `test`, and `timed`. |
| `autowrap.py` | High-level module that compiles symbolic expressions into callable Python binaries via f2py, Cython, or numpy-ufunc backends. Owns all backend-language compatibility logic: `_validate_backend_language` checks whether a user-specified target language is supported by the chosen compilation backend (raising ValueError if incompatible), and `_infer_language` selects the default language when none is provided, both driven by a `_lang_lookup` dict mapping backends to supported language tuples. The base class for all wrappers uses a class-level counter to assign each generated shared-object module a unique sequential name, ensuring that repeated compilations within the same session never collide; its `wrap_code` method creates temporary directories, generates and compiles code, imports the result, and increments the counter in a finally block. The main `autowrap` function catches `CodeGenArgumentListError` from `make_routine` and recovers by appending missing `OutputArgument`s to the argument list and retrying—this is the only place incomplete-argument-list recovery occurs. `CythonCodeWrapper` generates `.pyx` Cython wrapper files (Python-accessible bridge files for compiled C code) via `dump_pyx`; `dump_pyx` constructs the wrapper function body differently depending on whether the underlying C routine returns a value or is void: if `routine.results` is non-empty (non-void), the body uses `return <c_call>(...)` inlining the C call into a return statement; if empty (void), the body calls the C function as a standalone statement and then returns output arguments separately. Its `_partition_args` method categorizes routine arguments using an if/elif/else chain over OutputArgument, InOutArgument, and InputArgument, then runs a dimension-inference pass to detect scalar parameters that are array dimension sizes and remove them from the explicit parameter list so they are inferred at runtime. The ufunc backend wrapper (`UfuncifyCodeWrapper`) generates a complete C extension file for NumPy ufuncs via `dump_c`: it determines the number of input arguments (`n_in`) by partitioning the first routine's arguments and the number of output arguments (`n_out`) from `len(routines)` (one output per symbolic expression), then emits C declarations for args, steps, call arguments, and step increments in the generated loop body; its `_partition_args` rejects InOutArgument with a ValueError since ufunc semantics do not support combined input/output parameters. Also provides `binary_function` and `ufuncify`. |
| `benchmarking.py` | A py.test plugin for benchmark test collection and reporting: custom `Directory`/`Module` collectors scan for `bench_*` files and functions, a `Timer` subclass of `timeit.Timer` runs them, and `BenchSession` (a `TerminalSession` subclass) formats results in a table. The `Function.execute` method contains an auto-calibration algorithm for `timeit_`-prefixed tests: it iteratively adjusts the iteration count (multiplying by 10 when far below, or proportionally scaling when close) targeting 0.2 seconds of wall-clock time, then takes the minimum of 3 repeats—this is distinct from `timeutils.py`'s simpler `timed` function. Not a standalone timing utility. |
| `codegen.py` | Lower-level code generation: produces complete compilable source files in C, C++, Fortran, Julia, Rust, and Octave/Matlab from SymPy expressions. Defines `Routine`, `CodeGen`, `CCodeGen`, `FCodeGen`, `JuliaCodeGen`, `OctaveCodeGen`, `codegen`, and `make_routine`. `Routine.__init__` validates argument completeness and raises `CodeGenArgumentListError` when required arguments are missing, but performs no recovery, no argument categorization, no array-dimension inference, and no wrapper name resolution—all of those are handled solely in `autowrap.py`. Does NOT validate or check compatibility between compilation backends (f2py, Cython, etc.) and target languages—backend-language compatibility validation and default language inference live exclusively in `autowrap.py`. |
| `decorator.py` | Utility decorators including `threaded`/`xthreaded` (apply functions elementwise), `conserve_mpmath_dps`, `doctest_depends_on`, `public`, and `memoize_property`. |
| `enumerative.py` | Internal low-level multiset partition enumeration engine following Knuth's TAOCP algorithm 7.1.2.5M. `MultisetPartitionTraverser` is the core traversal class used internally by `iterables.py::multiset_partitions` for the general case—it is not the user-facing API for generating multiset partitions and does not handle special-case dispatch (e.g., all-identical elements, integer inputs, choosing number of parts). Also provides `count_partitions` with dynamic-programming memoization. |
| `exceptions.py` | Defines `SymPyDeprecationWarning`, a structured deprecation warning class that includes version, issue tracker link, and migration guidance. |
| `iterables.py` | Extensive collection of iterable utilities: `flatten`, `group`, `subsets`, `variations`, `topological_sort`, `sift`, `ordered`, integer `partitions` (dictionary-based generator using capacity/room tracking and backtracking—terminates when decomposition exceeds room and no keys remain), `_set_partitions` (enumerates all ways to assign n elements into non-overlapping groups using a restricted-growth-string counter where each digit is constrained to be at most one greater than the max of all digits to its left; based on Nijenhuis & Wilf's "nexequ" algorithm, not Knuth's TAOCP), `multiset_permutations` (generates unique permutations of a collection with repeated elements; optimizes the all-unique case where every element has multiplicity 1 by delegating to stdlib `permutations` instead of its own recursive algorithm), `multiset_combinations` (generates unique combinations from a collection with repeated elements; when elements are unhashable and cannot be used as dictionary keys, catches TypeError and falls back to sorting and grouping consecutive equal items instead of building a frequency dictionary), `multiset_partitions` (high-level dispatcher that handles special cases like all-identical elements by reducing to integer partitions, delegates general multiset cases to enumerative.py), `kbins` (partitions a sequence into k bins with a two-digit `ordered` flag controlling whether bin order and item order matter: None gives simple contiguous partitions, 00 unordered bins/unordered items, 10 ordered bins/unordered items via permuting multiset partitions, 01 unordered bins/ordered items, 11 both ordered), and many more combinatorial helpers for sequences and sets. |
| `lambdify.py` | Converts SymPy expressions into fast numerical lambda functions targeting math, mpmath, NumPy, TensorFlow, and other numeric backends. |
| `magic.py` | Contains the `pollute` function that injects name-object mappings into a caller's global namespace via frame introspection. |
| `memoization.py` | Memoization decorators for recurrence-defined sequences (`recurrence_memo`) and associated sequences (`assoc_recurrence_memo`). |
| `misc.py` | Miscellaneous helpers including `filldedent` (text formatting), `rawlines` (pasteable string repr), `translate` (character-level mapping like `str.translate`), `replace` (generic substring-replacement by dictionary mapping—not related to file paths or OS path separators), `find_executable`, and the `Undecidable` exception. |
| `pkgdata.py` | Package data-file acquisition. `get_resource(identifier, pkgname)` loads a bundled data file from a package by first resolving the module's `__file__` attribute (raises `IOError` if the module has no `__file__`), then checking whether the module has a custom `__loader__`—if a loader is present, it calls `loader.get_data(path)` and returns the result as a decoded `StringIO` stream; if no loader exists or loading fails, it falls back to direct filesystem `open()`. This is purely about loading static data resources from installed packages, not about converting expressions or generating code. |
| `pytest.py` | Defines test marker decorators and assertion helpers (`raises`, `skip`, `XFAIL`, `slow`) as a compatibility layer that works with and without py.test installed. Only defines markers and decorators—does not execute tests or handle runtime signals like `KeyboardInterrupt` (test execution and interrupt handling live in `runtests.py`). The `raises` function dispatches on its second argument: `None` returns a `RaisesContext` context manager, a callable is invoked directly, a string raises `TypeError` with a migration message (the old string-eval API has been phased out), and any other type raises `TypeError`. The `XFAIL` decorator wraps test functions: if the function raises an exception whose message is 'Timeout', it converts it to a `Skipped` exception instead of marking it as expected failure (`XFail`); other exceptions become `XFail`, and no exception becomes `XPass`. |
| `randtest.py` | Helpers for randomized testing of symbolic expressions (not doctest output verification): `random_complex_number`, `verify_numerically` (evaluates two symbolic expressions at random complex points and compares their numeric values—operates on SymPy expression objects, not on string output from doctests), `test_derivative_numerically`, and deterministic generator factories `_randrange`/`_randint` that accept a seed (None for random, int for seeded, or a list of predetermined values—list-seeded generators silently skip values outside the caller's requested interval via recursion). |
| `runtests.py` | SymPy's built-in test runner framework that actually executes test functions and handles runtime signals/interrupts. Compatible with py.test but requires no external dependencies. Supports doctest, test-execution time limits, and split-based parallelism. `SymPyTests.test_file` executes each test function in a file and contains special exception handling: `KeyboardInterrupt` during a slow-marked test is caught and reported as a skip (silently swallowed) rather than aborting the run, while non-slow tests re-raise the interrupt normally. Includes `convert_to_native_paths` which converts forward-slash-delimited paths to OS-native separators and fixes a Windows edge case where `os.path.join` drops the backslash after a drive-letter colon. `SymPyDocTests.get_test_files` collects source files for inline documentation testing by walking directories, filtering by glob pattern, and checking importability—it determines whether a file is an importable package member by looking for `__init__.py` in the file's immediate parent directory only (a known limitation). `SymPyDocTests._process_dependencies` checks external requirements before running a doctest. Also includes `SymPyDocTestRunner` (subclass of stdlib's `DocTestRunner`), `SymPyDocTestFinder` for recursive doctest discovery, `SymPyOutputChecker` for doctest output string comparison with approximate floating-point matching (extracts decimal numbers from expected/actual output strings via regex, compares with 1e-5 tolerance, and skips comparison for numbers whose expected string contains trailing ellipses '...'), and `_enhance_asserts`, an AST-based assertion rewriter that transforms comparison-based `assert` statements into richer diagnostics (temporary variables + formatted message) but returns non-comparison asserts (e.g., bare booleans or function calls) unchanged. |
| `source.py` | Interactive source inspection utilities: `source` (print an object's source code), `get_class`, and `get_mod_func` (resolve dotted class paths). |
| `timeutils.py` | Standalone adaptive execution timing (no py.test needed). `timed` auto-scales the number of iterations until the measurement is reliable, picks the best display unit (s/ms/μs/ns) via `log10` of the per-call time, and guards against math domain error when time is exactly zero by defaulting to nanoseconds (order 3). Also provides `timethis`, a decorator factory for profiling recursive algorithms: it uses a global `_timestack` variable to track nested call hierarchies—each instrumented call saves the current stack, creates a new entry `[name, children, elapsed, args]`, and on return either appends itself as a child of the parent entry (if nested) or prints the entire accumulated timing tree via `_print_timestack` (if it is the outermost call). Profiled function groups are controlled by the `SYMPY_TIMINGS` environment variable. |
| `mathml/__init__.py` | MathML utilities for transforming MathML content markup into MathML presentation markup using XSL transforms (requires lxml). |
