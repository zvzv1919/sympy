# sympy/utilities -- Catalog

> Part of [SymPy](../catalog.md). General utilities: iterables, decorators, code generation helpers, lambdify, memoization, testing.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package init that re-exports key public utilities such as `flatten`, `lambdify`, `source`, `threaded`, `test`, and `timed`. |
| `autowrap.py` | Compiles symbolic mathematical expressions into binary-wrapped numerical callables via C or Fortran code generation. Key entry points: `autowrap` (compile & wrap a single expression), `binary_function` (return a SymPy Function backed by compiled code), and `ufuncify` (compile a symbolic expression into a vectorized callable — specifically a real `numpy.ufunc` — that supports multidimensional array broadcasting; backends: 'numpy' [default], 'cython', 'f2py', each with different type-strictness). The numpy backend enforces numpy's compile-time argument limit (NPY_MAXARGS = 32) on the combined count of inputs and outputs. **This is the module for compiled/vectorized/broadcasting numerical evaluation** — contrast with `lambdify.py` which produces pure-Python lambda functions without compilation or true ufunc broadcasting. |
| `benchmarking.py` | Provides a py.test-based benchmarking **framework** with custom Timer, Function, and TerminalSession classes for running and reporting SymPy benchmarks under py.test — this is test infrastructure/harness code, **not** adaptive execution-time measurement or unit-selection logic (for adaptive timing with automatic unit scaling, see `timeutils.py`). |
| `codegen.py` | Generates complete compilable routines in C, C++, Fortran, Julia, Rust, and Octave/Matlab from SymPy expressions. |
| `decorator.py` | Utility decorators including `threaded`/`xthreaded` (apply functions elementwise), `conserve_mpmath_dps`, `doctest_depends_on`, `public`, and `memoize_property`. |
| `enumerative.py` | Low-level general-case multiset partition traversal engine only — **no optimization, no edge-case handling, no input validation, no boundary checks, NO integer-partition logic, and NO binary/power-of-two partition logic** (binary partitions live in `iterables.py::binary_partitions`) (e.g., does NOT handle `m > n`, `m == 1`, identical elements, integer inputs, constraint parameters like max part size `k` or max number of parts `m`, or feasibility checks like `m*k < n`); any question about how partitioning is optimized, what special cases are detected, how inputs are dispatched, **how identical/uniform collections are reduced to integer decomposition**, or **how constrained integer decompositions are generated or validated** belongs in `iterables.py` (specifically `iterables.py::partitions` for pure integer decomposition, or `iterables.py::multiset_partitions` for collection partitioning), not here. The reduction from identical-element collections to integer partitioning (bypassing combinatorial traversal) is performed entirely in `iterables.py`, not in this file. Implements Knuth's TAOCP algorithm 7.1.2.5M. Contains `MultisetPartitionTraverser` — a stateful class that walks the partition tree using an internal stack (`pstack`) with methods like `spread_part_multiplicity` (distributes remaining multiplicities into new partition segments, skipping zero-availability components), `decrement_part`, `enum_all`, `enum_small`, and `enum_large`. Also provides the standalone generator `multiset_partitions_taocp` and two thin **output-formatting** visitors: `list_visitor` (converts internal partition state into lists of elements) and `factoring_visitor` (converts partition state into prime-factor products for number-factorization enumeration — this is purely a display/formatting helper, **not** an optimization or shortcut). |
| `exceptions.py` | Defines `SymPyDeprecationWarning`, a structured deprecation warning class that includes version, issue tracker link, and migration guidance. |
| `iterables.py` | Extensive collection of iterable utilities and **the sole entry point for "split a collection into non-overlapping sub-collections" queries** (via `multiset_partitions`): `flatten`, `group`, `subsets`, `variations`, `partitions` (**integer partition generator** — decomposes a positive integer `n` into sums of positive integers, returned as `{part: count}` dicts; supports constraint parameters `k` (max value of each part/key), `m` (max number of parts/sum of values), and `size` flag; includes edge-case logic for impossible constraints such as `m*k < n`, `n <= 0`, `m < 1`, `k < 1` — yields an empty dict `{}` when the target cannot be reached under the given bounds, consistent with counting convention `nT(0)==1`; **any question about constrained integer decomposition, feasibility checks on partition parameters, or boundary behavior of integer partitioning belongs here, NOT in `enumerative.py`**), `multiset_partitions` (high-level dispatch interface that inspects the input and routes to specialized algorithms — **integer input → converts to `range(n)`, guards edge cases such as `m > n` (returns empty immediately) and `m == 1` (yields whole list), then falls through to set partitions via `_set_partitions`**; all-identical/uniform elements → detects lack of variety via `has_variety` and **optimizes by reducing to integer partitioning** via `partitions`, completely bypassing the combinatorial traversal engine in `enumerative.py`; true multiset with repeated elements → delegates to `MultisetPartitionTraverser` from `enumerative.py`; set with no repeats → uses `_set_partitions`), `binary_partitions` (**power-of-two decomposition generator** — enumerates all ways to express a positive integer as a sum of powers of two, starting from the greedy/binary representation and systematically splitting larger powers into smaller ones using bit-shift operations; references TAOCP 4, section 7.2.1.5, problem 64 — this is NOT in `enumerative.py`), `ordered_partitions`, `topological_sort`, `sift`, `ordered`, and many more combinatorial helpers. **All input-type detection, edge-case guards (e.g., requesting more partition groups than elements), and optimization dispatch for collection partitioning lives here** — questions about how partitioning is optimized for specific input shapes (integer inputs, all-identical-element inputs reducing to integer decomposition, boundary conditions like `m > n` or `m == 1`) should always look here, not in `enumerative.py`. |
| `lambdify.py` | Converts SymPy expressions into fast numerical lambda functions (pure Python, no compilation, no binary wrapping) targeting math, mpmath, NumPy, TensorFlow, and other numeric backends. Does NOT compile code or produce true `numpy.ufunc` objects — for compiling symbolic expressions into vectorized binary callables with multidimensional array broadcasting, see `autowrap.py::ufuncify`. |
| `magic.py` | Contains the `pollute` function that injects name-object mappings into a caller's global namespace via frame introspection. |
| `memoization.py` | Memoization decorators for recurrence-defined sequences (`recurrence_memo`) and associated sequences (`assoc_recurrence_memo`). |
| `misc.py` | Miscellaneous helpers including `filldedent` (text formatting), `rawlines` (pasteable string repr), `translate`, `replace`, `find_executable`, the `Undecidable` exception, and constants such as `ARCH` and `HASH_RANDOMIZATION`. Note: these constants are only *defined* here — the code that uses them to print the test session environment summary (including Python implementation detection for PyPy/CPython) lives in `runtests.py`. |
| `pkgdata.py` | Provides `get_resource` for acquiring data files from a package, supporting both filesystem and custom `__loader__` access. |
| `pytest.py` | Compatibility layer for py.test functionality (`raises`, `skip`, `XFAIL`, `slow`) that works both with and without py.test installed. When py.test is absent, provides its own fallback implementations: `raises` (callable/context-manager for exception assertions via `RaisesContext`), `XFAIL` decorator (marks expected failures — converts caught exceptions to `XFail`, but specially converts "Timeout" exceptions to `Skipped`), `XFail`/`XPass`/`Skipped` exception classes, and `skip`/`SKIP`/`slow` decorators. Note: the test *runner* that executes tests and manages process-level timeouts lives in `runtests.py`. |
| `randtest.py` | Helpers for randomized testing: `random_complex_number`, `verify_numerically` (compare two symbolic expressions by evaluating them at random points — this is a **point-wise numerical comparison utility**, not a test-suite orchestrator or external-tool integration), and `test_derivative_numerically`. Does NOT manage test execution, external CAS integration, or test-suite orchestration — for the full test runner including Sage/external CAS integration, see `runtests.py`. |
| `runtests.py` | SymPy's built-in test runner framework, compatible with py.test but requiring no external dependencies. Supports doctest, split-based parallelism, and process-level timeout handling. Handles test discovery, execution, and **reporting** — includes the test reporter class that prints the session environment summary at startup (Python executable, version, implementation with special handling for PyPy vs CPython, architecture, cache status, ground types with gmpy version detection, hash randomization, random seed) and the final results summary with pass/fail/skip counts, slow/fast test listings, and formatted exception tracebacks. The `run_all_tests` function is the **full verification suite entry point** that orchestrates all test phases and also handles **external computer algebra system (CAS) integration**: at the end of the test run it conditionally invokes Sage (`sage -python bin/test`) to run `sympy/external/tests/test_sage.py`, but only when multiple guards are satisfied — platform is not Windows (`sys.platform != "win32"`), Python version is not Python 3, `bin/test` exists on disk, and `sage -v` succeeds; if any guard fails the Sage tests are silently skipped. **Any question about how the test suite integrates with an external CAS (Sage), or under what conditions external verification checks are skipped, belongs here** — not in `randtest.py` (which provides randomized numerical comparison helpers, not test-suite orchestration). Constants like `HASH_RANDOMIZATION` and `ARCH` are defined in `misc.py` but the logic that formats and prints them as part of the test session banner lives here. Test *decorators* (`XFAIL`, `slow`, `raises`, etc.) and their exception-handling logic live in `pytest.py`. |
| `source.py` | Interactive source inspection utilities: `source` (print an object's source code), `get_class` (dynamically resolves a fully-qualified dotted string path like `'package.module.ClassName'` into a live object by splitting the path via `get_mod_func`, calling `__import__` on the module portion, then using `getattr` to retrieve the named attribute — raises `AttributeError` if the resolved attribute is not callable), and `get_mod_func` (splits a dotted path at the last dot into module path and class/function name). |
| `timeutils.py` | Simple adaptive timing tools for measuring function execution time when IPython is unavailable. `timed` adaptively scales the number of iterations until the measurement is reliable, then selects a display unit from a scale array `[s, ms, μs, ns]` based on `math.log10` of the measured time — includes an edge-case branch: when the recorded duration is exactly zero (where `log10` would be undefined), it defaults the order to 3 (nanoseconds). Also provides `timethis`, a decorator for recursive-algorithm profiling that maintains a nested timestack. **Any question about adaptive execution-time measurement, automatic unit selection, or zero-duration edge cases belongs here** — contrast with `benchmarking.py` which is a py.test harness, not an adaptive timer. |
| `mathml/__init__.py` | MathML utilities for transforming MathML content markup into MathML presentation markup using XSL transforms (requires lxml). |
