# sympy/plotting — Catalog

> Part of [SymPy](../catalog.md). 2-D and 3-D plotting with backends for matplotlib, pyglet, and text-based output.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package init that re-exports the public plotting API: `plot`, `plot_parametric`, `plot3d`, `plot3d_parametric_line`, `plot3d_parametric_surface`, `plot_implicit`, `textplot`, and `PygletPlot`. |
| `plot.py` | Core plotting module defining the `Plot` class (the main plot container), data series hierarchy, rendering backends, and the public convenience functions `plot`, `plot_parametric`, `plot3d`, `plot3d_parametric_line`, and `plot3d_parametric_surface`. The `plot3d` function is the public API entry point for creating 3D surface visualizations from a mathematical expression over two independent variable domains: it accepts expressions and optional x/y ranges, validates and normalizes user-supplied arguments via `check_arguments` (expecting 1 expression + 2 range variables), constructs `SurfaceOver2DRangeSeries` data objects, assembles them into a `Plot`, and displays it. `plot3d_parametric_surface` similarly handles parametric surfaces (3 expressions + 2 range variables → `ParametricSurfaceSeries`). These are distinct from the pyglet backend's `PlotSurface` class which only handles low-level OpenGL vertex calculation and rendering. `Plot` stores data series in an internal `_series` list and supports container protocols: `__getitem__`, `__setitem__` (trivial single-line replacement that only accepts a `BaseSeries` instance by index — no argument parsing, no geometry handling), and `__delitem__`. This is the primary `Plot` class used by the public API — distinct from `PygletPlot` in the pyglet backend. Also defines the `_arity` helper function that determines how many arguments a callable accepts (e.g., for color functions): on Python 3 it uses `inspect.signature` and counts only `POSITIONAL_OR_KEYWORD` parameters, deliberately excluding `*args`, `**kwargs`, keyword-only, and positional-only parameters from the count. Also defines `check_arguments`, the shared argument-validation and range-inference function used by all convenience plot functions. `check_arguments` converts flat argument lists into `(exprs, ranges)` tuples, auto-generating default ranges when none are provided. It has a notable design limitation: when `expr_len == 3`, the "series of plots with same range" branch is explicitly skipped because 3-element expression tuples are indistinguishable from range tuples, so multiple 3-expression parametric surface plots with shared ranges cannot be parsed in that code path. Each convenience function pops display-control kwargs (e.g. `show`) from `kwargs` before forwarding the remaining kwargs to series constructors and the `Plot` constructor. The `plot` function collects free symbols from all input expressions, raises `ValueError` if more than one distinct variable appears across univariate expressions, and defaults to `Symbol('x')` when no free symbols exist (constant expressions). The series hierarchy includes `BaseSeries`, 2D line series (`LineOver1DRangeSeries` and `Parametric2DLineSeries`), 3D line series (`Parametric3DLineSeries`), and surface series (`SurfaceOver2DRangeSeries` and `ParametricSurfaceSeries`). `SurfaceBaseSeries.get_color_array` handles custom callable surface coloring: it vectorizes the callable, uses `_arity` to determine the number of arguments, and dispatches differently for parametric surfaces (passing parameter-mesh face centers) versus explicit surfaces (passing coordinate-mesh face centers), supporting 1-, 2-, or 3-argument callables. `LineOver1DRangeSeries.get_segments` implements adaptive recursive subdivision for single-expression curves (a SymPy expression over a 1D range), including special handling when both endpoints of an interval evaluate to complex (non-real) numbers (represented as `None`): it samples 10 intermediate points and recursively refines only sub-intervals containing real-valued results. `Parametric2DLineSeries.get_segments` implements analogous adaptive subdivision for 2D parametric curves with similar complex-number handling. Also contains `MatplotlibBackend`, `TextBackend`, and `DefaultBackend`. `DefaultBackend` selects `MatplotlibBackend` when matplotlib is available, otherwise falls back to `TextBackend`. `TextBackend.show` raises `ValueError` if the plot contains more than one series or a non-1D-range series, restricting ASCII fallback to single univariate expressions. `MatplotlibBackend.process_series` selects the appropriate matplotlib drawing call for each series type; for implicit series it decides between region-fill rendering (when `get_raster` returns 2 elements from interval math) and contour/contourf rendering (when it returns mesh arrays with a `plot_type` flag distinguishing equality from inequality). |
| `plot_implicit.py` | Implicit plotting that *uses* interval arithmetic from `intervalmath/` to render equations, inequalities, and boolean combinations. Defines `ImplicitSeries` (which calls into `lib_interval` for math and logic) and the `plot_implicit` convenience function. When an expression has only one free variable (e.g., `y - 1`), `plot_implicit` creates a synthetic `Dummy` symbol for the missing coordinate axis so a 2-D plot can still be produced. It also wraps bare (non-relational) expressions in `Eq(expr, 0)`, recursively expands boolean combinations to detect equality/inequality types, and silently clamps the adaptive subdivision depth to [0, 4]. Does not itself define interval math functions or ternary logic operators. |
| `textplot.py` | Provides `textplot`, a low-level function that renders a crude ASCII-art plot of a single-variable SymPy expression over a given interval to the terminal. This is the rendering primitive called by `TextBackend` in `plot.py`; it does not handle multi-expression validation or backend selection (those are in `plot.py`). |
| `experimental_lambdify.py` | Internal lambdify variant that converts SymPy expressions into callable numerical functions for evaluation during plotting. Parses expression strings into function trees and translates function names to math/numpy/mpmath equivalents. Does not perform any validation of free variables or plotting logic. |
| `intervalmath/__init__.py` | Package init for the interval math subpackage; re-exports the `interval` class and all interval-aware math functions (sin, cos, exp, log, sqrt, etc.). |
| `intervalmath/interval_arithmetic.py` | Defines the `interval` class representing a floating-point interval with a validity flag. Implements arithmetic operators and comparisons used by `plot_implicit` for adaptive region subdivision. |
| `intervalmath/lib_interval.py` | Implements interval-aware versions of standard math functions (exp, log, sin, cos, tan, sqrt, Abs, floor, ceil, inverse hyperbolic trig, etc.) over `interval` objects, using numpy for speed. Also defines ternary (three-valued: True/False/None) logic operators `And` and `Or` that combine 2-tuples of comparison results for range-based curve rendering. |
| `pygletplot/__init__.py` | Package init for the pyglet-based 3D plotting backend; defines a thin `PygletPlot` factory function inside a top-level `try/except` block that simply delegates to the `PygletPlot` class in `pygletplot/plot.py`. If any exception occurs during definition (e.g., the pyglet dependency is not installed), the except clause redefines `PygletPlot` as a stub that re-raises the stored exception when called. The factory function's docstring duplicates the class docstring from `plot.py` but contains no logic of its own. |
| `pygletplot/plot.py` | Implements the `PygletPlot` class for the pyglet 3-D backend. Its class docstring is the primary documentation for: (1) the flexible variable-interval syntax with partial `[var, min, max, steps]` specifications (including edge cases like `[100]` for steps-only, `[]` for all-defaults, `[-13,13]` for min/max-only); (2) the automatic decision logic that renders a Cartesian graph when one expression is given versus a parametric trajectory when two or three expressions are given, and distinguishes 1D curves from 2D surfaces by counting free variables; (3) the indexed-slot calculator interface; (4) supported coordinate modes (cartesian, parametric, polar, cylindrical, spherical). Its `__init__` method pops the `axes` keyword argument from the window kwargs, parses it as a semicolon-delimited option string (via `parse_option_string`), and uses the result to configure the `PlotAxes` object separately — remaining kwargs are forwarded to the window. Manages window lifecycle in `show()` (reuses an existing window or creates a new one, with a special case for automated doctest runs). Provides `wait_for_calculations`, which busy-waits (polling with `sleep(0)`) under a render lock until all registered functions' asynchronous vertex and color-vertex computations have finished. Its `__setitem__` method parses and assigns plot functions by index: it guards against `GeometryEntity` objects being unpacked as sequences (since they are iterable but should be treated as single arguments), wraps non-sequence args into a list, and delegates to `PlotMode` for parsing. Also manages plot function collections, coordinate modes, color schemes, and image saving. |
| `pygletplot/color_scheme.py` | Pyglet-backend-only color mapping: defines `ColorGradient` and `ColorScheme` for converting already-computed vertex positions to RGB colors via gradient interpolation. Not used by the core series in `plot.py` (which have their own `get_color_array` methods for arity-based callable dispatch). `ColorScheme.apply_to_curve` and `apply_to_surface` iterate over pyglet vertex arrays, skip `None` vertices, silently catch color-function exceptions, scale to [0,1], and apply the gradient. |
| `pygletplot/managed_window.py` | Provides `ManagedWindow`, a pyglet `Window` subclass that runs its entire event loop (`__event_loop__`) in a separate thread, serving as the base class for `PlotWindow`. Assumes pyglet is already importable (imports `pyglet.gl`, `pyglet.window`, `pyglet.clock` at module level); missing-dependency errors are handled upstream in `pygletplot/__init__.py`, not here. The event loop acquires a global `gl_lock` mutex both during initialization and on every rendering frame iteration, using nested try/try/finally blocks to guarantee the lock is always released even when uncaught exceptions occur during dispatching or rendering. On exception the loop sets `has_exit = True` to terminate gracefully. Subclasses override `setup`, `update`, and `draw` hook methods. |
| `pygletplot/plot_axes.py` | Implements `PlotAxes` and helper classes (`PlotAxesOrdinate`, `PlotAxesFrame`) for rendering labeled coordinate axes with tick marks in the pyglet 3-D plot window. |
| `pygletplot/plot_camera.py` | Defines `PlotCamera`, which manages the OpenGL camera (projection, rotation, zoom, panning) for the pyglet plotting window, supporting both perspective and orthographic modes. |
| `pygletplot/plot_controller.py` | Implements `PlotController`, which translates keyboard and mouse input into camera rotation, zoom, and other interactive actions in the pyglet plot window. Its `update` method branches on `is_2D()` (true when all plotted functions have ≤1 independent variable and ≤2 dependent variables): in 2D mode, arrow keys perform camera translation instead of 3D rotation, and z-axis keyboard rotation is suppressed. Mouse drag similarly switches between spherical rotation (3D) and translation (2D). |
| `pygletplot/plot_curve.py` | Defines `PlotCurve`, a `PlotModeBase` subclass for the pyglet backend only. Calculates vertex positions and renders 1-D parametric curves as wireframe line strips using uniform sampling (not adaptive). Does not implement adaptive refinement or complex-value handling (that logic is in `plot.py`'s `Parametric2DLineSeries.get_segments`). |
| `pygletplot/plot_interval.py` | Defines `PlotInterval`, an internal data-structure class representing a named variable range with step count, used to generate evaluation grids for pyglet plot modes. Does not document or define the flexible interval shorthand syntax (e.g., `[100]` for steps-only) — that syntax and its edge cases are documented in the `PygletPlot` factory function's docstring in `pygletplot/__init__.py`. |
| `pygletplot/plot_mode.py` | Defines `PlotMode`, the grandparent class for all pyglet plot modes. Internal infrastructure for mode registration (maintaining a class-level registry of mode subclasses) and lookup by string alias or independent/dependent variable count. Its `_get_default_mode` implements a recursive fallback: when no default mode is registered for the exact independent-variable count, it increments the count and retries up to the maximum, only raising an error when all higher counts are also exhausted. Does not parse or validate plot arguments/expressions (that is `check_arguments` in `plot.py`), does not handle rendering style selection (that is in `plot_mode_base.py`), and does not contain user-facing entry-point logic (that is in `pygletplot/__init__.py`). |
| `pygletplot/plot_mode_base.py` | Defines `PlotModeBase`, the intended parent class for concrete plot modes. Provides threaded vertex/color calculation, display-list management via a render stack, and the base `draw` implementation. `_render_stack_top` retrieves the top element from the render stack for drawing: if the element is a callable, it compiles it into an OpenGL display list; if it is an already-compiled display list, it checks validity via `glIsList` and regenerates from the stored callable if the list has been invalidated (e.g., after a context loss). Contains the rendering style auto-selection logic in its style property setter: when the style is set to an empty string, it examines the maximum step count across all intervals and uses a threshold (step_max > 40) to choose between 'both' (wireframe + solid combined) and 'solid' (filled only). Also manages color property changes (wrapping values into `ColorScheme`). Its `_get_evaluator` method implements evaluator selection with fallback from fast lambda-based to slower SymPy substitution-based evaluation. |
| `pygletplot/plot_modes.py` | Defines concrete plot modes for the pyglet backend: `Cartesian2D`, `Cartesian3D`, `ParametricCurve2D`, `ParametricCurve3D`, `ParametricSurface`, `Polar`, `Cylindrical`, and `Spherical`. Each mode implements both `_get_sympy_evaluator` (substitution-based, using Python's built-in `math` trig functions like `p_cos`/`p_sin` for direct numeric evaluation) and `_get_lambda_evaluator` (using symbolic trig with `lambdify` for compiled evaluation). The `Spherical` mode converts a radial function of two angular variables (azimuthal and elevation) into Cartesian (x, y, z) coordinates; `Cylindrical` and `Polar` similarly perform their respective coordinate transformations. |
| `pygletplot/plot_object.py` | Defines `PlotObject`, a minimal base class for anything that can be drawn in the pyglet plot window, providing a `visible` flag and a `draw` method stub. |
| `pygletplot/plot_rotation.py` | Utility functions for computing 3-D rotation matrices from sphere-mapped screen coordinates, used for interactive trackball-style rotation in the pyglet backend. |
| `pygletplot/plot_surface.py` | Defines `PlotSurface`, a `PlotModeBase` subclass that calculates and renders 2-D parametric surfaces (wireframe and solid quad strips) in the pyglet backend. This is a low-level OpenGL rendering class only — it does not validate user arguments, parse expressions, or create data series. For the public API that converts mathematical expressions into 3D surface visualizations (argument validation, range inference, series construction), see `plot3d` in `plot.py`. |
| `pygletplot/plot_window.py` | Implements `PlotWindow`, the `ManagedWindow` subclass that sets up OpenGL state, coordinates the camera and controller, and drives the per-frame drawing loop for pyglet plots. Its `draw` method acquires the render lock once and, during the same iteration that calls each function's `_draw`, also collects vertex and color-vertex computation progress data for the window title-bar caption update — explicitly avoiding a second lock-and-iterate pass per frame. It selects the default viewing orientation (rotation preset) from the first rendered function and applies it to the camera, using a flag that resets when the function list becomes empty. |
| `pygletplot/util.py` | OpenGL and math utility functions for the pyglet backend: model/projection matrix retrieval, screen-to-model coordinate conversion, interpolation, vector operations, and option-string parsing. Includes `billboard_matrix`, which makes drawn primitives always face the viewer by fetching the current 4×4 modelview matrix, resetting the upper-left 3×3 rotation submatrix to the identity while leaving translation and the bottom row unchanged, and reloading it via `glLoadMatrixf`. |
