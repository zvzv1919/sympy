# sympy/functions — Catalog

> Part of [SymPy](../catalog.md). Elementary and special mathematical functions (trig, exponential, Bessel, combinatorial, etc.).

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Top-level package init that imports and re-exports all public functions from the combinatorial, elementary, and special subpackages. Also defines module-level shorthand aliases (e.g., `ln = log`) so that common mathematical notations like `ln` are available as direct imports from the top-level `functions` package — these aliases live here, not in the submodule where the underlying function is implemented (e.g., `ln` is NOT defined in `elementary/exponential.py`). |
| `combinatorial/__init__.py` | Subpackage init for combinatorial functions; imports the `factorials` and `numbers` modules. |
| `combinatorial/factorials.py` | Implements combinatorial factorial-related functions: `factorial`, `factorial2`, `subfactorial` (derangement/fixed-point-free permutation counting), `RisingFactorial`, `FallingFactorial`, and `binomial`. Note: despite the name similarity, Stirling numbers are **not** here — they live in `combinatorial/numbers.py` (which has both the public `stirling` function and the private `_stirling1`/`_stirling2` helpers with closed-form shortcut formulas). `subfactorial` includes a rewrite rule (`_eval_rewrite_as_uppergamma`) expressing the result as Γ(n+1, -1)/e (upper incomplete gamma divided by Euler's number) — this rewrite lives here, not in `special/gamma_functions.py`. Note: Catalan numbers C_n = C(2n,n)/(n+1), despite being defined via central binomial coefficients (`binomial` from this file), are implemented in `combinatorial/numbers.py` — including their special-case `eval` logic for negative integer arguments (n = −1 → −1/2, n ≤ −2 → 0). Note: logarithmic derivatives of the factorial/gamma function and their sign properties are handled by polygamma in `special/gamma_functions.py`. |
| `combinatorial/numbers.py` | Implements combinatorial number sequences: Fibonacci, Lucas, harmonic, Bernoulli, Bell, Euler, Catalan, Genocchi, and **Stirling** numbers/polynomials. The `catalan` class's `eval` method contains special-case handling for negative integer arguments with distinct behavior: n = −1 returns −1/2, while n ≤ −2 returns 0; for non-negative integers and non-integer negatives it computes via the gamma-function formula 4^n·Γ(n+½)/(√π·Γ(n+2)). This negative-integer edge-case logic for Catalan numbers lives here, not in `combinatorial/factorials.py` (where `factorial.eval` returns ComplexInfinity for all negative integers without distinguishing individual values). The Stirling number support includes the public `stirling(n, k, kind=...)` dispatcher and the private cached helpers `_stirling1`/`_stirling2` that contain the actual recursive computation with special-value shortcut formulas (e.g., for first-kind Stirling numbers: k==1 → factorial, k==n-1 → binomial, k==n-2 and k==n-3 → closed-form expressions involving binomials). These Stirling helpers live here, **not** in `combinatorial/factorials.py`. Also includes combinatorial counting helpers (`nC`, `nP`, `nT`) for combinations, permutations, and partitions. The `harmonic` class models generalized harmonic numbers H_{n,m} = Σ_{k=1}^{n} 1/k^m (a generalized number-theoretic summation with upper limit n and order parameter m). Its `eval` method contains explicit branching for the infinite upper-limit case (n = ∞): negative order m → NaN, m ≤ 1 → ∞, m > 1 → ζ(m). All of this edge-case evaluation logic (including the NaN return for negative order) lives here, not in `special/zeta_functions.py`. The class also supports rational arguments via a Gauss-digamma-style trigonometric closed form (splitting n = u + p/q and using cosine, log-sine, and cotangent terms), memoized computation for integer arguments, and provides rewrite rules to polygamma. Despite the zeta connection, harmonic number logic lives here — not in `special/zeta_functions.py`, which implements the standalone Riemann zeta, Lerch transcendent, and polylogarithm functions. |
| `elementary/__init__.py` | Subpackage init for elementary functions; imports complexes, exponential, hyperbolic, integers, trigonometric, and miscellaneous modules. |
| `elementary/complexes.py` | Implements complex-number operations: `re`, `im`, `sign`, `Abs`, `conjugate`, `arg`, `polar_lift`, `periodic_argument`, `principal_branch`, `transpose`, `adjoint`, and related helpers. `polar_lift` lifts values onto the Riemann surface (multi-sheeted covering surface) of the complex logarithm — its `eval` method first handles numeric inputs by computing the argument (phase angle) and only proceeding if the angle matches one of four recognized values (0, π/2, −π/2, π), returning the product of the absolute value and an `exp_polar(I*angle)` factor; for non-numeric products, it classifies multiplicative factors into three bins (already-polar, strictly positive real, and everything else needing recursive lifting) and recombines them accordingly. This phase-angle recognition and factor-partitioning logic lives here, not in `elementary/exponential.py` (which handles `exp` and `log` evaluation but not lifting onto the covering surface). `periodic_argument` represents the argument on a quotient of this Riemann surface with a given period. Note: branch-cut logic for specific functions (e.g., `log` branch selection for imaginary arguments) is handled within those functions' own `eval` methods (see `elementary/exponential.py`), not here — `polar_lift` handles the lifting/wrapping onto the covering surface, while `log.eval` handles branch selection for evaluation. Similarly, conjugation and branch-cut handling for special-function integrals (`li`, `Ei`, `Si`, `Ci`, etc.) lives in `special/error_functions.py`. |
| `elementary/exponential.py` | Implements exponential and logarithmic functions (`exp`, `exp_polar`, `log`, `LambertW`) with series expansion support for the Gruntz limit algorithm. This file handles only the basic exponential `e^x` and logarithm — NOT even/odd combinations of exponentials like `(e^x + e^{-x})/2` or `(e^x - e^{-x})/2`, which are hyperbolic functions (`cosh`, `sinh`, etc.) defined in `elementary/hyperbolic.py`. `exp_polar` represents "polar numbers" that do NOT wrap around at 2π (unlike ordinary `exp`); its `_eval_evalf` method contains a guard that checks whether the imaginary part of the argument lies within the principal range (−π, π] — if the imaginary part falls outside this range, it refuses to evaluate numerically and returns self unchanged, because floating-point evaluation would give incorrect results for non-principal arguments. It also handles a boundary edge case near π: when the imaginary part is positive but numerical evaluation of `exp(...)` produces a result with a negative imaginary part (due to floating-point rounding pushing the angle just past π), it discards the imaginary part and returns only the real component. This polar-number numerical evaluation guard logic lives here, not in `special/error_functions.py` (which has its own separate analytic continuation logic for the generalized exponential integral `expint`). The `log.eval` classmethod contains branch-cut selection logic for complex arguments: it detects negative real inputs (returning `πi + log(-arg)`) and purely imaginary inputs with rational coefficients (returning `±πi/2 + log(|coeff|)` depending on sign), determining which branch of the complex logarithm to use. See `elementary/complexes.py` for general complex-number operations like `arg`, `polar_lift`, and `Abs` — but branch-cut logic specific to `log` evaluation lives here. |
| `elementary/hyperbolic.py` | Implements elementary hyperbolic functions (`sinh`, `cosh`, `tanh`, `coth`, `sech`, `csch`) and their inverses (`asinh`, `acosh`, `atanh`, `acoth`, `asech`, `acsch`). These are the point-valued hyperbolic functions (e.g., `cosh(z) = (e^z + e^{-z})/2`) — NOT the hyperbolic sine/cosine *integrals* (`Shi`, `Chi`), which are definite-integral transforms living in `special/error_functions.py`. Each forward hyperbolic function's `eval` method handles special-value evaluation: real infinities return the expected limits (e.g., `sinh(∞)` → `∞`, `sinh(-∞)` → `-∞`), but `ComplexInfinity` (zoo) returns `NaN` since the limit is direction-dependent; also handles `Zero` → `0`, negative arguments via odd/even symmetry, purely imaginary arguments via circular identities (e.g., `sinh(ix)` → `i*sin(x)`), and composition with inverse hyperbolic functions. This special-value and automatic-simplification logic is defined here in the source — not in the test files. Each inverse hyperbolic function's `eval` method contains logic to detect purely imaginary arguments and rewrite the result in terms of the corresponding circular trigonometric inverse (e.g., `atanh(i*x)` → `i*atan(x)`, `acoth(i*x)` → `-i*acot(x)`). Also defines the `ReciprocalHyperbolicFunction` base class (parent of `csch`, `sech`, `coth`) which provides a delegation pattern for reciprocal functions: `_rewrite_reciprocal` delegates rewrite calls (e.g., rewrite-as-exp, rewrite-as-tractable) to the underlying non-reciprocal function and returns the reciprocal of the result, but includes a guard that returns `None` if the rewrite produced an unchanged expression (preventing no-op or infinite-loop rewrites). This reciprocal rewrite delegation logic lives here, not in `elementary/exponential.py`. |
| `elementary/integers.py` | Implements rounding functions: `floor`, `ceiling`, and `frac` (fractional part). |
| `elementary/miscellaneous.py` | Implements miscellaneous elementary functions: `sqrt`, `cbrt`, `root`, `real_root`, `Min`, `Max`, and the `IdentityFunction`. |
| `elementary/piecewise.py` | Implements the `Piecewise` function (conditional/branch-based expression container) and the `piecewise_fold` simplification utility. This file defines the `Piecewise` data structure and its evaluation/simplification logic — but rewrite methods that convert *other* functions into `Piecewise` form (e.g., `Heaviside._eval_rewrite_as_Piecewise`, `HyperRep._eval_rewrite_as_nonrep`) live in those functions' own source files (`special/delta_functions.py`, `special/hyper.py`, etc.), not here. |
| `elementary/trigonometric.py` | Implements trigonometric functions (`sin`, `cos`, `tan`, `cot`, `sec`, `csc`, `sinc`) and their inverses (`asin`, `acos`, `atan`, `acot`, `asec`, `acsc`, `atan2`). The `sinc` class (cardinal sine function, sin(x)/x) has its own `eval` method with special-value handling for infinities: real ±∞ returns `Zero` (well-defined limit), but `ComplexInfinity` returns `NaN` (no well-defined limit from arbitrary complex directions); also handles `Zero` → `One`, negative argument extraction, and pi-multiple simplification for integer and half-integer multiples of π. This infinity-handling and special-value evaluation logic for the cardinal sine lives here — not in `special/singularity_functions.py` (which implements the unrelated Macaulay bracket for beam analysis) or `special/bessel.py` (though `sinc` can be rewritten as a zeroth-order spherical Bessel function `jn(0, x)` via `_eval_rewrite_as_jn`). |
| `elementary/benchmarks/bench_exp.py` | Benchmark for `exp.subs()` performance on exponential expression substitution. |
| `special/__init__.py` | Subpackage init for special functions; imports gamma, error, zeta, tensor, delta, elliptic, beta, Mathieu, singularity, and polynomial modules. |
| `special/bessel.py` | Implements Bessel functions (`besselj`, `bessely`, `besseli`, `besselk`), Hankel functions (`hankel1`, `hankel2`), spherical Bessel functions (`jn`, `yn`), spherical Hankel functions (`hn1`, `hn2`), and Airy functions (`airyai`, `airybi`). Each class contains an `eval` classmethod with special-case evaluation logic for boundary/edge-case arguments (e.g., zero argument behavior branching on order parameter properties like real/imaginary part). The spherical Hankel classes (`hn1`, `hn2`) inherit from `SphericalHankelBase`, whose `_eval_expand_func` branches on whether the order is an integer: integer orders get fully reduced to trigonometric terms (sin/cos) via an internal `_expand` helper, while non-integer orders decompose into a symbolic sum of component spherical Bessel functions (`jn ± i*yn`). Rewrite methods (`_eval_rewrite_as_bessely`, `_eval_rewrite_as_jn`, `_eval_rewrite_as_yn`) also live here. This is where return values for specific inputs are determined — not in the test files. |
| `special/beta_functions.py` | Implements the Euler beta function `B(x, y)` with differentiation, conjugation, and numerical evaluation support. |
| `special/bsplines.py` | Implements B-spline basis functions (`bspline_basis`, `bspline_basis_set`) as piecewise polynomials over a knot vector. |
| `special/delta_functions.py` | Implements the `DiracDelta` distribution (continuous delta) and the `Heaviside` step function (unit step). `Heaviside.eval` performs automatic simplification based on argument sign: negative→0, positive→1, zero→user-supplied H0 parameter (configurable value at the indeterminate point), NaN→NaN; it also raises `ValueError` for non-real (complex) arguments via `fuzzy_not(im(arg).is_zero)`. `Heaviside` also defines rewrite methods that convert the step function into equivalent representations: `_eval_rewrite_as_Piecewise` converts to a piecewise/conditional-branch form with boundary-condition logic that shifts inequality directions depending on the value-at-origin parameter H0 (H0=0 uses ≤ for the zero branch, H0=1 uses ≥, unspecified H0 keeps the origin value unevaluated as `Heaviside(0)`), and `_eval_rewrite_as_sign` expresses the step function as `sign(x)/2 + 1/2` (only when H0=½ or unspecified). These rewrite-to-Piecewise and rewrite-to-sign conversion methods live here, not in `elementary/piecewise.py` (which defines the `Piecewise` class itself but not rewrite rules for other functions). `Heaviside.fdiff` returns `DiracDelta`. `DiracDelta.eval` performs analogous simplification: positive/negative real args→0, NaN→NaN, and crucially raises `ValueError` for complex-valued arguments with nonzero imaginary part (via `fuzzy_not(im(arg).is_zero)`), enforcing that the impulse distribution is only defined for real values. For the discrete delta (KroneckerDelta, 1 when indices match, 0 otherwise), see `special/tensor_functions.py`. Note: `SingularityFunction` in `special/singularity_functions.py` delegates to `Heaviside` and `DiracDelta` from this file — the actual step/impulse evaluation logic lives here. |
| `special/elliptic_integrals.py` | Implements complete and incomplete elliptic integrals of the first (`elliptic_k`, `elliptic_f`), second (`elliptic_e`), and third kind (`elliptic_pi`). |
| `special/error_functions.py` | Implements error functions (`erf`, `erfc`, `erfi`, `erf2`, `erfinv`, `erfcinv`), exponential integrals (`Ei`, `expint`, `E1`, `li`, `Li`), trigonometric and hyperbolic integrals (`Si`, `Ci`, `Shi`, `Chi`), and Fresnel integrals (`fresnels`, `fresnelc`). Each error function class's `eval` method includes **composition/inverse simplification**: when an error function is applied to the result of its corresponding inverse function, it collapses to the inner argument (e.g., `erf(erfinv(x))` → `x`, `erfc(erfcinv(x))` → `x`). This is implemented as a conditional branch in `eval` checking `arg.func` against the inverse class — the actual simplification logic lives here in the source, not in the test files (`special/tests/test_error_functions.py`). The trig/hyperbolic integral classes (`Si`, `Ci`, `Shi`, `Chi`) all inherit from `TrigonometricIntegral`, which dispatches argument transformations via class methods: `_minusfactor(z)` handles negated arguments (e.g., `Chi(-z)` → `Chi(z) + iπ`, `Ci(-z)` → `Ci(z) + iπ`), `_Ifactor(z, sign)` handles multiplication by `i` (e.g., `Ci(iz)` → `Chi(z) + iπ/2`, `Shi(iz)` → `i·Si(z)`). These negation and imaginary-argument transformation rules live here — not in `elementary/hyperbolic.py` (which has only the elementary point-valued hyperbolic functions like `cosh`, `sinh`) or `elementary/trigonometric.py` or `special/hyper.py`. Each error function class (including `erf`, `erfc`, and the imaginary error function `erfi`) also contains its own `as_real_imag` method for decomposing complex-valued inputs into real and imaginary parts — for purely real arguments it short-circuits to `(self, 0)`, while for complex arguments it uses an algebraic decomposition via `sq = -y²/x²` to split the result into real and imaginary components. This real/imaginary decomposition logic lives here, not in `elementary/complexes.py` (which only provides the generic `re`/`im` extraction operations). The `expint` class's `eval` method includes half-integer order detection (`not nu.is_Integer and (2*nu).is_Integer`) that reduces half-integer orders to error functions via `uppergamma` — the detection and reduction logic is in `expint.eval` here, not in `special/gamma_functions.py`. Crucially, `expint.eval` also handles analytic continuation when the argument carries a nonzero winding number (branch factor) around the origin: it calls `extract_branch_factor()` on the argument, and when the winding number n ≠ 0, it applies different continuation formulas depending on whether the order parameter is a positive integer (correction term involving `(-1)^(nu-1)/factorial(nu-1)`) or non-integer (correction term involving `exp(2*I*pi*nu*n)*gamma(1-nu)`). This branch-cut / analytic continuation logic for the generalized exponential integral lives here, not in `special/gamma_functions.py` (which handles branch cuts for `lowergamma`/`uppergamma` themselves) or `special/hyper.py`. Each trig/hyperbolic integral class (`Si`, `Ci`, `Shi`, `Chi`) and each error function class also defines its own `_latex` rendering method (with argument-count validation raising `ValueError` and optional exponent formatting) — these LaTeX methods live here, not in `special/gamma_functions.py` (which has its own `_latex` for the gamma function with a similar signature). |
| `special/gamma_functions.py` | Implements the gamma function, upper/lower incomplete gamma functions (`uppergamma`, `lowergamma`), log-gamma, polygamma (`digamma`, `trigamma`), and related utilities. `lowergamma.eval` includes its own branch-factor extraction and analytic continuation logic for the incomplete gamma function itself: it calls `extract_branch_factor()` on the argument and applies different continuation formulas for positive-integer orders (unpolarify only), non-positive-integer orders (correction via `2*pi*I*n*(-1)**(-a)/factorial(-a)`), and non-integer orders (scaling by `exp(2*pi*I*n*a)`). This branch-cut logic is solely for `lowergamma`/`uppergamma` — the analogous but distinct analytic continuation of the generalized exponential integral E_n (`expint`) lives in `special/error_functions.py` (which references lowergamma's approach in comments but implements its own separate integer-vs-non-integer branching formulas). Polygamma represents higher-order logarithmic derivatives of the factorial/gamma function; includes sign-determination logic (`_eval_is_positive`, `_eval_is_negative`) that decides positivity or negativity based on whether the derivative order is even or odd. Polygamma also contains rewrite methods that convert it into equivalent representations: `_eval_rewrite_as_harmonic` expresses the n-th order log-derivative of the factorial function in terms of generalized harmonic numbers (discrete summation sequences of reciprocal powers), with distinct handling for the zeroth-order case (harmonic(z-1) minus Euler-Mascheroni) vs. higher orders (alternating sign × factorial × (zeta − harmonic)); `_eval_rewrite_as_zeta` rewrites in terms of the Hurwitz zeta function. These rewrite-to-harmonic/zeta conversions live here, not in `combinatorial/factorials.py` (which handles factorial computation and its basic `fdiff` derivative delegation to polygamma) or `combinatorial/numbers.py` (which defines the harmonic number class itself). Note: rewrite rules that express other functions *in terms of* uppergamma (e.g., subfactorial as Γ(n+1,-1)/e) live in those functions' own files (e.g., `combinatorial/factorials.py`), not here. Similarly, the generalized exponential integral `expint`'s half-integer order reduction (which uses uppergamma internally) is handled in `special/error_functions.py`, not here. The `gamma` class has a `_latex` rendering method (with argument-count validation and optional exponent formatting), but note that other special function classes like `Chi`, `Ci`, `Si`, `Shi` in `special/error_functions.py` have their own structurally similar `_latex` methods — look there for LaTeX rendering of trigonometric/hyperbolic integrals. |
| `special/hyper.py` | Implements the generalized hypergeometric function `hyper` (pFq), the Meijer G-function `meijerg`, and the `HyperRep` base class for analytic continuation representations. `HyperRep._eval_rewrite_as_nonrep` extracts the branch factor (winding number) from the argument to decide between "negative argument" and standard expression variants, then constructs a `Piecewise` result based on magnitude. Concrete `HyperRep` subclasses (e.g., `HyperRep_power1`, `HyperRep_log1`, etc.) supply the small/big expressions for each regime. |
| `special/mathieu_functions.py` | Implements Mathieu functions (`mathieus`, `mathieuc`) and their derivatives (`mathieusprime`, `mathieucprime`) for the Mathieu differential equation. |
| `special/polynomials.py` | Implements special orthogonal polynomials: Jacobi, Gegenbauer, Chebyshev first kind T (`chebyshevt`) and second kind U (`chebyshevu`), Legendre, associated Legendre, Hermite, Laguerre, and associated Laguerre. All concrete polynomial classes inherit from an `OrthogonalPolynomial` base class defined here, which provides shared evaluation and complex-analysis methods: `_eval_at_order` evaluates at non-negative integer orders via dummy-variable substitution into the underlying polynomial generator, and `_eval_conjugate` computes the complex conjugate by conjugating only the evaluation variable (second argument) while leaving the degree/order parameter (first argument) unchanged — this selective-conjugation behavior is defined here, not in `elementary/complexes.py` or `special/beta_functions.py` (where the beta function conjugates all its arguments). The Jacobi polynomial subclass further overrides `_eval_conjugate` to conjugate the variable argument while preserving the degree and both shape parameters (alpha, beta). Each polynomial's `eval` classmethod contains special-value evaluation logic for symbolic (non-numeric) degree parameters at specific points: for example, `chebyshevt.eval` (first-kind Chebyshev) returns `cos(π·n/2)` at x=0, returns 1 at x=1, applies `(-1)**n` symmetry for negative x, and reflects negative degree to positive — these closed-form trigonometric expressions and symmetry transformations for symbolic degree live here, not in `special/bessel.py` (which has its own zero-argument evaluation logic for Bessel functions of the first/second kind, a different meaning of "first kind"). Each Chebyshev polynomial class also defines an `fdiff` method for differentiation with respect to the variable: `chebyshevt.fdiff` expresses the derivative of the first-kind Chebyshev polynomial T_n as `n * U_{n-1}(x)` (a scalar multiple of the second-kind Chebyshev polynomial), and `chebyshevu.fdiff` expresses the derivative of U_n in terms of both T and U — these derivative connections between first-kind and second-kind Chebyshev basis functions live here, not in `special/bessel.py` (where "first kind" and "second kind" refer to Bessel functions, not trigonometric-cosine/sine-weighted orthogonal polynomials). The Laguerre polynomial's `eval` classmethod contains an exponential-weight transformation for symbolic negative degree: when `n.could_extract_minus_sign()`, it returns `exp(x) * laguerre(n-1, -x)`, rewriting the expression using an exponential factor and argument negation; for fixed negative integer n it raises `ValueError`. Similarly, Hermite's `eval` raises `ValueError` for negative integer degree. These sign-of-degree transformations and validations for orthogonal polynomial basis functions live here — not in `special/bessel.py` (which handles order-sign transformations for Bessel/Hankel functions). |
| `special/singularity_functions.py` | Implements the `SingularityFunction` (Macaulay bracket notation) used in structural engineering beam analysis. `SingularityFunction.eval` reduces to `Heaviside(x-a)*(x-a)**n` for n≥0 and `Derivative(DiracDelta(x-a), ...)` for n<0 — it delegates to `Heaviside` and `DiracDelta` from `special/delta_functions.py` and does not itself implement step-function simplification, value-at-zero handling, or complex-argument validation. |
| `special/spherical_harmonics.py` | Implements spherical harmonic functions `Ynm`, `Ynm_c` (conjugate), and `Znm` (real form). `Ynm.eval` performs automatic simplification for negative arguments: negated azimuthal order m triggers a `(-1)^m * exp(-2*I*m*phi)` factor, negated polar angle theta simply flips the sign, and negated azimuthal angle phi multiplies by `exp(-2*I*m*phi)` — these sign-handling transformations (which go beyond simple sign flips) live here, not in `elementary/trigonometric.py`. `Ynm._eval_expand_func` expands the angular (theta/phi) part into associated Legendre polynomials and exponentials — this is unrelated to radial wave-function expansion, which lives in `special/bessel.py`. |
| `special/tensor_functions.py` | Implements the `KroneckerDelta` (discrete delta: 1 when indices match, 0 otherwise) and `LeviCivita` (Levi-Civita symbol / `Eijk`) tensor-index functions. `KroneckerDelta` includes power-evaluation logic (`_eval_power`) with a subtle edge case for the reciprocal (exponent -1) vs. other negative exponents, as well as fermi-level index assumptions. Not to be confused with the continuous `DiracDelta` distribution in `special/delta_functions.py`. |
| `special/zeta_functions.py` | Implements the Riemann `zeta` function, `dirichlet_eta`, Lerch transcendent (`lerchphi`), `polylog`, and Stieltjes constants. Note: partial sums of reciprocal powers (generalized harmonic numbers H_{n,m} = Σ 1/k^m) and their expansion/evaluation logic live in `combinatorial/numbers.py`, not here — even though H_{∞,m} converges to ζ(m). |
| `special/benchmarks/bench_special.py` | Benchmark for spherical harmonics (`Ynm`) evaluation performance. |
