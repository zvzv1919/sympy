# sympy/sets — Catalog

> Part of [SymPy](../catalog.md). Set theory: intervals, unions, intersections, finite sets, and conditional sets.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point that re-exports the public API: `Set`, `Interval`, `Union`, `Intersection`, `EmptySet`, `FiniteSet`, `ProductSet`, `Complement`, `SymmetricDifference`, `ImageSet`, `Range`, `ComplexRegion`, `Contains`, `ConditionSet`, and the `imageset` helper. |
| `sets.py` | Core set-theory classes including the `Set` base class, `Interval`, `Union`, `Intersection` (the generic container/reducer for multi-set intersections), `Complement`, `SymmetricDifference`, `EmptySet`, `UniversalSet`, `FiniteSet`, and `ProductSet`, plus the `imageset` top-level helper function. The `imageset()` function is the primary entry point for computing forward images of sets under transformations — it is the **sole place** where different callable forms are normalized into a canonical representation: native Python `lambda` functions, symbolic `FunctionClass` objects (like `sin`), and explicit `(variable, expression)` pairs are all converted into symbolic `Lambda` wrappers (generating uniquely named variables as needed) before delegating to `ImageSet`; it also includes an identity-mapping shortcut. `Union.__iter__` implements element-by-element iteration over a combined collection of sets using a round-robin interleaving strategy, and raises `TypeError("Not all constituent sets are iterable")` when any member set does not support enumeration — this is distinct from `Range.__iter__` in `fancysets.py` which handles iteration over integer sequences. For the `ImageSet` class itself, see `fancysets.py`. `FiniteSet._eval_Eq` implements equality comparison for discrete sets: when the other operand is not also a `FiniteSet`, it returns indeterminate (`None`) for compound set types (`Union`, `Complement`, `Intersection`, `ProductSet`) but definitively `false` for all other set types (e.g., `Interval`). `Interval` implements `_union` with logic to merge overlapping continuous ranges — including the subtle case where a half-open endpoint is "filled in" (closed) when the other operand (e.g., a `FiniteSet`) contains that boundary point. `Interval._contains` builds logical expressions checking membership against open/closed bounds. Each set class implements `as_relational(symbol)` to rewrite itself as relational/logical expressions (e.g., `FiniteSet` becomes a disjunction of equalities, `Interval` becomes a conjunction of inequalities). `FiniteSet._contains` implements membership testing with three-valued logic: it iterates over elements comparing via `Eq(e, other)`, returning `true` immediately on a match, accumulating `None` if any comparison is indeterminate (symbolic equality that can't be resolved to true or false even after simplification), and returning that `None` (rather than `false`) at the end — this is the canonical place for handling indeterminate/symbolic membership in explicitly enumerated sets. Also includes set comparison operators and powerset evaluation. `FiniteSet.__new__` accepts an `evaluate` keyword argument (defaulting to `global_evaluate[0]`): when `evaluate=True` and zero arguments are passed, it short-circuits and returns `EmptySet()`; when `evaluate=False`, no such check occurs and an object with zero elements can be constructed — this is the canonical place for evaluate-dependent construction behavior of discrete number sets. `Intersection._handle_finite_sets` is the **canonical method for computing intersections involving discrete bounded (finite) sets**: it uses three-valued logic (`fuzzy_and`/`fuzzy_bool`) to partition each element into confirmed, rejected, or indeterminate (unknown) membership — and then applies a **symbolic-vs-concrete pruning** pass on the unknowns: it separates elements that contain `Symbol` variables from those that are purely numeric, compares the symbolic element lists across all finite-set arguments, and removes concrete unknowns that provably cannot belong to the intersection. This symbolic-vs-concrete distinction for pruning indeterminate elements during finite-set overlap computation lives entirely here, **not** in `conditionset.py` (which performs a simpler true/false/indeterminate sift at construction time without any symbolic-element comparison or pruning). Note: type-specific `_intersect` methods for extended set types like `Range` live in `fancysets.py`, not here. |
| `fancysets.py` | Extended ("fancy") set types: `Naturals`, `Naturals0`, `Integers`, `Reals`, `ImageSet`, `Range` (finite or infinite integer sequences), `ComplexRegion` (polar/rectangular regions of the complex plane), and `normalize_theta_set`. `ImageSet` stores and evaluates a pre-normalized `Lambda` transformation over a base set — it does **not** handle conversion of raw Python callables or function classes into Lambda form (that normalization is performed by the `imageset()` helper in `sets.py`). `ImageSet.__new__` contains constructor-level short-circuits: if the lambda is the identity function it returns the base set directly, and if the lambda is **constant** (its expression has no free symbols or no args, i.e., the transformation doesn't actually depend on its variables) it returns a singleton `FiniteSet` of that constant value rather than creating an `ImageSet` object. `ImageSet._contains` is the **canonical membership test** for determining whether a given element belongs to the range of a mapping applied over a domain — it works by **inverting the transformation**: for multivariate mappings (`_is_multivariate`), it checks whether the Jacobian matrix is all-numeric to decide between using `linsolve` (linear system approach) versus solving each component equation individually via `solveset`; for univariate mappings, it distinguishes scalar→scalar (single `solveset` call) from scalar→vector (solving each component and checking base-set membership). This inverse-solving membership logic lives entirely here, **not** in `sets.py` (which only contains the `imageset()` construction helper). `Range.__iter__` iterates over integer sequences and raises errors for infinite ranges, but iteration over *combined* collections of sets (with non-iterable member handling) is in `Union.__iter__` in `sets.py`. Each fancy set class implements its own `_intersect` method with type-specific logic. `ImageSet._intersect` handles intersection of a function-mapped set with an `Interval` by inverting the lambda expression at the interval's endpoints using `invert_real`/`invert_complex` from `sympy.solvers.solveset`: when the inverted boundary values are complex (non-real) but the target interval is a subset of the reals, it falls back to `solveset` to solve the equation over the reals; if the resulting solution set is a parametric/conditional type (`ImageSet` or `ConditionSet`), the method bails out and returns `None`. `Range._intersect` handles intersection of a discrete integer sequence with a continuous `Interval`, adjusting effective start/end boundaries when the interval has open endpoints at integer values (ceiling/floor with membership checks). For the generic `Intersection` container class, see `sets.py`. |
| `contains.py` | Defines the `Contains` Boolean function, which represents the symbolic assertion that an element belongs to a set (element-of predicate). Does NOT convert sets into relational/logical form — see `as_relational` in `sets.py` for that. |
| `conditionset.py` | Defines `ConditionSet`, a set comprehension class representing `{x | condition(x) is True for x in S}`, with support for intersection and membership testing. `ConditionSet.__new__` handles the special case where the base set is a `FiniteSet` by sifting elements into definitely-true, definitely-false, and indeterminate buckets *at construction time* — this is a simple partition without any symbolic-vs-concrete element analysis or cross-set comparison. For the more advanced logic that computes multi-set overlaps of finite sets by distinguishing variable-containing (symbolic) elements from concrete elements in order to prune indeterminate unknowns, see `Intersection._handle_finite_sets` in `sets.py`. |
