# sympy/sets — Catalog

> Part of [SymPy](../catalog.md). Set theory: intervals, unions, intersections, finite sets, and conditional sets.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point that re-exports the public API: `Set`, `Interval`, `Union`, `Intersection`, `EmptySet`, `FiniteSet`, `ProductSet`, `Complement`, `SymmetricDifference`, `ImageSet`, `Range`, `ComplexRegion`, `Contains`, `ConditionSet`, and the `imageset` helper. |
| `sets.py` | Core set-theory classes including the `Set` base class, `Interval` (continuous real intervals with open/closed boundary options), `Union`, `Intersection`, `Complement`, `SymmetricDifference`, `EmptySet`, `UniversalSet`, `FiniteSet`, and `ProductSet`. The `Interval` constructor (`__new__`) handles boundary edge cases: when both endpoints are equal and any boundary is open/exclusive, it returns `EmptySet`; when both are closed it returns a `FiniteSet` singleton — this is the constructor to look at for questions about interval creation with equal endpoints or open/closed boundary behavior. The `Set` base class defines the `contains` method which handles element-membership queries: it delegates to `_contains` and, when membership is indeterminate (returns `None`), returns an unevaluated symbolic `Contains` expression instead of raising an error. `FiniteSet._contains` implements three-valued membership logic. `Intersection._handle_finite_sets` handles uncertain membership when computing the **intersection** of multiple sets (not condition-based filtering — that is in `conditionset.py`). Set classes here also implement `_eval_Eq` for symbolic equality (`Eq`) comparisons between sets — e.g., `Interval._eval_Eq` returns `None` (unevaluated) when the other object is a compound set type (Union, Complement, Intersection, ProductSet) but returns `false` for all other non-Interval types, enabling three-valued equality dispatch. Set classes here also implement `as_relational(symbol)` methods that rewrite a set as an equivalent logical/relational expression over `symbol` — e.g., `FiniteSet.as_relational` produces a disjunction (`Or`) of equality constraints (`Eq(symbol, elem)` for each element), while `Interval.as_relational` produces a conjunction of inequalities. This is the conversion path from set-theoretic representations to Boolean/relational form. `Interval._eval_imageset` is the method that actually **computes the concrete image/range** of a bounded real interval under a symbolic function — this is where the system determines the output interval's endpoints and their open/closed status. It handles two major cases: (1) **Piecewise functions**: iterates over each conditional branch, intersects the branch's condition-set with the remaining domain, computes the image for that sub-interval, unions the results, and progressively removes already-processed portions of the input domain via `Complement`; (2) **Continuous functions**: evaluates the function at endpoints (using limits for open boundaries), finds critical points via `solveset(diff(...))`, computes `Min`/`Max` of all extrema, and determines output boundary openness — crucially, when the function is **monotonically decreasing** (`_start > _end`), the openness of the output's left boundary is taken from the input's **right** boundary and vice versa, because a decreasing function reverses endpoint ordering. Singularities cause the domain to be split into sub-intervals. Also contains the `imageset` top-level helper function — the primary entry point for constructing image sets. This function handles all input normalization — it **converts** native Python lambdas (`lambda x: ...`) and built-in math functions (like `sin`, `cos`, any `FunctionClass`) into symbolic `Lambda` objects by generating a uniquely named variable symbol to avoid name collisions, then wrapping the call into `Lambda(var, f(var))`. It also handles identity-function short-circuiting, and critically, **composition/flattening of nested image sets**: when the input set is itself an image set and both transformations are single-variable, it composes them into a single transformation over the underlying base set, avoiding nested wrappers. |
| `fancysets.py` | Extended ("fancy") set types: `Naturals`, `Naturals0`, `Integers`, `Reals`, `ImageSet`, `Range` (discrete integer step-sequences, not continuous intervals — for continuous real intervals with open/closed boundaries see `Interval` in `sets.py`), `ComplexRegion`, and `normalize_theta_set`. Each number-set class (`Naturals`, `Naturals0`, `Integers`) implements its own `_contains` method with three-valued membership logic — e.g., `Naturals._contains` returns `True` when the element is both positive and integer, `False` when it is definitely not an integer or definitely not positive, and implicitly `None` (indeterminate) when the element is known to be an integer but its positivity is unknown (and similarly `Naturals0._contains` checks `is_nonnegative`). `Range._contains` also propagates `None` when the candidate's integer nature is unknown, and uses `self.stop` as the reference point for infinite-start ranges. `ImageSet` is a **symbolic container/representation** for {f(x) | x ∈ S} — it stores the transformation and domain but does **not** compute concrete output intervals or determine endpoint openness (that computation lives in `Interval._eval_imageset` in `sets.py`). `ImageSet._contains` implements membership checking by solving for candidate pre-image values and verifying each lies in the domain set. `ImageSet._intersect` computes intersections with other sets. Note: `ImageSet` does **not** convert Python lambdas or perform composition/flattening (that lives in the `imageset()` helper in `sets.py`). `ComplexRegion` handles polar/rectangular regions of the complex plane. It stores its input sets (either a single `ProductSet` or a `Union` of `ProductSet`s) in `self._sets`. Key properties: `psets` returns a **tuple** of the constituent `ProductSet`s — when the stored sets is a single `ProductSet` (not a `Union`), it wraps it in a one-element tuple to guarantee a uniform iterable return type for downstream consumers like `a_interval` and `b_interval`; `_contains` iterates over `psets` to check membership. `Integers` includes `_eval_imageset` which simplifies image-set expressions over ℤ. |
| `contains.py` | Defines the `Contains` Boolean function — a symbolic element-of predicate. Its `eval` classmethod delegates to the set's `contains` method and guards against infinite recursion by returning `None` if the result is already a `Contains` instance. |
| `conditionset.py` | Defines `ConditionSet`, a set comprehension class representing `{x | condition(x) is True for x in S}`. The constructor (`__new__`) is where condition-based filtering and simplification happens: when the base set is a `FiniteSet`, it evaluates the user-supplied condition on each element using `fuzzy_bool` and `sift`, partitioning elements into True/False/None buckets. If all elements resolve, it returns a plain `FiniteSet` of the True elements; if some are indeterminate (`None`), it returns a `Union` of the definitely-true `FiniteSet` and a residual `ConditionSet` wrapping only the indeterminate elements. This is the file to look at for any question about constructing condition-filtered sets or partial evaluation of membership conditions. Note: this file does NOT handle converting sets into relational/logical form (that is `as_relational` in `sets.py`). Also supports intersection narrowing and condition-based symbolic membership testing (checking whether the condition predicate holds for a given element within the base set). |
