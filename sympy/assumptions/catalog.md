# sympy/assumptions — Catalog

> Part of [SymPy](../catalog.md). Assumption system for declaring and querying properties of symbols (positive, integer, etc.).

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports `AppliedPredicate`, `Predicate`, `AssumptionsContext`, `assuming`, `Q`, `ask`, `register_handler`, `remove_handler`, and `refine`. |
| `ask.py` | **The authoritative source for predicate membership semantics and boundary rules** — defines the `AssumptionKeys` class (the `Q` object) where each predicate's mathematical definition, set-membership boundaries, and edge-case classifications are specified in docstrings. For example, the imaginary predicate here explicitly defines that zero is NOT imaginary, the complex predicate excludes infinity, and complement predicates like `Q.nonpositive`/`Q.nonnegative` require real membership (unlike their negations `~Q.positive`/`~Q.negative`) — e.g. `Q.nonnegative(I)` is false but `~Q.negative(I)` is true. Any question about *why* a value is or isn't classified under a predicate (membership boundary behavior) is answered here, not in `handlers/`. Covers scalar predicates (`Q.integer`, `Q.rational`, `Q.real`, `Q.complex`, `Q.positive`, `Q.negative`, `Q.imaginary`, `Q.nonnegative`, `Q.nonpositive`, `Q.prime`, `Q.composite`, `Q.even`, `Q.odd`, etc.), matrix-structure predicates (`Q.diagonal`, `Q.symmetric`, `Q.square`, `Q.fullrank` — whose docstring specifies that a square full-rank matrix has nonzero determinant, `Q.positive_definite`, `Q.orthogonal`, `Q.unitary`, `Q.singular`, `Q.invertible`), matrix-element predicates (`Q.integer_elements`, `Q.real_elements`, `Q.complex_elements`), and `Q.is_true`. Also defines `_extract_facts(expr, symbol)` with asymmetric None-handling (And filters out None children; Or requires all non-None), the `ask()` function, `register_handler()`/`remove_handler()`, and `ask_full_inference()` — the **first SAT fallback** in the resolution chain before `satask()`. |
| `ask_generated.py` | Auto-generated file (via `bin/ask_update.py`) containing two precomputed data structures for inter-predicate implications: (1) `get_known_facts_cnf()` returns all known facts as CNF clauses, including multi-predicate conjunctive implications that require two predicates to hold simultaneously; (2) `get_known_facts_dict()` returns a per-predicate flat-set dictionary mapping each predicate to the set of all predicates it *alone* implies — this dict cannot represent conjunctive implications. This structural gap means the `ask()` system must fall back to SAT solving for conjunctive implications. |
| `assume.py` | Core infrastructure for the assumption system: `AssumptionsContext` (set of active assumptions), `AppliedPredicate` (a predicate applied to an expression), `Predicate` class (with `eval` method that dispatches to registered handlers by iterating MRO to find handler methods by expression class name — this is direct resolution dispatch, not a registry data structure), and low-level `add_handler`/`remove_handler` instance methods, global assumptions store, and the `assuming` context manager. `Predicate.eval` is where handler results are collected and consistency-checked: if two different handlers (resolutors) both return non-None but conflicting truth values for the same query, it raises `ValueError('incompatible resolutors')`. This conflict detection is the core error-handling path for assumption resolution disputes. Does not contain the top-level `register_handler()`/`remove_handler()` functions (those are in `ask.py`), does not define predicate semantics, and does not contain any handler registry class (that is `ClassFactRegistry` in `sathandlers.py`). |
| `refine.py` | Implements `refine()`, which simplifies expressions using assumptions, along with specialized refinement handlers for `Abs`, `Pow`, `exp`, `Q.real`, `atan2`, `Piecewise`, and sign. The `refine_Pow` handler contains detailed assumption-driven simplification of power expressions — including special-case logic for `(-1)**(half-integer)` forms (e.g. `(-1)**((-1)**n/2 + m/2)`) where it doubles the exponent, handles minus-sign extraction via `could_extract_minus_sign()`, decomposes into terms, and uses even/odd parity queries to determine the simplified result. Any question about simplifying powers of negative one under assumptions belongs here, not in `handlers/order.py`. |
| `satask.py` | SAT-based assumption querying via `satask()`: the **second/deeper SAT fallback** invoked by `ask()` only after `ask_full_inference()` (in `ask.py`) returns None. Unlike `ask_full_inference` which tests against precomputed `known_facts_cnf` only, `satask()` iteratively gathers expression-specific relevant facts from handlers and `fact_registry` to build a richer satisfiability problem. Questions about the initial SAT-based fallback mechanism (testing proposition satisfiability against known facts CNF) belong in `ask.py` (`ask_full_inference`), not here. |
| `sathandlers.py` | Defines `UnevaluatedOnFree`, a deferred Boolean-function base class for logical predicate wrappers, with subclasses `AllArgs`, `AnyArgs`, `ExactlyOneArg` that vectorize predicates over expression args. Defines `ClassFactRegistry` (a `MutableMapping` subclass), the inheritance-aware handler registry that maps expression classes to SAT-based inference rules: its `__getitem__` performs superclass aggregation by iterating all registered keys and using `issubclass` to union handlers from every registered parent class, so querying a subclass automatically inherits all handlers registered for its ancestors. Also provides `register_fact()` and the global `fact_registry` instance populated with built-in rules for `Mul`, `Add`, `Pow`, `MatMul`, `Integer`, etc. Additionally defines `evaluate_old_assump`/`_old_assump_replacer` which passively translates new-style predicate queries (e.g. `Q.commutative`) into legacy `.is_*` attribute lookups without applying any default-value logic or assumption overrides. This is infrastructure for SAT-based evaluation mechanics only — active commutativity query handling with defaults and assumption overrides is in `handlers/common.py`. |
| `handlers/__init__.py` | Package init for assumption handlers; re-exports `AskHandler`, `CommonHandler`, `AskCommutativeHandler`, `TautologicalHandler`, and `test_closed_group`. |
| `handlers/calculus.py` | Query handlers exclusively for boundedness predicates (`finite`, `infinite`) — determines whether expressions built from `Add`, `Mul`, `Pow`, `Symbol`, and special constants are bounded. Does NOT handle sign or positivity queries for any function. |
| `handlers/common.py` | Base handler classes: `AskHandler` (empty marker base class with no resolution, registry, or dispatch logic — handler-to-class registration and inheritance-based lookup live in `sathandlers.py`'s `ClassFactRegistry`), `CommonHandler` (always-true/false helpers), `AskCommutativeHandler` (the authoritative handler that determines commutativity for symbols — defaults to True when `is_commutative` is None/unset, and performs a dual-check when `is_commutative` is not None by also consulting explicit assumptions so that `~Q.commutative(x)` in assumptions can override an intrinsic `is_commutative=True`), and `TautologicalHandler` which implements three-valued logic (True/False/None) for **evaluating the truth value** of boolean connectives (`Or`, `And`, `Not`, `Implies`, `Equivalent`) under incomplete knowledge—e.g., `Or` short-circuits on True, propagates None if any arg is unknown, returns False only when all args are definitively False. This handler evaluates whether a compound proposition is true/false/unknown; it does NOT extract or filter symbol-relevant sub-facts from compound expressions (that is `_extract_facts` in `ask.py`). Also provides `test_closed_group` for checking closure under an operation. |
| `handlers/matrices.py` | Query handlers that *evaluate* matrix-related predicates (square, symmetric, invertible, orthogonal, unitary, positive-definite, upper/lower-triangular, diagonal, fullrank, singular) on specific matrix expression types. Contains evaluation dispatch logic only — predicate semantic definitions and inter-predicate inference rules are in `ask.py`. |
| `handlers/ntheory.py` | Query handlers that *evaluate* number-theory predicates (prime, composite, even, odd, rational/irrational) on specific expression types. This is where all runtime edge-case evaluation logic for number-theory queries lives — any question about how the assumption system handles special values (like whether 1 is composite, how primality is tested, or parity of specific expressions) belongs here. For example, composite evaluation queries `Q.positive`, then `Q.integer`, then `Q.prime`, and includes an explicit guard against classifying 1 as composite (since 1 is a positive non-prime integer but is not composite). Primality checking delegates to `isprime()` for numeric values. Predicate semantic definitions and docstrings are in `ask.py`, but the actual handling of special-case values during query evaluation lives here. |
| `handlers/order.py` | Query handlers that *evaluate* order-relation and sign predicates (negative, nonnegative, nonzero, zero, **positive**, nonpositive, extended_real) on specific expression types. Determines the **sign** of `Add`, `Mul`, `Pow`, `log`, `exp`, `factorial`, `Abs`, trig inverses (`atan`, `asin`, `acos`, `acot`), `Trace`, `Determinant`, and `MatrixElement`. For example, `AskPositiveHandler.log` infers ln(x) > 0 by checking whether (x − 1) is positive (i.e. x > 1). Strictly evaluation/dispatch logic — does NOT define predicate semantics (those are in `ask.py`), does NOT simplify or refine expressions (that is in `refine.py`), and does NOT document the distinction between negated predicates (`~Q.positive`) vs complement predicates (`Q.nonpositive`). |
| `handlers/sets.py` | Query handlers that *evaluate* set-membership predicates (integer, rational, irrational, real, extended_real, hermitian, complex, imaginary, antihermitian, algebraic) on specific expression types including `Add`, `Mul`, `Pow`, `exp`, `log`, trig functions, `Symbol`, `Number`, and `ImaginaryUnit`. For compound expressions, handlers implement algebraic closure rules — e.g. `AskRealHandler.Mul` iterates factors and uses XOR parity tracking of imaginary factors to determine if a product is real (real×real→real, imaginary×imaginary→real, real×imaginary→not real), returning None if any factor is neither confirmed real nor imaginary. `AskRealHandler.Pow` handles real-ness of power expressions with detailed case analysis. `AskImaginaryHandler.Mul` similarly tracks factor classifications. Any question about whether an expression *belongs to* a number set (real, imaginary, integer, rational, complex, etc.) is handled here, NOT in `handlers/order.py` which handles *sign/ordering* predicates. Predicate semantic definitions and boundary rules (e.g. whether zero is imaginary) are in `ask.py`. |
