# sympy/assumptions — Catalog

> Part of [SymPy](../catalog.md). Assumption system for declaring and querying properties of symbols (positive, integer, etc.).

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports `AppliedPredicate`, `Predicate`, `AssumptionsContext`, `assuming`, `Q`, `ask`, `register_handler`, `remove_handler`, and `refine`. |
| `ask.py` | Defines the `AssumptionKeys` class (the `Q` object) with all supported predicate keys — each predicate's docstring documents its precise semantic constraints, logical relationships between predicates, and edge cases. Covers number-theory predicates (e.g., `Q.prime` is defined as requiring a natural number greater than 1, so negative integers like `-3` return `False`; `Q.composite` requires a positive integer with at least one non-trivial divisor, so boundary values like `composite(0)`, `composite(1)`, and `composite(2)` all return `False` — 2 is the smallest prime and has no divisors other than 1 and itself; `Q.even`/`Q.odd` for parity), numeric predicates (e.g., `Q.nonzero` requires realness, so `Q.nonzero(I)` is False while `~Q.zero(I)` is True; similarly `Q.nonpositive` vs `~Q.positive` differ for complex numbers), and matrix predicates (e.g., `Q.diagonal`, `Q.upper_triangular`, `Q.lower_triangular`, `Q.fullrank`, `Q.square`, `Q.symmetric`, `Q.orthogonal`, `Q.positive_definite` — the docstrings define how predicates interrelate — including implication chains such as orthogonal → invertible (a matrix satisfying M^T M = I is necessarily non-singular), unitary → invertible, and diagonal ↔ upper-triangular ∧ lower-triangular). Each predicate's docstring includes worked `ask()` examples demonstrating cross-predicate inferences — e.g., the `diagonal` predicate shows that querying diagonality given both lower- and upper-triangular assumptions returns `True`, illustrating how the system determines that satisfying both triangularity conditions implies only main-diagonal entries. Also defines the `ask()` function that queries expressions against assumptions using registered handlers, and the `_extract_facts()` helper which recursively extracts facts relevant to a specific symbol from compound logical assumptions — it applies De Morgan's law to negated conjunctions/disjunctions, filters out `None` sub-results for `And` (conjunctions) while requiring all sub-results present for other connectives (`Or`, etc.). **Critically, this file also contains `get_known_facts()`, which assembles the complete static knowledge base of logical entailment rules between predicates as a single `And(...)` conjunction of `Implies` and `Equivalent` statements** — e.g., integer implies rational, rational implies algebraic, zero implies even, diagonal implies symmetric, orthogonal implies positive-definite, upper-triangular ∧ lower-triangular implies diagonal, fullrank ∧ square implies invertible, etc. This conjunction is the human-readable *source of truth* for all inter-predicate entailment relationships; `ask_generated.py` contains the machine-compiled CNF and dict forms derived from it. **This is the authoritative source for what each predicate *means* — including domain restrictions and edge cases (e.g., whether negative integers count as prime)**; look in `handlers/` for the resolution *implementation* logic that evaluates these predicates on specific expression types. |
| `ask_generated.py` | Auto-generated file (via `bin/ask_update.py`) containing the **compiled/encoded forms** of inter-predicate entailment rules, derived from `ask.py::get_known_facts()`. Provides two functions: `get_known_facts_cnf()` returns all known facts as a single `And(...)` of `Or(Not(...), ...)` clauses in Conjunctive Normal Form — this is where specific logical deduction rules are *concretely encoded* for the SAT solver in `satask.py`, including both simple two-literal implications (e.g., `Or(Not(Q.diagonal), Q.lower_triangular)` encoding diagonal → lower-triangular) and compound multi-literal deduction rules as three-or-more-way disjunctions (e.g., `Or(Not(Q.lower_triangular), Not(Q.upper_triangular), Q.diagonal)` encoding that simultaneously satisfying both triangular orientations entails diagonal). `get_known_facts_dict()` returns a precomputed transitive-closure dict mapping each predicate to the set of predicates it implies. **If the question is about where a specific entailment rule is stored/encoded for the inference engine, this file contains the actual encoded data**; for the human-readable source definitions and semantic reasoning behind the rules, see `ask.py`. |
| `assume.py` | Core infrastructure for the assumption system: `AssumptionsContext` (set of active assumptions), `AppliedPredicate` (a predicate applied to an expression), `Predicate` (including `Predicate.eval` which resolves truth values by walking the expression type's MRO across registered handler classes and raises on conflicting resolutor results), global assumptions store, and the `assuming` context manager. This is where direct resolution dispatch happens — not in `satask.py` (SAT-based) or `handlers/` (individual handler logic). |
| `refine.py` | Implements `refine()`, which simplifies expressions using assumptions, along with specialized refinement handlers for `Abs`, `Pow`, `exp`, `Q.real`, `atan2`, `Piecewise`, and sign. |
| `satask.py` | SAT-based assumption querying via `satask()`: converts a proposition and assumptions into a satisfiability problem and iteratively gathers all relevant known facts to determine truth values. |
| `sathandlers.py` | Defines helper Boolean-function classes for SAT-based inference and a `ClassFactRegistry` that maps expression types to SAT-based inference rules for `satask`. The central class is `UnevaluatedOnFree`, a `BooleanFunction` subclass that wraps predicate logic expressions and enforces strict validation in its `__new__` constructor: it raises `ValueError` if applied predicates target more than one distinct symbol/expression (e.g., `Or(Q.positive(x), Q.negative(y))` is rejected because `x` and `y` differ), and also raises `ValueError` if the argument mixes free (unapplied) and applied predicates. On valid singly-applied input it calls `apply()`, and on free predicates it remains unevaluated (for later evaluation via `.rcall()`). Subclasses `AllArgs`, `AnyArgs`, `ExactlyOneArg` vectorize predicates over expression `.args`; `CheckOldAssump` bridges to the old assumption system. See `handlers/common.py` for the separate `TautologicalHandler` that evaluates logical connectives during direct (non-SAT) queries. |
| `handlers/__init__.py` | Package init for assumption handlers; re-exports `AskHandler`, `CommonHandler`, `AskCommutativeHandler`, `TautologicalHandler`, and `test_closed_group`. |
| `handlers/calculus.py` | Query handlers for calculus-related predicates (`finite`, `infinite`) that determine boundedness of expressions built from `Add`, `Mul`, `Pow`, `Symbol`, and special constants. The `AskFiniteHandler.Pow` method contains the authoritative logic for whether an exponentiation is bounded: it compares the absolute value of the base to unity (|base| ≤ 1 vs |base| ≥ 1) combined with the sign of the exponent (positive vs negative) to decide boundedness — e.g., |base| ≤ 1 with positive exponent → bounded, |base| ≥ 1 with negative exponent → bounded, unbounded base with nonzero exponent → unbounded. This is the only location for finiteness/boundedness evaluation of `Pow` — `handlers/order.py` handles sign predicates on `Pow`, not boundedness. |
| `handlers/common.py` | Base handler classes: `AskHandler` (abstract base), `CommonHandler` (always-true/false helpers), `AskCommutativeHandler`, and `TautologicalHandler` (evaluates compound logical connectives — `And`, `Or`, `Not`, `Implies`, `Equivalent` — using three-valued logic where indeterminate/`None` truth values are propagated: conjunction short-circuits on `False` but accumulates `None`, disjunction short-circuits on `True` but accumulates `None`, implication is reduced to `~p | q`). Also provides `test_closed_group` for checking closure under an operation. This is where the *logical connective evaluation* happens during a query; `satask.py` is a separate SAT-based pathway. |
| `handlers/matrices.py` | Query handler *implementations* for evaluating matrix-related predicates on specific expression types (`MatMul`, `MatAdd`, `MatrixSymbol`, etc.) — determines truth values by inspecting expression structure (e.g., checking whether all factors of a `MatMul` satisfy a predicate). This file does NOT define what predicates mean or how they relate to each other (e.g., whether orthogonal implies invertible) — for predicate *definitions*, semantic meaning, and inter-predicate logical relationships (such as orthogonal → invertible, unitary → invertible), see `ask.py`. |
| `handlers/ntheory.py` | Query handler *implementations* for number-theory predicates: prime, composite, even, and odd. Contains the evaluation logic (e.g., calls `isprime()`) but does *not* define the predicates' semantic meaning, domain constraints, or boundary-case behavior (e.g., whether negative integers are prime, or why `composite(2)` returns `False`) — for predicate definitions, edge-case documentation, and worked boundary-case examples see `ask.py`. Does *not* handle rational/irrational classification — those are in `handlers/sets.py`. |
| `handlers/order.py` | Query handlers for order-relation predicates (negative, nonnegative, nonzero, zero, positive, nonpositive, extended_real) applied to `Add`, `Mul`, `Pow`, and numeric types. These handlers *evaluate* sign/order truth values for specific expression types — they do NOT define predicate semantics or domain constraints (those are in `ask.py`), and they do NOT handle boundedness/finiteness queries (those are in `handlers/calculus.py`). |
| `handlers/sets.py` | Query handlers for set-membership predicates: integer, rational, irrational, real, extended_real, hermitian, complex, imaginary, antihermitian, and algebraic. The `AskImaginaryHandler` contains per-expression-type methods including `Pow` (multi-branch logic for imaginary status of powers), `log` (imaginary status of logarithms — includes a hardcoded workaround for `log(exp(I))` and `log(exp(-I))` where the general `Q.nonpositive` query on exp with imaginary arguments incorrectly returns `None`), and `exp`. Also includes `Pow` handlers that determine rationality/irrationality of exponentiation (e.g., prime base with rational exponent yields irrational), as well as rationality of transcendental functions (`exp`, `log`, `sin`, `cos`, etc.). This is the authoritative location for rational/irrational classification — not `handlers/ntheory.py`. For sign/order predicates (negative, nonpositive, positive, etc.) applied to `Pow` and other expression types, see `handlers/order.py`. |
