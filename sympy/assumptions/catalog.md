# sympy/assumptions — Catalog

> Part of [SymPy](../catalog.md). Assumption system for declaring and querying properties of symbols (positive, integer, etc.).

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports `AppliedPredicate`, `Predicate`, `AssumptionsContext`, `assuming`, `Q`, `ask`, `register_handler`, `remove_handler`, and `refine`. |
| `ask.py` | Defines the `AssumptionKeys` class (the `Q` object) with all predicate key definitions — scalar predicates (e.g. `Q.integer`, `Q.rational`, `Q.real`, `Q.complex`, `Q.positive`, `Q.negative`, `Q.imaginary`, `Q.nonnegative`, `Q.nonpositive`, `Q.prime`, `Q.composite`, `Q.even`, `Q.odd`, etc.), matrix-structure predicates (e.g. `Q.diagonal`, `Q.symmetric`, `Q.square`, `Q.fullrank`, `Q.positive_definite`, `Q.orthogonal`, `Q.unitary`, `Q.singular`, `Q.invertible`), and matrix-element predicates (e.g. `Q.integer_elements`, `Q.real_elements`, `Q.complex_elements`). Each predicate definition includes its mathematical docstring with precise membership semantics, edge-case behavior (e.g. `Q.composite` documents that 0, 1, and 2 are all not composite), and usage examples that demonstrate inter-predicate inference (e.g. `Q.diagonal` shows inferring diagonal from `Q.lower_triangular & Q.upper_triangular`). Critically documents the semantic distinction between predicate negation (`~Q.positive`) and complement predicates (`Q.nonpositive`): negation simply means "not known positive" while complement predicates additionally require real membership, so e.g. `~Q.positive(I)` is True but `Q.nonpositive(I)` is False. Also defines the `ask()` function, `register_handler()` and `remove_handler()` for dynamically adding/removing handlers in the ask system (notably, `register_handler` auto-creates a new `Predicate` on `Q` if the property name doesn't already exist), `ask_full_inference()` for SAT-based property inference, and `compute_known_facts()`/`single_fact_lookup()` for precomputing inter-predicate implication data. This is where predicates are *defined* with their semantic boundaries and edge-case rules; handlers that *evaluate* them on specific expression types live under `handlers/`. |
| `ask_generated.py` | Auto-generated file (via `bin/ask_update.py`) containing two precomputed data structures for inter-predicate implications: (1) `get_known_facts_cnf()` returns all known facts as CNF clauses, including multi-predicate conjunctive implications like `Or(Not(Q.fullrank), Not(Q.square), Q.invertible)` (meaning fullrank ∧ square → invertible) that require two predicates to hold simultaneously; (2) `get_known_facts_dict()` returns a per-predicate flat-set dictionary mapping each predicate to the set of all predicates it *alone* implies — this dict cannot represent conjunctive implications, so e.g. `Q.fullrank` maps only to `{Q.fullrank}` despite the CNF rule above. This structural gap means the `ask()` system must fall back to SAT solving for conjunctive implications. |
| `assume.py` | Core infrastructure for the assumption system: `AssumptionsContext` (set of active assumptions), `AppliedPredicate` (a predicate applied to an expression), `Predicate` class (with `eval` method that dispatches to registered handlers by iterating MRO to find handler methods by expression class name — this is direct resolution dispatch, not a registry data structure), and low-level `add_handler`/`remove_handler` instance methods, global assumptions store, and the `assuming` context manager. Does not contain the top-level `register_handler()`/`remove_handler()` functions (those are in `ask.py`), does not define predicate semantics, and does not contain any handler registry class (that is `ClassFactRegistry` in `sathandlers.py`). |
| `refine.py` | Implements `refine()`, which simplifies expressions using assumptions, along with specialized refinement handlers for `Abs`, `Pow`, `exp`, `Q.real`, `atan2`, `Piecewise`, and sign. The `refine_Pow` handler contains detailed assumption-driven simplification of power expressions — including special-case logic for `(-1)**(half-integer)` forms (e.g. `(-1)**((-1)**n/2 + m/2)`) where it doubles the exponent, handles minus-sign extraction via `could_extract_minus_sign()`, decomposes into terms, and uses even/odd parity queries to determine the simplified result. Any question about simplifying powers of negative one under assumptions belongs here, not in `handlers/order.py`. |
| `satask.py` | SAT-based assumption querying via `satask()`: converts a proposition and assumptions into a satisfiability problem and iteratively gathers all relevant known facts to determine truth values. |
| `sathandlers.py` | Defines `UnevaluatedOnFree`, a deferred Boolean-function base class for logical predicate wrappers, with subclasses `AllArgs`, `AnyArgs`, `ExactlyOneArg` that vectorize predicates over expression args. Defines `ClassFactRegistry` (a `MutableMapping` subclass), the inheritance-aware handler registry that maps expression classes to SAT-based inference rules: its `__getitem__` performs superclass aggregation by iterating all registered keys and using `issubclass` to union handlers from every registered parent class, so querying a subclass automatically inherits all handlers registered for its ancestors. Also provides `register_fact()` and the global `fact_registry` instance populated with built-in rules for `Mul`, `Add`, `Pow`, `MatMul`, `Integer`, etc. Additionally defines `evaluate_old_assump`/`_old_assump_replacer` which passively translates new-style predicate queries (e.g. `Q.commutative`) into legacy `.is_*` attribute lookups without applying any default-value logic or assumption overrides. This is infrastructure for SAT-based evaluation mechanics only — active commutativity query handling with defaults and assumption overrides is in `handlers/common.py`. |
| `handlers/__init__.py` | Package init for assumption handlers; re-exports `AskHandler`, `CommonHandler`, `AskCommutativeHandler`, `TautologicalHandler`, and `test_closed_group`. |
| `handlers/calculus.py` | Query handlers exclusively for boundedness predicates (`finite`, `infinite`) — determines whether expressions built from `Add`, `Mul`, `Pow`, `Symbol`, and special constants are bounded. Does NOT handle sign or positivity queries for any function. |
| `handlers/common.py` | Base handler classes: `AskHandler` (abstract base), `CommonHandler` (always-true/false helpers), `AskCommutativeHandler` (the authoritative handler that determines commutativity for symbols — defaults to True when `is_commutative` is None/unset, and performs a dual-check when `is_commutative` is not None by also consulting explicit assumptions so that `~Q.commutative(x)` in assumptions can override an intrinsic `is_commutative=True`), and `TautologicalHandler` which implements three-valued logic (True/False/None) for evaluating boolean connectives (`Or`, `And`, `Not`, `Implies`, `Equivalent`) under incomplete knowledge—e.g., `Or` short-circuits on True, propagates None if any arg is unknown, returns False only when all args are definitively False. Also provides `test_closed_group` for checking closure under an operation. |
| `handlers/matrices.py` | Query handlers that *evaluate* matrix-related predicates (square, symmetric, invertible, orthogonal, unitary, positive-definite, upper/lower-triangular, diagonal, fullrank, singular) on specific matrix expression types. Contains evaluation dispatch logic only — predicate semantic definitions and inter-predicate inference rules are in `ask.py`. |
| `handlers/ntheory.py` | Query handlers that *evaluate* number-theory predicates (prime, composite, even, odd, rational/irrational) on specific expression types. Contains evaluation dispatch logic only — predicate semantic definitions, edge-case rules (e.g. whether 0, 1, 2 are composite), and docstrings are in `ask.py`. |
| `handlers/order.py` | Query handlers that *evaluate* order-relation and sign predicates (negative, nonnegative, nonzero, zero, **positive**, nonpositive, extended_real) on specific expression types. Determines the **sign** of `Add`, `Mul`, `Pow`, `log`, `exp`, `factorial`, `Abs`, trig inverses (`atan`, `asin`, `acos`, `acot`), `Trace`, `Determinant`, and `MatrixElement`. For example, `AskPositiveHandler.log` infers ln(x) > 0 by checking whether (x − 1) is positive (i.e. x > 1). Strictly evaluation/dispatch logic — does NOT define predicate semantics (those are in `ask.py`), does NOT simplify or refine expressions (that is in `refine.py`), and does NOT document the distinction between negated predicates (`~Q.positive`) vs complement predicates (`Q.nonpositive`). |
| `handlers/sets.py` | Query handlers that *evaluate* set-membership predicates (integer, rational, irrational, real, extended_real, hermitian, complex, imaginary, antihermitian, algebraic) on specific expression types. Contains evaluation dispatch logic only — predicate semantic definitions and boundary rules (e.g. whether zero is imaginary) are in `ask.py`. |
