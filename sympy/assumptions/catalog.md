# sympy/assumptions — Catalog

> Part of [SymPy](../catalog.md). Assumption system for declaring and querying properties of symbols (positive, integer, etc.).

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports `AppliedPredicate`, `Predicate`, `AssumptionsContext`, `assuming`, `Q`, `ask`, `register_handler`, `remove_handler`, and `refine`. |
| `ask.py` | Defines the `AssumptionKeys` class (the `Q` object) with all supported predicate keys — each predicate's docstring documents its precise semantic constraints, logical relationships between predicates, and edge cases. Covers both numeric predicates (e.g., `Q.nonzero` requires realness, so `Q.nonzero(I)` is False while `~Q.zero(I)` is True; similarly `Q.nonpositive` vs `~Q.positive` differ for complex numbers) and matrix predicates (e.g., `Q.diagonal`, `Q.upper_triangular`, `Q.lower_triangular`, `Q.fullrank`, `Q.square`, `Q.symmetric`, `Q.orthogonal`, `Q.positive_definite` — the docstrings define how predicates interrelate, such as diagonal being equivalent to the conjunction of upper-triangular and lower-triangular). Also defines the `ask()` function that queries expressions against assumptions using registered handlers, and the `_extract_facts()` helper which recursively extracts facts relevant to a specific symbol from compound logical assumptions — it applies De Morgan's law to negated conjunctions/disjunctions, filters out `None` sub-results for `And` (conjunctions) while requiring all sub-results present for other connectives (`Or`, etc.). Look here for predicate *definitions, semantics, and inter-predicate relationships*; look in `handlers/` for the resolution *implementation* logic that evaluates these predicates on specific expression types. |
| `ask_generated.py` | Auto-generated file (via `bin/ask_update.py`) containing precomputed known-fact implications between predicates in CNF and a single-fact lookup dict. |
| `assume.py` | Core infrastructure for the assumption system: `AssumptionsContext` (set of active assumptions), `AppliedPredicate` (a predicate applied to an expression), `Predicate` (including `Predicate.eval` which resolves truth values by walking the expression type's MRO across registered handler classes and raises on conflicting resolutor results), global assumptions store, and the `assuming` context manager. This is where direct resolution dispatch happens — not in `satask.py` (SAT-based) or `handlers/` (individual handler logic). |
| `refine.py` | Implements `refine()`, which simplifies expressions using assumptions, along with specialized refinement handlers for `Abs`, `Pow`, `exp`, `Q.real`, `atan2`, `Piecewise`, and sign. |
| `satask.py` | SAT-based assumption querying via `satask()`: converts a proposition and assumptions into a satisfiability problem and iteratively gathers all relevant known facts to determine truth values. |
| `sathandlers.py` | Defines helper Boolean-function classes (`UnevaluatedOnFree`, `AllArgs`, `AnyArgs`, `ExactlyOneArg`, `CheckOldAssump`) and a `ClassFactRegistry` that maps expression types to SAT-based inference rules for `satask`. |
| `handlers/__init__.py` | Package init for assumption handlers; re-exports `AskHandler`, `CommonHandler`, `AskCommutativeHandler`, `TautologicalHandler`, and `test_closed_group`. |
| `handlers/calculus.py` | Query handlers for calculus-related predicates (`finite`, `infinite`) that determine boundedness of expressions built from `Add`, `Mul`, `Pow`, `Symbol`, and special constants. |
| `handlers/common.py` | Base handler classes: `AskHandler` (abstract base), `CommonHandler` (always-true/false helpers), `AskCommutativeHandler`, and `TautologicalHandler` (evaluates compound logical connectives — `And`, `Or`, `Not`, `Implies`, `Equivalent` — using three-valued logic where indeterminate/`None` truth values are propagated: conjunction short-circuits on `False` but accumulates `None`, disjunction short-circuits on `True` but accumulates `None`, implication is reduced to `~p | q`). Also provides `test_closed_group` for checking closure under an operation. This is where the *logical connective evaluation* happens during a query; `satask.py` is a separate SAT-based pathway. |
| `handlers/matrices.py` | Query handler *implementations* for evaluating matrix-related predicates on specific expression types (`MatMul`, `MatAdd`, `MatrixSymbol`, etc.) — determines truth values for predicates like square, symmetric, invertible, orthogonal, unitary, positive-definite, upper/lower-triangular, diagonal, fullrank, and singular. For predicate *definitions* and their semantic relationships (e.g., what diagonal means, how it relates to triangularity), see `ask.py`. |
| `handlers/ntheory.py` | Query handlers for number-theory predicates: prime, composite, even, and odd. Does *not* handle rational/irrational classification — those are in `handlers/sets.py`. |
| `handlers/order.py` | Query handlers for order-relation predicates (negative, nonnegative, nonzero, zero, positive, nonpositive, extended_real) applied to `Add`, `Mul`, `Pow`, and numeric types. |
| `handlers/sets.py` | Query handlers for set-membership predicates: integer, rational, irrational, real, extended_real, hermitian, complex, imaginary, antihermitian, and algebraic. Includes `Pow` handlers that determine rationality/irrationality of exponentiation (e.g., prime base with rational exponent yields irrational), as well as rationality of transcendental functions (`exp`, `log`, `sin`, `cos`, etc.). This is the authoritative location for rational/irrational classification — not `handlers/ntheory.py`. |
