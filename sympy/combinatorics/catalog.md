# sympy/combinatorics -- Catalog

> Part of [SymPy](../catalog.md). Combinatorics: permutations, partitions, polyhedra, group theory, and Graycode.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package initializer; imports and re-exports the main public classes and functions (Permutation, Prufer, Subset, Partition, Polyhedron, PermutationGroup, GrayCode, named groups, etc.). |
| `coset_table.py` | Implements the `CosetTable` class and Todd-Coxeter coset enumeration algorithms (relator-based and coset-table-based) for finitely presented groups. |
| `fp_groups.py` | Defines `FpGroup` (finitely presented groups) and related algorithms including low-index subgroup enumeration, Reidemeister-Schreier presentations, and permutation group isomorphism. Does **not** pre-set or determine algebraic properties like nilpotency or solvability — for named group construction with pre-computed structural properties (including dihedral/symmetric/alternating groups), see `named_groups.py`. |
| `free_group.py` | Implements `FreeGroup` and `FreeGroupElement` for constructing and manipulating free groups and their elements with word-level arithmetic. The **`__str__` method** uses a **generator-count threshold of 30** to switch display formats: when `rank > 30`, it returns a compact summary string `<free group with N generators>` instead of listing all generators; at 30 or fewer generators, it enumerates them as `<free group on the generators (x, y, z, ...)>` — this display-threshold logic lives here in `FreeGroup`, **not** in `fp_groups.py::FpGroup` (which is a finitely *presented* group with relators, not a free group). Also provides three factory functions with different return conventions: `free_group` (returns a flat tuple of the group and its generators for unpacking), `xfree_group` (returns the group and a nested tuple of generators), and `vfree_group` (injects the generators directly into the caller's **global namespace** via `pollute`, avoiding explicit unpacking — this is the variant for automatic namespace injection of named algebraic elements). |
| `generators.py` | Provides generator functions that **yield individual `Permutation` elements** (not `PermutationGroup` objects) of standard groups: `symmetric`, `cyclic`, `alternating`, `dihedral`, and Rubik's cube generators. The `dihedral(n)` generator includes special-case handling for degenerate polygons (n=1, n=2) where the group cannot naturally embed in Sn, hardcoding embeddings in S2 and S4 respectively. The `rubik(n)` function generates permutations for an arbitrary n×n Rubik's cube using face-matrix manipulation; when rotating the outermost slice (index 0), it additionally rotates the corresponding face itself, unlike deeper interior slices which only cycle adjacent strips. Internally, `rubik` defines a **dual-purpose local `perm` function**: when called with no argument (or `show=0`), it reads the current face-matrix state, assembles a flat permutation list, wraps it in a `Permutation`, and appends it to the accumulator list `g`; when called with `show=1`, it instead **returns** the raw flat list without appending, enabling identity verification. After generating all slice permutations for each spatial direction (F, R, D), the function uses `assert perm(1) == I` (where `I = list(range(6*n**2))`) to **verify that the cube's state has been properly restored** to the original identity configuration — this assertion-based restoration check lives here, **not** in `permutations.py` (whose `is_Identity` property checks whether an already-constructed `Permutation` object is the identity, but is not involved in the rubik generator's state-verification mechanism). For constructing named group *objects* (`PermutationGroup`) with pre-set algebraic properties, see `named_groups.py`. |
| `graycode.py` | Implements the `GrayCode` class for generating and manipulating Gray codes (reflected binary codes) over n-dimensional binary cubes. The `rank` property gives the ordinal position of a raw bit-pattern string within the Gray code sequence — it does **not** accept subset objects (for ranking a chosen subset within Gray code order, see `subsets.py::Subset.rank_gray`). Also provides standalone module-level conversion functions: `gray_to_bin` (converts reflected binary encoding back to standard positional binary using cumulative XOR), `bin_to_gray` (converts standard binary to reflected binary), `get_subset_from_bitstring` (extracts a subset from a set using a bitmask string), and `graycode_subsets` (enumerates all subsets in Gray code order). |
| `group_constructs.py` | Provides the `DirectProduct` function for computing the direct product of multiple `PermutationGroup` objects (high-level group API); operates on group objects, not on raw BSGS base/generator pairs. Shifts each group's generators into a combined degree space by array-slicing into identity-initialized arrays, then **deduplicates** the resulting shifted generators (removing duplicate permutations, e.g., multiple identity-like generators from trivial input groups) before constructing the result `PermutationGroup` with `dups=False`. Does not specifically filter identity permutations (unlike `tensor_can.py::bsgs_direct_product`), but does eliminate exact duplicates. For BSGS-level direct products that combine base-and-strong-generating-set structures (with identity filtering and signed-permutation support), or for raw array-form generator direct products that handle sign information in the last two positions, see `tensor_can.py::bsgs_direct_product` and `tensor_can.py::perm_af_direct_product`. |
| `homomorphisms.py` | Implements `GroupHomomorphism` and a `homomorphism()` factory for creating and working with group homomorphisms between permutation groups and finitely presented groups. |
| `named_groups.py` | Factory functions for constructing standard named `PermutationGroup` objects (construction only — does **not** compute runtime group properties like order/size; for computing the number of elements in a group, including fast-path optimizations for symmetric and alternating groups, see `perm_groups.py::PermutationGroup.order`): `SymmetricGroup`, `CyclicGroup`, `DihedralGroup` (the group of rigid motions / symmetries of a regular n-gon — constructs rotation and reflection generators; uses a **bitwise power-of-2 check** (`n & (n-1) == 0`) to pre-set nilpotency, since the dihedral group's lower central series terminates at the identity if and only if the vertex count is a power of 2), `AlternatingGroup` (the group of **even permutations** on n elements), `AbelianGroup`, and `RubikGroup`. Each factory **pre-sets algebraic properties** (commutativity, nilpotency, solvability) on the returned group based on element-count thresholds — e.g., `AlternatingGroup` marks the group non-abelian/non-nilpotent at n≥4 and non-solvable at n≥5 (A5 is the smallest non-solvable group); for n=1 or n=2 the normal generator logic is bypassed entirely, returning a trivial identity-only group. Small degenerate cases (n=1, n=2) receive special handling with trivial generators across all factories. For yielding individual permutation elements rather than group objects, see `generators.py`. This module is the correct location for questions about algebraic property determination (nilpotency, solvability, etc.) of specific named groups — **not** `fp_groups.py`, which handles finitely presented group construction and word-level algorithms but does not pre-set or determine these structural properties. |
| `partitions.py` | Defines `Partition` (set partitions — a collection of **disjoint** subsets whose union equals a given set) and `IntegerPartition` classes, along with RGS (restricted growth string) ranking/unranking utilities. The **constructor (`Partition.__new__`)** validates that each argument is a list or `FiniteSet`, then enforces the disjointness invariant by **flattening all subsets into a single list and checking for duplicate elements** via `has_dups` — if any element appears in more than one subset (i.e., subsets overlap), a `ValueError("Partition contained duplicated elements.")` is raised. This duplicate/overlap validation lives here, **not** in `subsets.py` (which deals with individual subsets of a universal set, not partitions-as-sets-of-disjoint-sets). `Partition` supports **rank-based arithmetic**: `__add__` and `__sub__` advance or retreat through all possible set partitions (groupings) of the partition's members by incrementing/decrementing the RGS rank with **modular wrap-around** (`offset % RGS_enum(size)`), cycling back to the beginning when exceeding the total count of partitions. This rank-based modular cycling through set groupings lives here, **not** in `perm_groups.py` (whose `coset_rank`/`coset_unrank` converts between *group elements* and lexicographic indices in a permutation group's stabilizer chain — a different kind of ranking). Also provides `from_rgs` for constructing a `Partition` from a restricted growth string, and `RGS_rank`/`RGS_unrank`/`RGS_enum` module-level functions for converting between RGS sequences and ordinal positions. |
| `perm_groups.py` | Core `PermutationGroup` class implementing group-theoretic operations: **`order()`** computes the total number of elements (size) of the group — uses fast-path shortcuts when the group is recognized as a full symmetric group (`factorial(n)`) or alternating group (`factorial(n)/2`), otherwise falls back to multiplying the sizes of coset transversals from the stabilizer chain decomposition; this is the **only** location of group-order computation logic (not in `named_groups.py`, which only pre-sets algebraic properties during construction but does not compute order). Also provides orbits, stabilizers, centralizer computation, normal closure (`normal_closure` computes the smallest normal subgroup containing a given input — uses `hasattr`-based type dispatch at the end of the method to accept a `PermutationGroup`, a list/sequence of permutations, or a single `Permutation` element, wrapping the latter cases into a `PermutationGroup` and recursing), orbit representative computation (`orbit_rep` finds a group element mapping one point to another using the Schreier vector — when the source and target points are identical, the while-loop accumulator stays empty and the method returns an identity permutation via `range(degree)` instead of composing generators), Schreier-Sims algorithm — `schreier_sims` is the main entry point that computes the stabilizer chain G > G_{b_1} > … > 1, its coset transversals, and basic orbits; it **caches/memoizes** results by checking `self._transversals` and returning immediately if already computed, avoiding redundant recomputation on repeated calls; when the computed base sequence is empty (trivial group / identity-only generators), it explicitly sets transversals and basic orbits to empty lists rather than attempting orbit computation. Lazy-init properties `basic_stabilizers`, `basic_orbits`, and `basic_transversals` all share the same trigger: they check whether `self._transversals` (the cached coset-representative dictionaries) is empty to decide whether `schreier_sims()` needs to run — notably, `basic_stabilizers` does **not** have its own dedicated cache field but instead inspects `_transversals` as a proxy for whether the BSGS computation has already occurred, then builds and returns the stabilizer chain fresh each time from the cached base and strong generators via `_distribute_gens_by_base`. The underlying `schreier_sims_incremental` is the polynomial-time incremental variant that extends a partial base/generating set to a full BSGS, handling edge cases like generators that fix all existing base points by appending new moved points, identity removal, and trivial-group shortcuts. **Coset ranking/unranking** (`coset_rank` and `coset_unrank`): converts between group elements and lexicographic integer indices using a mixed-radix number system based on the stabilizer chain — `coset_rank` encodes an element as an integer by accumulating orbit-index digits weighted by orbit sizes at each stabilizer level; `coset_unrank` reverses this by using `divmod` at each level to extract the mixed-radix digit, look up the corresponding orbit element, and multiply the transversal elements together to reconstruct the group element. These ranking/unranking methods live here, **not** in `util.py`. Also provides `baseswap` for swapping two consecutive base points in a BSGS — the deterministic version iterates over the basic orbit, computing the image of the next base point under each transversal inverse: when this image falls outside the subsequent stabilizer's orbit, the algorithm **prunes** by removing the orbit of that candidate under the current generators from the search set (rather than adding a new generator); otherwise it composes the two transversal elements and adds the result as a new generator if it moves the base point to a new orbit element; also has a randomized (Las Vegas) variant. Coset decomposition (`coset_factor`), subgroup testing, and general `subgroup_search` (depth-first backtrack search over base images with per-level pruning predicates built from orbit representatives and transversals — initializes a base ordering augmented with **sentinel boundary values**: one element larger than all points and one smaller than all points, used in minimality tests during the search; accepts user-defined property predicates to filter which group elements are included in the result subgroup). Also contains standalone module-level orbit functions that do **not** require BSGS data: `_orbit` computes the set of elements reachable from a starting point via BFS-like expansion over generators (supports action modes for unions, tuples, and frozensets), using a boolean `used` array to track visited indices; `_orbits` partitions the full index set {0,…,degree−1} into disjoint equivalence classes by repeatedly picking the smallest unassigned index, computing its orbit via `_orbit`, removing those indices from the remaining set, and repeating until all indices are assigned — this is the **only** location of standalone orbit-partitioning logic; `util.py` does **not** contain an `_orbits` function (it only has `_orbits_transversals_from_bsgs` which requires pre-computed BSGS data). The constructor (`__new__`) accepts generators of different sizes and automatically pads them to a uniform degree, reconciling domain-size mismatches. Also provides random/pseudo-random group element generation: `make_perm` composes n randomly selected permutations from the group starting from the identity — accepts either an integer count with an optional seed, or a sequence of selection indices (in which case providing a separate seed raises `ValueError`); `random` returns a random element via coset unranking; `random_pr` uses the product replacement algorithm with a cached internal random-generator state (`_random_gens`). For building a group as a direct product of existing groups, see `group_constructs.py`. For BSGS-specific orbit/transversal computation from a base and distributed strong generators, see `util.py::_orbits_transversals_from_bsgs`. The `is_alt_sym` method tests whether a group is alternating or symmetric using random permutations, but the actual prime-cycle-length arithmetic check it delegates to lives in `util.py`. |
| `permutations.py` | Core `Permutation` and `Cycle` classes for representing and manipulating **individual** permutations in array and cyclic notation, with support for composition (the `__mul__` operator computes `b(a(i))` and **automatically pads the shorter operand** with identity elements when two permutations have different domain sizes, reconciling length mismatches at the individual-permutation level — this is distinct from `perm_groups.py::PermutationGroup.__mul__` which computes the *group-level* direct product by shifting generator index spaces), inversion, parity (`is_even`/`is_odd`), and lexicographic ranking. **Multi-format constructor (`Permutation.__new__`)**: the constructor accepts seven distinct input representations and decides which internal form to produce — (a) no args → identity of given size, (b) single integer `n` → identity on 0…n, (c) multiple integer args → interpreted as a single cycle, (d) flat list of ints → **array form** (direct index mapping), (e) list of lists → **cyclic form** (disjoint cycle notation, converted to array form internally), (f) a `Cycle` object → converted to array form via `.list()`, (g) an existing `Permutation` → returned as-is or resized. The constructor distinguishes array notation from cycle notation by checking whether elements are themselves sequences (`is_sequence`); if a mix of sequence and non-sequence elements is found, a `ValueError` is raised. **Input-format gotcha**: passing a flat iterable like `range(n)` or a flat list `[0,1,2,…]` is interpreted as **array form**, but wrapping that iterable inside an extra set of brackets (e.g., `[range(n)]` or `[[0,1,2,…]]`) silently switches interpretation to **cycle notation**, producing a completely different permutation — this is a documented subtlety in the `Permutation` class docstring. Any question about how individual element reorderings are created from different input formats (flat integer lists, nested lists of disjoint swaps, cycle objects) belongs here, **not** in `perm_groups.py` (whose constructor assembles a *group* from generator permutations, not an individual permutation from raw input). Also contains **module-level array-form permutation utility functions** that operate on raw Python lists (not `Permutation` objects): `_af_rmul` composes two permutations in array form; `_af_rmuln` composes an arbitrary number of permutations in array form — it unrolls explicit nested-index-lookup branches for up to 8 operands for performance, and for **more than 8 permutations** falls back to a recursive divide-and-conquer strategy that splits the operand list in half, recurses on each half, and composes the two results, avoiding deeply nested index chains; `_af_parity` computes the parity of a permutation in array form by counting cycles; `_af_invert` finds the inverse of an array-form permutation. Does **not** set group-level algebraic properties (commutativity, nilpotency, solvability) — for constructing named groups of even permutations (alternating groups) or other standard groups with pre-set algebraic properties, see `named_groups.py`. The `rank()` method computes the lexicographic position of a permutation using the Lehmer code (factorial number system) and caches the result in `_rank` for repeated lookups. Also provides `unrank_lex`/`unrank_nonlex` for reconstructing permutations from rank, and `next_lex`/`next_nonlex` for iteration. Includes the `josephus` classmethod — a deque-based simulation of the Josephus circular elimination problem (every m-th element is removed from a ring of n elements) that returns the elimination order as a `Permutation`; has a parameter `s` that switches the step size to 1 when `s` items remain, selecting the remainder one-by-one. Also provides `full_cyclic_form` — a property that returns the cycle decomposition **including length-1 orbits (fixed-point singletons)**: it computes which elements are absent from the standard `cyclic_form` (which omits fixed points) and appends them as single-element cycles, producing a complete partition of the domain into disjoint orbits; any question about decomposing a finite bijection into disjoint orbits that **includes** trivial/fixed-point orbits belongs here, **not** in `perm_groups.py::_orbits` (which partitions the index set of a *group* into equivalence classes, not the cycle structure of an individual permutation). The **`__repr__`** method implements **economical printing**: in array-form display, it strips trailing fixed points (elements mapping to themselves at the end of the array) to minimize output length, appending a `size=N` parameter when the full domain size differs from the trimmed display; any question about how the string representation of a reordering omits trailing identity-mapped elements to shorten output belongs here, **not** in `perm_groups.py`. Also provides permutation distance metrics: `get_positional_distance` (L1/element-wise), `get_precedence_distance`, and `get_adjacency_distance`. For subset-level lexicographic ranking, see `subsets.py`. Does **not** contain random/seeded permutation generation from a group — composing randomly selected group elements (with seed or index-based selection) is in `perm_groups.py::PermutationGroup.make_perm`. |
| `polyhedron.py` | Implements the `Polyhedron` class for representing polyhedral symmetry groups, with pre-built instances for the five Platonic solids (tetrahedron, cube, octahedron, dodecahedron, icosahedron). Includes internal helper functions such as a shorthand string parser (`_string_to_perm`) that composes face-rotation permutations for the dodecahedron pgroup — characters '0'/'1' select base rotations while other digit characters act as repeat-count multipliers for the previous rotation. Also contains `_pgroup_of_double` for computing dual-polyhedron permutation groups. The **constructor (`Polyhedron.__new__`)** validates that rotation permutations match the number of corners; when **no rotation permutations are provided** (empty or omitted pgroup), it **defaults to an identity-only `PermutationGroup`** (a single identity permutation `Perm(range(len(corners)))`) rather than leaving the group unset — this fallback lives here in the constructor, **not** in `named_groups.py` (which constructs standard named groups like `SymmetricGroup` but is not involved in polyhedron default symmetry assignment). The constructor docstring demonstrates how applying symmetry group elements generates all valid orientations of a solid and verifies that sequential transformation application equals composite permutation application. |
| `prufer.py` | Implements the `Prufer` class for the bijection between labeled trees and Prufer sequences, with ranking/unranking and tree-edge conversion methods. |

| `subsets.py` | Implements the `Subset` class for enumerating subsets of a set via binary, lexicographic, and Gray code orderings with ranking/unranking support. Includes `rank_gray`/`unrank_gray` and `rank_binary`/`unrank_binary` for converting between ordinal positions and actual subset (power-set element) objects. `rank_gray` determines the ordinal position of a chosen collection of elements within Gray code ordering by converting the subset to a bit-list and delegating to `GrayCode.rank`. The unranking methods (e.g., `unrank_gray`) compose a bit-pattern lookup with `subset_from_bitlist` to return a full `Subset` object — they live here, not in `graycode.py`. Provides **binary-order traversal/iteration** over power-set elements: **`iterate_binary(k)`** steps forward or backward by `k` positions in standard binary counting order — it converts the current subset to a bit-list, interprets it as an integer, adds `k` with **modular wrap-around** (`% 2**superset_size`), then converts back to a bit-string and returns the corresponding `Subset` via `subset_from_bitlist`; this modular arithmetic ensures that stepping past the last subset (all elements) wraps to the empty set and vice versa. Convenience wrappers `next_binary` and `prev_binary` call `iterate_binary(1)` and `iterate_binary(-1)` respectively. This binary-order subset stepping with bit-encoded modular cycling lives here, **not** in `partitions.py` (whose `Partition.__add__`/`__sub__` cycle through set *partitions* (groupings into disjoint subsets) via RGS rank arithmetic — a different combinatorial object). Also provides **Gray code traversal/iteration** over power-set elements: `iterate_graycode(k)` steps forward or backward by an arbitrary number of positions `k` in reflected binary code order using modular arithmetic on the Gray code rank (`(rank_gray + k) % cardinality`), with convenience wrappers `next_gray` and `prev_gray` for single-step traversal — this is the location for stepping through subsets in Gray code order (not `graycode.py`, which handles raw bit-pattern generation/conversion but not subset-level traversal). Similarly, `next_lexicographic` and `prev_lexicographic` provide single-step traversal in dictionary order. Any question about ranking, unranking, or **traversing/iterating** a **subset** (collection of elements from a universal set) in binary or Gray code order belongs here; see `graycode.py` only for raw bit-pattern-level Gray code generation, conversion between binary and reflected binary encodings, and bit-string ranking without subset semantics. |
| `tensor_can.py` | Algorithms for tensor canonicalization using permutation group double-coset representatives (`double_coset_can_rep` — finds canonical forms for tensors, not a general-purpose subgroup search; for depth-first backtrack search over group elements satisfying a predicate, see `perm_groups.py::subgroup_search`), including dummy-index symmetry handling. Also provides BSGS *composition* utilities specific to tensor contexts: `bsgs_direct_product` for combining two base-and-strong-generating-set (BSGS) structures into a single BSGS — operates on base/generator pairs (not `PermutationGroup` objects), filters out identity permutations from the combined generators, and falls back to returning a single identity generator when all combined generators reduce to the identity; `perm_af_direct_product` for computing the **raw array-form direct product** of two lists of generators acting on disjoint index ranges — in signed mode (`signed=True`), each generator carries **sign information in its last two positions** (the final two elements encode a sign/orientation indicator), and the function strips these sign positions before padding, inserts the other group's index range in the middle, then re-appends the sign positions shifted by the other group's size, producing combined generators over the merged index space with sign tracking preserved; in unsigned mode, generators are simply concatenated with identity padding — this low-level array-form generator combination lives here, **not** in `group_constructs.py` (whose `DirectProduct` operates on high-level `PermutationGroup` objects without sign-position handling); and `get_symmetric_group_sgs` for minimal BSGS of (anti)symmetric tensors. Does **not** contain general BSGS construction algorithms (Schreier-Sims, incremental BSGS) — those live in `perm_groups.py`; low-level BSGS helpers (orbit/transversal computation, strip, distribution) are in `util.py`. Does **not** contain graph isomorphism / graph fingerprinting logic — for computing a canonical certificate of an undirected graph (by reducing it to a tensor canonicalization problem), see `testutil.py::graph_certificate`. |
| `testutil.py` | Testing/verification utilities for the combinatorics module. Contains **only** naive (brute-force) reference implementations used in test suites to validate the optimized algorithms in `perm_groups.py` and `tensor_can.py` — never called in production codepaths. Key functions: (1) `canonicalize_naive` — brute-force tensor canonicalization that enumerates all slot and dummy symmetry permutations, sorts them, and detects zero tensors by finding consecutive sorted permutations that agree on all positions except the last (differing sign); this is the naive counterpart to `tensor_can.py::double_coset_can_rep`. (2) `_verify_bsgs` — **validates** a proposed base and strong generating set (BSGS) by distributing the generators across base points, then iteratively comparing the order of each successive point-stabilizer subgroup against the candidate subgroup at that level, and confirming the final stabilizer is trivial (order 1); this is the definitive location for BSGS **correctness verification** — `perm_groups.py` only *computes* the BSGS, it does not verify one. (3) `_verify_centralizer`, `_verify_normal_closure` — naive verification wrappers that mirror the `hasattr`-based duck-typing dispatch found in the production `perm_groups.py` methods but compute results via brute-force enumeration for correctness checking. (4) `graph_certificate` — computes a unique canonical fingerprint for an **undirected graph** (without external edges) given as an adjacency-list dict, enabling graph isomorphism testing (two structurally equivalent graphs produce identical certificates). The algorithm **reduces the graph to a tensor canonicalization problem**: it models each vertex as a symmetric tensor whose number of indices equals the vertex degree, assigns even/odd index pairs to each edge, assembles these into a flat index array, and then delegates to `tensor_can.canonicalize` to compute the canonical (standard) form — this tensor-reduction approach to graph fingerprinting lives here, **not** in `tensor_can.py` (which provides the general-purpose tensor canonicalization engine `double_coset_can_rep` / `canonicalize` but has no graph-specific logic). This is a brute-force approach not intended for production use. For production (optimized) algorithms including normal closure computation, orbit representatives, and type-dispatch logic, see `perm_groups.py`. |
| `util.py` | Internal low-level utility functions for computational group theory: base ordering, **prime-cycle-length verification** (checks whether a permutation contains a cycle whose length is a prime number strictly between n/2 and n−2 — this is the concrete arithmetic check used by the higher-level alternating/symmetric group test in `perm_groups.py`), BSGS-related **`_strip`** (attempts to decompose/sift a permutation through a stabilizer chain by iterating over base points: at each level, computes the image of the base point under the current element, checks if that image lies in the corresponding orbit — if it does **not**, the function **returns early** with the partially-reduced element and the level number `i + 1` at which sifting failed, signaling unsuccessful membership; if the image is in the orbit, it multiplies by the inverse transversal to continue stripping — this early-return-on-missing-orbit-element behavior is the key mechanism for detecting non-membership, and it lives here, **not** in `perm_groups.py::coset_unrank` which converts integer indices to group elements via mixed-radix decomposition without membership testing), **`_strip_af`** (optimized array-form variant of `_strip` where the element, transversals, and result are all in raw list form instead of `Permutation` objects; includes an **identity-detection short-circuit**: when the current element `h` exactly equals the transversal element `u` at some level, it returns `(False, base_len + 1)` immediately — the `False` sentinel signals that the residual is the identity permutation without computing the full product, since `h * u^{-1}` would be identity; this identity-detection optimization lives here, **not** in `perm_groups.py::orbit_rep`), and distribution routines — notably `_distribute_gens_by_base` which sorts generators into successive stabilizer levels based on which base points each generator fixes, and for **stabilizer depths that no generator reaches** (i.e., levels beyond the deepest any generator fixes all prior base points), fills those levels with a list containing only the **identity permutation** as a fallback (constructed via `_af_new(list(range(degree)))`); this identity-fallback behavior for empty stabilizer levels lives here, **not** in `perm_groups.py` (whose `schreier_sims_incremental` extends a partial BSGS but does not handle per-level identity insertion), **BSGS-specific orbit/transversal computation** (`_orbits_transversals_from_bsgs` — given a foundation sequence (base) and generators already partitioned by stabilizer-level membership, computes the point-sets (orbits) each stabilizer level acts on and the coset representative dictionaries mapping each orbit point to the group element that carries the base point to it; accepts a `transversals_only` flag that skips orbit-list construction when only the coset representative mappings are needed, returning just the dictionaries — this is the location for deriving orbit/transversal structures from pre-distributed generators, **not** `perm_groups.py` which handles the Schreier-Sims stabilizer chain computation itself and element enumeration/generation via `generate_schreier_sims`), **lazy BSGS structure completion** (`_handle_precomputed_bsgs` — given whichever subset of BSGS-derived structures are already available (transversals, orbits, distributed generators), lazily fills in the missing ones by calling `_orbits_transversals_from_bsgs` and `_distribute_gens_by_base` as needed, avoiding redundant recomputation), and redundant generator removal (`_remove_gens` — prunes unnecessary generators from a strong generating set to obtain a smaller equivalent set; this is a one-time set-reduction operation, not a caching or recomputation-avoidance mechanism). Does **not** contain: (1) general orbit-partitioning functions that work from raw generators without BSGS — those standalone `_orbit`/`_orbits` functions live in `perm_groups.py`; (2) coset ranking/unranking (mixed-radix index ↔ group element conversion) — that lives in `perm_groups.py`; (3) base swapping algorithms — `baseswap` lives in `perm_groups.py`; (4) high-level group algorithms (centralizer, normalizer, subgroup search, Schreier-Sims) — those also live in `perm_groups.py`; (5) group element enumeration/generation in coset rank order — `generate_schreier_sims` lives in `perm_groups.py`. |
