| `simplify.py` | Core simplification routines including `simplify`, `separatevars` (and its internal helper `_separatevars`), `nsimplify`, `besselsimp`, `logcombine`, `posify`, `signsimp`, and `bottom_up`. **`_separatevars`** decomposes a multi-variable expression into a product of single-variable factors; when the expression is a sum (Add), it uses `args_cnc` to compute the intersection of commutative multiplicative components across all terms, strips out numeric constants, removes those shared factors from each term, then attempts a second round of `factor()` on the remainder — only accepting the factored form if it is no longer an Add. This two-pass approach (extract common non-numeric multiplicative factors, then try factoring the stripped remainder) is the mechanism for isolating variables from sums; it is distinct from `radsimp.py`'s `collect` (which groups terms by a user-specified symbolic expression) and from `cse_main.py`'s `opt_cse` (which factors shared operands for CSE pre-processing). The `simplify` entry point uses a **`_eval_simplify` dispatch**: it first tries calling `expr._eval_simplify(**kwargs)` to delegate to any custom general-simplification method on the expression object before applying standard simplification heuristics — this is the *general* simplification dispatch, distinct from `trigsimp.py`'s trig-specific `_eval_trigsimp` dispatch. For expressions that are **not basic arithmetic operations** (not Add, Mul, Pow, or ExpBase), `simplify` has a dedicated **inverse-function collapsing** path: if the expression is a `Function` with an `inverse` attribute, and it wraps a single argument that is itself an instance of that inverse function with a single argument (e.g., `sin(asin(x))`, `log(exp(x))`), it collapses the composition to the innermost argument. This inverse-function detection and cancellation lives here in `simplify.py`, **not** in `trigsimp.py` — even for trigonometric inverse pairs like sin/asin, cos/acos, tan/atan — because it is a generic algebraic identity (f(f⁻¹(x)) = x) handled before any domain-specific simplification strategies are applied. **`signsimp`** canonicalizes all Add sub-expressions with respect to leading negative signs: if an Add `a` satisfies `could_extract_minus_sign`, it is replaced with `Mul(-1, -a, evaluate=False)`, enabling signs to propagate through powers and products. The `evaluate` keyword (default True) controls whether "hollow" sign extractions are reverted: when True, if the sign-canonical form doesn't actually simplify the expression, the original Add is restored; when `evaluate=False`, the transformed form is **retained even when no real reduction occurred** — e.g., `exp(y - x)` becomes `exp(-(x - y))`. This sign-normalization of summation sub-expressions (extracting leading negative factors from Add nodes) is distinct from `powsimp.py` (which combines bases/exponents of algebraic powers but does not extract or canonicalize signs of Add sub-expressions) and from `fu.py` (which applies trig identity rewrites). Also contains `hypersimp` (simplifies the consecutive-term ratio f(k+1)/f(k) of a combinatorial expression by rewriting in terms of gamma functions and reducing; returns None if the result is not a rational function in k) and `hypersimilar` (tests hyper-similarity). |
| `trigsimp.py` | Trigonometric and hyperbolic simplification via `trigsimp` and `exptrigsimp`. **`exptrigsimp`** is the function responsible for converting between exponential (natural-base power) representations and periodic/hyperbolic function representations: given an expression, it generates multiple candidate rewrites — the original form, a rewrite in terms of `exp`, and a rewrite in terms of `cos` — then selects the candidate with the fewest operations using `count_ops` as its metric, providing automatic "best form" selection between exp and trig/hyperbolic representations. After choosing the minimal-ops form, it further converts remaining exp patterns into sinh/cosh or tanh via half-angle substitution patterns (e.g. detecting `exp(a)/exp(b)` ratios). This exp↔trig/hyperbolic conversion logic and its `count_ops`-based selection metric live here, not in `fu.py` (which handles trig-to-trig rule chains and uses expression complexity to compare candidates within its own rule-chain strategy). The `trigsimp` entry point uses a **duck-typing dispatch**: it first tries calling `expr._eval_trigsimp(**opts)` on the input expression, and only falls back to standard simplification methods if the expression doesn't define that method (catches `AttributeError`). This allows custom expression types to override trigonometric simplification behavior entirely. Also contains **`trigsimp_old`**, the legacy trig simplification routine (invoked when `old=True`). For **multi-variable expressions**, `trigsimp_old` uses `separatevars` to split the expression into multiplicative factors by variable, then processes each factor independently: it saves the original factor, expands it via `expand_mul`, and simplifies the expanded form. If the simplified result equals the expanded form (i.e. no actual simplification occurred), the code **reverts to the original unexpanded factor** to "remove hollow factoring" — avoiding gratuitous expansion when it yields no benefit. For additive multi-variable expressions, it instead separates terms independent of each trig symbol and simplifies the dependent parts individually. Contains the `_trigpats` function which builds ordered pattern-matching rewrite-rule tables — most notably **`matchers_division`**, a sequence of (pattern, replacement, guard1, guard2) tuples for rewriting quotients/products of circular and hyperbolic functions into simpler forms (sin/cos→tan, tan·cos→sin, sinh/cosh→tanh, coth·tanh→1, etc.); the first 14 entries have a **critical ordering constraint** ("DO NOT REORDER THE FIRST 14") because `_match_div_rewrite` assumes they appear in exactly that order. Also builds `matchers_add` (angle-sum combination rules), `matchers_identity` (Pythagorean-identity rewrites), and `matchers_artifact` (cleanup rules), all used by the pattern-driven strategy. The cached recursive helper **`__trigsimp`** implements a **two-phase matching strategy** for Mul expressions: it first tries a fast direct rewrite via `_match_div_rewrite` (which handles both circular indices 0–5 and hyperbolic indices 8–13, with indices 6–7 explicitly skipped), and only if that returns None or no change does it fall back to full symbolic `.match()` pattern matching against the `matchers_division` patterns, with additional guards checking coefficient positivity and whether the matched sub-expression already contains trig/hyperbolic functions with the same argument. This two-phase approach (fast rewrite of products like sin·cos⁻¹→tan or sinh·cosh⁻¹→tanh, then general pattern fallback) is distinct from `fu.py`'s individual transform rules. The fast direct rewrite path in `__trigsimp` uses **`_replace_mul_fpowxgpow`**, a helper that rewrites products of two different periodic-function powers into a single equivalent function power — e.g., sin(x)^n · cos(x)^(-n) → tan(x)^n, or tan(x)^n · cos(x)^n → sin(x)^n. It collects exponents for each function type from the Mul args, finds arguments common to both function types, checks whether their exponents satisfy the required relationship, and rebuilds the product. **Critical validity guard**: the substitution only proceeds when the function base evaluates as positive (`b.is_positive`) OR the exponent is an integer (`e.is_integer`), preventing invalid transformations for complex arguments. This trig-specific power-product rewriting is distinct from `powsimp.py` (which handles general algebraic power combination, not trig function powers) and from `fu.py`'s TR111 (which handles single negative-power trig-to-reciprocal conversion, not products of two different trig function powers). Also contains a Groebner-basis strategy (`trigsimp_groebner`) that analyses generators of trig/hyperbolic terms, decomposes ratio-type functions (e.g. tan into sin and cos), constructs polynomial ideals, and reduces via Groebner bases. When the fraction's denominator only involves a subset of generators, `trigsimp_groebner` performs a **transitive-closure partitioning** of the generator set: for each coefficient, it starts from the generators appearing in that coefficient and the denominator, then iteratively expands the set by walking through ideal relations — if any polynomial in the ideal shares variables with the current set, all of that polynomial's generators are absorbed — until a fixed point is reached. This partitions the Groebner basis into disjoint subsets so each coefficient is simplified via `ratsimpmodprime` using only its relevant portion of the basis, rather than the full basis. This generator-partitioning-via-ideal-reachability logic lives here in `trigsimp.py`, **not** in `ratsimp.py`'s `ratsimpmodprime` (which is called as a subroutine but does not itself perform the partitioning or transitive closure computation). The Groebner strategy exposes a **hints system** that lets users guide simplification by expanding the search space: passing a number widens the angle multiples tried, passing a function (e.g. `tan`) adds it as a candidate, and passing an iterable like `(tan, x, y)` suggests angle-sum generators — enabling discovery of double-angle, half-angle, or angle-sum identities that the default search space would miss. Does NOT contain individual numbered transform rules (TR0–TR22, TR111), hyperbolic↔trig Osborne-rule conversion, or trig-term product-form decomposition — those live in `fu.py`. Note: the `_eval_trigsimp` dispatch here is distinct from the `_eval_simplify` dispatch in `simplify.py` — the latter handles general simplification, not trig-specific simplification. |
| `radsimp.py` | Radical simplification and term collection: `collect`, `rcollect`, `radsimp`, `collect_const`, `fraction`, `numer`, and `denom` for rationalizing denominators and grouping terms by a user-specified symbolic expression. `collect` groups terms by powers of a given symbol/expression but does not decompose expressions into independent single-variable factors or extract shared multiplicative components across all terms of a sum — for that, see `separatevars`/`_separatevars` in `simplify.py`. |
| `powsimp.py` | Power simplification via `powsimp` (combine bases/exponents of powers) and `powdenest` (simplify nested power expressions). Operates on general algebraic powers only — does not handle products of different periodic-function powers (e.g., sin(x)^n · cos(x)^m → tan(x)^n; that rewriting lives in `trigsimp.py`'s `_replace_mul_fpowxgpow`), trigonometric power identities, tangent addition fractions, or trig-to-reciprocal power conversions (those live in `fu.py`). |
| `ratsimp.py` | Rational expression simplification via `ratsimp` (common denominator, cancel, reduce) and `ratsimpmodprime` (simplification of rational expressions modulo a given polynomial prime ideal using Groebner bases). Does not construct ideals from trig/hyperbolic generators; for Groebner-based trig ideal construction and generator analysis see `trigsimp.py`. |
| `combsimp.py` | Combinatorial simplification via `combsimp`, which reduces expressions involving factorials, binomials, and Pochhammer symbols by rewriting through gamma functions. Does not handle consecutive-term ratio analysis (see `hypersimp` in `simplify.py` for that). |
| `gammasimp.py` | Gamma function simplification via `gammasimp`, applying rising-factorial rewriting, reflection theorem, and multiplication theorem to minimize gamma function count. |
| `sqrtdenest.py` | Denesting of nested square roots via `sqrtdenest`, with helpers for measuring sqrt depth and checking algebraic structure of radical expressions. Contains **`sqrt_depth`**, which computes the maximum nesting level of radical (half-power) subexpressions within a symbolic expression tree by recursively walking the tree: Add/Mul nodes pass through (taking the max depth of their children), half-power (square root) nodes increment the depth counter by 1, and atoms return 0. This radical-nesting-depth computation lives here, **not** in `radsimp.py` (which rationalizes denominators and collects terms but does not measure or track nesting depth of radical subexpressions). Also contains `is_algebraic` (checks whether an expression is built purely from rationals and radicals with algebraic operations) and `_subsets` (generates non-empty subsets in reverse lexicographic binary order for fourth-root denesting). |
| `fu.py` | Implementation of the Fu et al. trigonometric simplification algorithm. The top-level **`fu` orchestration function** is the main entry point: it first applies rule-chain RL1 (greedy sequence of tan/cot transforms) if the expression contains `tan`/`cot`, then applies rule-chain RL2 (greedy sequence of sin/cos transforms) if `sin`/`cos` are present, generates multiple candidate results at each stage, and returns the smallest candidate according to a user-supplied objective/measure function (defaulting to expression complexity). This chain-then-compare strategy — not Groebner bases or pattern tables — is what decides which rewrite rules fire first and which candidate wins. Also provides a library of numbered transform rules (TR0--TR22, TR111, TRmorrie) and combination transforms that are applied in heuristic order. **TR2i** converts sin/cos ratios into tan: it splits an expression into numerator and denominator power dictionaries, filters factors via an inner validity check, optionally factorizes Add terms, then joins matching sin/cos pairs into tan. In **half-angle mode** (`half=True`), TR2i also recognizes patterns where the numerator contains `1 + cos(x)` and the denominator contains `sin(x)`, converting them to `cot(x/2)` (i.e. `tan(x/2)**-n`), with an **additional positivity/integer guard** on the denominator factor: the conversion only proceeds if the exponent is an integer OR the sine base is positive. This half-angle sin/cos-ratio-to-tan conversion with its extra assumption check lives here in `fu.py`, **not** in `trigsimp.py`'s `_replace_mul_fpowxgpow` (which rewrites products of two different trig function powers like sin^n·cos^-n→tan^n, but does not handle `1+cos` sum patterns or half-angle tangent conversion). Contains **`process_common_addends`**, a helper that groups the terms of an Add by absolute coefficient value (key1) and/or a secondary grouping function (key2), then applies a given transformation to each group; raises **`ValueError('must have at least one key')`** if neither key1 (coefficient-based grouping) nor key2 (secondary grouping function) is specified. **TR0** is the rational polynomial simplification step: it deliberately avoids using `cancel` because `cancel` doesn't work with noncommutative expressions, and instead uses the alternative chain `.normal().factor().expand()` to simplify rational polynomials (e.g. combining like terms such as 3*x + 2*x). **TR8** converts products of `cos` and/or `sin` into sums or differences (product-to-sum identities, e.g. cos(a)·cos(b) → cos(a+b)/2 + cos(a−b)/2); on the **first invocation** (`first=True`) it separates the expression into numerator and denominator via `as_numer_denom`, applies TR8 recursively (`first=False`) to each part independently, then recombines with `gcd_terms`; on **recursive calls** (`first=False`) it categorizes Mul factors by trig type (cos, sin, or other), expanding integer powers into repeated factors, then pairs them using product-to-sum formulas. This first-call/recursive-call split for numerator/denominator handling is distinct from `trigsimp.py`'s `trigsimp_groebner`, which also processes numerator and denominator separately but via Groebner-basis polynomial reduction rather than product-to-sum trig identities. **TR9** converts sums of trigonometric terms into products (sum-to-product identities, e.g. cos(x)+cos(y) → 2·cos((x+y)/2)·cos((x−y)/2)); when given more than two terms (e.g. cos(x)+cos(y)+cos(z)), it uses a **pairwise combination strategy** — iterating over all pairs, merging matching pairs in-place (marking successfully combined terms as None), and recursively simplifying the resulting expression. **TR10** separates compound-angle sums inside sin/cos into angle-addition expansions (e.g. cos(a+b) → cos(a)cos(b)−sin(a)sin(b)). Includes **TR10i**, which recombines pairwise products of sine and cosine back into compound-angle expressions (e.g. cos(a)cos(b)+sin(a)sin(b) → cos(a−b)); for sums with more than two terms it iterates over all pairs, combining matching pairs in-place and continuing until no further reductions are found. **TR12/TR12i** handle tangent addition formulas: TR12 expands tan(x+y) into the addition formula, and TR12i reverses this — combining fractions of the form (tan(a)+tan(b))/(1−tan(a)·tan(b)) back into tan(a+b), with denominator-factor matching that handles power expressions (including factoring fallbacks when a Pow base doesn't match the expected tangent-product pattern). TR111 handles negative-power trig-to-reciprocal conversion (e.g. sin(x)**-2 → csc(x)**2), guarding on whether the exponent is a negative integer or the base is positive; unrecognized trig bases (e.g. sec, csc, cot) silently pass through unchanged. Also contains hyperbolic↔trigonometric conversion via the Osborne rule (`hyper_as_trig`, internal `_osborne`/`_osbornei`), which maps sinh/cosh/tanh/coth to trig equivalents (raising NotImplementedError for unmapped hyperbolic types like sech/csch), and `trig_split`, which decomposes weighted sums of periodic terms (a·cos + b·sin) into product form by detecting coefficient ratios (1:1→π/4, √3:1→π/3, 1:√3→π/6) to determine the phase angle. **TR14** converts factored products of the form `(trig(x) ± 1)*(trig(x) ∓ 1)` into negative squared complementary functions using the Pythagorean difference-of-squares identity — e.g. `(cos(x)-1)*(cos(x)+1)` → `-sin(x)**2`, `(sin(x)-1)*(sin(x)+1)` → `-cos(x)**2`. It classifies each Mul factor using `as_f_sign_1` to detect the `g*(f ± 1)` pattern, sorts factors to bring like-function terms adjacent, then pairs factors with the same trig function but opposite signs (±1 vs ∓1). When paired factors have **different exponents**, it takes the minimum exponent for the Pythagorean reduction and reinserts the remainder back into the processing queue for further pairing. On the first call, it splits numerator and denominator to handle only positive exponents. This factored-product Pythagorean reduction is distinct from `trigsimp.py`'s `__trigsimp` (which matches quotient/product patterns like sin/cos→tan via ordered rewrite-rule tables, not difference-of-squares `(f±1)(f∓1)` factor pairing). These are individual expression-level transform functions (each applied independently), not the ordered pattern-matching rewrite-rule tables (like `matchers_division` with its position-dependent ordering constraint) or Groebner-based hint-guided search-space expansion found in `trigsimp.py`. Does NOT handle multi-variable expression decomposition via `separatevars` or recursive per-variable factor simplification with hollow-factoring guards — that multi-variable decompose-and-reduce logic lives in `trigsimp.py`'s `trigsimp_old` (the legacy routine). For quotient-to-function rewrite rules defined as ordered pattern tuples (e.g., sin/cos→tan, sinh/cosh→tanh) with explicit ordering constraints, see `trigsimp.py`'s `_trigpats`. |
| `cse_main.py` | Common subexpression elimination via `cse`, identifying repeated subexpressions and replacing them with temporary variables to reduce redundant computation. Contains **`opt_cse`**, a pre-processing optimization pass that runs *before* redundant sub-expression detection: it traverses expressions to collect all Add/Mul (and MatAdd/MatMul) terms, rewrites negative coefficients as unevaluated `Mul(−1, ...)` and negative exponents as reciprocals `Pow(Pow(base, −exp), −1)` to expose hidden sharing, then uses **`_match_common_args`** to do pairwise intersection of argument sets across all collected sums (or products), factoring out shared operands into a common sub-term and propagating that factorization to subsequent terms. Also contains `tree_cse`, the main recursive tree-walk that performs the actual repeated-subexpression replacement after `opt_cse` pre-processing. Note: factoring shared operands out of sums/products (opt_cse) is distinct from `separatevars` in `simplify.py`, which splits an expression into multiplicative factors by variable independence. |
| `cse_opts.py` | Pre- and post-processing optimizations for CSE (`sub_pre`, `sub_post`) that canonicalize subtraction expressions to expose more common-subexpression opportunities. |
| `hyperexpand.py` | Expands hypergeometric and Meijer G-functions into named special functions using lookup tables and shift-operator algorithms based on Roach (1997). |
| `hyperexpand_doc.py` | Auto-generates a Sphinx docstring listing all known hypergeometric function formulas from `FormulaCollection` for documentation purposes. |
| `traversaltools.py` | Provides the `use` function for applying a transformation to an expression at a specified depth level in the expression tree. Uses a recursive inner function `_use` that descends through `expr.args`; when the target depth (level) is reached, applies the transformation function. **Atomic-node edge case**: if an `is_Atom` leaf node is encountered before reaching the requested depth, it is silently returned unchanged (no error raised) — meaning specifying a depth deeper than the expression tree simply skips transformation on leaves. |
| `epathtools.py` | Expression path tools: the `EPath` class and `epath` function for selecting and applying functions to parts of an expression tree using a path-based DSL. |
