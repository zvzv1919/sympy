| `simplify.py` | Core general-purpose simplification. The main `simplify` function is the top-level expression reducer: for non-arithmetic types (not Add/Mul/Pow/Exp) it detects single-argument function-inverse compositions (e.g., asin(sin(x)) → x) and recursively simplifies sub-expressions; for arithmetic types it orchestrates multiple strategies (cancel, together, factor_terms, hyperexpand, trigsimp, logcombine, combsimp, powsimp, etc.) and picks the shortest result. Also provides `separatevars` (decomposes an expression into a product of factors each depending on a single variable — transforms a sum into a multiplicative product by extracting shared commutative coefficients from all additive terms, then attempting to factor the remainder — if the remainder after factoring still depends on multiple independent variables, tries factoring again with `posify` when `force` is enabled; the `dict` mode maps each resulting factor to its corresponding symbol and returns None if any factor depends on more than one symbol), `nsimplify`, `besselsimp`, `posify`, and `bottom_up`. Contains `hypersimp(f, k)` which computes the consecutive term ratio f(k+1)/f(k) of a combinatorial term by rewriting in terms of gamma functions, expanding, and power-simplifying — if the result is a rational function of k (i.e. the term is hypergeometric), returns the simplified rational ratio; otherwise returns None indicating the term is not hypergeometric. Contains `hypersimilar(f, g, k)` which tests whether f and g are hyper-similar (their quotient is rational in k after gamma rewriting). Contains `signsimp(expr, evaluate)` which canonicalizes the sign of all Add sub-expressions: if an Add can have a sign extracted (via `could_extract_minus_sign`), it is replaced with `Mul(-1, a, evaluate=False)`, allowing signs to propagate through powers and products; it also replaces Mul atoms where double negation `-(- m)` yields a different form, enabling expressions like `n/x/(-n)**2 - 1/n/x` to reduce to zero. Contains `logcombine(expr, force)` which merges sums and products of log expressions (log(x)+log(y)→log(x*y), a*log(x)→log(x**a)) with assumption guards: coefficients must be real and arguments positive; notably, a coefficient of exactly -1 is explicitly excluded from absorption into the exponent (even though it is real) as a deliberate design choice — other negative real coefficients are allowed; a complex scalar multiplier (e.g. 2+3i) prevents merging even under `force=True` because it fails the real-coefficient check; when two log terms share the same coefficient magnitude but with opposite signs (e.g. k*log(a) - k*log(b)), they are combined into a single log of a division (k*log(a/b)), with the numerator/denominator assignment determined by comparing `count_ops` — the term whose coefficient has fewer operations becomes the numerator. Contains `nthroot(expr, n)` which computes a real nth-root of a sum of surds: it validates that all terms are rational-coefficient surds, then uses `nsimplify` with the surd constants; when the expression is negative and the root degree is odd, it negates the expression, computes the root of the positive version, verifies, and returns the negated result. Also contains `_nthroot_solve` which denests `p**(1/n)`: when `n` is a power of 2 it repeatedly square-root-denests and halves `n`, returning early without computing a minimal polynomial or solving; otherwise it falls back to `_minimal_polynomial_sq` and `solve`. |
| `trigsimp.py` | **Main entry point** for trigonometric (periodic) / hyperbolic simplification. The `trigsimp` function is the top-level dispatcher: it first attempts to delegate to the expression's own `_eval_trigsimp` method (custom reduction logic), and if that is absent, dispatches to one of several internal strategies selected by the `method` parameter — 'matching' (default, uses `futrig`), 'fu', 'groebner' (uses `trigsimp_groebner`), 'combined', or 'old'. Supports a `recursive` mode that first applies CSE to extract common subexpressions, simplifies the reduced expression, then back-substitutes each subexpression one at a time with re-simplification after every single substitution. Also contains `trigsimp_old`, the legacy simplification entry point invoked when `old=True` is passed to `trigsimp`: it handles multi-symbol expressions by separating variables and simplifying each factor independently, supports the same `recursive` CSE mode (extract common subexpressions, simplify main expression, back-substitute in reverse order with re-simplification after each substitution), and dispatches to method-specific strategies ('matching', 'groebner', 'combined') — this is the canonical location for the legacy/old-style trig simplification with recursive CSE. Also provides `exptrigsimp` for converting between exponential and trig/hyperbolic forms: it detects reciprocal exponential pairs and substitutes sinh/cosh, then converts exp ratio patterns like (e^a−1)/(e^a+1) into tanh/tan half-angle forms (avoiding infinite recursion by not computing the reciprocal ratio as 1/et) — this is the canonical location for exp-to-hyperbolic and exp-ratio-to-half-angle-tangent conversion, distinct from TR2i which only handles sin/cos ratios. Contains `futrig`, the default simplification strategy called by `trigsimp`: it orchestrates and sequences the TR transform rules (which are all defined in fu.py, not here) on circular trig subexpressions, and **critically, it is also where hyperbolic function simplification is orchestrated** — when the expression contains hyperbolic functions (sinh, cosh, tanh, etc.), `futrig` converts them to their circular trig equivalents via `hyper_as_trig`, runs the circular simplification pipeline, then converts back to hyperbolic form; this conversion-to-circular-and-back strategy is the mechanism by which hyperbolic expressions get simplified even though the core transform rules target circular functions. After simplification, `futrig` performs a special post-processing step: if the result changed and is a Mul whose first factor is a Rational number, it redistributes the leading coefficient by decomposing via `as_coeff_Mul()` and reconstructing — this ensures clean coefficient presentation on 2-arg Add results. The helper `_futrig` builds a nested rule tree and applies it via a greedy search with a multi-criteria objective function (`Lops`) that ranks candidate simplified forms by a tuple of (expression length L, operation count, node count, number of args, whether it is an Add) — this objective function is the mechanism that decides which intermediate result is "better" at each greedy step, and it lives here in trigsimp.py, not in fu.py. Also provides `trigsimp_groebner` for Groebner-basis-based trig/hyperbolic simplification that reduces expressions by computing polynomial normal forms modulo algebraic ideals encoding Pythagorean and double-angle identities — it performs global algebraic reduction, NOT pattern-based recombination of specific numerator/denominator component pairs into compound-angle forms (that is TR12i in fu.py). Also contains `_trigpats`, which lazily initializes and caches global pattern-matching tables used by the old `__trigsimp` matching strategy: `matchers_division` (Wild-based patterns for ratio rewrites like sin/cos→tan, tan·cos→sin, cot·sin→cos, and their hyperbolic analogs, plus (trig±1)·(trig∓1)→Pythagorean forms), `matchers_add` (angle-addition formula patterns like sin(a)cos(b)+cos(a)sin(b)→sin(a+b) for both circular and hyperbolic), `matchers_identity` (Pythagorean-type identity expansions like sin²→1-cos², tan²→sec²-1, and angle-sum expansions, for both circular and hyperbolic), and `artifacts` (cleanup patterns to reverse unhelpful identity substitutions) — these are static pattern tables only, not transform functions; actual application is done by `__trigsimp` and `_match_div_rewrite`. Also contains low-level helpers `_match_div_rewrite` and `_replace_mul_fpowxgpow` used by the old `__trigsimp` strategy — these perform function-type substitution on products (e.g. replacing sin(x)**a * cos(x)**(-a) with tan(x)**a) but do NOT apply product-to-sum identities, do NOT convert products of tan/cot into additive expressions (those are TR8 and TR13 in fu.py), and do NOT convert negative-exponent trig functions to their reciprocal counterparts (that is TR111 in fu.py). Does NOT contain individual trig identity transform rules (those are the TR-series in fu.py). |
| `radsimp.py` | Radical simplification and term collection: `collect`, `rcollect`, `radsimp`, `collect_const` for rationalizing denominators and grouping terms. `collect` groups additive terms of a sum by a user-specified pattern (symbol, power, or derivative expression), factoring out and aggregating the coefficients of each matching pattern while preserving the additive structure — it does NOT decompose into a product of single-variable factors. Internally it parses each multiplicative term into (base, rational_exponent, symbolic_exponent, derivative) tuples via a `parse_term` helper, with special-case handling for the natural exponential `exp()`. Supports an `exact=True` flag that restricts matching to the exact pattern specified: by default, collecting w.r.t. a function collects all derivatives of that function too, but with `exact=True` only the precise derivative order (or the function itself) is matched — e.g. collecting w.r.t. `Derivative(f, x)` with `exact=True` will NOT group `Derivative(f, x, x)` terms. Also provides `rad_rationalize(num, den)` which recursively removes square roots from a denominator when both numerator and denominator are sums of terms whose squares are rational: it splits surds via `split_surds`, multiplies by the conjugate (a - b) to eliminate radicals, and recurses until the denominator is rational — this is the canonical location for recursive conjugate-multiplication denest of irrational denominators. Also provides `fraction(expr, exact)` which decomposes a product expression into (numerator, denominator) by splitting terms with negative exponents into the denominator — with an `exact` flag that changes handling of non-constant symbolic exponents. `numer`, `denom`, `numer_expand`, `denom_expand`, `fraction_expand` are thin wrappers around `fraction`. Also provides `split_surds` for decomposing surd sums. |
| `powsimp.py` | Power simplification via `powsimp` (combine bases/exponents of Pow expressions, e.g. x**a * x**b → x**(a+b)) and `powdenest` (simplify nested power expressions like (x**a)**b). Does not handle logarithm combining (see `logcombine` in simplify.py). |
| `ratsimp.py` | Rational expression simplification via `ratsimp` (common denominator, cancel, reduce) and `ratsimpmodprime` (simplification modulo a polynomial prime ideal using Groebner bases). |
| `combsimp.py` | Combinatorial simplification via `combsimp`, which reduces expressions involving factorials, binomials, and Pochhammer symbols by rewriting through gamma functions to minimize the number and argument size of combinatorial functions. Does NOT compute consecutive term ratios or test hypergeometric character (those are `hypersimp`/`hypersimilar` in simplify.py). |
| `gammasimp.py` | Gamma function simplification via `gammasimp`, applying rising-factorial rewriting, reflection theorem, and multiplication theorem to minimize gamma function count. |
| `sqrtdenest.py` | Denesting of nested square roots via `sqrtdenest`, with helpers for measuring sqrt depth and checking algebraic structure of radical expressions. Contains `_sqrtdenest_rec(expr)` which recursively denests square roots of three or more irrational summands using a field-extension splitting approach: when the expression under the radical is negative, it factors out sqrt(-1) (the imaginary unit) and recurses on the negated base before proceeding; it splits the expression under the radical into a + b·√(r_k) in a smaller field Q(√r_1,...,√r_{k-1}), computes a²−b²·r_k, and recurses; raises `SqrtdenestStopIteration` to signal failure when the intermediate result's sqrt depth exceeds 1 or when the denested form is not simpler (operation count check). Contains `_sqrt_match(p)` which decomposes a sum expression into the form [a, b, r] matching a + b*sqrt(r) by selecting the addend with maximal sqrt nesting depth as the radical part — when the expression is an Add but all addends have zero radical nesting depth, returns an empty list (no match); when all squared terms are rational, delegates to `split_surds`. Contains `sqrt_biquadratic_denest(expr, a, b, r, d2)` which denests sqrt(a + b*sqrt(r)) where a, b, r are linear combinations of square roots of positive rationals (SQRR); before running the algorithm it validates the SQRR property by iterating over the `.args` of a, b, and r, squaring each sub-term y and checking `y**2.is_Integer` and `y**2.is_positive` — if any sub-term fails this check, returns None. Contains `_denester(nested, av0, h, max_depth_level)` which implements the recursive Fagin et al. algorithm for denesting a list of expressions sharing a common bottom-level radicand; it matches each expression via `_sqrt_match` looking for a nonzero linear coefficient (b≠0) to determine the common radicand R — if none of the matched expressions have b≠0 then R remains None and the function falls back to returning `sqrt(nested[-1])` with a zero-flag list instead of recursing further. Also contains `_sqrt_numeric_denest` for numeric radical denesting. |
| `fu.py` | Implementation of the Fu et al. trigonometric simplification algorithm: a library of individual numbered transform rules (TR0–TR22, TR111, TRmorrie) applied in heuristic order. This is the canonical location for all individual trig identity transform rules — it does NOT contain the top-level `trigsimp` dispatcher (that is in trigsimp.py). Key transforms: TR0 (rational polynomial simplification of trig), TR1 (replaces reciprocal trig functions sec and csc with their explicit ratio forms 1/cos and 1/sin), TR3 (induced formula rule: canonicalizes negative arguments of trig functions e.g. sin(-a)→-sin(a), and when a trig function's argument lies strictly between π/4 and π/2, swaps it with its co-function evaluated at the complementary angle — e.g. cos(x)→sin(π/2−x), tan(x)→cot(π/2−x) — using a fmap dictionary lookup; this co-function swap is the canonical location for angle reduction in the π/4–π/2 range), TR2/TR2i (tan↔sin/cos ratio conversion — TR2i converts sin(x)/cos(x) ratios to tan(x) but guards on assumptions: the base must be positive or the exponent must be an integer for both numerator and denominator, otherwise the transformation is skipped; TR2i also supports a `half=True` mode that converts sin/cos half-angle ratio patterns like sin(x)/(1+cos(x))→tan(x/2) and (1+cos(x))/sin(x)→cot(x/2) (note: this handles only sin/cos ratio patterns, NOT exponential/exp ratio patterns — exp-ratio-to-half-angle-tangent conversion is in `exptrigsimp` in trigsimp.py), with additional assumption checks on the joining step requiring the exponent to be integer or the sin base to be positive before producing half-angle tangent results), TR5/TR6 via `_TR56` (Pythagorean identity sin²↔1-cos² / cos²↔1-sin² rewrites for even-power expressions, with a `pow` flag that when enabled restricts replacement to exponents that are perfect powers of 2, so e.g. exponent 6 is left unchanged), TR8 (product-to-sum: converts products of sin and cos into sums using product-to-sum identities like sin(a)*cos(b)→(sin(a+b)+sin(a-b))/2; on the initial call (`first=True`) it splits the expression into numerator and denominator, recursively transforms each with `first=False`, recombines via `gcd_terms`, and if the result is a two-factor Mul where the first factor is Rational and the second is an Add, re-normalizes by decomposing via `as_coeff_Mul()` and reconstructing — this Rational*Add re-normalization ensures canonical coefficient presentation; when a factor has an integer exponent such as cos(x)**3, it expands the power into repeated individual factors before pairing — this is the canonical location for decomposing integer-power trig bases into repeated factors for product-to-sum conversion), TR9 (sum-to-product: converts additions of cos or sin terms into products using sum-to-product identities, e.g. cos(a)+cos(b)→2·cos((a+b)/2)·cos((a-b)/2); for sums of more than two terms, uses a greedy pairwise strategy that tries all pairs to find combinable ones, updates in place, and recurses until no more pairs combine), TR10 (angle-addition expansion of sin/cos of sums, with a `first` flag: on the initial call arguments are canonically sorted via `ordered()`, but recursive sub-expansions pass `first=False` to preserve existing argument order), TR10i (inverse of TR10: combines sums of sin/cos products back into compound-angle sin/cos functions — for sums with more than two terms, uses a greedy pairwise strategy that iterates over all pairs, attempts to combine each pair via `trig_split`, marks consumed terms as None and updates in place, then reconstructs the Add and recurses until no more pairs combine; after the main pairwise pass, runs a dedicated post-processing loop that groups remaining addends by their radical coefficient (square-root-of-integer factor) and specifically searches for inducible pairs in a √3:1 ratio that ended up in separate groups during the initial coefficient-based sorting — this handles edge cases like sin(x)+√3·cos(x) where the √3 factor caused the terms to be sorted into different buckets), TR11 (double-angle rewrite), TR12 (expand tan of a sum into a rational expression of individual tans, with canonical sorting on first call), TR13 (product-of-tangents/cotangents transformation: converts products of tan or cot into sums using addition-formula identities — processes factors pairwise in a while loop popping two at a time; when there is an odd number of factors, the single unpaired leftover tan or cot is appended unchanged to the result), TR12i (inverse tangent addition recombination: given a ratio whose numerator is a sum of two tangent (trigonometric-ratio) functions and whose denominator contains their product minus one, combines it back into a single compound-angle tangent — detects the characteristic denominator pattern `1 - tan(a)*tan(b)` via `as_f_sign_1` and pairs it with matching numerator `tan(a) + tan(b)` to produce `tan(a+b)`; processes denominator and numerator factors individually, handling Add factors by factoring them, and Pow factors by checking if the base matches the tangent-product pattern — for Pow denominator factors whose base does NOT match, falls back to factoring and splitting into multiplicative sub-factors; for Pow numerator factors similarly falls back to factoring when the base is not a tangent sum; also handles sign-flipped numerator sums by trying `ok(-ni)` and inserting a NegativeOne factor), TR14 (difference-of-squares trig identities: pairs (trig±1) factors with opposite signs and combines them via Pythagorean identities, e.g. (cos(x)+1)(cos(x)-1)→-sin²(x); on its initial call, if the Mul expression has a non-trivial denominator (terms with negative exponents), it splits into numerator and denominator via `as_numer_denom()`, recursively simplifies each independently with `first=False`, and returns early — the main pairing logic only runs on the recursive calls where each part has only positive exponents; before the pairing logic, each Pow factor is checked: if the exponent is non-integer AND the base is not positive, the factor is skipped entirely and placed in the unprocessed list — this prevents invalid transformations on expressions like (cos(x)-1)**(1/2); when paired factors have different numeric exponents it takes the minimum exponent for combination and reinserts the remainder back into the processing queue; also handles equal symbolic exponents), TR111 (converts negative-exponent trig functions to positive-exponent reciprocal counterparts: tan(x)**(-n)→cot(x)**n, sin(x)**(-n)→csc(x)**n, cos(x)**(-n)→sec(x)**n; applies only when the base is positive or the exponent is both integer and negative — this guard ensures correctness for complex-valued expressions). Also provides the `fu` function, the main orchestrator that applies transform rules in a two-phase heuristic pipeline: first it applies TR1 (sec/csc→cos/sin), then if the expression contains tan or cot, it runs RL1 (the first rule list) — critically, if tan/cot still persist after RL1, it falls back to TR2 to convert all remaining tan/cot into sin/cos ratios before proceeding; then if the expression has sin/cos, it runs RL2 (the second rule list) followed by TR8 and TRmorrie, selecting the best among all intermediate results via the measure function — this fallback TR2 conversion when tan/cot survive RL1 is the canonical location for the tan/cot elimination fallback in the fu algorithm. The `fu` function uses "JIT"-like factoring via `factor_terms`: factoring is delayed until deemed necessary, and if factoring a common multiplicative factor out of a sum does not lead to further trig simplification, the factored form is discarded and the original unfactored expression is kept (e.g. `a*cos(x)*cos(y) + a*sin(x)*sin(z)` remains unfactored because the factored form doesn't simplify trigonometrically). By design, its greedy heuristic approach may produce non-optimal results because it does not try all possible pairings of sum terms during argument collection (the combinatorial explosion makes exhaustive search impractical), so the result depends on which terms happen to combine first. Also provides combination subroutines (`CTR1`–`CTR4`) orchestrating rule subsequences, `process_common_addends` for grouping summation addends by the absolute value of their coefficient magnitude and an optional secondary key, then applying a transformation to groups with more than one member — negative coefficients are handled by negating both the coefficient and the argument so the sign is transferred onto the argument; raises `ValueError` when coefficient-based grouping is disabled (`key1=False`) and no secondary classifier (`key2`) is provided, since at least one grouping key is required, `trig_split` for decomposing a pair of terms (each a product expression possibly containing a square-root factor alongside periodic functions) into a canonical tuple (gcd, s1, s2, a1, a2, bool) representing gcd*(s1*f(a1) + s2*f(a2)) — internally, each input term is decomposed into a (radical, cosine, sine) component tuple by an inner helper that parses a product into at most one square-root factor (Pow with exponent 1/2), one cosine, and one sine, returning None if the product structure doesn't match; extracts a GCD factor via `Factors`, determines sign indicators s1/s2, and classifies each remainder; operates in single-function mode (default, each term after GCD must be a bare trig function, products return None) or double-function mode (`two=True`, allows cos*sin products with optional radical coefficients for sum-to-product/product-to-sum identities and determines a phase angle offset by comparing radical coefficient ratios against cached √2/√3 constants to recognize standard angles like π/6, π/4, π/3), `as_f_sign_1` for two-term sign decomposition, and `_osborne`/`_osbornei` which are the actual implementation of hyperbolic↔trig conversion via the Osborne rule — `_osborne` maps each hyperbolic function to its trig equivalent (sinh→I*sin, cosh→cos, tanh→I*tan, coth→cot/I) and raises `NotImplementedError` for any other hyperbolic function (e.g. sech, csch) since only these four standard conversions are implemented; `_osbornei` performs the inverse conversion back from trig to hyperbolic. |
