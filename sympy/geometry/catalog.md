# sympy/geometry — Catalog

> Part of [SymPy](../catalog.md). Computational geometry: points, lines, polygons, circles, ellipses, and curves.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package initializer that imports and re-exports all public geometry classes (Point, Line, Ellipse, Circle, Polygon, Plane, Curve, Parabola) and utility functions. |
| `entity.py` | Defines `GeometryEntity`, the base class for all geometric objects, and `GeometrySet`, a base for entities that can also act as SymPy Sets. Defines the module-level `ordering_of_classes` list that establishes a priority ordering of all geometry types (Point2D, Point3D, Point, Segment, Ray, Line, ..., Parabola); this ordering is used by `__cmp__` and, critically, defines the **intersection responsibility protocol**: when two different entity types can intersect, the type with the higher index in `ordering_of_classes` is responsible for implementing the intersection logic with anything having a lower index. `GeometryEntity.intersection` is the abstract base that raises `NotImplementedError` — its docstring documents this delegation protocol; subclasses override it in their respective files. Provides base-class default implementations of rotation (generic, delegates to affine matrix — subclasses like Point2D, RegularPolygon, Ellipse override with specialized logic), scaling, translation, reflection, `encloses` (entity-contains-entity check via type-based dispatch — determines whether one geometric entity fully contains another entity, not individual points; for RegularPolygon targets, first checks center enclosure as an early exit before checking vertices; for general Polygons, checks all vertices; for Ellipses, checks center and boundary), and symbolic substitution (`_eval_subs` handles sequence-to-Point conversion, dispatching to Point3D or Point2D based on the entity type). Subclasses like Ellipse and Circle override these defaults when geometry-specific constraints apply. Also defines standalone module-level functions `scale(x, y, pt)`, `translate(x, y)`, and `rotate(th)` that construct and return 3×3 affine transformation matrices for 2D coordinate transformations; `scale` builds a scaling matrix relative to an arbitrary reference point by composing translate-to-origin, scale, translate-back; `translate` builds a translation matrix; `rotate` builds a rotation matrix about the origin. These return Matrix objects (not geometry entities) and are used by `Point2D.transform`. |
| `point.py` | Implements `Point`, `Point2D`, and `Point3D` classes representing points in n-dimensional Euclidean space, with operations like pairwise distance (computes Euclidean distance between two individual points, not multi-point nearest/farthest algorithms — those live in `util.py`), midpoint, collinearity checks (`is_collinear`, `are_collinear`), `Point2D.is_concyclic` (static method that determines whether a set of 2D points all lie on the same circle — returns False for 0 points, True for 1–2, checks non-collinearity for 3, and for 4+ constructs a Circle from the first three then checks containment of the rest; returns False if the first three are collinear since no circle can be formed), `Point3D.are_coplanar` (static method with its own full implementation — deduplicates the input points via `set`, raises `ValueError` if fewer than 3 distinct points remain, iterates to find three non-collinear points to construct a `Plane`, then checks all remaining points against that plane via `Plane.is_coplanar`; raises `ValueError` if all points are collinear and no plane can be formed; does NOT delegate to `util.are_coplanar`), `Point3D.direction_ratio` (component differences between two 3D points) and `Point3D.direction_cosine` (normalizes direction ratios by their magnitude — divides each component by `sqrt(sum of squares)` with no guard against zero magnitude when points are identical), coordinate transformations including `Point2D.transform` (applies a 3×3 affine transformation matrix to a 2D point using homogeneous coordinates — validates that the input has `.shape`, is square, and is 3×3, raising `ValueError` otherwise), `Point2D.scale`, `Point2D.translate`, `Point2D.rotate` (applies counterclockwise angular rotation about an optional pivot point by manually computing the 2D sin/cos rotation matrix — translates to origin if a custom pivot is provided, applies the rotation, then translates back; this is the concrete 2D rotation implementation, distinct from the base `GeometryEntity.rotate` default), and `Point.intersection` (for two Points, checks dimension match and equality; for a non-Point argument, delegates to that object's own `intersection` method — this is where Point-vs-other-entity intersection is resolved). Also provides dual equality: `__eq__` does structural tuple comparison while `equals` does component-wise symbolic equality. |
| `line.py` | Implements 2D line-like entities: `LinearEntity`, `Line`, `Ray`, `Segment` (all 2D only). `LinearEntity.intersection` computes crossing points using Cramer's rule for non-parallel entities, then validates candidates via coordinate-betweenness (for segments) and direction-consistency (for rays) rather than fragile equality-based containment; also handles parallel/collinear overlap cases. `LinearEntity.arbitrary_point` generates a parametric point on the line/ray/segment using a named parameter (default `'t'`); raises `ValueError` if the parameter name conflicts with symbols already present in the entity's definition. Supports perpendicularity, parallelism, angle computation, containment checks, and `LinearEntity.projection` (projects a point, line, ray, or segment onto the 2D linear entity — for linear entity inputs, projects both defining endpoints onto the infinite line and reconstructs the same entity type; when both endpoints collapse to the same projected point, returns that single point instead of a degenerate entity; raises `GeometryError` for any unsupported geometry type that is neither a Point nor a LinearEntity, e.g. Circle or Ellipse). |
| `line3d.py` | Implements 3D line-like entities: `LinearEntity3D`, `Line3D`, `Ray3D`, `Segment3D`. `LinearEntity3D.__new__` is the base constructor for all 3D linear entities — validates that two defining points are distinct and raises `ValueError` for duplicate points. `Segment3D.__new__` overrides the base constructor with its own endpoint ordering and degenerate-case logic: reorders the two endpoints first by x-coordinate, then by y-coordinate if x's are equal, but the z-coordinate is explicitly excluded from the ordering decision; if both points are identical, returns a Point3D instead of a segment. Provides 3D-specific direction properties, distance calculations, `LinearEntity3D.perpendicular_segment` (computes the shortest segment from a 3D point to a 3D line — docstring claims it returns the point itself when the point lies on the line, but implementation raises `NotImplementedError` instead), perpendicular lines, `LinearEntity3D.projection` (projects a point, line, ray, or segment onto a 3D line/ray/segment (not onto a plane) — for non-point inputs, projects both defining endpoints onto the underlying infinite line and reconstructs the same entity type from those projected points; then intersects the reconstructed entity with `self` to clip the result to the bounds of the original entity rather than extending infinitely; when both endpoints collapse to the same point, the projected entity degenerates to a single point; raises `GeometryError` for unsupported types), `Ray3D.contains` (determines whether a 3D point lies on the half-line by first checking collinearity, then applying direction-based membership using `xdirection`, `ydirection`, and `zdirection` properties — checks the first non-zero directional component to decide the coordinate comparison; the z-direction branches have a sign inconsistency where both positive and negative z use `<=` instead of mirroring the `>=`/`<=` pattern used for x and y), parallel tests, `LinearEntity3D.is_perpendicular` (checks orthogonality of two 3D lines by computing the dot product of their direction_ratio components via strict equality to zero — no symbolic simplification is applied, so symbolic expressions that simplify to zero may not be recognized), `LinearEntity3D.is_similar` (determines if two 3D lines are collinear, i.e. lie on the same infinite path — compares direction_cosine tuples for exact equality and checks point containment; note: opposite orientations yield negated direction cosines, which can cause a false negative), and `are_concurrent` (static method that checks whether a collection of 3D geometric entities all meet at a single point — finds the intersection of the first two lines, then verifies the remaining lines pass through that point; returns False for 0–1 inputs, for parallel lines, or if any argument is not a valid line-like object; handles non-line-like arguments gracefully by catching `AttributeError` when the object lacks an `intersection` method, returning False instead of raising an error). |
| `plane.py` | Implements the `Plane` class for 3D planes (flat two-dimensional surfaces in three-dimensional space), constructed from three points or a point and normal vector. `Plane.__new__` validates that three input points are non-collinear and raises `ValueError('Enter three non-collinear points')` if they all lie on the same line, preventing degenerate plane construction. `Plane.are_concurrent` (static method) determines whether multiple planes all share a single common line of intersection — deduplicates via set conversion, returns False for fewer than 2 planes, computes the intersection line of the first two planes, then verifies each subsequent plane's intersection with the first lies on that same line. Supports intersection with lines and other planes, distance calculations, point projection (`projection`), 3D line/ray/segment projection onto the plane surface (`projection_line` — projects each endpoint onto the plane and reconstructs the same entity type; when the line is aligned with the plane's normal direction both endpoints project to the same location, so the method returns a single Point3D instead of a linear entity), `Plane.arbitrary_point` (generates a parametric Point3D that traces a unit circle around the plane's base point `p1` as the parameter varies from 0 to 2*pi — handles axis-aligned normals with direct cos/sin construction, and for general normals projects a trial point onto the plane and solves for a scale factor to enforce unit distance), and `Plane.random_point` (returns a random point on the plane by evaluating `arbitrary_point` at a random parameter value). |
| `polygon.py` | Implements `Polygon`, `RegularPolygon`, and `Triangle` classes. Provides area, perimeter, centroid, angle computations, point enclosure testing (`encloses_point` — determines whether a single point lies strictly inside the polygon using a dual-algorithm approach: for convex polygons uses cross-product orientation consistency, for non-convex polygons uses a ray-casting odd-crossing algorithm; returns False for boundary points, None for symbolic coordinates), `Polygon.arbitrary_point` (generates a parametric point that traces the polygon's perimeter as a piecewise function over each side — raises `ValueError` if the parameter name conflicts with symbols already present in the polygon's vertex definitions, guarding against symbol collision; delegates to each side's `arbitrary_point` and stitches results together with `Piecewise`), `Polygon.__contains__` (the `in` operator — for a Polygon argument it only checks equality, not geometric containment; for a Segment it checks if it matches any side; for a Point it checks vertices and sides), `Polygon.intersection` (decomposes polygon-polygon overlap into per-edge intersection checks, collecting results and deduplicating via `uniq`), `Polygon.distance` (computes the shortest distance between the polygon and another object — for a Point argument, iterates over all edges returning the minimum edge-to-point distance with no convexity requirement; for another Polygon, requires both polygons to be convex and delegates to a rotating-calipers algorithm `_do_poly_distance`; raises `NotImplementedError` for non-convex polygon pairs). `RegularPolygon` overrides `scale`, `rotate`, and `reflect` from `GeometryEntity` with geometry-aware logic: `RegularPolygon.scale` preserves the RegularPolygon type only for uniform scaling (x == y, adjusting the circumradius); for non-uniform/asymmetric scaling (x != y), it demotes to a general `Polygon` by expanding vertices first, then scaling. `RegularPolygon.rotate` composes an in-place rotation about the center with the base rotation. `RegularPolygon.reflect` recomputes center, radius sign, and spin angle after reflection. `RegularPolygon.__eq__` has special dispatch: if the other object is a Polygon but not a RegularPolygon, it delegates to `Polygon.__eq__` with swapped argument order. Specialized `Triangle` methods and properties: `Triangle.is_similar` (the concrete similarity algorithm for triangles — determines whether two triangles can be uniformly scaled to match by computing side-length ratios via `simplify` across all 6 permutations of edge orderings to resolve correspondence ambiguity; this is where the actual geometric comparison logic lives, not in `util.are_similar` which is only a dispatcher), circumcenter (found by intersecting perpendicular bisectors of edges), circumradius, circumcircle, incircle, medians, nine-point circle, orthocenter, altitudes, bisectors, and Euler line. |
| `ellipse.py` | Implements `Ellipse` (closed oval curve) and `Circle` classes with support for tangent lines, focal properties, eccentricity, arbitrary point generation, `Ellipse.is_tangent` (checks whether a given geometric object — Ellipse, LinearEntity, or Polygon — is tangent to the ellipse; for Polygon inputs, iterates over all sides, counts total intersection points across all edges, and returns True only if exactly one contact point exists), and `Ellipse.random_point` (generates a stochastic sample point on the ellipse by substituting rational cos/sin values — not the angular parameter t directly — into the parametric form to avoid floating-point rounding issues; retries up to 10 times if the generated coordinate pair fails the containment check due to symbolic simplification issues, and raises `GeometryError` if all retries are exhausted). `Ellipse.__contains__` (the `in` operator) checks if a Point satisfies the ellipse equation, but for another Ellipse it only checks equality — not geometric containment. `Circle.__new__` supports construction from center+radius or from three non-collinear points (checks collinearity and raises `GeometryError` if degenerate; computes center/radius via the circumscribed Triangle). `Ellipse.rotate` overrides the base rotation: only allows multiples of pi/2 for non-circular ellipses (swaps semi-axis lengths for odd pi/2 multiples, raises NotImplementedError otherwise). `Ellipse.reflect` overrides base reflection: handles axis-aligned lines directly but raises NotImplementedError for non-axis-aligned lines. `Ellipse.scale` overrides base scaling to transform semi-axis lengths directly. `Circle.intersection` handles circle-circle cases including concentric circles (same center): returns the circle itself if radii match, returns empty list if radii differ; for non-concentric circles uses algebraic intersection formulas. Each class has its own `intersection` method with type-based dispatch (delegating to internal helpers like `_do_line_intersection` and `_do_ellipse_intersection`); for geometry types not explicitly handled (not Point, LinearEntity, Circle, or Ellipse), `Ellipse.intersection` falls back to calling `o.intersection(self)`, reversing the dispatch to the other object; notably, for two identical ellipses it returns the ellipse object itself rather than a list, inconsistent with the documented return type of list of GeometryEntity. |
| `curve.py` | Implements the `Curve` class for general user-defined parametric 2D curves (not ellipses, circles, or other built-in conic shapes — those are in `ellipse.py`). Defined by explicit coordinate functions and a parameter with lower/upper limits, e.g. `(sin(t), cos(t))` for `t` in `[0, 2*pi]`. Supports arc length computation, arbitrary point generation (substitutes parameter into the curve's parametric coordinate functions), and plotting-related methods. Has no `random_point` method and no containment-check retry logic. `Curve._eval_subs` overrides the base substitution: only performs substitution when the substituted symbol matches the curve's bound parameter variable (converting the curve to a Point2D); if a different symbol is substituted, implicitly returns None so no substitution occurs. Does not handle line/ray/segment projection or spatial clipping. |
| `parabola.py` | Implements the `Parabola` class, a conic section with eccentricity always equal to 1, defined by a focus (special point) and directrix (guiding line). `Parabola.__new__` enforces that the directrix must be horizontal or vertical — raises `NotImplementedError` for diagonal/tilted directrix lines (slope neither 0 nor infinity); also raises `ValueError` if focus is not 2D or lies on the directrix. `Parabola.vertex` computes the turning point (extremal point) by subtracting the signed half-distance parameter from the appropriate coordinate of the focus, branching on whether the axis of symmetry is horizontal (slope == 0) or vertical to decide which coordinate to adjust. `Parabola.equation` derives the implicit second-degree algebraic expression, branching on axis orientation to swap which coordinate gets the squared term vs. the linear term (horizontal axis squares y, vertical axis squares x). Also supports axis of symmetry, focal length, and `p_parameter` (the signed focal parameter — its absolute value equals the focal length, but its sign encodes which direction the parabola opens: positive for rightward-opening horizontal or upward-opening vertical parabolas, negative for leftward or downward; determined by comparing the directrix position against the focus coordinate along the axis of symmetry). |
| `util.py` | Module-level utility functions (not class methods): `intersection` (thin convenience wrapper that delegates to the first entity's own `intersection` method — actual intersection logic lives in the entity classes in `line.py`, `ellipse.py`, etc.), `convex_hull`, `closest_points` (sweep-line nearest-pair algorithm that locally redefines its distance function when any point coordinate is non-rational — branches between `math.sqrt` for rational intermediate results and SymPy's symbolic `sqrt` for irrational ones), `farthest_points` (rotating-calipers maximum-distance algorithm that also locally redefines its distance function when any coordinate is non-rational — same rational/symbolic sqrt branching as `closest_points`), `are_coplanar` (module-level coplanarity check for mixed 3D entities including points, lines, and planes — if a Plane is present, checks all others against it; for pure Point3D inputs, pops two points and removes all collinear points from the rest, then attempts to form a Plane from three non-collinear points; returns False when fewer than 3 points remain or when all points are collinear, treating the degenerate collinear case as "not coplanar"; also handles 2D geometry objects by converting their defining points to 3D with z=0), `are_similar` (thin dispatcher only — contains no similarity logic itself; first checks equality, then delegates to `e1.is_similar(e2)`, falling back to `e2.is_similar(e1)` on `AttributeError`; if neither entity supports the comparison, raises `GeometryError`; actual similarity algorithms live in entity classes like `Triangle.is_similar` in `polygon.py`), `centroid` (computes the weighted average position / center of mass for a *collection* of geometry objects — for Points, averages equally; for Segments, weights each midpoint by segment length; for Polygons, weights each polygon's centroid by its area; requires all inputs to be the same type; this is distinct from `Polygon.centroid` which computes the centroid of a single polygon's vertices), and `idiff` (implicit differentiation). |
| `exceptions.py` | Defines `GeometryError`, the exception class raised by geometry module classes. |
