# sympy/series — Catalog

> Part of [SymPy](../catalog.md). Series expansions, limits (Gruntz algorithm), formal power series, Fourier series, and sequences.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; imports and re-exports the public API (limit, series, Order, fourier_series, fps, sequences, etc.). |
| `acceleration.py` | Numerical convergence acceleration for slowly converging sequences and partial sums. Contains `richardson` (Richardson extrapolation using finite-difference weights) and `shanks` (Shanks transformation) which applies a nonlinear recurrence formula `(z*x - y²)/(z + x - 2y)` on a table of partial-sum values to improve limit approximation, with support for m-fold recursive application. These are numerical sequence-to-sequence mappings, not symbolic limit computation. |
| `approximants.py` | Generator for consecutive Pade approximants of a series, also usable for computing rational generating functions. |
| `formal.py` | Formal power series (FPS) of continuous functions, including algorithms for computing closed-form coefficient formulas (rational, hypergeometric, simpleDE) and the `FormalPowerSeries` class. Contains the concrete `_eval_term` implementation that evaluates individual terms by combining the coefficient sequence (`ak`) with the basis (`xk`), and uses range-based logic to selectively include singular/independent (`ind`) addends based on their power of x relative to the requested index. Also provides truncation, polynomial extraction, and derivative computation for FPS. Deals with representing analytic functions as power series, not with discrete sequence recurrences or generating functions. |
| `fourier.py` | Fourier series representation and computation, providing the `FourierSeries` class and the `fourier_series` constructor with truncation, shifting, and scaling operations. |
| `gruntz.py` | Implementation of the Gruntz algorithm for computing symbolic **continuous** limits — the core algorithmic engine (not the user-facing API, which is in `limits.py`). The main `gruntz()` entry point converts all limit problems to the z→∞ case: for a finite point z0 with dir="+", it substitutes z→z0+1/z; for dir="-", z→z0-1/z; for z0=-∞, z→-z. After conversion, it delegates to `limitinf` which computes limits at infinity by finding the most-rapidly-varying (MRV) subexpressions — a **set** of comparably-growing nested subexpressions used for rewriting, not for picking a single dominant additive term — and rewriting the expression in terms of those subexpressions for series expansion. Before returning, `gruntz()` applies a final heuristic transformation that rewrites the result in terms of familiar special functions. Also contains `rewrite` (transforms an expression using the MRV set into a canonical variable), `mrv`, `mrv_max`, `sign`, `build_expression_tree`, and other internal helpers. |
| `kauers.py` | Finite difference operators for polynomials and sums, providing `finite_diff` and `finite_diff_kauers` utilities. |
| `limits.py` | Public `limit` function and `Limit` class — the user-facing API for symbolic limits (e.g. lim x→0 sin(x)/x = 1). `Limit.doit` tries fast heuristics first (e.g. simple substitution checks), then delegates to `gruntz()` in `gruntz.py` for the actual asymptotic algorithm. Does not itself implement the finite-to-infinity conversion or the final result transformation — those live in `gruntz.py`. |
| `limitseq.py` | Limits of discrete sequences at infinity. Provides `limit_seq` for computing sequence limits, `difference_delta` for discrete differences, and `dominant` for identifying the single fastest-growing **additive component** of a symbolic sum by computing pairwise ratios of terms and checking their limits as the index → ∞ — returns the unique dominant term, or `None` when no single term grows strictly faster than all others (i.e. multiple terms have comparable asymptotic growth). This is the file for questions about picking the biggest additive piece of an expression. |
| `order.py` | The `Order` (big-O) class representing the limiting behavior of a function, used to track truncation error in series expansions. |
| `residues.py` | Computes the residue of an expression at a point via Laurent series expansion, supporting the Residue Theorem. |
| `sequences.py` | Discrete *sequence* classes (`SeqBase`, `SeqFormula`, `SeqPer`, `SeqAdd`, `SeqMul`, `EmptySequence`) and the `sequence` constructor. `SeqBase` is the base for sequences only (not series); provides coefficient access (`coeff`), arithmetic ops, iteration via its own `_ith_point` (separate from the series hierarchy), and `find_linear_recurrence` which discovers the shortest linear recurrence relation from initial terms (via matrix determinant/LU-solve) and optionally constructs the rational ordinary generating function (OGF) numerator and denominator from the recurrence coefficients. |
| `series.py` | Thin wrapper providing the top-level `series` function, which delegates to `Expr.series()` for Taylor/Laurent expansion. |
| `series_class.py` | Abstract base class `SeriesBase` for *series expansion* representations (parent of `FourierSeries`, `FormalPowerSeries`), defining the common abstract interface (interval, start, stop, length, `_eval_term` stub) and the iteration/indexing machinery (`__iter__`, `__getitem__`, `_ith_point`). When a series expansion's starting bound is negative infinity, `_ith_point` reverses direction — iterating from the stop point backwards. This is the file for questions about how series expansions compute positions during iteration. Does not contain any concrete term-evaluation logic — subclasses in `formal.py` and `fourier.py` implement `_eval_term`. |
| `benchmarks/bench_limit.py` | Benchmark for the `limit` function, timing `limit(1/x, x, oo)`. |
| `benchmarks/bench_order.py` | Benchmark for `Order` addition, timing the creation of a large sum with an `O(x^1001)` term. |
