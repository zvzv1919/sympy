# sympy/series — Catalog

> Part of [SymPy](../catalog.md). Series expansions, limits (Gruntz algorithm), formal power series, Fourier series, and sequences.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; imports and re-exports the public API (limit, series, Order, fourier_series, fps, sequences, etc.). |
| `acceleration.py` | Convergence acceleration methods for series and sequences, including Richardson extrapolation and the Shanks transformation. |
| `approximants.py` | Generator for successive rational approximations (Padé approximants) of a series given as a **list of numeric coefficients**. Iteratively inverts the coefficient list to produce better and better rational-function approximations; terminates early (returns from the generator) when the remaining coefficient list consists entirely of zeros. This is the file for questions about iterating over coefficient lists and early-termination edge cases—**not** `formal.py`, which deals with closed-form coefficient formulas for formal power series. |
| `formal.py` | Formal power series (FPS) implementation, including algorithms for deriving **closed-form coefficient formulas** from a symbolic function (`rational_algorithm` for rational functions, plus hypergeometric and simpleDE methods) and the `FormalPowerSeries` class. Also contains the `fps()` convenience constructor function, which includes **variable auto-detection logic**: if no expansion variable is given, it auto-detects for univariate expressions (single free symbol), returns the expression unchanged for constant expressions (no free symbols) or when computation yields no result, and raises `NotImplementedError` for multivariate expressions (more than one free symbol). Also contains arithmetic operator overloads (add, subtract, multiply) on `FormalPowerSeries` objects, with logic for aligning mismatched coefficient starting indices (extracting gap terms into the independent/constant part) when combining two series expansions. Note: `rational_algorithm` here computes a formula for the k-th coefficient of a formal power series—it does **not** produce successive rational approximations from a coefficient list (that is `approximants.py`). For variable auto-detection on **discrete sequences** (not power series), see `sequences.py`. |
| `fourier.py` | Fourier series representation and computation, providing the `FourierSeries` class and the `fourier_series` constructor with truncation, shifting, and scaling operations. Also contains **arithmetic operator overloads** (add, subtract) on `FourierSeries` objects: `__add__` checks that periods match (raises `ValueError` otherwise), combines the underlying symbolic functions, and includes an **edge-case short-circuit**—if the combined function no longer contains the expansion variable (i.e., the variable cancels out when two series are added), it returns the plain symbolic expression directly instead of wrapping it in a new `FourierSeries` object. The `fourier_series` constructor similarly returns the input expression unchanged if it has no dependence on the expansion variable. Note: these are **series-level** (periodic expansion) arithmetic operations—for raw **term-wise discrete sequence** combination, see `SeqAdd` in `sequences.py`. |
| `gruntz.py` | Implementation of the Gruntz algorithm for computing symbolic limits. Contains the `gruntz()` entry-point function, which first converts all limit problems to z→∞ form: finite-point directional limits are transformed via variable substitution (e.g., `z0 - 1/z` for left-sided, `z0 + 1/z` for right-sided), and -∞ limits use a sign flip. The core algorithm then compares most-rapidly-varying (MRV) subexpressions, rewrites the expression in terms of those subexpressions, and performs series expansion. Also contains the `SubsSet` class (a `dict` subclass) that tracks mappings from MRV expressions to placeholder dummy variables, along with associated rewrite rules; its `union` method merges two such mapping sets, resolving conflicting placeholder assignments for shared expressions by remapping variables and updating the rewrite rules via substitution. See `limits.py` for the public `limit()` dispatcher that calls `gruntz()`. Note: the reciprocal-substitution fast-path for infinity limits lives in `limits.py` (in its `heuristics` function), not here. |
| `kauers.py` | Finite difference operators for polynomials and sums, providing `finite_diff` and `finite_diff_kauers` utilities. |
| `limits.py` | Public `limit` function and `Limit` class for computing limits of expressions at a point. Contains a `heuristics()` fast-path that handles simple cases before resorting to the full Gruntz algorithm: for infinity limits it applies a reciprocal substitution (`z → 1/z`) and re-evaluates toward zero—if the result is still an unevaluated `Limit` object (i.e., the substitution could not be resolved), it bails out and returns `None`; for composite expressions (Mul/Add/Pow/Function) it evaluates limits of individual arguments and reassembles. Falls back to `gruntz()` in `gruntz.py` for the full algorithm. Does **not** itself perform the directional substitution for finite-point limits (left/right conversion to z→∞)—that transformation lives in `gruntz.py`. |
| `limitseq.py` | Limits of **discrete sequences** at infinity (as opposed to continuous symbolic limits in `limits.py`/`gruntz.py`). The main function `limit_seq` uses an iterative Stolz-Cesàro–style algorithm: in a bounded retry loop it (1) splits the expression into numerator/denominator, (2) applies the discrete `difference_delta` operator to both, (3) extracts the fastest-growing addend from each via the `dominant` helper, and (4) repeats on the simplified ratio. Also contains edge-case short-circuits: if the specified limit variable is not in the expression's free symbols, returns the expression unchanged; if no variable is given and the expression has no free symbols, likewise returns as-is. The `dominant` function finds the single most-rapidly-growing term in a sum by pairwise ratio comparison. This file handles expressions built from rational functions, indefinite sums (`Sum`), and indefinite products—**not** the MRV/rewrite approach used by `gruntz.py` for continuous limits, and **not** the public `Limit` class or `heuristics` fast-path in `limits.py`. |
| `order.py` | The `Order` (big-O) class representing the limiting behavior of a function, used to track truncation error in series expansions. |
| `residues.py` | Computes the residue of an expression at a point via Laurent series expansion, supporting the Residue Theorem. Uses an iterative retry loop with geometrically increasing expansion orders (0, 1, 2, 4, …, 32); includes a workaround that skips and retries when the series result contains only a truncation/Order term and all concrete terms vanish to zero. |
| `sequences.py` | Sequence classes (`SeqBase`, `SeqFormula`, `SeqPer`, `SeqAdd`, `SeqMul`, `EmptySequence`) and the `sequence` convenience constructor for defining and manipulating symbolic sequences. `SeqBase` (inherits `Basic`) provides iteration, indexing, and `_ith_point` for discrete sequences; `_ith_point` includes a **negative-infinity edge case**: when the sequence's lower bound is negative infinity, it reverses direction—using `stop` as the initial reference point and stepping backward (step = -1) instead of forward from `start`. `SeqFormula.__new__` includes **variable/dummy auto-detection logic**: if no explicit limits/variable are given, it auto-detects for univariate formulas (single free symbol), creates a `Dummy('k')` index variable for constant formulas (no free symbols), and raises `ValueError` for multivariate formulas (more than one free symbol). Handles raw term-wise sequence operations; does **not** handle series-level arithmetic like combining two infinite series expansions (that logic lives in `formal.py`). For variable auto-detection on **formal power series** (not discrete sequences), see `formal.py`. Note: `series_class.py` has a parallel base class `SeriesBase` (inherits `Expr`) with its own `_ith_point` for continuous series (Fourier/formal power series)—questions about **discrete sequence** indexing, element position, and the sequence-level negative-infinity edge case belong here in `sequences.py`, not in `series_class.py`. |
| `series.py` | Thin wrapper providing the top-level `series` function, which delegates to `Expr.series()` for Taylor/Laurent expansion. Contains no edge-case handling for vanishing terms or truncation—see `residues.py` for iterative Laurent expansion with retry logic, and `approximants.py` for coefficient-list processing with early termination. |
| `series_class.py` | Abstract base class `SeriesBase` (inherits `Expr`) for **continuous series** representations (Fourier series, formal power series), defining the common interface (interval, start, stop, length, term) used by `FourierSeries` and `FormalPowerSeries`. Also contains iteration and indexing logic: `_ith_point` computes the i-th traversal point, `__iter__` yields successive terms, `__getitem__` supports integer indexing and slicing. Note: `sequences.py` has a parallel base class `SeqBase` (inherits `Basic`) with its own `_ith_point` for **discrete sequences**—questions about discrete sequence indexing, element position computation, or sequence-level negative-infinity start-point handling belong in `sequences.py`, not here. |
| `benchmarks/bench_limit.py` | Benchmark for the `limit` function, timing `limit(1/x, x, oo)`. |
| `benchmarks/bench_order.py` | Benchmark for `Order` addition, timing the creation of a large sum with an `O(x^1001)` term. |
