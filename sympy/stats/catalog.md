# sympy/stats — Catalog

> Part of [SymPy](../catalog.md). Symbolic probability and statistics: random variables, distributions, and expectation.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point for the stats module. Re-exports all public symbols (distributions, query functions, symbolic probability classes) from submodules. |
| `rv.py` | Core random variable framework and **public API functions that perform actual computation** of statistical quantities. Defines the **base domain class hierarchy** for representing sample spaces: `RandomDomain` (abstract base with `__contains__` stub), `SingleDomain` (single-variable domain whose `__contains__` checks that the sample point has exactly one element, then verifies symbol identity and value membership — this is the **canonical base implementation** of one-variable membership testing, handling the multi-entry vs single-pair distinction; `SingleFiniteDomain` in `frv.py` inherits from `SingleDomain` indirectly but `FiniteDomain.__contains__` uses simple set membership instead), `ConditionalDomain` (abstract domain that merely **stores** an attached logical condition without processing it — the actual interpretation of And/Or conditions during integration happens in the concrete subclass `ConditionalContinuousDomain` in `crv.py`), and `ProductDomain` (Cartesian product of domains). These base classes define the containment/membership semantics that subclasses in `crv.py` and `frv.py` inherit or override. Also defines probability spaces (`PSpace`, `SinglePSpace`, `ProductPSpace`), random symbols, and fundamental operators like `probability`, `expectation`, `density`, `where`, `given`, `cdf`, and `sample`. The **`given` function** is the central conditional-expression handler: it transforms a stochastic expression under a condition into an equivalent unconditional form. It contains a critical **single-variable equality shortcut** — when the condition is an `Equality` involving exactly one stochastic variable and the domain is not already conditioned, `given` solves the equality for that variable via `solveset` and directly substitutes each solution into the expression, returning the sum of substituted results. This bypasses full conditional measure-space construction entirely. Only when this shortcut does not apply (e.g., inequality conditions, multiple random variables, or already-conditioned domains) does `given` fall back to constructing the full joint probability space, building a conditional space from it, and swapping random symbols to point at the new conditioned space. This function is **not** in `crv.py` — `crv.py`'s `ConditionalContinuousDomain.integrate` handles integration-bound tightening for continuous conditional domains, but the equality-solving shortcut that avoids conditional space construction lives here. The **`expectation` function** is the concrete computation engine for expected values: it handles non-random early return, Monte Carlo sampling, conditional expectation (via recursive `given()` reduction), and critically implements a **linearity optimization** — when the expression is an `Add` (sum of stochastic terms), it recursively computes `expectation` of each summand separately and sums the results, rather than integrating the entire sum at once; for non-sum expressions, it delegates to `pspace(expr).integrate(expr)`. Note that `symbolic_probability.py`'s `Expectation.doit()` also implements its own linearity expansion at the symbolic level (distributing over `Add` and factoring out deterministic terms from `Mul`), but that expansion produces unevaluated `Expectation` sub-expressions rather than evaluated integrals — the `rv.py` version here is the one that actually evaluates the integrals numerically. The `cdf` function computes cumulative distributions: when a conditioning constraint is supplied, it reduces the problem to the unconditional case by calling `given()` to rewrite the expression, then recursively computes the unconditional CDF — it does **not** compute conditional CDFs directly. The `where` and `density` functions follow the same conditional→unconditional reduction pattern via `given()`. Contains the `Density` class whose `doit()` method dispatches density computation: for deterministic expressions (no random symbols) it returns a DiracDelta point-mass distribution, for single random variables it returns the underlying distribution directly, and for general expressions it delegates to the probability space's `compute_density`. Also contains boolean dependence/independence testing (`dependent`, `independent`, `pspace_independent`) that detects whether two stochastic expressions are statistically related by comparing conditional vs marginal densities. Includes helper utilities `rv_subs`, `NamedArgsMixin`, and `_value_check`. Unlike `symbolic_probability.py` (which holds unevaluated symbolic wrappers), this module contains the functions that **actually evaluate** probabilities, densities, and CDFs. |
| `rv_interface.py` | User-facing interface that wraps the core `rv` functions into convenient aliases (`P`, `E`, `variance`, `std`, `skewness`, `covariance`, `correlation`, `moment`, `cmoment`, `smoment`). These are the functions that **actually compute** numeric statistical measures — they contain the concrete formulas and arithmetic, not just symbolic wrappers. `variance` delegates to `cmoment(X, 2)`; `std` (standard_deviation) returns `sqrt(variance(…))`; `covariance` computes `E((X-E(X))*(Y-E(Y)))` via three expectation calls; `correlation` (Pearson coefficient) divides covariance by the product of standard deviations — this division is **unguarded**, so if either random variable is constant (zero spread / zero standard deviation), it produces a division-by-zero. `moment`, `cmoment`, `smoment` compute raw, central, and standardised moments respectively. Unlike `symbolic_probability.py` (which holds inert `Expr` subclasses for display/algebraic manipulation), this module performs the real arithmetic. For boolean dependence/independence testing (whether knowing one variable changes another's distribution), see `rv.py`. |
| `crv.py` | Continuous random variable infrastructure. Implements `ContinuousDomain`, `ContinuousPSpace`, and single/product/conditional continuous probability spaces with integration-based **actual computation** of densities, CDFs, and probabilities. Defines the concrete continuous domain subclasses (`SingleContinuousDomain`, `ProductContinuousDomain`, `ConditionalContinuousDomain`) that override the abstract base classes in `rv.py`. `ConditionalContinuousDomain.integrate` is where boolean conditions attached to a restricted domain are actually **processed during integration**: it walks the condition tree, handles conjunctions (And) by tightening integration limits, and explicitly raises `NotImplementedError` for disjunctive (Or) conditions — this is the code that determines how logical conditions on a continuous domain are resolved into concrete integral bounds. For the abstract base `ConditionalDomain` (which only stores the condition without processing it), see `rv.py`. `ContinuousPSpace.probability` computes the likelihood of a condition: it first attempts a univariate path via `where`; if that raises `NotImplementedError` (e.g. multivariate or complex conditions), it falls back by computing a density of the expression difference (lhs − rhs), wrapping it in a `ContinuousDistributionHandmade` if needed, creating a fresh `SingleContinuousPSpace`, and recursively computing the probability in that simpler univariate space. `SingleContinuousDistribution` provides inverse-CDF sampling: it symbolically inverts the cumulative distribution function via `solveset`, caches the result, and draws random realizations by evaluating the inverse at a uniform random value; raises `NotImplementedError` when symbolic inversion fails or yields multiple solutions. Also provides the **generic** `compute_cdf` (integration of PDF from left bound), `compute_density` (marginalization or DiracDelta approach), and `expectation` — these are base implementations that individual distribution classes in `crv_types.py` may **override** with distribution-specific simplification logic (e.g., substituting `Min`/`Max` subexpressions with boundary values). **`SingleContinuousPSpace.integrate`** is the method that actually evaluates expected values for single continuous random variables: it first tries calling the distribution's `expectation` method, and if that raises **any exception** (`except Exception`), it falls back to constructing a raw `Integral` of `expr * self.pdf` over the distribution's support — this try/except fallback is the mechanism that ensures expectation computation degrades gracefully rather than failing outright when the distribution's built-in expectation method encounters difficulties. Unlike `symbolic_probability.py` (which holds unevaluated symbolic `Probability` expressions), this module performs the actual integration-based evaluation. |
| `crv_types.py` | Prebuilt continuous distribution types. Provides constructors, parameter validation (`check` methods using `_value_check`), and **closed-form PDF definitions** for over 35 named distributions including: standard families (Normal, Exponential, Gamma, Beta, Uniform, Cauchy, Chi-squared, Weibull, Pareto, etc.) as well as **inverse/reciprocal families** (GammaInverse, GaussianInverse) whose PDFs involve negative powers of x and exponentials of negative parameters over x (e.g. `b**a/gamma(a) * x**(-a-1) * exp(-b/x)` for the inverse gamma). Each distribution is a `SingleContinuousDistribution` subclass with a `pdf` method returning the symbolic density expression, plus a factory function (e.g. `GammaInverse(name, a, b)`) that creates the corresponding `RandomSymbol`. **Some distributions override inherited methods with distribution-specific simplification logic** — notably, the equal-probability (flat/constant) distribution overrides `compute_cdf` to post-process the generic CDF result by substituting specific `Min` expressions with boundary parameter values (e.g., replacing `Min(z, left)` with `left`), and similarly overrides `expectation` to simplify `Min`/`Max` subexpressions involving its boundary parameters. Several distributions also override `sample` with direct calls to `random` module functions. While `crv.py` provides the generic integration-based CDF/expectation infrastructure, `crv_types.py` is where **distribution-specific overrides and simplifications** of those computations live. |
| `drv.py` | Discrete random variable infrastructure for distributions over infinite/countable supports (e.g. integers). Defines `SingleDiscreteDistribution` and `SingleDiscretePSpace` with summation-based CDF computation, inverse-CDF sampling, and expectation. `SingleDiscreteDistribution._inverse_cdf_expression` symbolically inverts the discrete CDF via `solveset`: it wraps the solve call in a try/except for `NotImplementedError`, and explicitly checks `len(inverse_cdf) != 1` — if the inversion produces **multiple candidate solutions** (or none), it raises `NotImplementedError("Could not invert CDF")` rather than picking one arbitrarily. The `sample` method calls `_inverse_cdf_expression` and applies `floor()` to the result. `compute_cdf` uses `summation` of the PDF from the set's infimum and wraps the result in `Piecewise` to zero out values left of the domain. This is the **discrete** counterpart to `SingleContinuousDistribution._inverse_cdf_expression` in `crv.py`; both share the same pattern of raising `NotImplementedError` for non-unique inversions, but `drv.py` handles discrete/integer supports while `crv.py` handles continuous/real supports. |
| `drv_types.py` | Prebuilt **infinite-support** discrete distribution types. Provides constructors and PDF definitions for the Poisson and Geometric distributions only. These distributions have countably infinite sample spaces (all non-negative integers). Parameter validation uses `_value_check` from `rv.py`. For **finite-support** discrete distributions (Binomial, Bernoulli, Die, Coin, etc.), see `frv_types.py` instead. |
| `frv.py` | Finite discrete random variable infrastructure. Implements `FiniteDomain` (subclass of `RandomDomain` from `rv.py`), `SingleFiniteDomain`, `ProductFiniteDomain`, `ConditionalFiniteDomain`, `FinitePSpace`, `SingleFinitePSpace`, `ProductFinitePSpace`, and related classes for random variables with a finite set of outcomes. `FiniteDomain.__contains__` simply checks element membership in its finite set (unlike the base `SingleDomain.__contains__` in `rv.py` which validates sample-point length and symbol identity). **`ConditionalFiniteDomain`** represents a finite domain restricted by a logical predicate (e.g. "die roll is even"). Its `__new__` constructor performs **foreign-symbol validation**: it checks that the condition's free symbols are a subset of the domain's free symbols, and raises a `ValueError` if the predicate references unknown variables not belonging to the original sample space — this prevents creating a constrained domain whose condition could never be evaluated through enumeration. Its `_test` method evaluates the condition on a single element via `xreplace`, with special handling for `Equality` objects, and `__iter__` filters the parent domain's elements through `_test`. This is the finite/discrete counterpart to `ConditionalContinuousDomain` in `crv.py` (which restricts continuous domains by tightening integration bounds); the finite version works by enumeration rather than integration. Also defines `SingleFiniteDistribution` with dict-based PMF lookup. Uses explicit enumeration for density, CDF (`compute_cdf`, `sorted_cdf`), probability, and conditional spaces — the finite CDF is built by iterating over discrete outcomes and accumulating probabilities, with no `Piecewise` boundary logic needed since the outcome set is finite and fully enumerated (contrast with `drv.py`'s `compute_cdf`, which uses `summation` over an infinite support and wraps the result in a `Piecewise` to force the CDF to zero below the support's infimum). **`FinitePSpace.sample()`** is the runtime method that draws a random realization from a finite probability space: it builds a sorted CDF via `sorted_cdf`, draws a uniform random number, then iterates through CDF entries with a linear search to find where the random value falls below a cumulative probability — if no entry matches (which should be impossible for a valid distribution), it hits an `assert False` guard as an unreachable fallback. This is the code that actually executes random sampling for all finite RVs (Die, Coin, Bernoulli, etc.) — `frv_types.py` only defines the distribution constructors and PMFs, not sampling logic. For the abstract base domain classes and their containment semantics, see `rv.py`. See `drv.py` for infinite-support discrete variables. For **symbolic rewriting** of expected values into probability-weighted sum/integral form (e.g., `Expectation(X).rewrite(Probability)`), including the branch that checks whether a finite space is involved, see `symbolic_probability.py`'s `Expectation._eval_rewrite_as_Probability` — that is distinct from the actual enumeration-based integration performed here. |
| `frv_types.py` | Prebuilt **finite-support** discrete distribution types. Provides constructors and PMF definitions for Die, Coin, Bernoulli, Binomial, DiscreteUniform, Hypergeometric, Rademacher, and custom `FiniteRV`. **Parameter validation** for these distributions lives here — notably, `BinomialDistribution.__new__` uses fuzzy arithmetic (`fuzzy_not`, `fuzzy_and`) to validate that the trial count is a non-negative integer and the success probability lies in [0, 1], raising `ValueError` otherwise. This fuzzy-logic validation pattern (rather than `_value_check` used in `drv_types.py`) is characteristic of finite distribution constructors in this file. These classes define the probability mass functions (outcome-to-probability mappings); runtime operations like sampling, CDF computation, and probability evaluation are handled by `frv.py`. For infinite-support discrete distributions (Poisson, Geometric), see `drv_types.py`. |
| `symbolic_probability.py` | Symbolic (unevaluated) probability expression **wrappers** — `Expr` subclasses (`Probability`, `Expectation`, `Variance`, `Covariance`) used for display and algebraic manipulation, **not** for actually computing numeric values like Pearson correlation coefficients or detecting division-by-zero edge cases. **`Expectation.__new__`** contains a critical **deterministic short-circuit**: when no conditioning event is supplied and the expression contains no `RandomSymbol` (i.e., it is purely deterministic with no stochastic variables), the constructor returns the raw expression itself instead of wrapping it in a symbolic `Expectation` object — the expected value of a constant is that constant. This check (`expr.has(RandomSymbol)`) happens at object construction time, before `doit()` is ever called. This is distinct from the non-random early return in `rv.py`'s `expectation` function, which operates at the computation/evaluation level rather than at symbolic object construction. **`Expectation.doit()`** implements the **linearity of expectation at the symbolic level**: for `Add` (sum) expressions it distributes — returning a sum of individual `Expectation` objects — and for `Mul` (product) expressions it separates deterministic (non-`RandomSymbol`) factors from stochastic ones, pulling deterministic factors out of the `Expectation`. This is the canonical code for symbolic expansion/simplification of expected-value expressions involving sums and mixed deterministic-random products. **`Expectation._eval_rewrite_as_Probability`** converts an expected-value expression into a probability-weighted sum/integral form (`arg * Probability(Eq(rv, symbol))`), with explicit branching on the probability space type: for **continuous** spaces it produces an `Integral`, for **finite** discrete spaces it raises `NotImplemented` (note: this is a bug — `NotImplemented` is the operator-overloading singleton, not the exception `NotImplementedError`), and for **infinite discrete** spaces it produces a `Sum`. This method also contains symbol-renaming logic (lowercase vs `_1` suffix). The `_eval_rewrite_as_Integral`/`_eval_rewrite_as_Sum` methods delegate to the computation functions in `rv.py`. `Variance.doit()` decomposes the variance of a sum of random variables into individual variance terms plus pairwise covariance terms (the bilinearity expansion), and factors out squared constants from products. **`Covariance.doit()`** implements the **bilinearity of covariance at the symbolic level**: it decomposes each argument (linear combination like `a*X + b*Y`) into (coefficient, random-variable) pairs via `_expand_single_argument`, then distributes the bilinear operation over all pairs to produce a sum of pairwise covariance terms with appropriate coefficient products (e.g. `Covariance(a*X + b*Y, c*Z + d*W)` → `a*c*Covariance(X,Z) + a*d*Covariance(W,X) + ...`). It also handles special cases: returns `Variance(arg)` when both arguments are identical, and returns zero when an argument contains no random symbols. This is the canonical place for symbolic variance/covariance decomposition of random-variable expressions. For actual probability/CDF/density computation logic (including fallback strategies and conditional→unconditional reduction), see `rv.py` and `crv.py`. In particular, processing of boolean domain conditions (And/Or restrictions on continuous domains) during integration — including the `NotImplementedError` raised for disjunctive (Or) conditions — lives in `ConditionalContinuousDomain.integrate` in `crv.py`, not here. See `error_prop.py` for approximate Taylor-based error propagation (a different mechanism). |
| `error_prop.py` | Approximate arithmetic error propagation via first-order Taylor expansion. Implements `variance_prop` to propagate variance through general mathematical expressions (Add, Mul, Pow, exp) using partial derivatives, optionally including covariance terms. Unlike `symbolic_probability.py` (which performs exact symbolic expansion of `Variance`/`Covariance` for sums of random variables), this module uses a linearisation approximation suitable for error-analysis workflows. |
