# sympy/concrete — Catalog

> Part of [SymPy](../catalog.md). Finite and infinite sums and products: symbolic evaluation, convergence testing, Gosper's algorithm, and Kronecker-delta simplification.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports `Product`, `product`, `Sum`, and `summation` from the `products` and `summations` submodules. |
| `summations.py` | Implements the `Sum` class (unevaluated finite/infinite additive summations) with symbolic evaluation (`doit`, `eval_sum`, `eval_sum_symbolic`, `eval_sum_hyper`), convergence/absolute-convergence testing, Euler-Maclaurin approximation, telescopic summation, zeta-function matching, limit reversal (`reverse_order`), and the convenience function `summation`. For reversed bounds where **both bounds are explicitly present** and start > end, `Sum` uses the additive (negation) convention; for the multiplicative (reciprocal) convention see `products.py`. **Does not** handle missing/absent bounds (e.g., `(x, 1, None)`) or traversal-direction decisions when a bound is `None` — that canonicalization happens in `expr_with_limits.py`'s `_process_limits`. |
| `products.py` | Implements the `Product` class (unevaluated finite/infinite multiplicative products) with symbolic evaluation (`doit`, `_eval_product`), convergence testing (`is_convergent`), limit reversal (`reverse_order`), and the convenience function `product` that constructs and immediately evaluates a `Product`. The `doit` method implements the **Karr convention for reversed bounds**: when the starting index exceeds the ending index, the product is evaluated by swapping the bounds (adjusting by ±1) and taking the reciprocal of the general term, yielding 1/∏f(i) instead of ∏f(i). `_eval_product` is the **core term-type dispatcher**: it pattern-matches the term structure and applies specialised evaluation strategies for each case — constant terms, single-point evaluation, integer-range unrolling, polynomial factoring via `RisingFactorial`, additive (`is_Add`) numerator/denominator splitting, multiplicative (`is_Mul`) factor-by-factor recursion, **power expressions (`is_Pow`)** (when the base is index-independent the exponent is summed via `summation`; when the exponent is index-independent the base product is recursively evaluated and raised to that exponent), and nested `Product` terms. KroneckerDelta terms are detected here but immediately delegated to `delta.py` for splitting/simplification. |
| `expr_with_limits.py` | Defines the `ExprWithLimits` and `AddWithLimits` base classes (shared by `Sum`, `Product`, and `Integral`), implementing bound canonicalization (`_process_limits`), property accessors (`function`, `limits`, `variables`, `free_symbols`), substitution (`_eval_subs`), dummy-variable renaming (`as_dummy`), and additive operations like `_eval_factor` and `_eval_expand_basic`. `_process_limits` converts user-supplied limit specs into canonical `Tuple(symbol, lower, upper)` form and handles partial-bound cases: when only a starting bound is given with no ending bound (e.g. `(x, 1, None)`), it reverses the traversal direction (flips the orientation sign) and stores the single provided value as the remaining bound. This orientation adjustment during canonicalization is distinct from the reversed-bounds evaluation conventions in `summations.py` and `products.py`, which handle the case where both bounds are present but start > end. |
| `expr_with_intlimits.py` | Defines `ReorderError` and the `ExprWithIntLimits` base class (extending `ExprWithLimits`), which adds integer-limit operations used by `Sum` and `Product` to transform and permute their limit tuples. Key methods: `index` (maps a symbolic variable to its positional index among limits), `change_index` (substitutes the iteration variable and adjusts bounds), **`reorder`** (rearranges/permutes nested limit tuples given pairs that may freely mix symbolic variable names and numeric positional indices — each pair is normalised to integer positions via `index` then delegated to `reorder_limit`), and `reorder_limit` (swaps two specific limit tuples by integer position). All limit-reordering and index-permutation logic lives here, **not** in `expr_with_limits.py` (which handles bound canonicalization and substitution). |
| `gosper.py` | Implements Gosper's hypergeometric summation algorithm via `gosper_normal` (rational normal form), `gosper_term` (antidifference computation), and `gosper_sum` (closed-form evaluation of definite/indefinite hypergeometric sums). |
| `guess.py` | Provides heuristic sequence-analysis utilities: `find_simple_recurrence_vector` and `find_simple_recurrence` for detecting linear recurrences, `rationalize` for approximating floats as rationals via continued fractions, and `guess_generating_function_rational`/`guess_generating_function` for guessing generating functions from a list of terms. |
| `delta.py` | Provides helper functions and the public routines `deltaproduct` and `deltasummation` for evaluating products and sums that contain `KroneckerDelta` (discrete indicator) terms. `deltaproduct` handles the core logic of splitting an additive expression inside a finite product into its indicator part and remaining terms, recursively computing sub-products around each indicator occurrence. `deltasummation` applies analogous simplification for sums. Internal helpers include `_has_simple_delta`, `_extract_delta`, `_expand_delta`, `_remove_multiple_delta`, and `_simplify_delta`. **Note:** when a product or sum involves KroneckerDelta splitting/simplification, the logic lives here—not in `products.py` or `summations.py`, which delegate to this module. |
