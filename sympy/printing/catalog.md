# sympy/printing — Catalog

> Part of [SymPy](../catalog.md). Output formatting: LaTeX, MathML, pretty-print, C/Fortran/JS/Julia/Rust/GLSL code generation, and more.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports public printing functions (`latex`, `pretty`, `ccode`, `fcode`, `mathematica_code`, etc.) from submodules. |
| `printer.py` | Defines the `Printer` base class that all printers inherit from, implementing the dispatch mechanism that resolves `_print_<ClassName>` methods by MRO. The `_print` method walks the expression's class hierarchy looking for `_print_<ClassName>` handler methods; when no matching handler is found anywhere in the MRO, it falls back to `self.emptyPrinter(expr)` which defaults to `str(expr)` — this is the ultimate fallback that produces a string representation for unhandled expression types. The `__init__` method validates configuration settings against `_default_settings` and raises `TypeError` for any unrecognized option keys. All subclass printers inherit this initialization and settings-validation logic. |
| `defaults.py` | Provides the `DefaultPrinting` mixin that gives SymPy objects readable `__str__` and `__repr__` via `sstr`. |
| `conventions.py` | Shared helper utilities for printers: `split_super_sub` parses a single symbol's *name string* (e.g., `"x_i__j"`) into its name/superscript/subscript text components for display — includes a special post-processing exception where trailing digits in the name portion (e.g., 'alpha11') are automatically split off and inserted as a subscript even without an explicit `_` marker. `requires_partial` detects when partial-derivative notation is needed. Does not handle the rendering or formatting of mathematical objects like deltas or tensors. |
| `precedence.py` | Defines operator-precedence constants (`PRECEDENCE` dict) and the `precedence()` function used by printers to decide when parentheses are required. |
| `codeprinter.py` | `CodePrinter` — abstract base class for generating source code in non-Python programming languages (C, Fortran, JS, Julia, Rust, etc.); not the "string output formatter" for display (that is `str.py`) and not used for Python executable repr output (see `repr.py` for that). Extends `StrPrinter` with shared code-generation infrastructure; overrides `_print_Mul` from `StrPrinter` for code-generation output contexts (the canonical string-display version lives in `str.py`). Provides the `doprint` method (internal infrastructure implementing shared output-format logic such as string-vs-tuple selection via `human` setting — not a public entry point; each language's convenience function like `jscode()`, `fcode()`, `ccode()` in its own module is the intended public API), the `@requires` decorator, and code-specific default settings like `reserved_word_suffix` and `error_on_reserved` (these apply a simple suffix to reserved words in target languages, without collision-avoidance loops — for Python-specific keyword escaping with collision checking, see `python.py`). Contains `_sort_optimized`, the loop-nesting-order optimization algorithm that scores each subscript index by its position in `Indexed` array arguments (via `_rate_index_position`) to decide which index becomes the innermost vs outermost loop — subclasses override `_rate_index_position` to implement row-major or column-major ordering. Also contains `_print_Assignment` which handles assignment dispatch for `MatrixSymbol` and `Indexed` contractions (language-specific conditional rendering of `Piecewise` is in each language's own printer, e.g. `ccode.py`, `fcode.py`). Delegates initialization and settings validation to the base `Printer` class in `printer.py`. Not used directly; each language has its own module with a concrete printer. |
| `str.py` | `StrPrinter` — the canonical "string output formatter" and default single-line string printer used for display; provides `sstr()` and `sstrrepr()` convenience functions. Produces flat one-line text representations without 2-D layout. Questions about how the "string output formatter" or "string renderer" handles expressions should look here first. Contains `_print_Mul` for flat one-line product rendering (no 2-D layout); for the 2-D pretty-printer's fraction rendering with numerator/denominator decomposition, see `pretty/pretty.py`. `_print_Symbol` returns the bare symbol name without any assumption metadata. |
| `repr.py` | `ReprPrinter` — the executable-code printer for generating Python repr strings; produces `srepr()` output where `eval(srepr(expr)) == expr` holds, giving a round-trippable representation of expressions. This is the "executable-code printer" for Python repr output — not related to non-Python language code generation (C/Fortran/JS/etc.) which lives in `codeprinter.py`. Contains `_print_MatrixBase` which handles matrix repr formatting, including a special XOR-based check for matrices with zero rows but nonzero columns (or vice versa) that emits explicit dimension arguments. `_print_Symbol` includes any declared assumption properties (e.g., `positive=True`, `commutative=False`) in the output string so that Symbol metadata survives the round-trip. |
| `python.py` | `PythonPrinter` — generates executable Python code strings (with `Symbol`/`Function` import preambles) via the `python()` function. Focuses on producing runnable scripts with variable declarations. The `python()` function contains the keyword-conflict resolution logic: when a symbol or function name is a reserved Python keyword (e.g., `'lambda'`), it appends underscores in a while-loop until the new name does not collide with any already-tracked symbol or function name — this handles the case where another variable already uses the underscore-appended variant. Does not embed Symbol assumption properties in its output. |
| `latex.py` | `LatexPrinter` — converts SymPy expressions to LaTeX markup (typeset mathematical notation); provides the `latex()` convenience function. Contains hundreds of `_print_<Type>` methods with per-type formatting logic for rendering specific mathematical objects (e.g., KroneckerDelta, DiracDelta, LeviCivita, Piecewise, sums, matrices, sets, intervals) as LaTeX markup strings — not 2-D spatial layout. Contains `_print_Derivative` which handles rendering of differentiation expressions: decides between partial (`\partial`) and ordinary (`d`) notation via `requires_partial`, handles single-variable derivatives as a simple fraction, and for multi-variable higher-order derivatives groups consecutive identical variables to compute multiplicity and formats the denominator with exponents — this grouping and rendering logic lives here, not in `conventions.py` which only provides the partial-vs-ordinary detection helper. Contains `_print_Differential` which renders the exterior derivative (differential form) to LaTeX: for coordinate-based scalar fields (having `_coord_sys`) it emits `\mathrm{d}` with the coordinate name, but for general form fields the else branch returns a plain `d(...)` string with unreachable dead code after the return that would have produced properly typeset `\mathrm{d}\left(...\right)` output — this is a known bug where the formatted version never executes. Contains `_needs_mul_brackets` which decides whether an expression needs parentheses when printed as part of a Mul product, with position-aware logic: container-like objects (Integral, Sum, Product, Piecewise) require brackets only when they are not the last factor in the product, controlled by `first` and `last` parameters — this is the LaTeX-specific bracket-wrapping decision for multiplication, distinct from the generic precedence system in `precedence.py`. Contains `_print_Interval` which handles interval-to-LaTeX conversion including the degenerate/singleton case where both endpoints are equal, rendering as a set `\left\{x\right\}` instead of the usual open/closed bracket notation. `_print_Add` handles typeset addition by iterating ordered terms and checking each term's leading coefficient sign: negative-coefficient terms emit a ` - ` separator and negate the term so it renders as `a - b` rather than `a + -b`. These methods control fine-grained typesetting decisions such as subscript/superscript layout, delimiter choice, and index separator style. Also contains a LaTeX-specific module-level `translate` function and `modifier_dict` dictionary that recursively resolve symbol name suffixes (e.g., accents like hat/dot/prime, font styles like bold/cal/frak) into nested LaTeX command strings (not Unicode combining characters) — turning names like `alphahatdotprime` into nested `\hat{\dot{…}}'` output. `_print_Symbol` checks for backslashes in symbol names to bypass sub/superscript parsing and return pre-formatted TeX names verbatim. Contains `_print_DMP` and `_print_DMF` for LaTeX rendering of dense polynomial (DMP) and dense fraction field (DMF) objects: when the polynomial has an associated ring, it attempts conversion to a symbolic expression via `ring.to_sympy()`; if this conversion raises `SympifyError`, it catches the exception and falls back to printing `repr(p)` as plain text — this is a specific error-handling fallback for ring-based polynomial conversion failure. |
| `mathml.py` | `MathMLPrinter` — renders expressions as MathML (Content markup) XML; provides `mathml()` and `print_mathml()`. |
| `ccode.py` | `C89CodePrinter` and `C99CodePrinter` — generate C89/C99 source code from expressions, mapping SymPy functions to their `math.h` equivalents. Contains `_print_Pow` with special-case exponent handling: exponent `-1` emits `1.0/base` (simple division instead of `pow()`), exponent `0.5` emits `sqrt(base)`, and all other exponents use `pow(base, exp)`. `_print_Piecewise` contains the conditional-branching logic: when the expression contains assignments it emits multi-line `if/else if/else` block statements, otherwise it produces nested inline C ternary operators (`(cond) ? (val) : ...`) for use within expressions. Also contains `_print_For` for loop generation, `_print_sign` for sign idiom, and `indent_code` for brace/paren-aware indentation. |
| `cxxcode.py` | `CXX98CodePrinter`, `CXX11CodePrinter`, and `CXX17CodePrinter` — generate C++ code, extending the C printers with C++ standard-library math functions and reserved words. |
| `fcode.py` | `FCodePrinter` and the top-level `fcode()` convenience function — the entry point for converting SymPy expressions into Fortran (77/90/95/2003/2008) source code strings. Fortran is a compiled scientific language with column-major array storage; `_traverse_matrix_indices` iterates columns then rows (j outer, i inner) to match Fortran's column-major memory layout, and `_get_loop_opening_ending` shifts loop bounds by +1 for Fortran's 1-based indexing. The `_print_Piecewise` method generates standard-version-dependent conditional code: for expressions containing assignments it emits if/elseif/else blocks, for standard ≥ 95 it uses nested inline `merge()` calls, and for older standards it raises `NotImplementedError`; always requires a default-true final branch (raises `ValueError` otherwise). Also supports automatic nested loop generation for `Indexed` tensor contractions, matrix element-wise assignment via `MatrixSymbol`, column-width wrapping, fixed/free source format with configurable leading columns, implicit typing, and Fortran-specific math intrinsics. |
| `rcode.py` | `RCodePrinter` — converts expressions into R language code, mapping SymPy functions to R's built-in math functions. |
| `jscode.py` | `JavascriptCodePrinter` and the top-level `jscode()` convenience function — the entry point for converting SymPy expressions into JavaScript (browser-compatible scripting language) source code strings using `Math.*` functions. Contains `_print_Pow` with special-case exponent handling: exponent `-1` emits `1/base` (simple division instead of `Math.pow`), exponent `0.5` emits `Math.sqrt(base)`, and all other exponents use `Math.pow(base, exp)`. The `jscode()` function accepts a `human` parameter that controls the output format: when `human=True` (default) it returns a single string with constant declarations prepended, when `human=False` it returns a tuple of (symbols_to_declare, unsupported_functions, code_text). Also supports `assign_to` for assignment statements, `user_functions` for custom function mappings, and `contract` for `Indexed` tensor contraction loop generation. Contains `indent_code` which handles automatic brace/paren-aware indentation of generated code lines: strips leading whitespace, then for each line decreases the nesting level before appending if it starts with a closing token (`}` or `)`) and increases the level after appending if it ends with an opening token (`{` or `(`) — this indentation logic is self-contained here, not in the base `codeprinter.py`. |
| `julia.py` | `JuliaCodePrinter` — generates Julia source code from expressions; provides `julia_code()`. Unconditionally emits element-wise dot operators (`.*`, `.^`, `./`) for all plain `Symbol` operands regardless of whether they are numeric; uses standard algebraic operators (`*`, `^`) only for `MatrixSymbol` operands. Does not inspect operand types to decide operator style — the choice is purely based on symbol kind (MatrixSymbol vs everything else). Renders `Piecewise` as inline ternary or if-else, and validates that Piecewise has a default branch (raises error otherwise). |
| `octave.py` | `OctaveCodePrinter` and the top-level `octave_code()` convenience function — the primary entry point for converting SymPy expressions into MATLAB/Octave-compatible code strings; all operator-style and function-mapping decisions are self-contained in this module (not in the base `codeprinter.py`). Targets a 1-based, column-major language: `_traverse_matrix_indices` iterates columns then rows for column-major storage order, and loop bounds are shifted by +1 for 1-based indexing. Contains `_print_MatrixSlice` which converts 0-based symbolic array slicing into Octave's 1-based sub-range extraction syntax — shifts lower bound by +1, replaces upper bound with `end` when it matches the dimension size, collapses full-range slices to `:`, and formats non-unit steps as `start:step:end`; also contains `_print_MatrixElement` which shifts both row and column indices by +1 for single-element access. Handles language-specific math function translations, such as `_print_sinc` which divides the argument by π because Octave's built-in `sinc` implements the normalized sinc (sin(πx)/(πx)) rather than the standard mathematical sinc (sin(x)/x). Dynamically selects element-wise vs standard operators on a per-operand basis: in `_print_Mul`, `_print_Pow`, and division logic, it checks each operand's `.is_number` property to decide whether to emit `.*`/`./`/`.^` (for symbolic operands) or `*`/`/`/`^` (for numeric constants). Renders imaginary number literals in Octave's `Ni` format. Converts `Piecewise` expressions in two modes: inline element-wise nested form using `.*` and `~(cond)` operators, or block-style `if/elseif/else/end` structure; requires the last branch to have a default-true condition (raises `ValueError` otherwise). Contains `indent_code` which handles Octave-specific indentation using regex patterns: keywords like `elseif` and `else` appear in both the increase and decrease regex lists, causing them to first dedent (aligning with the opening `if`) and then indent (for the body that follows) — this indentation logic is self-contained here, not in the base `codeprinter.py`. |
| `rust.py` | `RustCodePrinter` — generates Rust source code from expressions using `f64` methods; provides `rust_code()`. |
| `glsl.py` | `GLSLPrinter` — emits GLSL (OpenGL Shading Language) code from expressions, with options for operator vs. function style and matrix formatting. |
| `mathematica.py` | `MCodePrinter` — converts expressions to Wolfram Mathematica syntax; provides `mathematica_code()`. The `__init__` method handles user-supplied custom function mappings: it merges `user_functions` from settings into `known_functions`, normalizing string-valued mappings into the list-of-tuples-with-conditions format expected by `_print_Function`. Contains a bug where list-format user mappings are silently not registered (the `update` call is inside the `not isinstance(v, list)` branch). Contains `_print_Integral` which handles indefinite vs definite integral conversion: for a single-variable indefinite integral (one variable, no bounds), it restructures arguments to `[integrand, variable]` only; for definite integrals or multi-variable integrals, it passes `expr.args` directly with full limit tuples — output is wrapped in `Hold[Integrate[...]]`. |
| `lambdarepr.py` | `LambdaPrinter`, `NumPyPrinter`, `NumExprPrinter`, and `TensorflowPrinter` — generate Python-ecosystem strings suitable for `lambdify`, NumPy, NumExpr, and TensorFlow respectively. `NumPyPrinter` handles vectorized piecewise functions (converting `Piecewise` to numpy `select()` with `default=nan`), relational operators (mapping the six standard comparison ops to numpy functions like `equal`, `not_equal`, `less`, etc., and falling back to the parent printer for non-standard relational operators), logical operators for array-based numerical evaluation, and vector/matrix operations including `_print_DotProduct` which transposes vector arguments to ensure correct 1×n by n×1 orientation for `numpy.dot`, and `_print_MatMul` for chained `.dot()` calls. `NumExprPrinter` converts expressions to strings for the numexpr fast evaluation engine, mapping sympy function names to numexpr equivalents; it explicitly blacklists matrix types (dense, sparse, immutable) and Python collection types (list, tuple, dict) by raising `TypeError`, and wraps output in `evaluate(...)`. These printers produce Python-level code only — they do not generate if/elseif/else block structures or element-wise operator forms used by scientific-language code printers like Julia or Octave. |
| `dot.py` | `dotprint()` — renders the expression tree as a Graphviz DOT graph (graph-description-language output), with helper functions `purestr`, `styleof`, `attrprint`, `dotnode`, and `dotedges`. Handles duplicate sub-expressions via a `repeat` parameter: when `repeat=True` (default), each occurrence of the same sub-expression gets a distinct node identifier by appending a position tuple (its path in the arg tree, e.g., `(1, 0)` for `expr.args[1].args[0]`) to the node name — ensuring that shared sub-expressions appear as separate nodes in the graph; when `repeat=False`, identical sub-expressions collapse to a single node, which may cause the edge count to differ from the number of args. Also supports `maxdepth` to limit traversal depth and `labelfunc` to customize leaf node labels. |
| `tree.py` | `print_tree()` and `tree()` — produce a hierarchical ASCII-art tree representation of an expression's internal structure (class names and assumptions). Uses `pprint_nodes()` which renders sibling branches with `+-` prefixes and distinguishes earlier children from the last child on continuation lines: earlier siblings get `|` pipe-character prefixes to show the branch continues, while the last child gets blank-space prefixes indicating no further siblings. This is a simple text-based structural dump, not a 2-D mathematical layout. |
| `tableform.py` | `TableForm` — formats 2-D tabular data for display in ASCII, LaTeX, or other output modes, with support for headings and alignment. Contains `_latex()` which generates LaTeX tabular output with per-column formatting: column formats can be callable functions `f(value, row, col)`, and when such a callable returns None for a cell the code falls back to the printer's `_print` method for that cell. Also contains `_sympystr()` for plain-text table rendering with column-width alignment. |
| `preview.py` | `preview()` — compiles an expression to LaTeX then renders it as PNG, DVI, PostScript, or PDF using an external TeX distribution and viewer. Contains viewer selection logic that auto-detects available system viewers per output format, supports `viewer="file"` for file output, and handles in-memory stream output via `viewer="BytesIO"` with an `outputbuffer` argument. Includes deprecation handling for the legacy `viewer="StringIO"` name (silently converted to BytesIO with a warning) and raises `ValueError` when no outputbuffer is provided for stream-based viewers. |

| `pretty/pretty.py` | `PrettyPrinter` — the core 2-D ASCII/Unicode terminal pretty-printer (this is the module for "pretty-printing" questions) with `_print_<Type>` methods that compose `prettyForm` objects for each expression type. Handles complex 2-D spatial layouts including multi-row/multi-column parameter grids for special functions (e.g., Meijer G-function with 2×2 parameter arrangement, hyper-geometric functions), vertical separators, annotated symbols with index subscripts/superscripts, and visual alignment of arguments. Contains `_hprint_vec` which renders a list of pretty-printed elements as a horizontal comma-separated row — when the list is empty (e.g., an empty parameter list in a hypergeometric function), it returns a single space as fallback; this helper is used by `_print_hyper` and `_print_meijerg` for parameter vector layout. Contains `_print_Subs` which renders substitution/evaluation-at-a-point expressions with a vertical bar `|` notation: the main expression is parenthesized, a vertical bar is drawn to its right, and variable=value assignment pairs are placed as subscripts below the bar by shifting the baseline. Contains `_print_Integral` which renders definite integrals with elongated integral signs, distinguishing between 2-element limits (only upper bound shown, lower bound left empty) and 3-element limits (both bounds displayed), with ASCII-mode spacing adjustments for bound alignment. Contains `_print_Rational` and `__print_numer_denom` which handle rational number display: only fractions where both numerator and denominator have absolute value ≥ 10 are rendered as visual stacked fractions; smaller fractions (e.g., 3/7) return None and fall back to the default `emptyPrinter` for flat string output. Contains `_print_Float` which implements the `full_prec="auto"` precision setting: when set to "auto", it uses the print recursion depth (`_print_level`) to show full precision only for top-level expressions (level 1) and reduced precision for floats nested inside larger expressions. Also handles display truncation of sequences (`_print_SeqFormula`, `_print_SeqPer`, `_print_SeqAdd`, `_print_SeqMul`) with asymmetric ellipsis logic depending on whether a sequence starts at negative infinity or extends to positive infinity. Includes special-case `_print_` methods that disambiguate function names from Greek letter symbols (e.g., `_print_Chi` renders the hyperbolic cosine integral as literal "Chi" text to prevent it from being displayed as the Greek letter χ). Contains `_print_Add` which handles addition layout including a deferred-rendering strategy for rational number terms (fractions with denominator > 1): these terms are initially stored as placeholders, then after all other terms are laid out, they are rendered either as vertical stacked fractions (numerator over denominator) or as inline flat text depending on whether any other term in the sum has height greater than one line — ensuring visual consistency of the output. Contains `_print_Mul` which decomposes symbolic products into numerator and denominator factor lists (factors with negative exponents go to denominator), with a subtle distinction: factors raised to exactly `-1` use `evaluate=True` (allowing simplification) while other negative rational exponents use `evaluate=False` to suppress simplification when negating the exponent — this method handles factor decomposition and delegates visual composition (including minus-sign rendering and dash disambiguation) to `prettyForm.__mul__` in `stringpict.py`. Contains `_print_MatrixElement` which conditionally renders matrix elements as subscripted symbols (e.g., A₁₂) when the parent is a MatrixSymbol with numeric indices, or as bracket-indexed notation (e.g., A[i, j]) otherwise. Contains `_print_AlgebraicNumber` which renders algebraic extension elements with two distinct paths: when the element has a generator alias (`is_aliased`), it converts via `as_poly().as_expr()` (polynomial form first, then expression) before printing; otherwise it calls `as_expr()` directly — this aliased vs non-aliased distinction changes the rendered output. Contains `_print_DMP` and `_print_DMF` for pretty-printing dense polynomial (DMP) and dense fraction field (DMF) representations: attempts ring-based conversion to a symbolic expression via `ring.to_sympy()`, and on `SympifyError` falls back to printing `repr(p)` as plain text. Contains `_print_Cycle` for pretty-printing permutation cycles with three branches: empty cycle renders as empty parentheses, identity permutation (no elements moved, cyclic form is empty list) renders the largest element index in parentheses, and normal cycles render each tuple without commas. Contains `_print_Pow` which decides how to render exponentiation in 2-D layout based on the exponent value: exponent exactly `-1` renders as a reciprocal fraction `1/base`, a unit-numerator rational exponent (like `1/3`) with atomic denominator renders as an nth-root symbol via `_print_nth_root`, any other negative rational exponent renders as `1/(base^|e|)`, relational bases get parenthesized before raising, and all remaining cases use standard base-to-the-power notation — this branching logic determines the visual form of power expressions in pretty-printed output. Orchestrates layout of expressions but delegates symbol/character lookup to `pretty_symbology.py` and 2-D picture manipulation to `stringpict.py`. |
| `pretty/pretty_symbology.py` | Low-level Unicode/ASCII character-lookup layer for the pretty printer — this is where the rendering decision for mathematical constants and symbols is made, and where unicode auto-detection happens. Contains `pretty_try_use_unicode()` which probes whether the output stream supports non-ASCII rendering by checking `sys.stdout.encoding` — when stdout is redirected through a pipe or is a non-terminal stream, `encoding` is `None` and the function returns without enabling unicode; otherwise it attempts to encode Greek and atom symbols using the detected encoding, and only enables unicode if all succeed. Contains `xstr()`, the mode-aware string conversion function that chooses between the wide-character string constructor (`unicode()`) and the byte-string constructor (`str()`) based on the current unicode display mode flag — this is the single decision point for how the human-readable pretty printer converts values to strings depending on display mode. Contains `pretty_atom()` which maps atom names (Pi, Infinity, Exp1, ImaginaryUnit, EmptySet, number sets, etc.) to Unicode display characters via `atoms_table`; in ASCII mode (non-Unicode), if no `default` fallback string is provided, it raises `KeyError('only unicode')` as a control-flow signal to tell the caller to fall back to the default printer — this exception-based fallback is the mechanism that determines what happens when constants cannot be rendered in ASCII. Defines the `_xobj_unicode` and `_xobj_ascii` dictionaries that specify how tall multi-line delimiters (parentheses, brackets, curly braces, floor/ceiling, integrals, summation) are composed from individual Unicode character pieces. Contains `xobj()` which constructs variable-height spatial objects (lists of equal-length strings) for delimiters and vertical symbols — this is the function that assembles tall brackets, braces, integral signs, etc. from top/extension/bottom/middle character pieces defined in `_xobj_unicode`/`_xobj_ascii`; for symbols with a center piece (e.g., curly braces), it enforces odd height by incrementing even-length requests by 1. Also provides `xsym()` for operator symbology, Greek letter tables, sub/superscript digit mappings, and `pretty_symbol()` which converts symbol names with superscript/subscript indices into Unicode-rendered forms — critically, if superscript character mapping fails for any character, the function abandons pretty subscript mapping as well and falls back entirely to plain underscore-separated notation (subscripts are not independently attempted). Defines `modifier_dict` mapping accent names (hat, bar, vec, dot, tilde, mathring, check, breve, acute, grave, prime, etc.) to lambdas that append Unicode combining characters (e.g., COMBINING CIRCUMFLEX ACCENT, COMBINING OVERLINE, COMBINING RIGHT ARROW ABOVE, COMBINING RING ABOVE), and bracket-style wrappers (norm, abs, avg, mag) to lambdas that surround the symbol with Unicode delimiter characters — this is the mechanism for applying accent decorations and bracket wrappers to variable names using Unicode combining characters in pretty-printed output. Does not decide when or whether to apply brackets — only supplies the characters. |
| `pretty/stringpict.py` | `stringPict` and `prettyForm` — data structures representing 2-D ASCII pictures with baseline tracking, providing operations like horizontal/vertical joining, alignment, and binding-power parenthesization. Contains `stack()` which vertically composes pictures top-to-bottom with centering, and handles a special LINE sentinel value that gets replaced with a horizontal dash row spanning the maximum width of all composed elements — this is used for rendering fraction bars and similar horizontal separators. `below()` and `above()` delegate to `stack()` for vertical composition with different baseline handling. Contains the `render` method which handles terminal line-wrapping: it splits wide expressions into column-width segments and decides whether to insert blank vertical spacer lines between wrapped segments based on picture height (single-line pictures get no spacers; multi-line pictures get blank-line separators for readability). Contains `parens()` which wraps a picture in bracket delimiters and includes an ASCII-mode fallback that collapses multi-line brackets to single-line to avoid ugly tall parentheses. Does not handle character/symbol lookup. |
