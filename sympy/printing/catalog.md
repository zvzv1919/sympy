# sympy/printing — Catalog

> Part of [SymPy](../catalog.md). Output formatting: LaTeX, MathML, pretty-print, C/Fortran/JS/Julia/Rust/GLSL code generation, and more.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports public printing functions (`latex`, `pretty`, `ccode`, `fcode`, `mathematica_code`, etc.) from submodules. |
| `printer.py` | Defines the `Printer` base class that all printers inherit from, implementing the dispatch mechanism that resolves `_print_<ClassName>` methods by MRO. |
| `defaults.py` | Provides the `DefaultPrinting` mixin that gives SymPy objects readable `__str__` and `__repr__` via `sstr`. |
| `conventions.py` | Shared helper utilities for printers: `split_super_sub` splits symbol names at `^` and `_` delimiters into name/superscript/subscript parts (structural splitting only, no accent/decoration handling — does not strip suffix modifiers like "hat", "dot", "prime"), and `requires_partial` is a small boolean helper that detects when partial-derivative notation is needed (checks free-variable count). **These are low-level helpers only** — the actual rendering logic that calls them lives in the printer classes: `latex.py` `translate()` handles recursive Greek-letter and accent-modifier suffix stripping (including the edge-case guard preventing stripping when the entire string is a modifier keyword); `pretty/pretty.py` contains the derivative rendering method that calls `requires_partial` and builds the full 2-D fraction layout with repeated-variable grouping. |
| `precedence.py` | Defines operator-precedence constants (`PRECEDENCE` dict) and the `precedence()` function used by printers to decide when parentheses are required. |
| `codeprinter.py` | `CodePrinter` base class for all code-generation printers (C, Fortran, JS, etc.), extending `StrPrinter` with assignment handling, loop generation, and the `@requires` decorator. |
| `str.py` | `StrPrinter` — the default human-readable string printer; provides `sstr()` and `sstrrepr()` convenience functions. Contains extensive `_print_<Type>` dispatch methods for a wide range of SymPy objects including polynomials (DMP, DMF — with try/except fallback when ring-to-symbolic conversion fails), sets, tuples, matrices, symbols, units, and more. This is the primary "convert to string" printer; `repr.py` is only for round-trippable `srepr()` output. |
| `repr.py` | `ReprPrinter` — produces `srepr()` output where `eval(srepr(expr)) == expr` holds, giving a round-trippable representation of expressions. |
| `python.py` | `PythonPrinter` — generates executable Python code strings (with `Symbol`/`Function` import preambles) via the `python()` function. |
| `pycode.py` | `PythonCodePrinter`, `MpmathPrinter`, `NumPyPrinter`, and `SciPyPrinter` — emit Python code targeting the standard math library, mpmath, NumPy, or SciPy respectively. |
| `latex.py` | `LatexPrinter` — converts SymPy expressions to LaTeX markup; provides the `latex()` convenience function. Contains hundreds of `_print_<Type>` dispatch methods for rendering specific expression types as LaTeX, including special mathematical symbols (KroneckerDelta, DiracDelta, LeviCivita, Heaviside, SingularityFunction), calculus constructs (integrals, sums, limits, derivatives), matrices, sets, sequences, polynomials, and more — each with type-specific formatting decisions (e.g. subscript separators, accent handling, bracket styles). Symbol name rendering is handled by a pipeline: names already containing a backslash (i.e. pre-escaped LaTeX) are emitted verbatim, bypassing further processing; otherwise names are split into base/superscript/subscript parts (via `conventions.py`'s `split_super_sub`) and each part is decorated by the module-level `translate()` helper, which recursively converts symbol name strings (e.g. "alphahatdotprime") into LaTeX with nested accent decorations by stripping modifier suffixes (longest first) via `modifier_dict`, and mapping Greek letters via `tex_greek_dictionary`. |
| `mathml.py` | `MathMLPrinter` — renders expressions as MathML (Content markup) XML; provides `mathml()` and `print_mathml()`. |
| `ccode.py` | `C89CodePrinter` and `C99CodePrinter` — generate C89/C99 source code from expressions, mapping SymPy functions to their `math.h` equivalents. |
| `cxxcode.py` | `CXX98CodePrinter`, `CXX11CodePrinter`, and `CXX17CodePrinter` — generate C++ code, extending the C printers with C++ standard-library math functions and reserved words. |
| `fcode.py` | `FCodePrinter` — generates Fortran 77/90/95 code from expressions, handling column-width wrapping, implicit typing, and Fortran-specific math intrinsics. |
| `rcode.py` | `RCodePrinter` — converts expressions into R language code, mapping SymPy functions to R's built-in math functions. |
| `jscode.py` | `JavascriptCodePrinter` — emits JavaScript code using `Math.*` functions; provides `jscode()`. |
| `julia.py` | `JuliaCodePrinter` — generates Julia source code from expressions; provides `julia_code()`. |
| `octave.py` | `OctaveCodePrinter` — produces Octave/Matlab-compatible code from expressions; provides `octave_code()`. |
| `rust.py` | `RustCodePrinter` — generates Rust source code from expressions using `f64` methods; provides `rust_code()`. |
| `glsl.py` | `GLSLPrinter` — emits GLSL (OpenGL Shading Language) code from expressions, with options for operator vs. function style and matrix formatting. |
| `mathematica.py` | `MCodePrinter` — converts expressions to Wolfram Mathematica syntax; provides `mathematica_code()`. |
| `lambdarepr.py` | `LambdaPrinter`, `NumExprPrinter`, and `TensorflowPrinter` — generate Python strings suitable for `lambdify`, NumExpr, and TensorFlow respectively. |
| `dot.py` | `dotprint()` — renders the expression tree as a Graphviz DOT graph, with helper functions `purestr`, `styleof`, `attrprint`, `dotnode`, and `dotedges`. |
| `tree.py` | `print_tree()` and `tree()` — produce an indented ASCII tree representation of an expression's class hierarchy and assumptions. |
| `tableform.py` | `TableForm` — formats 2-D tabular data for display in ASCII, LaTeX, or other output modes, with support for headings and alignment. |
| `preview.py` | `preview()` — compiles an expression to LaTeX then renders it as PNG, DVI, PostScript, or PDF using an external TeX distribution and viewer. |
| `gtk.py` | `print_gtk()` — renders an expression via MathML in the Gtkmathview widget (requires libgtkmathview-bin). |
| `theanocode.py` | `TheanoPrinter` — translates SymPy expressions into Theano tensor-variable graphs for GPU-accelerated numerical computation. |
| `llvmjitcode.py` | `LLVMJitPrinter` and `llvm_callable()` — compiles SymPy expressions to native machine code via LLVM IR using the llvmlite library. |
| `pretty/__init__.py` | Sub-package entry point for the ASCII/Unicode 2-D pretty-printer; re-exports `pretty`, `pprint`, and related functions. |
| `pretty/pretty.py` | `PrettyPrinter` — the core 2-D ASCII-art / Unicode pretty-printer that builds multi-line box-drawing representations of expressions (the "human-readable output formatter"). Contains hundreds of `_print_<Type>` dispatch methods for specific expression types including: number-domain fields (`_print_RealField`, `_print_ComplexField`, `_print_FiniteField`, etc.) which render symbols like ℝ/ℂ with precision subscripts for non-default precision; **derivative rendering** that decides between the partial differential symbol (∂) vs ordinary 'd' (by calling `conventions.requires_partial` and checking unicode support), groups repeated independent variables with exponent counts, and builds a fraction-like numerator/denominator layout; **rational number / fraction rendering** with a digit-threshold heuristic — when both numerator and denominator are ≥ 10 (multi-digit), displays as a vertical stacked division, otherwise returns `None` to fall back to the default inline representation; calculus constructs like limits (with directional superscript ±  suppression when approaching infinity), sums, and integrals; matrices, sets, sequences, and algebraic structures. Also defines the module-level convenience functions `pretty()`, `pretty_print()`/`pprint`, and `pager_print()` — the pager variant defaults `num_columns` to 500000 to disable line wrapping for sideways-scrolling pagers like `less -S`, but auto-detects terminal width when `num_columns=None` is passed. |
| `pretty/pretty_symbology.py` | Symbolic primitives and Unicode/ASCII abstraction layer for the pretty printer: Greek letter tables, sub/superscript digit mappings, box-drawing characters, and related helpers. |
| `pretty/stringpict.py` | `stringPict` and `prettyForm` — data structures representing 2-D ASCII pictures with baseline tracking, used for composing multi-line pretty-print output. `stringPict` provides low-level layout primitives (stacking, concatenation, padding, parenthesization) — including a `parens` method that wraps a picture in left/right delimiters whose height matches the expression; critically, `parens` contains an ASCII-mode "no ugly" hack: when the renderer is in non-unicode (ASCII) mode and a caller-supplied flag is set, it overrides the delimiter height to 1 and resets the baseline to 0, forcing single-character-tall delimiters regardless of the expression's actual height. `prettyForm` extends it with arithmetic operator overloads (`__pow__`, `__mul__`, `__div__`) that implement rendering-decision heuristics — e.g. `__pow__` decides whether to place an exponent inline next to a function name (like sin²(x)) or stacked above a parenthesized base, based on the base's binding level and the exponent's height. Does not contain expression-type dispatch (`_print_<Type>`) methods or output/paging functions — those live in `pretty/pretty.py`. |
