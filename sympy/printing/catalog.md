# sympy/printing — Catalog

> Part of [SymPy](../catalog.md). Output formatting: LaTeX, MathML, pretty-print, C/Fortran/JS/Julia/Rust/GLSL code generation, and more.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports public printing functions (`latex`, `pretty`, `ccode`, `fcode`, `mathematica_code`, etc.) from submodules. |
| `printer.py` | Defines the `Printer` base class that all printers inherit from, implementing the dispatch mechanism that resolves `_print_<ClassName>` methods by MRO. The core `_print` method walks the expression's MRO looking for a matching `_print_<ClassName>` handler; when **no handler is found** for any ancestor class, the fallback `emptyPrinter` callable is invoked as a last resort to produce a string representation. Subclass printers (StrPrinter, ReprPrinter, etc.) override `emptyPrinter` with their own fallback behavior, but the MRO-walking dispatch loop and the fallback invocation logic live here in the base class — look here for questions about the general dispatch/fallback mechanism, not in subclass files. |
| `defaults.py` | Provides the `DefaultPrinting` mixin that gives SymPy objects readable `__str__` and `__repr__` via `sstr`. |
| `conventions.py` | Shared helper utilities for printers: `split_super_sub` splits symbol names at `^` and `_` delimiters into name/superscript/subscript parts (structural splitting only, no accent/decoration handling — does not strip suffix modifiers like "hat", "dot", "prime"); additionally, after parsing delimiters, it applies a regex-based trailing-digit special case — if the base name ends with digits (e.g. "alpha2", "x12"), those digits are automatically split off and inserted as the first subscript entry (so "alpha2" yields name="alpha" with subscript ["2"]), providing a UX convenience for rendering indexed variables. `requires_partial` is a small boolean helper that detects when partial-derivative notation is needed (checks free-variable count). **These are low-level helpers only** — the actual rendering logic that calls them lives in the printer classes: `latex.py` `translate()` handles recursive Greek-letter and accent-modifier suffix stripping (including the edge-case guard preventing stripping when the entire string is a modifier keyword); `pretty/pretty.py` contains the derivative rendering method that calls `requires_partial` and builds the full 2-D fraction layout with repeated-variable grouping. |
| `precedence.py` | Defines operator-precedence constants (`PRECEDENCE` dict) and the `precedence()` function used by printers to decide when parentheses are required. |
| `codeprinter.py` | `CodePrinter` base class for all code-generation printers (C, Fortran, JS, etc.), extending `StrPrinter` with assignment handling, loop generation, and the `@requires` decorator. |
| `str.py` | `StrPrinter` — the default **flat, single-line** human-readable string printer (as opposed to `pretty/pretty.py` which produces 2-D multi-line output); provides `sstr()` and `sstrrepr()` convenience functions. Contains extensive `_print_<Type>` dispatch methods for a wide range of SymPy objects including: **addition/sum rendering** (`_print_Add`) which iterates over ordered terms, detects negative terms by checking whether the printed string starts with `'-'`, strips the sign, then reassembles terms with `+`/`-` separators — critically, the leading `+` sign of the first term is suppressed (replaced with empty string) so positive-leading sums don't start with `+`; also wraps lower-precedence terms in parentheses; **block matrix rendering** (`_print_BlockMatrix`) which has a special-case branch for single-block (1×1 shape) composed matrices — intended to unwrap the inner element rather than printing the full block structure, but contains a control-flow bug where the unwrapped result is computed but not returned, causing it to always fall through to printing the full blocks representation regardless of shape. Also handles polynomials (DMP, DMF — with try/except fallback when ring-to-symbolic conversion fails), sets, tuples, matrices, symbols, units, and more. This is the primary "convert to flat string" printer; `repr.py` is only for round-trippable `srepr()` output and does **not** handle BlockMatrix — it only has `_print_MatrixBase` for dense/sparse matrix types; `pretty/pretty.py` is for 2-D stacked rendering. |
| `repr.py` | `ReprPrinter` — produces `srepr()` output where `eval(srepr(expr)) == expr` holds, giving a round-trippable representation of expressions. Contains `_print_<Type>` dispatch methods for many types including: **matrix rendering** (`_print_MatrixBase`) which handles a special edge case for partially-empty matrices — when exactly one dimension is zero (e.g. 0×3 or 5×0, detected via XOR), it emits an explicit constructor with rows, cols, and an empty list rather than the normal nested-list format; aliases for all sparse/dense/mutable/immutable matrix variants point to the same method. Also handles Symbols (including assumption attributes), Floats (with precision), Rationals, Booleans, and other atomic expressions. Does **not** handle BlockMatrix or composed/block-structured matrices — those are handled in `str.py`. See `str.py` for human-readable output; `repr.py` is strictly for reconstructable round-trip output. |
| `python.py` | `PythonPrinter` — generates executable Python code strings (with `Symbol`/`Function` import preambles) via the `python()` function. |
| `pycode.py` | `PythonCodePrinter`, `MpmathPrinter`, `NumPyPrinter`, and `SciPyPrinter` — emit Python code targeting the standard math library, mpmath, NumPy, or SciPy respectively. |
| `latex.py` | `LatexPrinter` — converts SymPy expressions to LaTeX markup; provides the `latex()` convenience function. **Not used for tabular/grid data** — LaTeX rendering of structured data grids (tables with row/column headings, per-column format callbacks, `\begin{tabular}` environments) is handled independently by `tableform.py`'s own `_latex` method. Contains hundreds of `_print_<Type>` dispatch methods for rendering specific expression types as LaTeX, including: **product/multiplication rendering** (`_print_Mul`) which splits an expression into numerator and denominator via `fraction()`, then decides between three fraction display modes: (1) when `fold_short_frac` is enabled and the denominator is short (≤ 2 tokens, no exponents), it uses **inline slash notation** (`a / b`); (2) when the numerator's token count exceeds `long_frac_ratio` times the denominator's length, it avoids `\frac{}{}` and instead emits `\frac{1}{denom}` times the numerator (to prevent overly wide stacked fractions); (3) otherwise it uses standard stacked `\frac{numer}{denom}` notation — also contains a nested `convert()` helper that inserts a special number-separator between adjacent numeric terms detected via regex; **addition/subtraction rendering** (`_print_Add`) which iterates over ordered terms and uses a negative-coefficient check (`_coeff_isneg`) to decide whether to emit a subtraction sign (" - ") and negate the term, or emit an addition sign (" + "), with bracket-wrapping for relational subexpressions; **algebraic root rendering** (`_print_ComplexRootOf`) which abbreviates the internal class name "ComplexRootOf" to the shorter "CRootOf" before emitting it as a `\operatorname{}` — this abbreviation is specific to the LaTeX output and mirrors a similar abbreviation in `str.py`, but the LaTeX version wraps the result in `\operatorname{}` markup; also `_print_RootSum` and `_print_Poly` which similarly use `\operatorname{}` for polynomial class names not in the accepted LaTeX functions list; special mathematical symbols (KroneckerDelta, DiracDelta, LeviCivita, Heaviside, SingularityFunction); calculus constructs — integrals (with multi-integral shorthand for ≤4 unbounded limits), sums, limits (with directional superscript suppression: when the approach target is ±∞ the direction indicator is omitted, but for finite targets the direction is always rendered as a superscript on the target value), derivatives; matrices, sets, sequences, polynomials, and more — each with type-specific formatting decisions (e.g. subscript separators, accent handling, bracket styles). Symbol name rendering is handled by a pipeline: names already containing a backslash (i.e. pre-escaped LaTeX) are emitted verbatim, bypassing further processing; otherwise names are split into base/superscript/subscript parts (via `conventions.py`'s `split_super_sub`) and each part is decorated by the module-level `translate()` helper, which recursively converts symbol name strings (e.g. "alphahatdotprime") into LaTeX with nested accent decorations by stripping modifier suffixes (longest first) via `modifier_dict`, and mapping Greek letters via `tex_greek_dictionary`. |
| `mathml.py` | `MathMLPrinter` — renders expressions as MathML (Content markup) XML; provides `mathml()` and `print_mathml()`. Contains `_print_<Type>` dispatch methods for many expression types including: **rational number rendering** (`_print_Rational`) which checks whether the denominator equals one — if so, it skips generating a `<divide>` element and instead emits a plain `<cn>` node containing only the numerator; otherwise it builds an `<apply><divide/>…</apply>` tree with separate `<cn>` nodes for numerator and denominator. Also includes product rendering (`_print_Mul`) that decomposes into coefficient and term factors, emitting `<times>` apply nodes; addition/subtraction (`_print_Add`) that tracks sign via `_coeff_isneg` to choose `<plus>` vs `<minus>` elements; matrix rendering (`_print_MatrixBase`) building `<matrix>`/`<matrixrow>` structures; limits, imaginary unit, Euler-gamma, golden ratio, and other special constants as dedicated MathML elements. |
| `ccode.py` | `C89CodePrinter` and `C99CodePrinter` — generate C89/C99 source code from expressions, mapping SymPy functions to their `math.h` equivalents. |
| `cxxcode.py` | `CXX98CodePrinter`, `CXX11CodePrinter`, and `CXX17CodePrinter` — generate C++ code, extending the C printers with C++ standard-library math functions and reserved words. |
| `fcode.py` | `FCodePrinter` — generates Fortran 77/90/95 code from expressions, handling Fortran-specific source-line continuation wrapping (splitting long generated code lines to comply with Fortran's fixed/free-format column limits — this is **compiler-mandated source-code wrapping**, not display/pager line wrapping), implicit typing, and Fortran-specific math intrinsics. Unlike Julia/Octave printers, Fortran does not use element-wise dotted operators (`.*`, `./`, `.^`); its `_print_Mul` uses standard scalar arithmetic operators only. Its `_print_Pow` has Fortran-specific special cases: inverse expressions use `1.0/x`, and **half-power (square root) expressions require integer-to-float conversion** because Fortran's intrinsic `sqrt()` does not accept integer arguments — numeric integer bases get a `.0d0` suffix appended (e.g. `sqrt(2.0d0)`), while symbolic integer expressions are wrapped in `dble()` (e.g. `sqrt(dble(n))`); non-integer bases pass through to plain `sqrt()`. Also handles complex number formatting: `_print_Add` separates real and imaginary parts into `cmplx()` calls, `_print_Mul` wraps imaginary products similarly, and `_print_Rational` emits double-precision literals (`p.0d0/q.0d0`). For display/pager line-wrapping of human-readable expression output, see `pretty/pretty.py`'s `pager_print()` and `pretty_print()`. |
| `rcode.py` | `RCodePrinter` — converts expressions into R language code, mapping SymPy functions to R's built-in math functions. |
| `jscode.py` | `JavascriptCodePrinter` — emits JavaScript code using `Math.*` functions; provides `jscode()`. |
| `julia.py` | `JuliaCodePrinter` — generates Julia source code from expressions; provides `julia_code()`. A key distinguishing feature is **element-wise (dotted) operator emission**: `_print_Mul` uses a `multjoin` helper that chooses between scalar `*` and broadcasting `.*` based on whether each operand is numeric, and similarly picks `/` vs `./` for division; `_print_Pow` applies the same logic for `^` vs `.^`. This dotted-operator behavior is unique to Julia (and Octave) among the code-generation printers — Fortran (`fcode.py`) and C (`ccode.py`) do not use dotted operators. Also uses column-major (Fortran-order) matrix traversal. Has its own `_print_Assignment` (copied from `codeprinter.py` but customized) that rewrites Piecewise right-hand sides: when not in inline mode, each branch of a multi-branch conditional (Piecewise) is restructured into a separate per-branch assignment before printing, rather than emitting the conditional directly. Also handles indexed-loop contraction and Julia-specific constant rendering (pi, e, Euler-gamma, Catalan, golden ratio) with inline vs non-inline modes. See `codeprinter.py` for the base `CodePrinter` class; `julia.py` overrides assignment handling with Julia-specific Piecewise decomposition. |
| `octave.py` | `OctaveCodePrinter` — produces Octave/Matlab-compatible code from expressions; provides `octave_code()`. Like `julia.py`, uses **element-wise (dotted) operator emission**: `_print_Mul` uses a `multjoin` helper that chooses between scalar `*` and broadcasting `.*` based on whether each operand is numeric, and similarly picks `/` vs `./` for division; `_print_Pow` applies the same logic for `^` vs `.^`. Also contains `_print_Mul` logic that separates commutative and non-commutative factors (NC factors use standard `*` join). Has its own `indent_code` method that auto-indents generated Octave code using regex-based keyword detection: keywords like `function`, `if`, `for` increase indentation, while `end` decreases it — notably, keywords that simultaneously close and open a block (like `else`, `elseif`) appear in **both** the increase and decrease lists, causing them to first dedent (aligning with the parent block) then indent (for their body); blank/empty lines are preserved without indentation. See `julia.py` for Julia's very similar element-wise operator logic; see `codeprinter.py` for the base `CodePrinter` class. |
| `rust.py` | `RustCodePrinter` — generates Rust source code from expressions using `f64` methods; provides `rust_code()`. |
| `glsl.py` | `GLSLPrinter` — emits GLSL (OpenGL Shading Language) code from expressions, with options for operator vs. function style and matrix formatting. |
| `mathematica.py` | `MCodePrinter` — converts expressions to Wolfram Mathematica syntax (Wolfram Language); provides `mathematica_code()`. Uses `[…]` brackets for function calls (e.g. `Sin[x]`) and curly braces for lists. Contains `_print_Mul` that separates commutative and non-commutative factors via `args_cnc()`: commutative factors are delegated to the parent `CodePrinter._print_Mul`, while **non-commutative factors are joined with `**`** (which appears to be a bug — should be `*`). Also has `_print_Pow`, `_print_Function` (with conditional known-function lookup table mapping SymPy names to Mathematica names like `sin→Sin`, `acos→ArcCos`), and `_print_Integral` with definite vs indefinite integral distinction. See `codeprinter.py` for the base `CodePrinter` class. |
| `lambdarepr.py` | `LambdaPrinter`, `NumExprPrinter`, and `TensorflowPrinter` — generate Python strings suitable for `lambdify`, NumExpr, and TensorFlow respectively. |
| `dot.py` | `dotprint()` — renders the expression tree as a Graphviz DOT graph, with helper functions `purestr`, `styleof`, `attrprint`, `dotnode`, and `dotedges`. |
| `tree.py` | `print_tree()` and `tree()` — produce an indented ASCII tree representation of an expression's class hierarchy and assumptions. |
| `tableform.py` | `TableForm` — formats 2-D tabular data for display in ASCII, LaTeX, or other output modes, with support for row/column headings, alignment, and zero-suppression (replacing 0/"0" entries with blanks). The `__init__` method handles **`None` entries differently based on whether the user explicitly provides a `pad` (fill) character**: when no pad is specified, `None` values in data cells are left as-is (preserved); when the user explicitly provides a pad character, `None` cells are replaced with the pad symbol — this is controlled by an internal `ok_None` flag set during initialization. Also pads short rows to the width of the longest row. Contains its own `_latex` method (independent of `latex.py`'s `LatexPrinter`) that generates a `\begin{tabular}…\end{tabular}` environment directly: supports per-column formatting via callable callbacks or `%`-style format strings — when a callable formatter returns `None`, the system falls back to the default printer output; when no formatter is specified, numeric values are automatically wrapped in dollar signs (`$…$`) for math mode. The ASCII renderer (`_sympystr`) handles column-width calculation, center-alignment padding, and heading separators. See also `latex.py` for general expression-to-LaTeX conversion (not tabular data). |
| `preview.py` | `preview()` — compiles an expression to LaTeX then renders it as PNG, DVI, PostScript, or PDF using an external TeX distribution and viewer. |
| `gtk.py` | `print_gtk()` — renders an expression via MathML in the Gtkmathview widget (requires libgtkmathview-bin). |
| `theanocode.py` | `TheanoPrinter` — translates SymPy expressions into Theano tensor-variable graphs for GPU-accelerated numerical computation. |
| `llvmjitcode.py` | `LLVMJitPrinter` and `llvm_callable()` — compiles SymPy expressions to native machine code via LLVM IR using the llvmlite library. |
| `pretty/__init__.py` | Sub-package entry point for the ASCII/Unicode 2-D pretty-printer; re-exports `pretty`, `pprint`, and related functions. |
| `pretty/pretty.py` | `PrettyPrinter` — the **human-readable terminal/console output** formatter: the core 2-D ASCII-art / Unicode pretty-printer that builds multi-line box-drawing representations of expressions for direct display (as opposed to `latex.py` which produces LaTeX markup strings, or `str.py` which produces flat single-line strings). Contains hundreds of `_print_<Type>` dispatch methods that decide **what** to render for each expression type, but delegates the **how** of visual composition (arithmetic layout like exponentiation placement, multiplication joining, division stacking) to `pretty/stringpict.py`'s `prettyForm` operator overloads. Importantly, sign simplification for multiplication (e.g. rendering `-1*x` compactly as `-x`) is **not** in this file — that logic lives in `pretty/stringpict.py`'s `prettyForm.__mul__` operator overload, which detects `-1` factors and replaces them with a minus sign. Contains `_print_<Type>` dispatch methods for specific expression types including: number-domain fields (`_print_RealField`, `_print_ComplexField`, `_print_FiniteField`, etc.) which render symbols like ℝ/ℂ with precision subscripts for non-default precision; **substitution/evaluation-at-a-point rendering** (`_print_Subs`) which draws a vertical bar (evaluation notation) next to a parenthesized expression with variable-value pairs as subscripts — critically, when the rendered expression is only 1 line tall, the code forces a minimum height of 2 for the vertical bar separator to ensure it remains visible; **derivative rendering** that decides between the partial differential symbol (∂) vs ordinary 'd' (by calling `conventions.requires_partial` and checking unicode support), groups repeated independent variables with exponent counts, and builds a fraction-like numerator/denominator layout; **rational number / fraction rendering** with a digit-threshold heuristic — when both numerator and denominator are ≥ 10 (multi-digit), displays as a vertical stacked division, otherwise returns `None` to fall back to the default inline representation; calculus constructs like limits (with directional superscript ±  suppression when approaching infinity), sums, and integrals; matrices, sets, sequences, and algebraic structures. Also defines the module-level convenience functions `pretty()`, `pretty_print()`/`pprint`, and `pager_print()` — the pager variant defaults `num_columns` to 500000 to disable line wrapping for sideways-scrolling pagers like `less -S`, but auto-detects terminal width when `num_columns=None` is passed. |
| `pretty/pretty_symbology.py` | Symbolic primitives and Unicode/ASCII abstraction layer for the pretty printer: Greek letter tables, sub/superscript digit mappings, box-drawing characters, and related helpers. Also contains the **tall-delimiter construction** function that assembles vertical bracket/brace/parenthesis glyphs of a requested height from piece definitions (top, bottom, extension, and optional center pieces stored in lookup dictionaries for both Unicode and ASCII modes) — including special handling when a delimiter has a designated center piece but the requested height is even (forces height to odd by incrementing). This is the **glyph assembly** layer (choosing and repeating character pieces to build a delimiter of a given height); the higher-level decision of *when* to apply delimiters and *how tall* they should be lives in `pretty/stringpict.py`'s `parens` method, while expression-type dispatch lives in `pretty/pretty.py`. |
| `pretty/stringpict.py` | `stringPict` and `prettyForm` — data structures representing 2-D ASCII pictures with baseline tracking, used for composing multi-line pretty-print output. **This is where the visual layout heuristics for arithmetic operations live** (not in `pretty/pretty.py`). `stringPict` provides low-level layout primitives (stacking, concatenation, padding, parenthesization) — including a `parens` method that wraps a picture in left/right delimiters whose height matches the expression; critically, `parens` contains an ASCII-mode "no ugly" hack: when the renderer is in non-unicode (ASCII) mode and a caller-supplied flag is set, it overrides the delimiter height to 1 and resets the baseline to 0, forcing single-character-tall delimiters regardless of the expression's actual height. `prettyForm` extends it with arithmetic operator overloads (`__pow__`, `__mul__`, `__div__`) that implement rendering-decision heuristics — e.g. **`__pow__` decides whether to place an exponent inline next to a function name (like sin²(x)) or stacked above a parenthesized base**: when the base has FUNC binding and the exponent is single-line, it uses inline form (exponent next to function name); when the exponent is multi-line (height > 1) or the base is not a function, it parenthesizes the base and stacks the exponent above it. `__mul__` handles sign simplification (`-1*x → -x`) — and includes a **double-dash prevention** check: after substituting `-1` with a bare `-`, if the next term's baseline picture also starts with a `-` character, a space is inserted (`'- '` instead of `'-'`) to prevent two adjacent dashes from becoming visually ambiguous. Does not contain expression-type dispatch (`_print_<Type>`) methods or output/paging functions — those live in `pretty/pretty.py`, which calls these operator overloads to compose final output. Does **not** contain the glyph-level assembly logic for building tall delimiters from character pieces (top/mid/bot/ext) — that lives in `pretty/pretty_symbology.py`. |
