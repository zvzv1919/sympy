# sympy/printing — Catalog

> Part of [SymPy](../catalog.md). Output formatting: LaTeX, MathML, pretty-print, C/Fortran/JS/Julia/Rust/GLSL code generation, and more.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports public printing functions (`latex`, `pretty`, `ccode`, `fcode`, `mathematica_code`, etc.) from submodules. |
| `printer.py` | Defines the `Printer` base class that all printers inherit from, implementing the dispatch mechanism that resolves `_print_<ClassName>` methods by MRO. The `__init__` method validates configuration settings against `_default_settings` and raises `TypeError` for any unrecognized option keys. All subclass printers inherit this initialization and settings-validation logic. |
| `defaults.py` | Provides the `DefaultPrinting` mixin that gives SymPy objects readable `__str__` and `__repr__` via `sstr`. |
| `conventions.py` | Shared helper utilities for printers: `split_super_sub` parses a single symbol's *name string* (e.g., `"x_i__j"`) into its name/superscript/subscript text components for display, and `requires_partial` detects when partial-derivative notation is needed. Does not handle the rendering or formatting of mathematical objects like deltas or tensors. |
| `precedence.py` | Defines operator-precedence constants (`PRECEDENCE` dict) and the `precedence()` function used by printers to decide when parentheses are required. |
| `codeprinter.py` | `CodePrinter` — abstract base class that language-specific code printers (C, Fortran, JS, etc.) inherit from. Extends `StrPrinter` with shared code-generation infrastructure: the `doprint` method for assignment-aware code output, the `@requires` decorator, and code-specific default settings like `reserved_word_suffix` and `error_on_reserved`. Contains `_sort_optimized`, the loop-nesting-order optimization algorithm that scores each subscript index by its position in `Indexed` array arguments (via `_rate_index_position`) to decide which index becomes the innermost vs outermost loop — subclasses override `_rate_index_position` to implement row-major or column-major ordering. Also contains `_print_Assignment` which handles `Piecewise`, `MatrixSymbol`, and `Indexed` contractions. Delegates initialization and settings validation to the base `Printer` class in `printer.py`. Not used directly; each language has its own module with a concrete printer. |
| `str.py` | `StrPrinter` — the default single-line string printer; provides `sstr()` and `sstrrepr()` convenience functions. Produces flat one-line text representations without 2-D layout. |
| `repr.py` | `ReprPrinter` — produces `srepr()` output where `eval(srepr(expr)) == expr` holds, giving a round-trippable, code-like representation of expressions. Contains `_print_MatrixBase` which handles matrix repr formatting, including a special XOR-based check for matrices with zero rows but nonzero columns (or vice versa) that emits explicit dimension arguments. `_print_Symbol` includes any declared assumption properties (e.g., `positive=True`, `commutative=False`) in the output string so that Symbol metadata survives the round-trip. |
| `python.py` | `PythonPrinter` — generates executable Python code strings (with `Symbol`/`Function` import preambles) via the `python()` function. Focuses on producing runnable scripts with variable declarations and keyword-escaping; does not embed Symbol assumption properties in its output. |
| `latex.py` | `LatexPrinter` — converts SymPy expressions to LaTeX markup; provides the `latex()` convenience function. Contains hundreds of `_print_<Type>` methods with per-type formatting logic for rendering specific mathematical objects (e.g., KroneckerDelta, DiracDelta, LeviCivita, Piecewise, integrals, sums, matrices, sets). These methods control fine-grained typesetting decisions such as subscript/superscript layout, delimiter choice, and index separator style. Also contains the module-level `translate` function and `modifier_dict` dictionary that recursively resolve symbol name suffixes (e.g., accents like hat/dot/prime, font styles like bold/cal/frak) into nested LaTeX commands — turning names like `alphahatdotprime` into nested `\hat{\dot{…}}'` output. `_print_Symbol` checks for backslashes in symbol names to bypass sub/superscript parsing and return pre-formatted TeX names verbatim. |
| `mathml.py` | `MathMLPrinter` — renders expressions as MathML (Content markup) XML; provides `mathml()` and `print_mathml()`. |
| `ccode.py` | `C89CodePrinter` and `C99CodePrinter` — generate C89/C99 source code from expressions, mapping SymPy functions to their `math.h` equivalents. |
| `cxxcode.py` | `CXX98CodePrinter`, `CXX11CodePrinter`, and `CXX17CodePrinter` — generate C++ code, extending the C printers with C++ standard-library math functions and reserved words. |
| `fcode.py` | `FCodePrinter` and the top-level `fcode()` convenience function — the entry point for converting SymPy expressions into Fortran (77/90/95/2003/2008) source code strings. Supports conditional branching from `Piecewise`, automatic nested loop generation for `Indexed` tensor contractions, matrix element-wise assignment via `MatrixSymbol`, column-width wrapping, implicit typing, and Fortran-specific math intrinsics. |
| `rcode.py` | `RCodePrinter` — converts expressions into R language code, mapping SymPy functions to R's built-in math functions. |
| `jscode.py` | `JavascriptCodePrinter` — emits JavaScript code using `Math.*` functions; provides `jscode()`. |
| `julia.py` | `JuliaCodePrinter` — generates Julia source code from expressions; provides `julia_code()`. Unconditionally emits element-wise dot operators (`.*`, `.^`, `./`) for all plain `Symbol` operands regardless of whether they are numeric; uses standard algebraic operators (`*`, `^`) only for `MatrixSymbol` operands. Does not inspect operand types to decide operator style — the choice is purely based on symbol kind (MatrixSymbol vs everything else). Renders `Piecewise` as inline ternary or if-else, and validates that Piecewise has a default branch (raises error otherwise). |
| `octave.py` | `OctaveCodePrinter` — produces Octave/Matlab-compatible code from expressions; provides `octave_code()`. Dynamically selects element-wise vs standard operators on a per-operand basis: in `_print_Mul`, `_print_Pow`, and division logic, it checks each operand's `.is_number` property to decide whether to emit `.*`/`./`/`.^` (for symbolic operands) or `*`/`/`/`^` (for numeric constants), using a `multjoin` helper that inspects adjacent terms individually. This per-operand numeric-vs-symbolic decision logic is the core of its operator selection, distinct from Julia's unconditional approach. Renders imaginary number literals in Octave's `Ni` format. Converts `Piecewise` expressions in two modes: inline element-wise nested form using `.*` and `~(cond)` operators, or block-style `if/elseif/else/end` structure; requires the last branch to have a default-true condition (raises `ValueError` otherwise). |
| `rust.py` | `RustCodePrinter` — generates Rust source code from expressions using `f64` methods; provides `rust_code()`. |
| `glsl.py` | `GLSLPrinter` — emits GLSL (OpenGL Shading Language) code from expressions, with options for operator vs. function style and matrix formatting. |
| `mathematica.py` | `MCodePrinter` — converts expressions to Wolfram Mathematica syntax; provides `mathematica_code()`. |
| `lambdarepr.py` | `LambdaPrinter`, `NumPyPrinter`, `NumExprPrinter`, and `TensorflowPrinter` — generate Python-ecosystem strings suitable for `lambdify`, NumPy, NumExpr, and TensorFlow respectively. `NumPyPrinter` handles vectorized piecewise functions (converting `Piecewise` to numpy `select()` with `default=nan`), relational operators, and logical operators for array-based numerical evaluation. `NumExprPrinter` converts expressions to strings for the numexpr fast evaluation engine, mapping sympy function names to numexpr equivalents; it explicitly blacklists matrix types (dense, sparse, immutable) and Python collection types (list, tuple, dict) by raising `TypeError`, and wraps output in `evaluate(...)`. These printers produce Python-level code only — they do not generate if/elseif/else block structures or element-wise operator forms used by scientific-language code printers like Julia or Octave. |
| `dot.py` | `dotprint()` — renders the expression tree as a Graphviz DOT graph, with helper functions `purestr`, `styleof`, `attrprint`, `dotnode`, and `dotedges`. |
| `tree.py` | `print_tree()` and `tree()` — produce an indented ASCII tree representation of an expression's class hierarchy and assumptions. |
| `tableform.py` | `TableForm` — formats 2-D tabular data for display in ASCII, LaTeX, or other output modes, with support for headings and alignment. |
| `preview.py` | `preview()` — compiles an expression to LaTeX then renders it as PNG, DVI, PostScript, or PDF using an external TeX distribution and viewer. Contains viewer selection logic that auto-detects available system viewers per output format, supports `viewer="file"` for file output, and handles in-memory stream output via `viewer="BytesIO"` with an `outputbuffer` argument. Includes deprecation handling for the legacy `viewer="StringIO"` name (silently converted to BytesIO with a warning) and raises `ValueError` when no outputbuffer is provided for stream-based viewers. |
| `gtk.py` | `print_gtk()` — renders an expression via MathML in the Gtkmathview widget (requires libgtkmathview-bin). |
| `theanocode.py` | `TheanoPrinter` — translates SymPy expressions into Theano tensor-variable graphs for GPU-accelerated numerical computation. |
| `llvmjitcode.py` | `LLVMJitPrinter` and `llvm_callable()` — compiles SymPy expressions to native machine code via LLVM IR using the llvmlite library. |
| `pretty/__init__.py` | Sub-package entry point for the ASCII/Unicode 2-D pretty-printer; re-exports `pretty`, `pprint`, and related functions. |
| `pretty/pretty.py` | `PrettyPrinter` — the core 2-D ASCII/Unicode human-readable pretty-printer with `_print_<Type>` methods that compose `prettyForm` objects for each expression type. Handles complex 2-D spatial layouts including multi-row/multi-column parameter grids for special functions (e.g., Meijer G-function with 2×2 parameter arrangement, hyper-geometric functions), vertical separators, annotated symbols with index subscripts/superscripts, and visual alignment of arguments. Contains `_print_Float` which implements the `full_prec="auto"` precision setting: when set to "auto", it uses the print recursion depth (`_print_level`) to show full precision only for top-level expressions (level 1) and reduced precision for floats nested inside larger expressions. Also handles display truncation of sequences (`_print_SeqFormula`, `_print_SeqPer`, `_print_SeqAdd`, `_print_SeqMul`) with asymmetric ellipsis logic depending on whether a sequence starts at negative infinity or extends to positive infinity. Includes special-case `_print_` methods that disambiguate function names from Greek letter symbols (e.g., `_print_Chi` renders the hyperbolic cosine integral as literal "Chi" text to prevent it from being displayed as the Greek letter χ). Orchestrates layout of expressions but delegates symbol/character lookup to `pretty_symbology.py` and 2-D picture manipulation to `stringpict.py`. |
| `pretty/pretty_symbology.py` | Low-level Unicode/ASCII character-lookup layer for the pretty printer. Contains `pretty_atom()` which maps atom names (Pi, Infinity, etc.) to display characters and raises `KeyError` when in ASCII mode with no default. Contains `xobj()` which returns the raw character pieces for variable-height delimiters. Also provides Greek letter tables, sub/superscript digit mappings, `pretty_symbol()`, and `xsym()`. Does not decide when or whether to apply brackets — only supplies the characters. |
| `pretty/stringpict.py` | `stringPict` and `prettyForm` — data structures representing 2-D ASCII pictures with baseline tracking, providing operations like horizontal/vertical joining, alignment, and binding-power parenthesization. Contains the `render` method which handles terminal line-wrapping: it splits wide expressions into column-width segments and decides whether to insert blank vertical spacer lines between wrapped segments based on picture height (single-line pictures get no spacers; multi-line pictures get blank-line separators for readability). Falls back to 78 columns when terminal width detection fails. `prettyForm` extends `stringPict` with math-aware operator methods (`__add__`, `__div__`, `__mul__`, `__pow__`) that compose stacked fractions, products, sums, and powers from 2-D picture pieces, applying binding-power logic to decide parenthesization and handling special cases like negative-numerator formatting in stacked divisions. Contains `parens()` which wraps a picture in bracket delimiters and includes an ASCII-mode fallback that collapses multi-line brackets to single-line to avoid ugly tall parentheses. Does not handle character/symbol lookup. |
