# sympy/printing — Catalog

> Part of [SymPy](../catalog.md). Output formatting: LaTeX, MathML, pretty-print, C/Fortran/JS/Julia/Rust/GLSL code generation, and more.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports public printing functions (`latex`, `pretty`, `ccode`, `fcode`, `mathematica_code`, etc.) from submodules. |
| `printer.py` | Defines the `Printer` base class that all printers inherit from, implementing the dispatch mechanism that resolves `_print_<ClassName>` methods by MRO. The `_print` method walks the expression's class hierarchy looking for `_print_<ClassName>` handler methods; when no matching handler is found anywhere in the MRO, it falls back to `self.emptyPrinter(expr)` which defaults to `str(expr)` — this is the ultimate fallback that produces a string representation for unhandled expression types. The `__init__` method validates configuration settings against `_default_settings` and raises `TypeError` for any unrecognized option keys. All subclass printers inherit this initialization and settings-validation logic. |
| `defaults.py` | Provides the `DefaultPrinting` mixin that gives SymPy objects readable `__str__` and `__repr__` via `sstr`. |
| `conventions.py` | Shared helper utilities for printers: `split_super_sub` parses a single symbol's *name string* (e.g., `"x_i__j"`) into its name/superscript/subscript text components for display, and `requires_partial` detects when partial-derivative notation is needed. Does not handle the rendering or formatting of mathematical objects like deltas or tensors. |
| `precedence.py` | Defines operator-precedence constants (`PRECEDENCE` dict) and the `precedence()` function used by printers to decide when parentheses are required. |
| `codeprinter.py` | `CodePrinter` — abstract base class for generating source code in non-Python programming languages (C, Fortran, JS, Julia, Rust, etc.); not used for Python executable repr output (see `repr.py` for that). Extends `StrPrinter` with shared code-generation infrastructure: the `doprint` method for assignment-aware code output, the `@requires` decorator, and code-specific default settings like `reserved_word_suffix` and `error_on_reserved`. Contains `_sort_optimized`, the loop-nesting-order optimization algorithm that scores each subscript index by its position in `Indexed` array arguments (via `_rate_index_position`) to decide which index becomes the innermost vs outermost loop — subclasses override `_rate_index_position` to implement row-major or column-major ordering. Also contains `_print_Assignment` which handles assignment dispatch for `MatrixSymbol` and `Indexed` contractions (language-specific conditional rendering of `Piecewise` is in each language's own printer, e.g. `ccode.py`, `fcode.py`). Delegates initialization and settings validation to the base `Printer` class in `printer.py`. Not used directly; each language has its own module with a concrete printer. |
| `str.py` | `StrPrinter` — the default single-line string printer; provides `sstr()` and `sstrrepr()` convenience functions. Produces flat one-line text representations without 2-D layout. |
| `repr.py` | `ReprPrinter` — the printer for generating executable Python code strings; produces `srepr()` output where `eval(srepr(expr)) == expr` holds, giving a round-trippable representation of expressions. Not related to language-specific code generation (C/Fortran/JS/etc.) which lives in `codeprinter.py`. Contains `_print_MatrixBase` which handles matrix repr formatting, including a special XOR-based check for matrices with zero rows but nonzero columns (or vice versa) that emits explicit dimension arguments. `_print_Symbol` includes any declared assumption properties (e.g., `positive=True`, `commutative=False`) in the output string so that Symbol metadata survives the round-trip. |
| `python.py` | `PythonPrinter` — generates executable Python code strings (with `Symbol`/`Function` import preambles) via the `python()` function. Focuses on producing runnable scripts with variable declarations and keyword-escaping; does not embed Symbol assumption properties in its output. |
| `latex.py` | `LatexPrinter` — converts SymPy expressions to LaTeX markup (typeset mathematical notation); provides the `latex()` convenience function. Contains hundreds of `_print_<Type>` methods with per-type formatting logic for rendering specific mathematical objects (e.g., KroneckerDelta, DiracDelta, LeviCivita, Piecewise, integrals, sums, matrices, sets). `_print_Add` handles typeset addition by iterating ordered terms and checking each term's leading coefficient sign: negative-coefficient terms emit a ` - ` separator and negate the term so it renders as `a - b` rather than `a + -b`. These methods control fine-grained typesetting decisions such as subscript/superscript layout, delimiter choice, and index separator style. Also contains the module-level `translate` function and `modifier_dict` dictionary that recursively resolve symbol name suffixes (e.g., accents like hat/dot/prime, font styles like bold/cal/frak) into nested LaTeX commands — turning names like `alphahatdotprime` into nested `\hat{\dot{…}}'` output. `_print_Symbol` checks for backslashes in symbol names to bypass sub/superscript parsing and return pre-formatted TeX names verbatim. |
| `mathml.py` | `MathMLPrinter` — renders expressions as MathML (Content markup) XML; provides `mathml()` and `print_mathml()`. |
| `ccode.py` | `C89CodePrinter` and `C99CodePrinter` — generate C89/C99 source code from expressions, mapping SymPy functions to their `math.h` equivalents. `_print_Piecewise` contains the conditional-branching logic: when the expression contains assignments it emits multi-line `if/else if/else` block statements, otherwise it produces nested inline C ternary operators (`(cond) ? (val) : ...`) for use within expressions. Also contains `_print_For` for loop generation, `_print_sign` for sign idiom, and `indent_code` for brace/paren-aware indentation. |
| `cxxcode.py` | `CXX98CodePrinter`, `CXX11CodePrinter`, and `CXX17CodePrinter` — generate C++ code, extending the C printers with C++ standard-library math functions and reserved words. |
| `fcode.py` | `FCodePrinter` and the top-level `fcode()` convenience function — the entry point for converting SymPy expressions into Fortran (77/90/95/2003/2008) source code strings. The `_print_Piecewise` method generates standard-version-dependent conditional code: for expressions containing assignments it emits if/elseif/else blocks, for standard ≥ 95 it uses nested inline `merge()` calls, and for older standards it raises `NotImplementedError`; always requires a default-true final branch (raises `ValueError` otherwise). Also supports automatic nested loop generation for `Indexed` tensor contractions, matrix element-wise assignment via `MatrixSymbol`, column-width wrapping, implicit typing, and Fortran-specific math intrinsics. |
| `rcode.py` | `RCodePrinter` — converts expressions into R language code, mapping SymPy functions to R's built-in math functions. |
| `jscode.py` | `JavascriptCodePrinter` — emits JavaScript code using `Math.*` functions; provides `jscode()`. |
| `julia.py` | `JuliaCodePrinter` — generates Julia source code from expressions; provides `julia_code()`. Unconditionally emits element-wise dot operators (`.*`, `.^`, `./`) for all plain `Symbol` operands regardless of whether they are numeric; uses standard algebraic operators (`*`, `^`) only for `MatrixSymbol` operands. Does not inspect operand types to decide operator style — the choice is purely based on symbol kind (MatrixSymbol vs everything else). Renders `Piecewise` as inline ternary or if-else, and validates that Piecewise has a default branch (raises error otherwise). |
| `octave.py` | `OctaveCodePrinter` — produces Octave/Matlab-compatible code from expressions; provides `octave_code()`. Targets a 1-based, column-major language: `_traverse_matrix_indices` iterates columns then rows for column-major storage order, and loop bounds are shifted by +1 for 1-based indexing. Dynamically selects element-wise vs standard operators on a per-operand basis: in `_print_Mul`, `_print_Pow`, and division logic, it checks each operand's `.is_number` property to decide whether to emit `.*`/`./`/`.^` (for symbolic operands) or `*`/`/`/`^` (for numeric constants). Renders imaginary number literals in Octave's `Ni` format. Converts `Piecewise` expressions in two modes: inline element-wise nested form using `.*` and `~(cond)` operators, or block-style `if/elseif/else/end` structure; requires the last branch to have a default-true condition (raises `ValueError` otherwise). |
| `rust.py` | `RustCodePrinter` — generates Rust source code from expressions using `f64` methods; provides `rust_code()`. |
| `glsl.py` | `GLSLPrinter` — emits GLSL (OpenGL Shading Language) code from expressions, with options for operator vs. function style and matrix formatting. |
| `mathematica.py` | `MCodePrinter` — converts expressions to Wolfram Mathematica syntax; provides `mathematica_code()`. The `__init__` method handles user-supplied custom function mappings: it merges `user_functions` from settings into `known_functions`, normalizing string-valued mappings into the list-of-tuples-with-conditions format expected by `_print_Function`. Contains a bug where list-format user mappings are silently not registered (the `update` call is inside the `not isinstance(v, list)` branch). |
| `lambdarepr.py` | `LambdaPrinter`, `NumPyPrinter`, `NumExprPrinter`, and `TensorflowPrinter` — generate Python-ecosystem strings suitable for `lambdify`, NumPy, NumExpr, and TensorFlow respectively. `NumPyPrinter` handles vectorized piecewise functions (converting `Piecewise` to numpy `select()` with `default=nan`), relational operators, logical operators for array-based numerical evaluation, and vector/matrix operations including `_print_DotProduct` which transposes vector arguments to ensure correct 1×n by n×1 orientation for `numpy.dot`, and `_print_MatMul` for chained `.dot()` calls. `NumExprPrinter` converts expressions to strings for the numexpr fast evaluation engine, mapping sympy function names to numexpr equivalents; it explicitly blacklists matrix types (dense, sparse, immutable) and Python collection types (list, tuple, dict) by raising `TypeError`, and wraps output in `evaluate(...)`. These printers produce Python-level code only — they do not generate if/elseif/else block structures or element-wise operator forms used by scientific-language code printers like Julia or Octave. |
| `dot.py` | `dotprint()` — renders the expression tree as a Graphviz DOT graph, with helper functions `purestr`, `styleof`, `attrprint`, `dotnode`, and `dotedges`. |
| `tree.py` | `print_tree()` and `tree()` — produce a hierarchical ASCII-art tree representation of an expression's internal structure (class names and assumptions). Uses `pprint_nodes()` which renders sibling branches with `+-` prefixes and distinguishes earlier children from the last child on continuation lines: earlier siblings get `|` pipe-character prefixes to show the branch continues, while the last child gets blank-space prefixes indicating no further siblings. This is a simple text-based structural dump, not a 2-D mathematical layout. |
| `tableform.py` | `TableForm` — formats 2-D tabular data for display in ASCII, LaTeX, or other output modes, with support for headings and alignment. |
| `preview.py` | `preview()` — compiles an expression to LaTeX then renders it as PNG, DVI, PostScript, or PDF using an external TeX distribution and viewer. Contains viewer selection logic that auto-detects available system viewers per output format, supports `viewer="file"` for file output, and handles in-memory stream output via `viewer="BytesIO"` with an `outputbuffer` argument. Includes deprecation handling for the legacy `viewer="StringIO"` name (silently converted to BytesIO with a warning) and raises `ValueError` when no outputbuffer is provided for stream-based viewers. |
| `gtk.py` | `print_gtk()` — renders an expression via MathML in the Gtkmathview widget (requires libgtkmathview-bin). |
| `theanocode.py` | `TheanoPrinter` — translates SymPy expressions into Theano tensor-variable graphs for GPU-accelerated numerical computation. |
| `llvmjitcode.py` | `LLVMJitPrinter` and `llvm_callable()` — compiles SymPy expressions to native machine code via LLVM IR using the llvmlite library. |
| `pretty/__init__.py` | Sub-package entry point for the ASCII/Unicode 2-D pretty-printer; re-exports `pretty`, `pprint`, and related functions. |
| `pretty/pretty.py` | `PrettyPrinter` — the core 2-D ASCII/Unicode human-readable pretty-printer with `_print_<Type>` methods that compose `prettyForm` objects for each expression type. Handles complex 2-D spatial layouts including multi-row/multi-column parameter grids for special functions (e.g., Meijer G-function with 2×2 parameter arrangement, hyper-geometric functions), vertical separators, annotated symbols with index subscripts/superscripts, and visual alignment of arguments. Contains `_print_Float` which implements the `full_prec="auto"` precision setting: when set to "auto", it uses the print recursion depth (`_print_level`) to show full precision only for top-level expressions (level 1) and reduced precision for floats nested inside larger expressions. Also handles display truncation of sequences (`_print_SeqFormula`, `_print_SeqPer`, `_print_SeqAdd`, `_print_SeqMul`) with asymmetric ellipsis logic depending on whether a sequence starts at negative infinity or extends to positive infinity. Includes special-case `_print_` methods that disambiguate function names from Greek letter symbols (e.g., `_print_Chi` renders the hyperbolic cosine integral as literal "Chi" text to prevent it from being displayed as the Greek letter χ). Contains `_print_Mul` which renders symbolic products as fractions by separating factors with negative exponents into a denominator list, with a subtle distinction: factors raised to exactly `-1` use `evaluate=True` (allowing simplification) while other negative rational exponents use `evaluate=False` to suppress simplification when negating the exponent. Contains `_print_MatrixElement` which conditionally renders matrix elements as subscripted symbols (e.g., A₁₂) when the parent is a MatrixSymbol with numeric indices, or as bracket-indexed notation (e.g., A[i, j]) otherwise. Orchestrates layout of expressions but delegates symbol/character lookup to `pretty_symbology.py` and 2-D picture manipulation to `stringpict.py`. |
| `pretty/pretty_symbology.py` | Low-level Unicode/ASCII character-lookup layer for the pretty printer — this is where the rendering decision for mathematical constants and symbols is made. Contains `pretty_atom()` which maps atom names (Pi, Infinity, Exp1, ImaginaryUnit, EmptySet, number sets, etc.) to Unicode display characters via `atoms_table`; in ASCII mode (non-Unicode), if no `default` fallback string is provided, it raises `KeyError('only unicode')` as a control-flow signal to tell the caller to fall back to the default printer — this exception-based fallback is the mechanism that determines what happens when constants cannot be rendered in ASCII. Defines the `_xobj_unicode` and `_xobj_ascii` dictionaries that specify how tall multi-line delimiters (parentheses, brackets, curly braces, floor/ceiling, integrals, summation) are composed from individual Unicode character pieces. Contains `xobj()` which returns raw character pieces for variable-height delimiters. Also provides `xsym()` for operator symbology, Greek letter tables, sub/superscript digit mappings, and `pretty_symbol()`. Does not decide when or whether to apply brackets — only supplies the characters. |
| `pretty/stringpict.py` | `stringPict` and `prettyForm` — data structures representing 2-D ASCII pictures with baseline tracking, providing operations like horizontal/vertical joining, alignment, and binding-power parenthesization. Contains the `render` method which handles terminal line-wrapping: it splits wide expressions into column-width segments and decides whether to insert blank vertical spacer lines between wrapped segments based on picture height (single-line pictures get no spacers; multi-line pictures get blank-line separators for readability). Falls back to 78 columns when terminal width detection fails. `prettyForm` extends `stringPict` with math-aware operator methods (`__add__`, `__div__`, `__mul__`, `__pow__`) that compose stacked fractions, products, sums, and powers from 2-D picture pieces, applying binding-power logic to decide parenthesization. `__add__` implements pretty addition with negative-sign optimization: when a term already carries a negative binding (NEG), the `+` sign is omitted and the existing minus sign is reused, so adding a negative term produces `a - b` rather than `a + -b`. `__mul__` detects when `-1` is a factor in a product and simplifies it to a leading minus sign (e.g., `-1 * x` → `-x`), and handles the edge case of consecutive minus signs at the start by inserting a space. `__div__` handles negative-numerator formatting in stacked divisions. Contains `parens()` which wraps a picture in bracket delimiters and includes an ASCII-mode fallback that collapses multi-line brackets to single-line to avoid ugly tall parentheses. Does not handle character/symbol lookup. |
