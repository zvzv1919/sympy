# sympy/liealgebras -- Catalog

> Part of [SymPy](../catalog.md). Lie algebras and root systems for classical groups (A, B, C, D, E, F, G).

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package init; imports `CartanType` to make it the primary public entry point. |
| `cartan_type.py` | Defines `CartanType_generator` (the factory callable `CartanType`) that dispatches to series-specific classes based on letter+rank, and `Standard_Cartan`, the concrete base class for all Cartan types. The `__call__` method is the sole entry point for constructing any Lie algebra type — it parses a string like `"E6"`, checks rank-range conditions per series (e.g. E requires 6≤n≤8, F requires n==4, G requires n==2), and dispatches to the appropriate `type_*.py` class. **Known bug**: only negative ranks raise `ValueError`; an out-of-range but non-negative rank for exceptional types (e.g. E5, F3, G4) silently falls through all conditionals and returns `None` instead of raising an error. When the issue is about the factory returning `None` or failing to error on invalid type/rank combinations, this is the target file. |
| `cartan_matrix.py` | Provides the `CartanMatrix` convenience function that returns the Cartan matrix for a given Lie algebra type string. |
| `dynkin_diagram.py` | Provides the `DynkinDiagram` convenience function that returns the ASCII Dynkin diagram for a given Lie algebra type string. |
| `root_system.py` | Implements the `RootSystem` class representing the root system of a simple Lie algebra. Key method `all_roots` builds the complete root set (positive and negative) by fetching the positive-roots dictionary from the type class, snapshotting its keys into a list to avoid infinite iteration, then appending negated copies with new integer keys — this is where positive-to-negative root generation and dictionary-mutation-during-iteration safety logic lives. Also provides simple root enumeration, root addition, Cartan matrix, and Dynkin diagram delegation. |
| `type_a.py` | `TypeA(Standard_Cartan)` -- series A (sl/su), the first series in the classification of simple Lie algebras: `positive_roots` enumerates all positive roots by iterating over ordered pairs (i,j) with 0≤i<j≤n, creating vectors with +1 at position i and -1 at position j via `basic_root(i,j)`, stored in a dict keyed by sequential integers (n*(n+1)/2 total); also provides simple roots, Cartan matrix, Dynkin diagram, and basis count for A_n. |
| `type_b.py` | `TypeB(Standard_Cartan)` -- series B (B_n) Lie algebras; `lie_algebra()` returns `"so(2n)"` (same string as type_d — distinguish by root structure, not label). Key distinguishing feature: the **last simple root** (index == rank) is a **lone unit vector** `[0,…,0,1]` — only a +1 in the final position with NO -1, fundamentally different from the preceding n-1 difference-vector roots that follow the A-series `(+1,-1)` pattern. When a problem asks about the last/nth simple root being a single unit vector in the orthogonal series, this is the target file. `positive_roots` generates **three** kinds of roots — e_i-e_j (difference), e_i+e_j (sum), **and** standalone unit vectors e_i; Cartan matrix has asymmetric boundary entry (-2 vs -1); Dynkin diagram with `=>=` double bond. |
| `type_c.py` | `TypeC(Standard_Cartan)` -- series C (sp) Lie algebras: root system data, Cartan matrix, and Dynkin diagram for C_n. |
| `type_d.py` | `TypeD(Standard_Cartan)` -- series D (D_n) Lie algebras; `lie_algebra()` also returns `"so(2n)"` (same string as type_b — distinguish by root structure, not label). Defines root system data only (root vectors, not reflection matrices). Key distinguishing feature: the **last simple root** (index == rank) is a **sum vector** `[0,…,0,1,1]` with +1s in **both** of the last two positions (branching node in D_n) — contrast with type_b where the last root is a lone unit vector `[0,…,0,1]`. `positive_roots` generates only **two** kinds of roots — e_i-e_j (difference) and e_i+e_j (sum), with NO standalone unit vector roots (unlike B-series which has three kinds); Cartan matrix, and branched Dynkin diagram. Does not contain Weyl group reflection matrices or matrix representations of generating reflections. |
| `type_e.py` | `TypeE(Standard_Cartan)` -- exceptional series E (E6, E7, E8), ranks 6–8: structural/algebraic data only (root vectors, Cartan matrix, Dynkin diagram) — does NOT contain Weyl/reflection group computations (those live in `weyl_group.py`). Constructor has a secondary rank validation but is only reached if `cartan_type.py`'s factory dispatches to it. 8-dimensional root vectors with half-integer components; `simple_root` dispatches by index; `positive_roots` has separate branches for n=6, 7, 8 each building combinatorial half-integer roots; Cartan matrix and branched Dynkin diagram. |
| `type_f.py` | `TypeF(Standard_Cartan)` -- exceptional Lie algebra F4, the unique rank-4 exceptional type: fixed dimension 4; `basic_root(i, j)` generates 4-dimensional difference vectors (+1 at i, -1 at j); `simple_root(i)` has three branches — for i<3 calls `basic_root` (note: missing `self.` prefix is a known bug causing NameError), i==3 returns unit vector, i==4 returns all-halves vector; `positive_roots` builds difference, sum, unit, and half-integer root vectors in 4D; Cartan matrix with asymmetric `=>=` double bond; Dynkin diagram. |
| `type_g.py` | `TypeG(Standard_Cartan)` -- exceptional Lie algebra G2 (rank-2, 3-dimensional root vectors): static structural data only — `simple_root`, `positive_roots` (short and long roots in 3D), Cartan matrix with asymmetric triple-bond entry, and Dynkin diagram. Contains no Weyl group or element-order logic. |
| `weyl_group.py` | `WeylGroup` class — the ONLY file for Weyl/reflection group computations (group size, element order, Coxeter diagrams, matrix representations): `group_order` computes the order of the Weyl group using series-specific conditional branches — formulaic for A/B/C/D (e.g. `(n+1)!`, `n!·2^n`) but hardcoded constants for each exceptional rank (E6→51840, E7→2903040, E8→696729600, F4→1152, G2→12), so an unrecognized rank falls through all conditionals and returns `None`; `element_order` computes individual element orders with series-specific algorithms — most series (A, D, E, F, B, C) use matrix power iteration (`matrix_form` raised until identity), but G2 uniquely avoids matrices and instead uses `delete_doubles` to iteratively reduce adjacent duplicate simple reflections in the word, then computes order from the reduced word length via an LCM formula involving 6 (the dihedral group order divided by 2); `coxeter_diagram` (the undirected graph of generating relations — delegates to the directed Dynkin diagram for simply-laced types A/D/E since removing arrows is a no-op, but constructs custom string diagrams with double/triple edges for non-simply-laced B/C/F/G); and `matrix_form`, which builds the standard **matrix representation** for each generating reflection with series-specific construction logic — for D-series, generators with index < rank are simple coordinate transpositions (swap rows/cols with +1 off-diagonal), but the last generator (index == rank) uniquely uses **negative off-diagonal entries** (-1) in the last two rows/columns instead of positive ones; for G/F/E series, generators use special rational-entry matrices (e.g. half-integer matrices for F4 and E-series). |
