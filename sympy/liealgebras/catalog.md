# sympy/liealgebras — Lie Algebras

Implements the classification of simple Lie algebras via Cartan types (A–G), their root systems, Cartan matrices, Dynkin diagrams, and Weyl groups.

## Glossary

- **Cartan type** — A letter (A–G) + rank classifying a simple Lie algebra.
- **Simple root** — An element of a minimal spanning subset of the root system.
- **Positive root** — A root expressible as a non-negative linear combination of simple roots.
- **Cartan matrix** — Square matrix encoding inner products between simple roots; determines the Lie algebra up to isomorphism.
- **Dynkin diagram** — Graph encoding the Cartan matrix; nodes = simple roots, edges = inner-product relations.
- **Weyl group** — Finite reflection group generated by reflections through hyperplanes orthogonal to simple roots.

---

## Core Infrastructure

### `__init__.py`
Re-exports `CartanType` from `cartan_type.py`. No other content.

### `cartan_type.py`
Factory and base class for Cartan type objects.

- **`CartanType_generator`** — Callable that parses a string like `"A4"` or list `['B', 3]` and returns the appropriate `Type{A..G}` instance. Validates rank constraints per series. Instantiated as the module-level singleton `CartanType`.
- **`Standard_Cartan`** — Base class for all concrete Cartan types (A–G). Stores `series` (letter) and `n` (rank). Provides `rank()` and `series()` accessors.

## Cartan Type Series

All type classes subclass `Standard_Cartan` and implement a uniform interface:
`dimension()`, `simple_root(i)`, `positive_roots()`, `roots()`, `highest_root()` (A only), `cartan_matrix()`, `basis()`, `lie_algebra()`, `dynkin_diagram()`.

Only deviations or notable details are called out below.

### `type_a.py`
Type A_n — corresponds to su(n+1). Rank n ≥ 1.

- `dimension()` → n+1 (one larger than rank).
- `basic_root(i, j)` — helper: vector with +1 at i, −1 at j.
- `positive_roots()` — all e_i − e_j for i < j; count = n(n+1).
- `highest_root()` → e_0 − e_n.

### `type_b.py`
Type B_n — corresponds to so(2n). Rank n ≥ 2.

- `dimension()` → n.
- Simple roots: first n−1 same as A_{n−1}; the nth root is the unit vector e_{n−1}.
- Positive roots include both e_i − e_j and e_i + e_j, plus unit vectors e_i; count = 2n².

### `type_c.py`
Type C_n — corresponds to sp(2n). Rank n ≥ 3.

- `dimension()` → n.
- nth simple root has a 2 in the last position (long root).
- Positive roots include e_i ± e_j and 2·e_i; count = 2n².
- Cartan matrix: last off-diagonal entry is −2 (swapped vs B_n).

### `type_d.py`
Type D_n — corresponds to so(2n). Rank n ≥ 3.

- `dimension()` → n.
- nth simple root: e_{n−2} + e_{n−1} (differs from A/B/C pattern).
- Dynkin diagram has a fork at the (n−2)th node.
- Positive roots: e_i ± e_j for i < j; count = 2n(n−1).

### `type_e.py`
Type E_n for n ∈ {6, 7, 8}. Fixed dimension 8 for all three.

- `simple_root(i)` — root 1 uses half-integer coordinates; root 2 is e_0 + e_1; roots 3+ follow the standard basis-difference pattern.
- `positive_roots()` — enumerates roots via brute-force nested loops over ±½ coordinate combinations with a parity constraint. Separate branches for E6/E7/E8.
- `basis()` → 78 / 133 / 248; `roots()` → 72 / 126 / 240.

### `type_f.py`
Type F_4 — fixed rank 4 only.

- `dimension()` → 4.
- 4th simple root: (−½, −½, −½, −½).
- Positive roots include half-integer coordinate roots alongside standard basis roots; 48 total.

**Caveat:** `simple_root()` calls bare `basic_root(...)` instead of `self.basic_root(...)` for i < 3 — this is a bug and will raise `NameError` at runtime.

### `type_g.py`
Type G_2 — fixed rank 2, dimension 3.

- Simple roots and positive roots are hardcoded (only 6 positive roots, 12 total).
- Cartan matrix: off-diagonal entries −1 and −3.
- Dynkin diagram uses triple-edge Unicode: `0≡<≡0`.

## Root Systems

### `root_system.py`
High-level `RootSystem` class — wraps a Cartan type and provides root-system operations.

- **`simple_roots()`** — collects all simple roots from the underlying type into a dict `{1: ..., n: ...}`.
- **`all_roots()`** — positive roots ∪ their negations.
- **`root_space()`** — returns a string representation of the root space as `"alpha[1] + ... + alpha[n]"`.
- **`add_simple_roots(root1, root2)`** — component-wise addition of two simple roots by index.
- **`add_as_roots(root1, root2)`** — adds two root vectors; returns the sum only if it is itself a root.
- **`cartan_matrix()`** / **`dynkin_diagram()`** — delegates to the underlying Cartan type.

## Weyl Groups

### `weyl_group.py`
`WeylGroup` class — represents the Weyl group of a simple Lie algebra.

- **`generators()`** — returns `['r1', ..., 'rn']`, the named generating reflections.
- **`group_order()`** — computes |W| by formula per series (e.g. (n+1)! for A_n, n!·2^n for B/C_n). Uses `mpmath.fac`.
- **`group_name()`** — human-readable description (e.g. "S5: the symmetric group acting on 5 elements" for A4).
- **`element_order(weylelt)`** — order of an element given as a product string like `'r1*r4*r2'`:
  - For most types: computes the matrix representation, then iterates M^k until identity.
  - For G_2: uses a combinatorial reduction via `delete_doubles()` and LCM-based formula.
- **`delete_doubles(reflections)`** — helper for G2: removes adjacent duplicate reflections from a list.
- **`matrix_form(weylelt)`** — converts a product-of-reflections string into an explicit matrix. Contains hardcoded generating matrices for each series (permutation matrices for A/D, sign-change matrices for B/C, rational-entry matrices for E/F/G).
- **`coxeter_diagram()`** — undirected version of the Dynkin diagram (arrows removed). Delegates to `dynkin_diagram()` for simply-laced types (A, D, E).

## Convenience Functions

### `cartan_matrix.py`
`CartanMatrix(ct)` — shorthand to get the Cartan matrix for a Cartan type string/list. Delegates to `CartanType(ct).cartan_matrix()`.

### `dynkin_diagram.py`
`DynkinDiagram(t)` — shorthand to get the Dynkin diagram string. Delegates to `CartanType(t).dynkin_diagram()`.

## Appendix

- **Bug in `type_f.py`:** `simple_root()` for i < 3 calls `basic_root(i-1, i)` without `self.`, which will raise `NameError`.
- **`group_order()` returns float:** because `mpmath.fac` returns a float, not an integer.
- **Copy-paste docstrings:** several `positive_roots()` methods in type_b through type_g have docstrings referring to "A_n" rather than the actual series — the code is correct, only the docs are misleading.
