> Part of [SymPy](../catalog.md). Symbolic integration: definite/indefinite integrals, transforms (Laplace, Fourier, Mellin), and the Risch algorithm.

| `__init__.py` | Package init; exports `integrate`, `Integral`, `line_integrate`, and all integral transform functions. |
| `integrals.py` | **Top-level integration entry point for the entire system.** The `integrate` function is the public API that users call for all definite and indefinite integration — it parses arguments, extracts keyword options (risch, meijerg, manual, conds), and delegates to `Integral.doit()`. Its docstring documents the complete strategy ordering the system uses when attempting integration. Also contains the `Integral` class (unevaluated integral representation) and `line_integrate`. `Integral.doit` is the evaluation method for definite and indefinite integrals — it iterates over integration limits, tries multiple strategies (including Meijer G-function definite integration via `meijerint_definite`), and handles the `conds` parameter for convergence conditions. Importantly, `Integral.doit` contains the meijerg fallback/give-up policy: for integrals with infinite bounds, it first tries `try_meijerg`; if that fails and the user explicitly requested only Meijer G methods (`meijerg=True`), it sets `antideriv = None` and gives up entirely rather than falling back to other techniques — this give-up decision lives here in `doit`, not in `meijerint_definite` or `meijerint.py`. Critically, `Integral.doit` contains nested-limit dependency detection: when evaluating multi-variable (nested) definite integrals, it tracks which limits have been left unevaluated ("undone") and checks whether the current limit's bounds contain free symbols from any undone limit's integration variable (or vice versa) — if such a dependency exists, the current limit is also left unevaluated ("blocked") to prevent incorrect evaluation when inner integration variables appear in outer bounds; it accumulates the free symbols of all undone limits' bounds in a set (`ulj`) and wraps blocked limits back into unevaluated `Integral` objects. This nested-limit blocking logic is specific to `Integral.doit` in this file — it does NOT exist in transform classes (those live in `transforms.py`). Also provides: `transform` (u-substitution on definite integrals), `_eval_derivative` (differentiation of integrals), `as_sum` (Riemann sum approximation with symbolic `limit()` at boundary points), and `_eval_integral` (strategy dispatcher that enforces a deliberate ordering: first polynomial fast-paths, then the full Risch decision procedure (`risch_integrate`) on the entire unsplit expression, and only afterward does it split sums into individual addends for term-wise integration — this ordering is intentional because `Integral(g1+g2)` may be computable even when `Integral(g1)+Integral(g2)` is not, so term-splitting is a last-resort fallback; within the per-term loop it tries trigonometric integration, delta/singularity integration, manual integration, Meijer G-functions, and heuristic Risch, with fallback re-evaluation of partial results); crucially, when all strategies fail for a single-term expression (`len(args) == 1`), a last-resort step expands the product via `f.expand(mul=True, deep=False)` and recursively retries if the result becomes a sum — this expansion is intentionally deferred (not done at the outset) because some expressions like `x**x*(1+log(x))` can only be integrated in unexpanded form. Note: piecewise/conditional handling for integral *transforms* (Laplace, Fourier, sine, cosine, Hankel) is NOT here — that logic lives in `transforms.py`. |
| `risch.py` | Implementation of the Risch algorithm — the deterministic decision procedure for integrating transcendental functions (exponentials and logarithms). Contains `integer_powers` which groups a list of expressions into clusters where each member is a rational multiple of a shared base, then normalizes the rational multiples into the smallest possible integer factors by computing the LCM of denominators — this is used to rewrite sums of exponentials (e.g., exp(x) + exp(x/2)) as powers of a single base exponential, avoiding algebraic extensions. The Risch-specific entry point `risch_integrate` (called as one sub-strategy by `integrate` in `integrals.py`) orchestrates the Risch algorithm process: it builds a tower of differential extensions, then iterates through extension levels in reverse order, calling appropriate sub-procedures (hyperexponential, primitive, or base-case) at each level, and either produces a closed-form elementary antiderivative or proves one does not exist. Also defines `NonElementaryIntegral` (subclass of `Integral`) to represent integrals proven to be non-elementary, and `DifferentialExtension` whose `__init__` constructs the transcendental extension tower by iteratively processing exp, log, and power sub-expressions; `DifferentialExtension` also provides `increment_level` and `decrement_level` methods to grow or shrink the working extension — `increment_level` raises `ValueError` when the level is already at maximum (-1), and `decrement_level` raises `ValueError` when it is already at minimum (-len(T)) — it classifies power expressions into numeric-base vs symbolic-base categories, converts non-base-E powers to exp(b*log(a)) form, and raises `NotImplementedError` for algebraic extensions (e.g., `x**(3/2)` where the base depends on the integration variable and the exponent is a non-integer rational). Contains `hermite_reduce` (Mack's Linear Version of Hermite Reduction for differential extensions) which decomposes a rational function f = a/d in k(t) into f = Dg + h + r where g is an exact derivative, h is simple (normal denominator), and r is reduced (special denominator) — this iteratively reduces the multiplicity of repeated denominator factors using extended GCD computations within the differential extension context. Also contains `canonical_representation` (splits a rational function in k(t) into polynomial + reduced + simple parts) and `polynomial_reduce` (writes p = Dq + r with deg(r) < deg(Dt)). Contains polynomial utility helpers: `gcdex_diophantine` (Extended Euclidean Algorithm, Diophantine version — solves s*a + t*b == c and reduces s modulo b when s.degree() >= b.degree(); contains a degree-comparison condition between the quotient polynomial s and the second argument b), `frac_in`, and `as_poly_1t`. Contains `recognize_log_derivative` — a pure boolean (True/False) predicate for the Risch algorithm's internal use, testing whether a rational function f in the differential extension tower is a logarithmic derivative (f = dv/v for some v in the extension field); it works by computing the Rothstein-Trager resultant between the squarefree denominator and a modified numerator (a - z*Dd), then checking whether all real roots of the resultant's special factor are integers — if any non-integer root exists, it returns False; this is an algebraic structural test within the Risch framework, unrelated to output formatting or real-vs-complex form decisions (for real/complex form of rational integration output, see `ratint` in `rationaltools.py`). Contains `residue_reduce` implementing the Lazard-Rioboo-Rothstein-Trager resultant reduction for computing the logarithmic part of antiderivatives of transcendental functions within the differential extension tower k(t) — this operates on rational functions in the extension field, not on plain polynomial-ring rational functions. Contains `integrate_primitive_polynomial` which integrates polynomials in a primitive (logarithmic) extension tower — it uses an iterative loop that peels off the leading coefficient at each step, calls `limited_integrate` at a decremented extension level to integrate the coefficient, accumulates the antiderivative terms, and subtracts the derivation to reduce the polynomial's degree; the loop terminates when the remainder has no terms in the extension variable (success) or when `limited_integrate` raises `NonElementaryIntegralException` (proving non-elementarity). Contains `integrate_primitive` which handles the full integration pipeline for primitive (logarithmic-type) extension fields — it chains together `hermite_reduce`, `residue_reduce`, and `integrate_primitive_polynomial` in sequence: first Hermite reduction decomposes the integrand, then residue reduction computes the logarithmic part; if the residue step indicates non-elementarity (`b` is False), it wraps the remainder as a `NonElementaryIntegral` proven to have no elementary antiderivative; if elementarity holds, it combines the results and calls `integrate_primitive_polynomial` on the polynomial remainder (see above), with a TODO noting incorrect behavior in the polynomial non-elementary fallback case; performs variable substitution back to original variables using the reversed extension tower. Contains `integrate_hyperexponential` which integrates functions in hyperexponential (exp-type) extension fields — it handles the edge case where the exponential term might equal 1 (exponent is zero) by producing a `Piecewise` expression: one branch substitutes the extension generator with 1 and integrates directly, the other uses the quotient as-is. Also contains `integrate_hypertangent_polynomial` for tangent-type extensions. Contains `get_case` which classifies the type of a derivation polynomial into one of {'exp', 'tan', 'base', 'primitive', 'other_linear', 'other_nonlinear'} — when the derivation doesn't involve the extension variable t, it further distinguishes 'base' (derivation is identically 1, meaning the ground field level) from 'primitive' (any other constant derivation, meaning a logarithmic extension); when it does involve t, it checks divisibility by t (exp), by 1+t² (tan), or classifies by degree. Also contains `derivation` which computes Dp for a polynomial p in the differential extension tower, with an optional `coefficientD` mode that differentiates only w.r.t. lower-level extensions treating the top variable as constant. |
| `rde.py` | Algorithms for solving the Risch Differential Equation (Dy + f*y == g), used as a sub-problem solver by the Risch algorithm. Contains `weak_normalizer` which is a preprocessing step for the Risch DE solver (not a logarithmic-derivative test and not a resultant-integrality decision procedure) — it constructs a correction factor q so that f - Dq/q is weakly normalized for subsequent Risch DE solving; it only looks at positive integer roots (not all roots) and uses them to build the correction polynomial, unlike the true logarithmic-derivative tests in `risch.py` (`recognize_log_derivative`) and `prde.py` (`is_log_deriv_k_t_radical_in_field`) which check whether ALL resultant roots satisfy integrality/rationality conditions as a yes/no decision. Contains the 5-step pipeline: normal denominator, special denominator (`special_denom` — handles 'exp', 'tan', 'primitive'/'base' cases for non-parametric RDEs; for 'primitive'/'base' it returns `(a, B, C, 1)` immediately — a trivial identity transform with `h=1` — completely bypassing the order-at computations and cancellation-checking logic that the 'exp' and 'tan' cases require), degree bounding (`bound_degree`), polynomial reduction (`spde`), and bounded-degree polynomial solving (`solve_poly_rde`). `solve_poly_rde` is the main dispatcher for step 4/5: it routes to different sub-algorithms based on whether `b` is zero and the degree relationship between `b` and the derivation `D` — specifically comparing `b.degree(t)` against `D.degree(t) - 1` to choose between `no_cancel_b_large` (when `b` has large degree or base case) and `no_cancel_b_small` (when `b` has small degree); the small-b path may return a triple `(h, b0, c0)` triggering a recursive call at a decremented extension level. `solve_poly_rde` also contains the cancellation-case dispatch: when cancellation applies and `b` is non-zero, it checks `DE.case` to route to `cancel_exp` (hyperexponential) or `cancel_primitive` (primitive/logarithmic), with a fallback `NotImplementedError` for other extension types. Also contains the cancellation-case solver implementations: `cancel_primitive` and `cancel_exp`. |
| `prde.py` | Algorithms for solving the Parametric Risch Differential Equation (Dy + f*y == Sum(ci*gi)), paralleling `rde.py` with parametric variants of each pipeline stage. Contains `prde_normal_denom` (normal denominator computation) and `prde_special_denom` (special denominator computation — handles 'exp', 'tan', 'primitive'/'base' cases; for 'primitive'/'base' it short-circuits by returning `(a, ba.quo(bd), G, 1)` without computing order at the special polynomial or checking for cancellation, since k<t> == k[t] in the primitive case; for 'exp'/'tan' it computes order bounds and checks for possible cancellation via `parametric_log_deriv`). Also contains a helper for extracting real and imaginary parts of a rational function evaluated at sqrt(-1) without performing the substitution — it classifies each term by its power degree modulo 4 to assign signs. Also contains `prde_spde` (Special Polynomial Differential Equation — parametric version), `prde_no_cancel_b_large` (parametric no-cancellation solver when deg(b) is large enough — iterates from degree n down to 0 inclusive), and `prde_no_cancel_b_small` (parametric no-cancellation solver when deg(b) < deg(D)-1 — iterates from degree n down to 1 only, with separate handling when deg(b) > 0; raises `NotImplementedError` when deg(b) <= 0 because a recursive call is not yet implemented). Also contains `is_deriv_k` which checks whether Df/f is the derivative of an element of k(t) using the structure theorem approach — it decomposes the problem into a linear system over logarithmic and hyperexponential monomials in the extension tower, solves for rational constant coefficients, and determines whether a candidate logarithmic monomial is algebraically dependent on existing ones (used during construction of differential extension towers to avoid introducing unnecessary transcendental elements). Also contains `constant_system` which enforces that solutions of a linear system over a differential field lie in the constant subfield — after RREF, it differentiates rows whose entries depend on the extension variable to generate additional constraint rows. Also contains `prde_linear_constraints` for generating linear constraints on constant parameters, `limited_integrate` / `limited_integrate_reduce` for the limited integration problem (f = Dv + Sum(ci*wi)) — `limited_integrate` builds a constant-coefficient system matrix via `prde_linear_constraints` and `constant_system`, computes its nullspace, and branches on the number of basis vectors: zero vectors → `NonElementaryIntegralException`; exactly one vector → normalizes the first entry to 1 and solves a standard Risch DE with the pre-computed denominator and degree bound (if the first entry is zero, raises `NonElementaryIntegralException`); multiple vectors → falls back to the full parametric solver `param_rischDE`, `parametric_log_deriv_heu` which is a heuristic for solving the equation n*f == Dv/v + m*Dθ/θ where θ is a hyperexponential monomial — it computes degree bounds from the derivation, solves for a rational constant relating leading coefficients, then checks if the resulting combination is a logarithmic derivative of a radical; returns None if no solution exists, or a triple (n, m, v) on success, and raises NotImplementedError if the heuristic fails (requiring the structure theorem approach), and `is_log_deriv_k_t_radical` / `is_log_deriv_k_t_radical_in_field` which test whether a rational function is the logarithmic derivative of a radical in a differential extension field — `is_log_deriv_k_t_radical_in_field` calls `residue_reduce` and returns None immediately if residue reduction fails (boolean flag b is False, indicating the function cannot be a log derivative of a radical — this is expected to "never happen" for parametric log derivative problems and likely indicates a bug); also returns None if the resultant roots are not all rational, or if the remainder polynomial after subtracting the residue derivation has degree too high; handles multiple cases ('exp', 'primitive', 'base', 'tan'); in the 'base' case it returns None immediately if the denominator is not square-free or if the numerator degree >= denominator degree. |
| `heurisch.py` | Heuristic (parallel) Risch algorithm for indefinite integration of transcendental elementary and special functions (Airy, Bessel, Whittaker, Lambert); provides `heurisch` and `heurisch_wrapper` along with the `components` helper. The `heurisch` function constructs a polynomial ansatz with undetermined coefficients: it computes a degree bound for the trial polynomial by analyzing the integrand's exponent structure — for fractional (rational) exponents p/q, it uses different formulas for positive vs negative rational powers (p+q-1 for positive, |p+q| for negative) to determine how many monomials to generate, then solves a linear system for the unknown coefficients. Also constructs a candidate antiderivative combining the polynomial part with a logarithmic part built from irreducible factors. Includes `DiffCache`, a derivative store for the parallel Risch algorithm, whose `get_diff` method has a key side effect: when a cylindrical function (Bessel, Hankel, spherical Bessel) of order n is encountered and its type is found in the precomputed `BesselTable`, `get_diff` not only caches the derivative of the requested function f(n, z) but also proactively caches the derivative of the adjacent-order function f(n-1, z) — this ensures both derivatives are expressed in terms of the algebraically independent pair {f(n), f(n-1)} rather than the standard three-term recurrence form. |
| `manualintegrate.py` | Integration method emulating by-hand techniques with step-by-step rules (namedtuples); provides `integral_steps` and `manualintegrate`. Rules decompose an integrand into named computation steps (e.g., `SubstitutionRule`, `PartsRule`, `PowerRule`, `ExpRule`, `PiecewiseRule`, `DerivativeRule`) for solving integrals. Also contains `substitution_rule` which performs u-substitution and handles a subtle edge case: when the scaling coefficient's denominator contains free symbols that could potentially be zero, it constructs a `PiecewiseRule` with separate branches for each possibly-zero factor (integrating with that factor set to zero) plus a default branch — this ensures correctness when certain parameter values would cause the substitution's scaling factor to blow up. Also contains rule evaluators (functions decorated with `@evaluates`) that execute each rule type — notably `eval_trigsubstitution` performs the geometric back-substitution for `TrigSubstitutionRule`: after computing the antiderivative in the angle parameter, it converts back to the original variable by solving for the trig function, computing triangle sides (opposite, adjacent, hypotenuse) from the numerator/denominator of the solved relation, then substituting all sin/cos/tan of the angle with ratios of triangle sides and the angle itself with the corresponding inverse trig function. Also `eval_derivativerule` handles integration of `Derivative` expressions: when the derivative has exactly one differentiation variable it returns the inner expression directly (fundamental theorem of calculus), otherwise it strips the last variable to reduce the derivative order by one. This is a downstream strategy called by `_eval_integral` in `integrals.py` — the core conditional power-rule logic (linear base with symbolic exponent, log vs power rule ambiguity) lives in `integrals.py`, not here. Contains dedicated trig power/product integration rules dispatched via `trig_powers_products_rule`: `trig_sincos_rule` (sin^m * cos^n products), `trig_tansec_rule` (tan^m * sec^n products), and `trig_cotcsc_rule` (cot^m * csc^n products). Each rule first applies preprocessing substitutions to normalize the integrand before pattern matching — e.g., `trig_tansec_rule` substitutes 1/cos→sec, while `trig_cotcsc_rule` substitutes 1/sin→csc, 1/tan→cot, and cos/tan→cot — then matches against a canonical pattern and dispatches to sub-cases based on parity/value of the exponents (e.g., odd-power, even-power conditions). These manual trig rules handle the full range of trig functions (tan, sec, cot, csc) with preprocessing, unlike `trigonometry.py` which only handles sin/cos products. Also contains `root_mul_rule` for integrating products of the form sqrt(a*x+b)*c via u-substitution (u = sqrt(a*x+b)) — includes an explicit infinite-recursion guard: before substituting, it checks whether the cofactor `c` itself matches sqrt(d*x+e)*f, and if so returns None to prevent the substitution from repeatedly matching the same sqrt-of-linear pattern. Also contains `quadratic_denom_rule` for a/(b*x²+c) integrands dispatching to arctan/arctanh/arccoth rules. |
| `meijerint.py` | Integration by rewriting integrands as Meijer G-functions (also known as Fox H-function family); exposes `meijerint_indefinite`, `meijerint_definite`, and `meijerint_inversion`. For indefinite integration (antiderivatives), `_meijerint_indefinite_1` rewrites the integrand as a G-function, shifts its parameters by the exponent (rho) to absorb the power-of-variable factor, then computes the antiderivative by prepending extra index parameters (0 and 1) to the G-function — the key decision is which arrangement to use: it checks whether the shifted lower parameters (`bm` after adding rho+1) contain non-positive integers, and if so swaps which parameter list gets the extra 0 vs 1 to avoid producing an ill-defined function. This is the low-level G-function computation backend — it does not define transform classes, orchestrate fallback strategies, or handle transform-specific error logic; in particular, `meijerint_inversion` only computes and returns the raw G-function inversion result (which may be a `Piecewise`) but does NOT inspect that result for unevaluated `Integral` objects or raise errors — that post-processing is done by the calling code in `transforms.py`. `meijerint_inversion` (inverse Laplace transform) pre-processes multiplicative integrands by filtering out exponential and power factors (e.g., `exp(a*x)` or `base**x`) and accumulating them into a cumulative shift value — power expressions are converted via logarithm (`a*log(base)`) — then after computing the core G-function inversion, it applies this shift to the time variable (`t + shift`) in the final result, effectively converting multiplicative exponential factors into a time-domain translation; for each factor it calls `_get_coeff_exp` to extract a linear coefficient in the integration variable — if extraction fails (raises `_CoeffExpValueError`, meaning the exponent is not of the form `a*x`), it silently falls back by setting `b=0`, treating the factor as non-exponential rather than raising an error. For Laplace inversion (`meijerint_inversion`), contains `_check_antecedents_inversion` which verifies convergence conditions for the Laplace inversion integral of a Meijer G-function — when the argument's exponent with respect to the integration variable is negative, it flips the G-function (via `_flip_g`) and recurses so the argument grows as |x| → ∞; also computes epsilon with a three-way branch based on q-p (sigma). Contains `_rewrite_inversion` to absorb x**s into the G-function parameters, and `_int0oo` for expressing zero-to-infinity integrals of G-function products. Contains `_condsimp` which performs ad-hoc boolean simplification of convergence conditions arising from G-function rewriting — it iteratively applies wildcard pattern-matching rules to combine strict-less-than with equality into non-strict inequality (e.g., `Or(p < q, Eq(p, q))` → `p <= q`), absorb weaker conditions into stronger ones, and convert equality conditions on `unbranched_argument`/`polar_lift` expressions into positivity constraints (e.g., `Eq(arg(polar_lift(p)**q), 0)` → `p > 0`). Contains the `_has` helper for checking whether integration results contain unresolved special functions — for Piecewise results it requires all branches to contain the target, not just any branch. Also contains a large lookup table (`_create_lookup_table`) mapping elementary/special functions to their Meijer G-function representations, product decomposition utilities (`_mul_as_two_parts`, `_mul_args`), and `_split_mul` which separates a multiplicative integrand into three factors: a constant coefficient, a pure power-of-variable term (x**s), and the remaining terms — it calls `expand_power_base` then iterates over multiplicative arguments, and for powers like `(c*x)**s` it extracts the numeric coefficient via `as_coeff_mul` and uses `polarify`/`unpolarify` to compute `c**s` cleanly, placing the coefficient part into fac and the variable power into po (not related to trig-to-gamma rewriting — that lives in `transforms.py`). `meijerint_definite` handles definite integration using a multi-stage pipeline: expansion/simplification, G-function rewriting, and a linearity fallback for sums; it immediately gives up (returns None) if the integrand contains `DiracDelta` or `SingularityFunction` terms, since these impulse/singularity distributions cannot be rewritten as G-functions; it also substitutes a fresh dummy symbol for the integration variable before proceeding, to avoid conflicts when the original variable appears in the integration bounds. |
| `meijerint_doc.py` | Auto-generates a Sphinx docstring listing all Meijer G-function lookup table entries for documentation purposes. |
| `transforms.py` | Unevaluated class representations, dispatch entry points, and backend computation functions for all integral transforms: Mellin, inverse Mellin, Laplace, inverse Laplace, Fourier, inverse Fourier, sine, cosine, and Hankel. Backend functions (e.g. `_inverse_laplace_transform`) contain the multi-strategy orchestration logic — for inverse Laplace, it first tries inverse Mellin transforms (change of variables), then falls back to `meijerint_inversion` from `meijerint.py`; after each fallback, it inspects the result and raises `IntegralTransformError` if a piecewise result's first branch still contains an unevaluated `Integral` (indicating an inversion integral of unrecognised form), with piecewise simplification at each stage. `InverseMellinTransform._compute_transform` validates input expressions against a whitelist of recognized functions (exp, gamma, sin, cos, tan, cot, cosh, sinh, tanh, coth, factorial, rf) before computing — any function depending on the transform variable that is not in this whitelist raises `IntegralTransformError`. `_sine_cosine_transform` computes half-line sine/cosine-kernel integrals and includes piecewise result validation: if the symbolic integration returns a `Piecewise`, it extracts the first branch and raises `IntegralTransformError` if that branch still contains an unevaluated `Integral`. `_hankel_transform` computes Bessel-function-based Hankel transforms using `besselj(nu, k*r)*r` kernels and has its own three-way error handling: if the result has no unevaluated `Integral` it returns directly; if it is not `Piecewise` it raises `IntegralTransformError('could not compute integral')`; if it IS `Piecewise` and the first branch still contains an unevaluated `Integral`, it raises `IntegralTransformError('integral in unexpected form')`. Also contains `_simplifyconds` for simplifying convergence conditions, `_rewrite_sin` which converts a sine function into a pair of gamma functions using the reflection formula `pi/sin(pi*x) = gamma(x)*gamma(1-x)` — it computes an integer shift via `ceiling()` to ensure the resulting gamma function arguments don't create poles inside the integration contour, and deliberately uses `as_real_imag()[0]` instead of `re()` because the latter does not expand correctly for the needed computation — and `_rewrite_gamma` which converts gamma-function products into Meijer G parameters for the inverse Mellin transform — crucially contains a nested `left` helper that determines whether each singularity (pole) lies to the left of the fundamental strip (integration contour) using heuristic inequality checks on the strip boundaries `a` and `b`: when both boundaries are unspecified or infinite it defaults to left, when one boundary is None it compares the pole against the known boundary; has asymmetric behavior for numerator vs denominator factors — when the pole position relative to the strip cannot be determined, numerator factors return None (indeterminate), while denominator factors also return None if strip boundaries or pole location contain symbolic free variables but raise `MellinTransformStripError('Pole inside critical strip?')` otherwise — it factorizes polynomial factors in the integrand by finding roots: for polynomials of degree > 1 it first tries `roots()` and falls back to `CRootOf.all_roots()` when not all roots are found, then decomposes each root into a gamma-compatible `(s - c)` factor; also includes validation that numerator gamma poles do not partially extend into the fundamental strip (raises `NotImplementedError` for partial overlap), rewriting of trig factors as gamma pairs (tan(a) is decomposed as sin(a)/sin(π/2−a), cos and cot similarly reduced to sine form, then each sine rewritten via the gamma reflection formula), and a multiplication theorem step that handles gamma functions whose coefficient on the integration variable has magnitude != 1 (e.g., Gamma(2*s+c)) by splitting them into multiple unit-coefficient gamma terms — this step requires the coefficient to be an integer and raises `TypeError` if it is not (e.g., Gamma(sqrt(2)*s+c)). |
| `trigonometry.py` | Integration of products of sin and cos only (sin(a*x)^n * cos(a*x)^m) via the `trigintegrate` function — uses reduction formulas and half-angle identities; does not handle tan, sec, cot, or csc products (those are in `manualintegrate.py`'s trig power/product rules). |
| `rationaltools.py` | Tools for integrating purely rational functions (polynomials over polynomials in a plain polynomial ring, with no differential extension tower): `ratint` (main entry point — performs indefinite integration of rational functions, including auto-detection of whether to produce real-valued logarithmic output vs complex RootSum expressions: when the `real` flag is not explicitly provided, `ratint` inspects all atoms of the input and checks `is_real` on each; if all non-variable atoms are real, it attempts `log_to_real` conversion and falls back to RootSum if that fails), `ratint_ratpart` (Horowitz-Ostrogradsky algorithm for decomposing a rational integrand f/g into A' + B where A is a rational function and B has a square-free denominator — computes the GCD of the denominator g with its own derivative g' to split g into factors u and v, sets up undetermined polynomial coefficients for the numerators of A and B, forms a constraint equation, and solves the linear system; operates on plain polynomials in k[x], distinct from `hermite_reduce` in `risch.py` which uses iterative extended-GCD within a differential extension tower k(t)), `ratint_logpart` (Lazard-Rioboo-Trager algorithm for the logarithmic part of rational integrals only — computes the resultant of the denominator g and a modified numerator, then performs square-free decomposition of the resultant; for each factor (q, i) in the square-free decomposition, if the degree of g equals the multiplicity i, it takes a shortcut by directly appending (g, q) without normalization, otherwise it performs full leading-coefficient inversion and polynomial quotient normalization; operates on plain polynomials in k[x], not applicable to transcendental function integration in differential extension towers), `log_to_real` (converts complex logarithmic terms from the Lazard-Rioboo-Trager result into real-valued expressions), and `log_to_atan` (converts complex logarithms to arctangent expressions). |

| `rubi/symbol.py` | Defines `matchpyWC` and the `WC` factory for creating MatchPy wildcard symbols compatible with SymPy's `Symbol` class. |
| `rubi/utility_function.py` | Large collection of utility/helper functions used by Rubi rules (predicates, simplifiers, normalizers, trig helpers, etc.) ported from Mathematica. |
| `rubi/parsetools/parse.py` | Parser for Mathematica `FullForm[DownValues[]]` output; converts Mathematica integration rules into MatchPy `ReplacementRule` format. |
| `rubi/rules/binomial_products.py` | Rubi transformation rules for integrands involving binomial product expressions (a + b*x^n)^p. |
| `rubi/rules/trinomial_products.py` | Rubi transformation rules for integrands involving trinomial product expressions (a + b*x^n + c*x^(2n))^p. |
| `rubi/rules/quadratic_products.py` | Rubi transformation rules for integrands involving quadratic product expressions (a + b*x + c*x^2)^p. |
| `rubi/rules/linear_products.py` | Rubi transformation rules for integrands involving linear expressions and basic algebraic forms. |
| `rubi/rules/integrand_simplification.py` | Rubi rules for simplifying integrands before applying other integration rules. |
| `rubi/rules/exponential.py` | Rubi transformation rules for integrands involving exponential functions F^(g*(e+f*x)). |
| `rubi/rules/logarithms.py` | Rubi transformation rules for integrands involving logarithmic functions. |
| `rubi/rules/sine.py` | Rubi transformation rules for integrands involving sine and cosine functions. |
| `rubi/rules/tangent.py` | Rubi transformation rules for integrands involving tangent and cotangent functions. |
| `rubi/rules/secant.py` | Rubi transformation rules for integrands involving secant and cosecant functions. |
| `rubi/rules/hyperbolic.py` | Rubi transformation rules for integrands involving hyperbolic functions (sinh, cosh, tanh, etc.). |
| `rubi/rules/inverse_trig.py` | Rubi transformation rules for integrands involving inverse trigonometric functions (asin, acos, atan, etc.). |
| `rubi/rules/inverse_hyperbolic.py` | Rubi transformation rules for integrands involving inverse hyperbolic functions (asinh, acosh, atanh, etc.). |
| `rubi/rules/piecewise_linear.py` | Rubi transformation rules for integrands involving piecewise-linear functions. |
| `rubi/rules/miscellaneous_algebraic.py` | Rubi transformation rules for miscellaneous algebraic integrands not covered by other rule modules. |
| `rubi/rules/miscellaneous_trig.py` | Rubi transformation rules for miscellaneous trigonometric integrands not covered by the primary trig rule modules. |
| `rubi/rules/miscellaneous_integration.py` | Rubi transformation rules for miscellaneous integration patterns (catch-all rules). |
