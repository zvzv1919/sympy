# sympy/integrals — Catalog

> Part of [SymPy](../catalog.md). Symbolic integration: definite/indefinite integrals, transforms (Laplace, Fourier, Mellin), and the Risch algorithm.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package init; exports `integrate`, `Integral`, `line_integrate`, and all integral transform functions. |
| `integrals.py` | Core `Integral` class (unevaluated integral representation) and the `integrate` / `line_integrate` entry points that dispatch to various integration strategies. `Integral` also provides: the `transform` method for change-of-variables (u-substitution) on definite integrals; `_eval_derivative` for differentiating integrals with respect to variables (applying the Fundamental Theorem of Calculus for indefinite integrals, and using dummy-variable masking for definite integrals); `as_sum` which approximates a definite integral as a finite numerical summation using rectangle-based quadrature methods (left, right, midpoint, trapezoid); and `_eval_integral` which is a dispatcher that tries multiple strategies in sequence (polynomial fast-paths, Risch delegation, sum-of-terms decomposition, manual integration, Meijer G-functions, heuristic Risch) but does not itself implement any algorithm's decision procedure. Key fallback mechanisms in `_eval_integral`: (1) when the Risch algorithm is called with `separate_integral=True` and returns a partially non-elementary result (elementary part + non-elementary remainder), `_eval_integral` recursively evaluates the non-elementary remainder via `.doit(risch=False)` to attempt integration using other strategies; (2) when a downstream strategy (such as manual integration) returns a partial result still containing unevaluated integral sub-expressions, `_eval_integral` re-evaluates those remaining pieces using the other available methods. `_eval_integral` also contains inline pattern-matching rules for simple forms — notably the power rule for `(a*x+b)**c`: when exponent is exactly -1 it returns a logarithm, when the conditions mode is 'piecewise' it returns a `Piecewise` covering both the log case (exponent == -1) and the standard power rule, and otherwise applies the standard power rule directly. |
| `risch.py` | Implementation of the Risch algorithm — the deterministic decision procedure for integrating transcendental functions (exponentials and logarithms). The main entry point `risch_integrate` orchestrates the process: it builds a tower of differential extensions, then iterates through extension levels in reverse order, calling appropriate sub-procedures (hyperexponential, primitive, or base-case) at each level, and either produces a closed-form elementary antiderivative or proves one does not exist. Also defines `NonElementaryIntegral` (subclass of `Integral`) to represent integrals proven to be non-elementary, and `DifferentialExtension` which constructs and manages the tower of extension levels. Contains `hermite_reduce` (Mack's Linear Version of Hermite Reduction for differential extensions) which decomposes a rational function f = a/d in k(t) into f = Dg + h + r where g is an exact derivative, h is simple (normal denominator), and r is reduced (special denominator) — this iteratively reduces the multiplicity of repeated denominator factors using extended GCD computations within the differential extension context. Also contains `canonical_representation` (splits a rational function in k(t) into polynomial + reduced + simple parts) and `polynomial_reduce` (writes p = Dq + r with deg(r) < deg(Dt)). Contains polynomial utility helpers: `gcdex_diophantine`, `frac_in`, and `as_poly_1t`. Contains `residue_reduce` implementing the Lazard-Rioboo-Rothstein-Trager resultant reduction for computing the logarithmic part of antiderivatives of transcendental functions. |
| `rde.py` | Algorithms for solving the Risch Differential Equation (Dy + f*y == g), used as a sub-problem solver by the Risch algorithm. |
| `prde.py` | Algorithms for solving the Parametric Risch Differential Equation (Dy + f*y == Sum(ci*gi)), paralleling `rde.py`. Contains a helper for extracting real and imaginary parts of a rational function evaluated at sqrt(-1) without performing the substitution — it classifies each term by its power degree modulo 4 to assign signs (degree 0: +real, degree 1: +imag, degree 2: −real, degree 3: −imag). Also contains `constant_system` which enforces that solutions of a linear system over a differential field lie in the constant subfield — after RREF, it differentiates rows whose entries depend on the extension variable to generate additional constraint rows. Also contains `prde_linear_constraints` for generating linear constraints on constant parameters, `limited_integrate` / `limited_integrate_reduce` for the limited integration problem (f = Dv + Sum(ci*wi)), and `is_log_deriv_k_t_radical` / `is_log_deriv_k_t_radical_in_field` which use the structure theorem to test whether a derivative is the logarithmic derivative of a radical in a differential extension field. |
| `heurisch.py` | Heuristic (parallel) Risch algorithm for indefinite integration of transcendental elementary and special functions (Airy, Bessel, Whittaker, Lambert); provides `heurisch` and `heurisch_wrapper` along with the `components` helper. Includes a derivative caching mechanism for cylindrical (Bessel-type) functions that simultaneously stores derivatives for adjacent orders (n and n-1) to avoid introducing algebraically dependent transcendentals — this ensures the algorithm's requirement that functions and derivatives are expressed in terms of algebraically independent transcendentals. |
| `manualintegrate.py` | Integration method emulating by-hand techniques with step-by-step rules (namedtuples); provides `integral_steps` and `manualintegrate`. Rules decompose an integrand into named computation steps (e.g., `SubstitutionRule`, `PartsRule`, `PowerRule`, `ExpRule`, `PiecewiseRule`) for solving integrals. This is a downstream strategy called by `_eval_integral` in `integrals.py` — the core conditional power-rule logic (linear base with symbolic exponent, log vs power rule ambiguity) lives in `integrals.py`, not here. |
| `meijerint.py` | Integration by rewriting integrands as Meijer G-functions; exposes `meijerint_indefinite`, `meijerint_definite`, and `meijerint_inversion`. For indefinite integration, `_meijerint_indefinite_1` rewrites the integrand as a G-function, shifts its parameters by the exponent (rho) to absorb the power-of-variable factor, then integrates by prepending index parameters — it selects between two alternative parameter arrangements based on whether certain shifted parameters would be non-positive integers (which would make the function ill-defined). This is the low-level G-function computation backend — it does not define transform classes, orchestrate fallback strategies, or handle transform-specific error logic (the orchestration and fallback logic for inverse transforms lives in `transforms.py`). Contains the `_has` helper for checking whether integration results contain unresolved special functions — for Piecewise results it requires all branches to contain the target, not just any branch. Also contains a large lookup table (`_create_lookup_table`) mapping elementary/special functions to their Meijer G-function representations, product decomposition utilities (`_mul_as_two_parts`, `_mul_args`), and `_split_mul` which separates a multiplicative integrand into three factors: a constant part, a pure power of the integration variable, and the remaining terms (with a fallback that expands the base via `expand_mul` if the initial coefficient-times-variable decomposition fails). `meijerint_definite` handles definite integration using a multi-stage pipeline: expansion/simplification, G-function rewriting, and a linearity fallback for sums. |
| `meijerint_doc.py` | Auto-generates a Sphinx docstring listing all Meijer G-function lookup table entries for documentation purposes. |
| `transforms.py` | Unevaluated class representations, dispatch entry points, and backend computation functions for all integral transforms: Mellin, inverse Mellin, Laplace, inverse Laplace, Fourier, inverse Fourier, sine, cosine, and Hankel. Backend functions (e.g. `_inverse_laplace_transform`) contain the multi-strategy orchestration logic — for inverse Laplace, it first tries inverse Mellin transforms (change of variables), then falls back to G-function inversion, with error handling and piecewise simplification at each stage. `InverseMellinTransform._compute_transform` validates input expressions against a whitelist of recognized functions (exp, gamma, sin, cos, tan, cot, cosh, sinh, tanh, coth, factorial, rf) before computing — any function depending on the transform variable that is not in this whitelist raises `IntegralTransformError`. `_sine_cosine_transform` computes half-line sine/cosine-kernel integrals and includes piecewise result validation: if the symbolic integration returns a `Piecewise`, it extracts the first branch and raises `IntegralTransformError` if that branch still contains an unevaluated `Integral`. Also contains `_simplifyconds` for simplifying convergence conditions, and `_rewrite_gamma` which converts gamma-function products into Meijer G parameters — including validation that numerator gamma poles do not partially extend into the fundamental strip (raises `NotImplementedError` for partial overlap), rewriting of trig factors (sin, cos, tan, cot) as gamma pairs, and a multiplication theorem step that handles gamma functions whose coefficient on the integration variable has magnitude != 1 (e.g., Gamma(2*s+c)) by splitting them into multiple unit-coefficient gamma terms — this step requires the coefficient to be an integer and raises `TypeError` if it is not (e.g., Gamma(sqrt(2)*s+c)). |
| `trigonometry.py` | Integration of products of trigonometric functions (sin, cos, tan, sec, csc, cot) via the `trigintegrate` function. |
| `rationaltools.py` | Tools for integrating purely rational functions (polynomials over polynomials in a plain polynomial ring, with no differential extension tower): `ratint`, `ratint_ratpart` (Hermite reduction for the rational part — operates on plain polynomials in k[x], distinct from `hermite_reduce` in `risch.py` which operates within a differential extension k(t)), `ratint_logpart` (Lazard-Rioboo-Trager for the logarithmic part of rational integrals only — not applicable to transcendental function integration), `log_to_real` (converts complex logarithmic terms from the Lazard-Rioboo-Trager result into real-valued expressions), and `log_to_atan` (converts complex logarithms to arctangent expressions). |
