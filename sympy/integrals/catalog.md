# sympy/integrals — Catalog

> Part of [SymPy](../catalog.md). Symbolic integration: definite/indefinite integrals, transforms (Laplace, Fourier, Mellin), and the Risch algorithm.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package init; exports `integrate`, `Integral`, `line_integrate`, and all integral transform functions. |
| `integrals.py` | Core `Integral` class (unevaluated integral representation) and the `integrate` / `line_integrate` entry points. The `_eval_integral` method implements the full integration pipeline: it first attempts whole-expression strategies, then splits sum integrands term-by-term and applies an ordered fallback chain to each term (power rule for linear bases → rational function decomposition → trig → Dirac delta → singularity functions → Risch → heuristic Risch). Importantly, when a term contains a big-O asymptotic remainder (order term) and integration of that remainder fails, the method immediately returns `None` (early bail-out) rather than trying other strategies — this is because no other method can handle the O() term either. Also includes guard logic that discards results from sub-methods when they return unevaluated `Integral` objects (e.g., manual mode) and fallback/fall-through behavior on failure. The `Integral` class also provides `as_sum(n, method)` for approximating a definite integral as a finite sum using rectangle-based methods (left, right, midpoint) or the trapezoid rule — this raises `NotImplementedError` for multidimensional integrals (more than one integration variable) and `ValueError` for non-definite integrals. For questions about numerical summation approximation of integrals (rectangle rule, trapezoid rule) or errors when approximating multi-variable integrals, look here rather than in `quadrature.py`. For questions about what happens when an antiderivative cannot be found for a particular term in a sum (including early abort scenarios), look here rather than in `heurisch.py`. |
| `risch.py` | Implementation of the Risch algorithm for transcendental function integration, including `DifferentialExtension`, `integer_powers`, and the main `risch_integrate` driver. Also contains `recognize_derivative` (checks if a rational function is the derivative of another rational function, using Laurent series and squarefree factorization of the denominator) and `recognize_log_derivative` (checks if a rational function f equals dv/v for some v by computing an elimination resultant between the denominator and a modified numerator, then testing whether all roots of that resultant polynomial are integers — notably, only *real* roots are examined; complex roots are explicitly ignored per a TODO comment, meaning the function may incorrectly return True when complex non-integer roots exist). Also contains `integrate_nonlinear_no_specials`, which integrates nonlinear monomials when the set of special irreducible polynomials is empty: it runs Hermite reduction followed by residue reduction, and if the residue reduction step indicates no elementary form exists (returns False), it returns early with partial results *before* reaching the polynomial reduction phase. For the related but distinct check of whether a function is the logarithmic derivative of a *radical* in a differential extension tower (using rational rather than integer root conditions), see `prde.py` instead. For solving Risch differential equations as sub-problems (including weak normalization), see `rde.py`. |
| `rde.py` | Algorithms for solving the Risch Differential Equation (Dy + f*y == g), used as a sub-problem solver by the Risch algorithm. Includes `weak_normalizer`, which adjusts a rational function so that none of the residues at its finite poles are positive integers — a necessary condition for having an elementary antiderivative. It does this by computing a square-free factorization of the denominator's normal part, forming a resultant polynomial in a new variable, finding the positive integer real roots of that resultant, then constructing a correction factor q as a product of GCDs so that f − Dq/q is weakly normalized. Also includes `order_at` and `order_at_oo` for computing pole/zero orders, `normal_denom` and `special_denom` for denominator decomposition, `bound_degree` for degree bounds, and `spde`/`solve_poly_rde` for the polynomial-level RDE solver. Does NOT contain integration drivers or derivative-recognition functions — for `recognize_log_derivative`, `recognize_derivative`, or `integrate_nonlinear_no_specials`, see `risch.py` instead. For the *parametric* version of these algorithms (Dy + f*y == Sum(ci*gi)), see `prde.py`. |
| `prde.py` | Algorithms for solving the Parametric Risch Differential Equation (Dy + f*y == Sum(ci*gi)), paralleling the methods in `rde.py`. Also contains `real_imag`, a helper that separates a rational function into its real and imaginary components when evaluated at the square root of negative one, *without* performing an explicit substitution — it classifies each polynomial term's exponent modulo 4 to determine sign contributions (powers 0,1,2,3 cycle through +real, +imag, −real, −imag), then combines numerator and denominator parts via the standard complex-division formula. This is used in the hypertangent case of the parametric special denominator computation. For separating real/imaginary parts of complex logarithmic terms arising from rational-function *integration* (using resultants and conjugate root pairs), see `log_to_real` in `rationaltools.py` instead — that is a different technique for a different purpose. Also contains `is_log_deriv_k_t_radical_in_field`, which checks whether a rational function in a differential field tower is the logarithmic derivative of a *radical* (Du/u) by performing residue reduction and testing that all roots of the resultant polynomial are rational. For the simpler check of whether a plain rational function is a logarithmic derivative (dv/v) using integer root conditions on the resultant, see `recognize_log_derivative` in `risch.py` instead. |
| `heurisch.py` | Heuristic Risch algorithm for indefinite integration; provides `heurisch` (core algorithm) and `heurisch_wrapper` (post-processing wrapper that inspects result denominators for symbolic poles, filters out poles already present in the original integrand, and returns a `Piecewise` only for genuinely new singularities). Also contains the `components` helper for decomposing expressions into transcendental building blocks. When the question involves avoiding unnecessary piecewise branches for division-by-zero or denominator singularities in integration results, look here rather than in `manualintegrate.py`. |
| `manualintegrate.py` | Step-by-step integration emulating by-hand techniques, returning a tree of named rule objects (namedtuples like `RewriteRule`, `URule`, etc.); provides `integral_steps` and `manualintegrate`. Includes its own pattern-matching trig integration subsystem: wildcard patterns (`sincos_pattern`, `tansec_pattern`, `cotcsc_pattern`) paired with conditional rewriting rules that apply classical identities (half-angle identities for both-even sin/cos products, Pythagorean identity extraction for odd-powered cases, etc.) before recursing. For questions about which identity or rewrite is applied during step-by-step antidifferentiation of trig products, look here. See also `trigonometry.py` for a separate, non-step-by-step trig integrator. |
| `meijerint.py` | Integration by rewriting integrands as Meijer G-functions; exposes `meijerint_indefinite`, `meijerint_definite`, and `meijerint_inversion`. `meijerint_inversion` implements the actual computational engine for inverse Laplace transforms: it filters exponential factors (both `exp(a*x)` and `base^(a*x)` power forms) out of a product-form integrand, extracts their linear-in-x coefficients to compute a frequency shift, converts power expressions to exponential form via logarithms, then rewrites the remaining integrand as Meijer G-functions for evaluation. For the unevaluated class representations and dispatch entry points for Laplace and other integral transforms, see `transforms.py` instead. |
| `meijerint_doc.py` | Auto-generates a Sphinx docstring listing all Meijer G-function lookup table entries for documentation purposes. |
| `transforms.py` | Integral transforms: Mellin, inverse Mellin, Laplace, inverse Laplace, Fourier, inverse Fourier, sine, cosine, and Hankel transforms with their unevaluated class representations and dispatch entry points. The Hankel transform implementation uses Bessel functions (besselj) and includes multi-branch error handling: if the integration result is not Piecewise, it raises an error; if it IS Piecewise, it extracts the first branch and checks whether that branch still contains an unevaluated Integral — if so, it raises a distinct error about "integral in unexpected form." For questions about error handling or piecewise results in Bessel-function-based integral transforms, look here. Also contains `_rewrite_gamma`, the central helper that converts a product of trigonometric functions, polynomial factors, and gamma functions into Meijer G-function parameters (an, ap, bm, bq) for the inverse Mellin transform's vertical-contour inversion. It decomposes all trigonometric factors — sine, cosine, tangent, and cotangent — into pairs of gamma functions using the reflection formula (e.g., sin(a) → gamma(a/π) · gamma(1−a/π)), with contour-aware shifting to keep gamma arguments well-defined within the fundamental strip. When a gamma function's linear coefficient in the integration variable is not ±1, `_rewrite_gamma` applies the gamma multiplication theorem (duplication formula) to split it into multiple gamma factors with unit coefficient, adjusting the overall scaling factor and exponential accordingly. Polynomial linear factors are fully factored via root-finding and converted to gamma pairs as well. The actual evaluation of inverse Laplace integrals (including exponential factor extraction and shift handling) is performed in `meijerint.py`, and the Meijer G lookup table lives there too — but the trigonometric-to-gamma decomposition and multiplication-theorem normalization logic lives here in `transforms.py`. For the Meijer G lookup table and G-function-based integration engine, see `meijerint.py` instead. |
| `trigonometry.py` | Direct (non-step-by-step) integration of products of sin^n(x)*cos^m(x) via the `trigintegrate` function, which returns a closed-form antiderivative without exposing intermediate rewriting steps. Uses reduction formulas that recurse through itself for most exponent combinations, but notably delegates to the general-purpose `integrate` routine (instead of recursing) in the special case where exponents are equal in magnitude but opposite in sign (m == -n), because the reduction eventually yields a constant term that the specialized trig integrator cannot handle. Also handles the m == n case via double-angle substitution. Does NOT handle tan/sec/cot/csc products. For step-by-step integration that shows which identities (half-angle, Pythagorean) are applied to trig products, see `manualintegrate.py` instead. |
| `rationaltools.py` | Tools for integrating rational functions: `ratint`, `ratint_ratpart`, and `ratint_logpart` implementing Hermite and Lazard-Rioboo-Trager methods. These compute the actual antiderivative of a rational function (always elementary). Also contains `log_to_real` and `log_to_atan` for converting complex-valued logarithmic terms (arising from rational function integration) into purely real-valued expressions using arctangent and natural logarithm. `log_to_real` substitutes t = u + iv, separates real/imaginary parts, computes resultants, finds roots filtered to real values, selects only conjugate pairs with positive imaginary part, and accumulates log/atan terms — it returns `None` if not all roots of the resultant are real (i.e., conversion to real form fails). For questions about how sums of complex logarithmic integration terms are converted to real form, or when that conversion fails, look here rather than in `meijerint.py`. For checking whether a function is the logarithmic derivative of a radical in a differential extension tower, see `prde.py` instead. |
| `deltafunctions.py` | Integration support for Dirac delta functions: `deltaintegrate` and the `change_mul` helper for rearranging delta-containing products. |
| `singularityfunctions.py` | Indefinite integration of `SingularityFunction` expressions via `singularityintegrate`. |
| `intpoly.py` | Integration of uni/bi/trivariate polynomials over 2D and 3D polytopes using the method of Chin et al. (2015); provides `polytope_integrate`. |
| `quadrature.py` | Gaussian quadrature rules: computes symbolic quadrature nodes (sample points) and weights for Gauss-Legendre, Gauss-Laguerre, Gauss-Hermite, Gauss-Chebyshev (T and U), Gauss-Jacobi, generalized Gauss-Laguerre, and Gauss-Lobatto methods. These functions return (node, weight) pairs for use in custom quadrature schemes — they do NOT approximate `Integral` objects directly. For rectangle/trapezoid numerical summation approximation of an `Integral`, see `Integral.as_sum` in `integrals.py` instead. |
