| `__init__.py` | Package init; exports `integrate`, `Integral`, `line_integrate`, and all integral transform functions. |
| `integrals.py` | Core `Integral` class (unevaluated integral representation) and the `integrate` / `line_integrate` entry points. The `_eval_integral` method implements the full integration pipeline: it first attempts whole-expression strategies, then splits sum integrands term-by-term and applies an ordered fallback chain to each term (power rule for linear bases → rational function decomposition → trig → Dirac delta → singularity functions → Risch → heuristic Risch). Importantly, when a term contains a big-O asymptotic remainder (order term) and integration of that remainder fails, the method immediately returns `None` (early bail-out) rather than trying other strategies — this is because no other method can handle the O() term either. Also includes guard logic that discards results from sub-methods when they return unevaluated `Integral` objects (e.g., manual mode) and fallback/fall-through behavior on failure. The `Integral` class also provides `as_sum(n, method)` for approximating a definite integral as a finite sum using rectangle-based methods (left, right, midpoint) or the trapezoid rule — this raises `NotImplementedError` for multidimensional integrals (more than one integration variable) and `ValueError` for non-definite integrals. For questions about numerical summation approximation of integrals (rectangle rule, trapezoid rule) or errors when approximating multi-variable integrals, look here rather than in `quadrature.py`. For questions about what happens when an antiderivative cannot be found for a particular term in a sum (including early abort scenarios), look here rather than in `heurisch.py`. |
| `risch.py` | Implementation of the Risch algorithm for transcendental function integration, including `DifferentialExtension`, `integer_powers`, `splitfactor` (which performs normal/special splitting factorization of a polynomial — decomposing p into p_n * p_s where p_s is special and each square factor of p_n is normal; this is NOT the same as Hermite reduction of a rational integrand), and the main `risch_integrate` driver. Also contains `recognize_derivative` (checks if a rational function is the derivative of another rational function, using Laurent series and squarefree factorization of the denominator) and `recognize_log_derivative` (checks if a rational function f equals dv/v for some v by computing an elimination resultant between the denominator and a modified numerator, then testing whether all roots of that resultant polynomial are integers — notably, only *real* roots are examined; complex roots are explicitly ignored per a TODO comment, meaning the function may incorrectly return True when complex non-integer roots exist). Also contains `integrate_nonlinear_no_specials`, which integrates nonlinear monomials when the set of special irreducible polynomials is empty: it runs Hermite reduction followed by residue reduction, and if the residue reduction step indicates no elementary form exists (returns False), it returns early with partial results *before* reaching the polynomial reduction phase. Contains `integrate_hyperexponential_polynomial`, which integrates Laurent-like polynomials in both positive and negative powers of a hyperexponential (exponential tower) variable: it iterates coefficient-by-coefficient from the most negative degree to the most positive degree, extracts each coefficient, and solves a first-order Risch differential equation for each term — notably, the zeroth-degree coefficient is explicitly skipped during this loop because it requires special handling outside the per-coefficient ODE framework. Also contains `integrate_primitive_polynomial`, which integrates a polynomial p in k[t] where t is a primitive (logarithmic) monomial: it uses an iterative while-loop that peels off the leading term at each step — extracting the leading coefficient, dropping to the next lower extension level via `DecrementLevel`, calling `limited_integrate` (from `prde.py`) to find an antiderivative of that coefficient, constructing a partial antiderivative `q0`, subtracting Dq0 from p (which reduces p's degree by at least one), and accumulating q0 into the running result q. If the leading coefficient's antiderivative cannot be expressed in closed form at the lower level (i.e., `limited_integrate` raises `NonElementaryIntegralException`), the loop terminates early and returns `(q, p, False)` indicating that the remainder has no elementary integral. For questions about iterative degree reduction when integrating univariate polynomials in a logarithmic extension variable within a differential field tower, or about what happens when a leading coefficient has no elementary antiderivative at a lower tower level, look here rather than in `rde.py` (which solves the Risch Differential Equation Dy + fy = g as a sub-problem but does not contain integration drivers or degree-reduction loops). Also contains `integrate_primitive` for integration of primitive (logarithmic) extensions using Hermite reduction, residue reduction, and polynomial integration (calling `integrate_primitive_polynomial` for the polynomial part). For questions about how antiderivatives of Laurent-like expressions (both positive and negative powers of an exponential extension variable) are computed term-by-term, or why the zero-degree term is skipped, look here rather than in `rde.py`. For the related but distinct check of whether a function is the logarithmic derivative of a *radical* in a differential extension tower (using rational rather than integer root conditions), see `prde.py` instead. For solving Risch differential equations as sub-problems (including weak normalization), see `rde.py`. |
| `rde.py` | Algorithms for solving the Risch Differential Equation (Dy + f*y == g), used as a sub-problem solver by the Risch algorithm. Includes `weak_normalizer`, which adjusts a rational function so that none of the residues at its finite poles are positive integers — a necessary normalization step (NOT a test for whether f equals dv/v). It does this by computing a square-free factorization of the denominator's normal part, forming a resultant polynomial in a new variable, finding the positive integer real roots of that resultant, then constructing a correction factor q as a product of GCDs so that f − Dq/q is weakly normalized. Note: `weak_normalizer` does NOT determine whether a rational function is a logarithmic derivative — it only removes positive-integer residues as a preprocessing step for the RDE solver. For the question "does there exist v such that f = dv/v?" (testing integrality of *all* roots of an elimination resultant), see `recognize_log_derivative` in `risch.py` instead. Also includes `order_at` and `order_at_oo` for computing pole/zero orders, `normal_denom` and `special_denom` for denominator decomposition, `bound_degree` for degree bounds, and `spde`/`solve_poly_rde` for the polynomial-level RDE solver. Does NOT contain integration drivers or derivative-recognition functions — for `recognize_log_derivative`, `recognize_derivative`, or `integrate_nonlinear_no_specials`, see `risch.py` instead. For the *parametric* version of these algorithms (Dy + f*y == Sum(ci*gi)), see `prde.py`. |
| `prde.py` | Algorithms for solving the Parametric Risch Differential Equation (Dy + f*y == Sum(ci*gi)), paralleling the methods in `rde.py`. Also contains `real_imag`, a helper that separates a rational function into its real and imaginary components when evaluated at the square root of negative one, *without* performing an explicit substitution — it classifies each polynomial term's exponent modulo 4 to determine sign contributions (powers 0,1,2,3 cycle through +real, +imag, −real, −imag), then combines numerator and denominator parts via the standard complex-division formula. This is used in the hypertangent case of the parametric special denominator computation. For separating real/imaginary parts of complex logarithmic terms arising from rational-function *integration* (using resultants and conjugate root pairs), see `log_to_real` in `rationaltools.py` instead — that is a different technique for a different purpose. Also contains `is_log_deriv_k_t_radical_in_field`, which checks whether a rational function in a differential field tower is the logarithmic derivative of a *radical* (Du/u) by performing residue reduction and testing that all roots of the resultant polynomial are rational. This function handles multiple cases recursively (primitive, exponential, hypertangent), with a ground-level 'base' case that checks three necessary conditions on the denominator: (1) the denominator must be square-free, (2) the degree of the numerator must be strictly less than the degree of the denominator, and (3) the numerator and denominator must be coprime (enforced via cancellation). If any of these conditions fails, the function returns None immediately. For questions about the base-case denominator conditions required for a rational function to be the logarithmic derivative of a radical, look here rather than in `rde.py` (which contains `weak_normalizer` — a preprocessing normalization step that removes positive-integer residues but does NOT test whether f equals Du/u). For the simpler check of whether a plain rational function is a logarithmic derivative (dv/v) using integer root conditions on the resultant, see `recognize_log_derivative` in `risch.py` instead. Also contains `parametric_log_deriv_heu`, a heuristic for solving the parametric logarithmic derivative equation n*f == Dv/v + m*Dtheta/theta. This heuristic computes an LCM of denominators, applies split factorization (via `splitfactor`), and derives a common factor `z` from the GCD of the normal part with its derivative — if this `z` turns out to be an element of the constant field (i.e., does not depend on the extension variable `DE.t`), the heuristic raises `NotImplementedError` because it cannot proceed without a nontrivial divisor for the polynomial division step. For questions about what happens when the split-factorization-derived common factor is constant, or about heuristic failure modes in parametric logarithmic derivative solving, look here rather than in `risch.py`. |
| `heurisch.py` | Heuristic Risch algorithm for indefinite integration; provides `heurisch` (core algorithm) and `heurisch_wrapper` (post-processing wrapper that inspects result denominators for symbolic poles, filters out poles already present in the original integrand, and returns a `Piecewise` only for genuinely new singularities). Also contains the `components` helper for decomposing expressions into transcendental building blocks. When the question involves avoiding unnecessary piecewise branches for division-by-zero or denominator singularities in integration results, look here rather than in `manualintegrate.py`. |
| `manualintegrate.py` | Step-by-step integration emulating by-hand techniques, returning a tree of named rule objects (namedtuples like `RewriteRule`, `URule`, etc.); provides `integral_steps` and `manualintegrate`. Includes its own pattern-matching trig integration subsystem: wildcard patterns (`sincos_pattern`, `tansec_pattern`, `cotcsc_pattern`) paired with conditional rewriting rules that apply classical identities (half-angle identities for both-even sin/cos products, Pythagorean identity extraction for odd-powered cases, etc.) before recursing. For questions about which identity or rewrite is applied during step-by-step antidifferentiation of trig products, look here. This module does NOT handle the reduction-formula delegation where sin^m(x)*cos^n(x) with opposite-sign exponents (m == -n) falls back to the general `integrate` routine — that logic lives in `trigonometry.py`. See also `trigonometry.py` for a separate, non-step-by-step trig integrator that uses reduction formulas and recursive integration of power products. |
| `meijerint.py` | Integration by rewriting integrands as Meijer G-functions; exposes `meijerint_indefinite`, `meijerint_definite`, and `meijerint_inversion`. `meijerint_inversion` implements the actual computational engine for inverse Laplace transforms: it filters exponential factors (both `exp(a*x)` and `base^(a*x)` power forms) out of a product-form integrand, extracts their linear-in-x coefficients to compute a frequency shift, converts power expressions to exponential form via logarithms, then rewrites the remaining integrand as Meijer G-functions for evaluation. For the unevaluated class representations and dispatch entry points for Laplace and other integral transforms, see `transforms.py` instead. For Hankel/Bessel-function-based transforms (including error handling for piecewise results or unevaluated integrals in transform output), see `transforms.py` — that logic is NOT in this file. |
| `meijerint_doc.py` | Auto-generates a Sphinx docstring listing all Meijer G-function lookup table entries for documentation purposes. |
| `transforms.py` | Integral transforms: Mellin, inverse Mellin, Laplace, inverse Laplace, Fourier, inverse Fourier, sine, cosine, and Hankel transforms with their unevaluated class representations and dispatch entry points. The `IntegralTransform` base class handles linearity by splitting sum-of-terms integrands, computing each term's transform independently, and then merging their convergence conditions via logical conjunction (`And`); if the merged conditions evaluate to `False` (i.e., are contradictory/unsatisfiable), the base class raises an `IntegralTransformError` — this error-handling path lives in `_collapse_extra`, not in `integrals.py`. For questions about what happens when convergence conditions from individual transform terms conflict or are contradictory, look here rather than in `integrals.py`. The Hankel transform implementation uses Bessel functions (besselj) and includes multi-branch error handling: if the integration result is not Piecewise, it raises an error; if it IS Piecewise, it extracts the first branch and checks whether that branch still contains an unevaluated Integral — if so, it raises a distinct error about "integral in unexpected form." For questions about error handling or piecewise results in Bessel-function-based integral transforms, look here. Also contains `_rewrite_sin`, a separate helper function that converts a single sine factor `sin(m*s + n)` into a pair of gamma functions compatible with a given fundamental strip (a, b). It uses the reflection formula `pi/sin(pi*x) = gamma(x)*gamma(1-x)` but must ensure the resulting gamma functions don't become undefined due to the integration contour placement — it computes an integer shift `r` via `ceiling(-m*a - re(n))` so that both gamma arguments are safely positioned within the strip, and returns `(gamma1, gamma2, fac)` with an appropriate sign factor `(-1)**r`. For questions about how sine-to-gamma conversion avoids producing undefined gamma functions or how the contour shift is computed for the G-function representation, look here rather than in `meijerint.py`. Also contains `_rewrite_gamma`, the central helper that converts a product of trigonometric functions, polynomial factors, and gamma functions into Meijer G-function parameters (an, ap, bm, bq) for the inverse Mellin transform's vertical-contour inversion. `_rewrite_gamma` calls `_rewrite_sin` internally for each sine/cosine factor. It decomposes all trigonometric factors — sine, cosine, tangent, and cotangent — into pairs of gamma functions using the reflection formula, with contour-aware shifting to keep gamma arguments well-defined within the fundamental strip. When a gamma function's linear coefficient in the integration variable is not ±1, `_rewrite_gamma` applies the gamma multiplication theorem (duplication formula) to split it into multiple gamma factors with unit coefficient, adjusting the overall scaling factor and exponential accordingly. Polynomial linear factors are fully factored via root-finding and converted to gamma pairs as well. The actual evaluation of inverse Laplace integrals (including exponential factor extraction and shift handling) is performed in `meijerint.py`, and the Meijer G lookup table lives there too — but the trigonometric-to-gamma decomposition, sine-to-gamma-pair conversion, and multiplication-theorem normalization logic lives here in `transforms.py`. For the Meijer G lookup table and G-function-based integration engine, see `meijerint.py` instead. |
| `trigonometry.py` | Direct (non-step-by-step) integration of products of sin^n(x)*cos^m(x) via the `trigintegrate` function, which returns a closed-form antiderivative without exposing intermediate rewriting steps. Internally uses dedicated recursive helper functions for pure sin^n(x) and cos^n(x) powers that handle both positive and **negative** integer exponents. For positive n, the recursion steps downward (n−2) with base cases at n=1 and n=0. For negative n (e.g., integrating 1/sin^3(x)), the recursion steps **upward** (n+2 toward zero), and the n=−1 base case specifically delegates back to the main dispatcher (rather than recursing into itself) to prevent infinite recursion — this is because 1/sin(x) requires a different integration technique. Uses reduction formulas that recurse through itself for most exponent combinations, but notably delegates to the general-purpose `integrate` routine (instead of recursing) in the special case where exponents are equal in magnitude but opposite in sign (m == -n), because the reduction eventually yields a constant term that the specialized trig integrator cannot handle. Also handles the m == n case via double-angle substitution. Does NOT handle tan/sec/cot/csc products. For step-by-step integration that shows which identities (half-angle, Pythagorean) are applied to trig products, see `manualintegrate.py` instead. For questions about how recursion terminates when integrating negative powers of sin or cos, look here rather than in `manualintegrate.py`. |
| `rationaltools.py` | Tools for integrating rational functions: `ratint`, `ratint_ratpart`, and `ratint_logpart` implementing Hermite and Lazard-Rioboo-Trager methods. These compute the actual antiderivative of a rational function (always elementary). `ratint_ratpart` implements the Hermite reduction (Horowitz-Ostrogradsky algorithm): given coprime polynomials f, g with deg(f) < deg(g), it decomposes f/g into A' + B where B has no repeated roots in its denominator. It does this by computing the GCD of g and g' (the derivative of the denominator) to obtain factors u and v, then setting up undetermined-coefficient polynomials A (over u) and B (over v), forming a system of linear equations from f = A'·v − A·(u'·v)/u + B·u, and solving for the unknown coefficients. For questions about how a rational integrand is split into a derivative of a rational expression plus a remainder whose denominator has no repeated factors using the GCD of the denominator with its derivative, look here rather than in `risch.py` (which contains `splitfactor` for normal/special splitting factorization — a different decomposition). `ratint` includes automatic real/complex domain detection: when the caller does not explicitly specify a `real` flag, `ratint` inspects all atoms (sub-expressions) of the integrand — if any atom (other than the integration variable) has `is_real` equal to False, the expression is treated as complex; otherwise it defaults to real. This domain choice affects the logarithmic part of the antiderivative: in complex mode, the logarithmic terms are expressed using `RootSum` with `Lambda` (compact complex logarithms); in real mode, the logarithmic terms are converted to real-valued form using `log_to_real` (arctangent and natural logarithm). For questions about how the integration routine automatically determines whether to produce real or complex logarithmic antiderivatives, or how the `real` flag is auto-detected from the integrand's atoms, look here rather than in `risch.py`. Also contains `log_to_real` and `log_to_atan` for converting complex-valued logarithmic terms (arising from rational function integration) into purely real-valued expressions using arctangent and natural logarithm. `log_to_real` substitutes t = u + iv, separates real/imaginary parts, computes resultants, finds roots filtered to real values, selects only conjugate pairs with positive imaginary part, and accumulates log/atan terms — it returns `None` if not all roots of the resultant are real (i.e., conversion to real form fails). For questions about how sums of complex logarithmic integration terms are converted to real form, or when that conversion fails, look here rather than in `meijerint.py`. For checking whether a function is the logarithmic derivative of a radical in a differential extension tower, see `prde.py` instead. |
