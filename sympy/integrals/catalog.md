> Part of [SymPy](../catalog.md). Symbolic integration: definite/indefinite integrals, transforms (Laplace, Fourier, Mellin), and the Risch algorithm.

| `__init__.py` | Package init; exports `integrate`, `Integral`, `line_integrate`, and all integral transform functions. |
| `integrals.py` | Core `Integral` class (unevaluated integral representation) and the `integrate` / `line_integrate` entry points that dispatch to various integration strategies. `Integral.doit` is the main evaluation method for definite and indefinite integrals — it iterates over integration limits, tries multiple strategies (including Meijer G-function definite integration via `meijerint_definite`), and handles the `conds` parameter for convergence conditions: when `conds='piecewise'` it wraps results in `Piecewise`, when `conds='separate'` it returns `(result, condition)` as a tuple but raises `ValueError` if the integral has multiple limits (multi-dimensional), and otherwise returns just the result. `Integral` also provides: the `transform` method for change-of-variables (u-substitution) on definite integrals; `_eval_derivative` for differentiating integrals with respect to variables (applying the Fundamental Theorem of Calculus for indefinite integrals, and using dummy-variable masking for definite integrals); `as_sum` which approximates a definite integral as a finite Riemann sum using rectangle-based quadrature methods (left, right, midpoint, trapezoid) — each method has special boundary-point handling that uses symbolic `limit()` instead of direct substitution to avoid discontinuities (e.g., left-hand rule uses `limit` at the lower boundary, right-hand rule has a code path for `limit` at the upper boundary, trapezoid uses `limit` at both endpoints); and `_eval_integral` which is a dispatcher that tries multiple strategies in sequence (polynomial fast-paths, Risch delegation, sum-of-terms decomposition, manual integration, Meijer G-functions, heuristic Risch) but does not itself implement any algorithm's decision procedure. Key fallback mechanisms in `_eval_integral`: (1) when the Risch algorithm is called with `separate_integral=True` and returns a partially non-elementary result (elementary part + non-elementary remainder), `_eval_integral` recursively evaluates the non-elementary remainder via `.doit(risch=False)` to attempt integration using other strategies; (2) when a downstream strategy (such as manual integration) returns a partial result still containing unevaluated integral sub-expressions, `_eval_integral` re-evaluates those remaining pieces using the other available methods. `_eval_integral` also contains inline pattern-matching rules for simple forms — notably the power rule for `(a*x+b)**c`: when exponent is exactly -1 it returns a logarithm, when the conditions mode is 'piecewise' it returns a `Piecewise` covering both the log case (exponent == -1) and the standard power rule, and otherwise applies the standard power rule directly. |
| `risch.py` | Implementation of the Risch algorithm — the deterministic decision procedure for integrating transcendental functions (exponentials and logarithms). The main entry point `risch_integrate` orchestrates the process: it builds a tower of differential extensions, then iterates through extension levels in reverse order, calling appropriate sub-procedures (hyperexponential, primitive, or base-case) at each level, and either produces a closed-form elementary antiderivative or proves one does not exist. Also defines `NonElementaryIntegral` (subclass of `Integral`) to represent integrals proven to be non-elementary, and `DifferentialExtension` whose `__init__` constructs the transcendental extension tower by iteratively processing exp, log, and power sub-expressions; `DifferentialExtension` also provides `increment_level` and `decrement_level` methods to grow or shrink the working extension — `increment_level` raises `ValueError` when the level is already at maximum (-1), and `decrement_level` raises `ValueError` when it is already at minimum (-len(T)) — it classifies power expressions into numeric-base vs symbolic-base categories, converts non-base-E powers to exp(b*log(a)) form, and raises `NotImplementedError` for algebraic extensions (e.g., `x**(3/2)` where the base depends on the integration variable and the exponent is a non-integer rational). Contains `hermite_reduce` (Mack's Linear Version of Hermite Reduction for differential extensions) which decomposes a rational function f = a/d in k(t) into f = Dg + h + r where g is an exact derivative, h is simple (normal denominator), and r is reduced (special denominator) — this iteratively reduces the multiplicity of repeated denominator factors using extended GCD computations within the differential extension context. Also contains `canonical_representation` (splits a rational function in k(t) into polynomial + reduced + simple parts) and `polynomial_reduce` (writes p = Dq + r with deg(r) < deg(Dt)). Contains polynomial utility helpers: `gcdex_diophantine`, `frac_in`, and `as_poly_1t`. Contains `recognize_log_derivative` which tests whether a rational function f in k(t) is a logarithmic derivative (i.e., f = dv/v for some v in k(t)*) by computing the Rothstein-Trager resultant between the denominator and a modified numerator, factoring it via `splitfactor_sqf`, and checking that all real roots of the special factors are integers — returns True/False; has a known limitation (TODO) that it does not consider complex roots. Contains `residue_reduce` implementing the Lazard-Rioboo-Rothstein-Trager resultant reduction for computing the logarithmic part of antiderivatives of transcendental functions. Contains `integrate_hyperexponential` which integrates functions in hyperexponential (exp-type) extension fields — it handles the edge case where the exponential term might equal 1 (exponent is zero) by producing a `Piecewise` expression: one branch substitutes the extension generator with 1 and integrates directly, the other uses the quotient as-is. Also contains `integrate_hypertangent_polynomial` for tangent-type extensions. Contains `get_case` which classifies the type of a derivation polynomial into one of {'exp', 'tan', 'base', 'primitive', 'other_linear', 'other_nonlinear'} — when the derivation doesn't involve the extension variable t, it further distinguishes 'base' (derivation is identically 1, meaning the ground field level) from 'primitive' (any other constant derivation, meaning a logarithmic extension); when it does involve t, it checks divisibility by t (exp), by 1+t² (tan), or classifies by degree. Also contains `derivation` which computes Dp for a polynomial p in the differential extension tower, with an optional `coefficientD` mode that differentiates only w.r.t. lower-level extensions treating the top variable as constant. |
| `rde.py` | Algorithms for solving the Risch Differential Equation (Dy + f*y == g), used as a sub-problem solver by the Risch algorithm. Contains `weak_normalizer` which ensures that a rational function f = a/d has no residue at any normal irreducible denominator factor that is a positive integer — it computes a resultant polynomial in an auxiliary variable z from the numerator and the square-free part of the normal denominator, finds the positive integer real roots of that resultant, and constructs a correction factor q as the product of GCDs so that f - Dq/q is weakly normalized. Contains the 5-step pipeline: normal denominator, special denominator (`special_denom` — handles 'exp', 'tan', 'primitive'/'base' cases for non-parametric RDEs; for 'primitive'/'base' it returns `(a, B, C, 1)` immediately — a trivial identity transform with `h=1` — completely bypassing the order-at computations and cancellation-checking logic that the 'exp' and 'tan' cases require), degree bounding (`bound_degree`), polynomial reduction (`spde`), and bounded-degree polynomial solving (`solve_poly_rde`). `solve_poly_rde` is the main dispatcher for step 4/5: it routes to different sub-algorithms based on whether `b` is zero and the degree relationship between `b` and the derivation `D` — specifically comparing `b.degree(t)` against `D.degree(t) - 1` to choose between `no_cancel_b_large` (when `b` has large degree or base case) and `no_cancel_b_small` (when `b` has small degree); the small-b path may return a triple `(h, b0, c0)` triggering a recursive call at a decremented extension level. Also contains cancellation-case solvers: `cancel_primitive` (logarithmic case) and `cancel_exp` (hyperexponential case). |
| `prde.py` | Algorithms for solving the Parametric Risch Differential Equation (Dy + f*y == Sum(ci*gi)), paralleling `rde.py` with parametric variants of each pipeline stage. Contains `prde_normal_denom` (normal denominator computation) and `prde_special_denom` (special denominator computation — handles 'exp', 'tan', 'primitive'/'base' cases; for 'primitive'/'base' it short-circuits by returning `(a, ba.quo(bd), G, 1)` without computing order at the special polynomial or checking for cancellation, since k<t> == k[t] in the primitive case; for 'exp'/'tan' it computes order bounds and checks for possible cancellation via `parametric_log_deriv`). Also contains a helper for extracting real and imaginary parts of a rational function evaluated at sqrt(-1) without performing the substitution — it classifies each term by its power degree modulo 4 to assign signs. Also contains `prde_spde` (Special Polynomial Differential Equation — parametric version), `prde_no_cancel_b_large` (parametric no-cancellation solver when deg(b) is large enough — iterates from degree n down to 0 inclusive), and `prde_no_cancel_b_small` (parametric no-cancellation solver when deg(b) < deg(D)-1 — iterates from degree n down to 1 only, with separate handling when deg(b) > 0; raises `NotImplementedError` when deg(b) <= 0 because a recursive call is not yet implemented). Also contains `constant_system` which enforces that solutions of a linear system over a differential field lie in the constant subfield — after RREF, it differentiates rows whose entries depend on the extension variable to generate additional constraint rows. Also contains `prde_linear_constraints` for generating linear constraints on constant parameters, `limited_integrate` / `limited_integrate_reduce` for the limited integration problem (f = Dv + Sum(ci*wi)), `parametric_log_deriv_heu` which is a heuristic for solving the equation n*f == Dv/v + m*Dθ/θ where θ is a hyperexponential monomial — it computes degree bounds from the derivation, solves for a rational constant relating leading coefficients, then checks if the resulting combination is a logarithmic derivative of a radical; returns None if no solution exists, or a triple (n, m, v) on success, and raises NotImplementedError if the heuristic fails (requiring the structure theorem approach), and `is_log_deriv_k_t_radical` / `is_log_deriv_k_t_radical_in_field` which test whether a rational function is the logarithmic derivative of a radical in a differential extension field — handles multiple cases ('exp', 'primitive', 'base', 'tan'); in the 'base' case it returns None immediately if the denominator is not square-free or if the numerator degree >= denominator degree (necessary conditions for being a log derivative in the ground field), and otherwise computes the answer from residue terms. |
| `heurisch.py` | Heuristic (parallel) Risch algorithm for indefinite integration of transcendental elementary and special functions (Airy, Bessel, Whittaker, Lambert); provides `heurisch` and `heurisch_wrapper` along with the `components` helper. The `heurisch` function constructs a polynomial ansatz with undetermined coefficients: it computes a degree bound for the trial polynomial by analyzing the integrand's exponent structure — for fractional (rational) exponents p/q, it uses different formulas for positive vs negative rational powers (p+q-1 for positive, |p+q| for negative) to determine how many monomials to generate, then solves a linear system for the unknown coefficients. Also constructs a candidate antiderivative combining the polynomial part with a logarithmic part built from irreducible factors. Includes a derivative caching mechanism for cylindrical (Bessel-type) functions that simultaneously stores derivatives for adjacent orders (n and n-1) to avoid introducing algebraically dependent transcendentals. |
| `manualintegrate.py` | Integration method emulating by-hand techniques with step-by-step rules (namedtuples); provides `integral_steps` and `manualintegrate`. Rules decompose an integrand into named computation steps (e.g., `SubstitutionRule`, `PartsRule`, `PowerRule`, `ExpRule`, `PiecewiseRule`) for solving integrals. This is a downstream strategy called by `_eval_integral` in `integrals.py` — the core conditional power-rule logic (linear base with symbolic exponent, log vs power rule ambiguity) lives in `integrals.py`, not here. Contains dedicated trig power/product integration rules dispatched via `trig_powers_products_rule`: `trig_sincos_rule` (sin^m * cos^n products), `trig_tansec_rule` (tan^m * sec^n products), and `trig_cotcsc_rule` (cot^m * csc^n products). Each rule first applies preprocessing substitutions to normalize the integrand before pattern matching — e.g., `trig_tansec_rule` substitutes 1/cos→sec, while `trig_cotcsc_rule` substitutes 1/sin→csc, 1/tan→cot, and cos/tan→cot — then matches against a canonical pattern and dispatches to sub-cases based on parity/value of the exponents (e.g., odd-power, even-power conditions). These manual trig rules handle the full range of trig functions (tan, sec, cot, csc) with preprocessing, unlike `trigonometry.py` which only handles sin/cos products. |
| `meijerint.py` | Integration by rewriting integrands as Meijer G-functions; exposes `meijerint_indefinite`, `meijerint_definite`, and `meijerint_inversion`. For indefinite integration, `_meijerint_indefinite_1` rewrites the integrand as a G-function, shifts its parameters by the exponent (rho) to absorb the power-of-variable factor, then integrates by prepending index parameters — it selects between two alternative parameter arrangements based on whether certain shifted parameters would be non-positive integers (which would make the function ill-defined). This is the low-level G-function computation backend — it does not define transform classes, orchestrate fallback strategies, or handle transform-specific error logic; in particular, `meijerint_inversion` only computes and returns the raw G-function inversion result (which may be a `Piecewise`) but does NOT inspect that result for unevaluated `Integral` objects or raise errors — that post-processing is done by the calling code in `transforms.py`. `meijerint_inversion` (inverse Laplace transform) pre-processes multiplicative integrands by filtering out exponential and power factors (e.g., `exp(a*x)` or `base**x`) and accumulating them into a cumulative shift value — power expressions are converted via logarithm (`a*log(base)`) — then after computing the core G-function inversion, it applies this shift to the time variable (`t + shift`) in the final result, effectively converting multiplicative exponential factors into a time-domain translation; for each factor it calls `_get_coeff_exp` to extract a linear coefficient in the integration variable — if extraction fails (raises `_CoeffExpValueError`, meaning the exponent is not of the form `a*x`), it silently falls back by setting `b=0`, treating the factor as non-exponential rather than raising an error. For Laplace inversion (`meijerint_inversion`), contains `_check_antecedents_inversion` which verifies convergence conditions for the Laplace inversion integral of a Meijer G-function — when the argument's exponent with respect to the integration variable is negative, it flips the G-function (via `_flip_g`) and recurses so the argument grows as |x| → ∞; also computes epsilon with a three-way branch based on q-p (sigma). Contains `_rewrite_inversion` to absorb x**s into the G-function parameters, and `_int0oo` for expressing zero-to-infinity integrals of G-function products. Contains `_condsimp` which performs ad-hoc boolean simplification of convergence conditions arising from G-function rewriting — it iteratively applies wildcard pattern-matching rules to combine strict-less-than with equality into non-strict inequality (e.g., `Or(p < q, Eq(p, q))` → `p <= q`), absorb weaker conditions into stronger ones, and convert equality conditions on `unbranched_argument`/`polar_lift` expressions into positivity constraints (e.g., `Eq(arg(polar_lift(p)**q), 0)` → `p > 0`). Contains the `_has` helper for checking whether integration results contain unresolved special functions — for Piecewise results it requires all branches to contain the target, not just any branch. Also contains a large lookup table (`_create_lookup_table`) mapping elementary/special functions to their Meijer G-function representations, product decomposition utilities (`_mul_as_two_parts`, `_mul_args`), and `_split_mul` which separates a multiplicative integrand into three factors: a constant coefficient, a pure power-of-variable term (x**s), and the remaining terms — it calls `expand_power_base` then iterates over multiplicative arguments, and for powers like `(c*x)**s` it extracts the numeric coefficient via `as_coeff_mul` and uses `polarify`/`unpolarify` to compute `c**s` cleanly, placing the coefficient part into fac and the variable power into po (not related to trig-to-gamma rewriting — that lives in `transforms.py`). `meijerint_definite` handles definite integration using a multi-stage pipeline: expansion/simplification, G-function rewriting, and a linearity fallback for sums. |
| `meijerint_doc.py` | Auto-generates a Sphinx docstring listing all Meijer G-function lookup table entries for documentation purposes. |
| `transforms.py` | Unevaluated class representations, dispatch entry points, and backend computation functions for all integral transforms: Mellin, inverse Mellin, Laplace, inverse Laplace, Fourier, inverse Fourier, sine, cosine, and Hankel. Backend functions (e.g. `_inverse_laplace_transform`) contain the multi-strategy orchestration logic — for inverse Laplace, it first tries inverse Mellin transforms (change of variables), then falls back to `meijerint_inversion` from `meijerint.py`; after each fallback, it inspects the result and raises `IntegralTransformError` if a piecewise result's first branch still contains an unevaluated `Integral` (indicating an inversion integral of unrecognised form), with piecewise simplification at each stage. `InverseMellinTransform._compute_transform` validates input expressions against a whitelist of recognized functions (exp, gamma, sin, cos, tan, cot, cosh, sinh, tanh, coth, factorial, rf) before computing — any function depending on the transform variable that is not in this whitelist raises `IntegralTransformError`. `_sine_cosine_transform` computes half-line sine/cosine-kernel integrals and includes piecewise result validation: if the symbolic integration returns a `Piecewise`, it extracts the first branch and raises `IntegralTransformError` if that branch still contains an unevaluated `Integral`. `_hankel_transform` computes Bessel-function-based Hankel transforms using `besselj(nu, k*r)*r` kernels and has its own three-way error handling: if the result has no unevaluated `Integral` it returns directly; if it is not `Piecewise` it raises `IntegralTransformError('could not compute integral')`; if it IS `Piecewise` and the first branch still contains an unevaluated `Integral`, it raises `IntegralTransformError('integral in unexpected form')`. Also contains `_simplifyconds` for simplifying convergence conditions, and `_rewrite_gamma` which converts gamma-function products into Meijer G parameters — including validation that numerator gamma poles do not partially extend into the fundamental strip (raises `NotImplementedError` for partial overlap), rewriting of trig factors as gamma pairs (tan(a) is decomposed as sin(a)/sin(π/2−a), cos and cot similarly reduced to sine form, then each sine rewritten via the gamma reflection formula), and a multiplication theorem step that handles gamma functions whose coefficient on the integration variable has magnitude != 1 (e.g., Gamma(2*s+c)) by splitting them into multiple unit-coefficient gamma terms — this step requires the coefficient to be an integer and raises `TypeError` if it is not (e.g., Gamma(sqrt(2)*s+c)). |
| `trigonometry.py` | Integration of products of sin and cos only (sin(a*x)^n * cos(a*x)^m) via the `trigintegrate` function — uses reduction formulas and half-angle identities; does not handle tan, sec, cot, or csc products (those are in `manualintegrate.py`'s trig power/product rules). |
| `rationaltools.py` | Tools for integrating purely rational functions (polynomials over polynomials in a plain polynomial ring, with no differential extension tower): `ratint` (main entry point — performs indefinite integration of rational functions, including auto-detection of whether to produce real-valued logarithmic output vs complex RootSum expressions: when the `real` flag is not explicitly provided, `ratint` inspects all atoms of the input and checks `is_real` on each; if all non-variable atoms are real, it attempts `log_to_real` conversion and falls back to RootSum if that fails), `ratint_ratpart` (Hermite reduction for the rational part — operates on plain polynomials in k[x], distinct from `hermite_reduce` in `risch.py` which operates within a differential extension k(t)), `ratint_logpart` (Lazard-Rioboo-Trager for the logarithmic part of rational integrals only — not applicable to transcendental function integration), `log_to_real` (converts complex logarithmic terms from the Lazard-Rioboo-Trager result into real-valued expressions), and `log_to_atan` (converts complex logarithms to arctangent expressions). |
