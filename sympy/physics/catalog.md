| `mechanics/kane.py` | KanesMethod class implementing Kane's method for forming equations of motion, producing mass matrix and forcing vector representations. The kanes_equations method forms Fr + Fr* = 0; when auxiliary generalized speeds are present, it creates a secondary KanesMethod instance to compute auxiliary equations (fraux + frstaraux), then appends them to the primary equations via col_join, yielding a combined vector of length (o - m + s). | `mechanics/lagrange.py` | LagrangesMethod class implementing Lagrange's method for deriving equations of motion from a Lagrangian, with support for constraints and non-conservative forces. The constructor validates the inertial frame argument: if a non-None value is provided that is not a ReferenceFrame instance, raises TypeError('frame must be a valid ReferenceFrame'); falsy values (None) pass through without validation. The core `form_lagranges_equations` method constructs the second-kind variational equations of motion, decomposed into four terms: (1) time derivative of the Lagrangian's Jacobian w.r.t. generalized velocities, (2) Lagrangian's Jacobian w.r.t. generalized coordinates, (3) constraint multiplier coupling terms, and (4) generalized forces from non-conservative loads. When constraints are present, it computes the undetermined multiplier coupling matrix (lam_coeffs) by taking the Jacobian of the combined constraint equations (time-differentiated holonomic + nonholonomic) with respect to generalized velocities — this matrix defines how each Lagrange multiplier enters each equation of motion. It then differentiates the constraint equations in time and separates the constraint mass matrix (Jacobian w.r.t. generalized accelerations) from the constraint forcing terms (remainder after zeroing all accelerations). Includes a to_linearizer method that decomposes the constrained equations into component matrices, validates that the user's partition of coordinates/speeds into independent and dependent subsets matches the number of holonomic and velocity constraints, discovers external dynamic symbols in the forcing terms and raises ValueError if any such symbol's time derivative is also present among those external symbols, and returns a Linearizer instance. |
| `mechanics/linearize.py` | Linearizer class that takes pre-decomposed system matrices and computes the linearized equations of motion via permutation matrices and matrix solves. | `vector/dyadic.py` | Dyadic class representing a second-order tensor (vector outer product, e.g., u|v) used for inertia tensors and other rigid body properties. Both the _latex and __str__ methods contain per-component rendering with sign-handling logic: coefficients of 1/-1 are elided, other coefficients are printed with Add-type (symbolic sum) values wrapped in parentheses for readability, and leading whitespace/sign is trimmed. The _latex method renders each dyadic component pair with `\otimes` between basis vectors and parenthesizes sum-type coefficients like (a+b). The _pretty method has parallel logic using `.parens()` on the pretty-printed form for Add-type coefficients. Not related to quantum tensor products. |

Zero-input edge cases: divergence of a zero vector returns scalar zero S(0), while curl of a zero vector returns vector zero Vector(0), reflecting their different output types (scalar vs vector). |

| `vector/functions.py` | Core vector functions: cross, dot, express, time_derivative (computes time derivative of a vector/scalar/dyadic in a given reference frame — for vector components already expressed in the target frame, differentiates directly; for components in a different rotating frame, applies the rotating-frame transport theorem by recursively computing the derivative in the component's own frame and adding the angular velocity cross-product term ω×v, where ω is the angular velocity of the component's frame relative to the target frame; for dyadics, applies the product rule across all three factors of each dyadic term; for scalars, re-expresses in the target frame's coordinates before differentiating), outer product, kinematic_equations (contains hard-coded kinematic differential equations mapping generalized coordinate time-derivatives to generalized speeds for all 12 Body/Space Euler angle rotation orders — asymmetric sequences like 123 have cos(q2) denominators while symmetric sequences like 121 have sin(q2) denominators, reflecting different singularity structures), get_motion_params (determines which kinematic quantities to compute — and in which direction (integration vs differentiation) — based on which of three motion orders the user provides: if acceleration is given (mode 2), integrates twice to get velocity then position; if velocity is given (mode 1), differentiates once for acceleration and integrates once for position; if only position is given (mode 0), differentiates twice. Uses an internal _process_vector_differential helper that integrates vector differentials component-wise with boundary conditions — when the input vector is the zero vector, it short-circuits and returns the boundary condition directly), partial_velocity (computes derivatives of linear/angular velocity vectors with respect to generalized speeds in a given frame — explicitly sets var_in_dcm=False during differentiation so direction cosine matrix dependence on speed variables is ignored, which is physically correct for analytical mechanics partial velocities in Kane's method), and dynamicsymbols (creates time-dependent symbolic functions of t). |
| `vector/point.py` | Point class representing a point in a dynamic system with position (set_pos, pos_from), velocity (vel, set_vel), acceleration (acc, set_acc), and the kinematic transport theorems. The acc method retrieves a point's acceleration in a given frame with fallback logic: if no explicit acceleration has been stored for that frame, it checks whether the stored velocity is non-zero — if so, it differentiates the velocity vector with respect to time in that frame to compute acceleration automatically; if velocity is zero, it returns a zero vector. a2pt_theory and a1pt_theory are the acceleration transport theorems (analogous to v2pt_theory/v1pt_theory). v1pt_theory implements the one-point theorem (^N v^P = ^B v^P + ^N v^O + ^N ω^B × r^OP) for a point P moving within a rotating body B: combines the point's velocity relative to the intermediate frame, the base point O's absolute velocity, and the cross product of angular velocity with the displacement vector. v2pt_theory implements the two-point theorem (^N v^P = ^N v^O + ^N ω^B × r^OP) for two points both fixed in a rotating frame. Also provides partial_velocity method for computing partial velocities with respect to generalized speeds. The internal _pdict_list method performs graph traversal to find a connecting path between two points through their chain of relative position/velocity definitions; raises ValueError("No Connecting Path found between ...") when no such chain exists. set_vel and set_pos accept plain integer 0 as shorthand for a zero vector (coerced via `if value == 0: value = Vector(0)`). |
| `vector/printing.py` | Custom printers (VectorStrPrinter, VectorLatexPrinter, VectorPrettyPrinter) and init_vprinting for physics vector/dynamics notation. |
| `vector/vector.py` | Vector class for representing 3D vectors in reference frames, with operations for dot product, cross product, magnitude, normalization, expression in different frames, and partial differentiation via the `diff` method. The `diff` method computes partial derivatives with respect to a variable in a given frame using three-branch logic: (1) components already in the derivative frame are differentiated directly, (2) components in a different frame whose DCM does not depend on the variable are differentiated in place, (3) components whose frame's rotation matrix (DCM) depends on the differentiation variable are first re-expressed into the derivative frame, differentiated, then converted back — this is the core cross-frame differentiation logic. Also has its own pretty-printing and string-printing methods (_pretty, __str__) that handle per-component rendering (e.g., wrapping Add-type scalar coefficients in parentheses). The pretty-print logic lives here on the Vector class, not in printing.py. |
