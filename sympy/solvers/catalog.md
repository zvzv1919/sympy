# sympy/solvers — Catalog

> Part of [SymPy](../catalog.md). Equation solving: algebraic, ODE, PDE, recurrence, inequality, and Diophantine solvers.

| File | Summary |

| `__init__.py` | Package init that re-exports the public API from submodules (solve, dsolve, pdsolve, rsolve, diophantine, solveset, etc.). |
| `solvers.py` | Core equation-solving module providing `solve()` for algebraic/transcendental equations, `nsolve()` for numerical solving, and legacy helpers for linear systems (`solve_linear_system`, which does NOT validate that unknowns are proper symbols — it assumes valid symbol inputs) and undetermined coefficients. Also contains `solve_undetermined_coeffs(equ, coeffs, sym)` as a standalone public function for solving parametric univariate polynomial equalities: given an equation `p(x; a_1, ..., a_k) == q(x)` where both sides are univariate in `sym` but depend on free parameters `coeffs`, it expands the expression, collects terms by powers of `sym` (using `collect(..., sym, evaluate=False)`), then checks whether the variable has been fully eliminated from every collected coefficient — if so, the resulting system of parameter-only equations is solved via `solve()` (Gaussian elimination); if collection fails to eliminate the variable, it returns `None` (no solution). This power-decomposition and variable-elimination technique for determining unknown parameters is entirely in `solve_undetermined_coeffs` in `solvers.py`, NOT in `_invert` in `solveset.py` (which handles algebraic inversion of single expressions, not parametric coefficient matching). The internal `_solve()` function handles multi-symbol solving: when multiple unknowns are given, it first identifies a parametric free variable from `free_symbols` (a variable present in both the independent and dependent parts of the expression) and attempts coefficient matching via `solve_undetermined_coeffs` using that parameter, then falls back to per-variable linear resolution (`solve_linear`) for each symbol one at a time, discarding any solution whose expression depends on a previously solved variable (circular-dependency check), and falling back to non-linear solving for remaining symbols. This parametric-variable identification and coefficient-matching logic is unrelated to the bivariate substitution decomposition in `bivariate.py`. Also contains `solve_linear(lhs, rhs, symbols, exclude)`, which isolates a single variable that appears at first degree in the numerator of a rational expression. `solve_linear` uses a four-tuple return protocol to communicate distinct outcomes: `(0, 1)` means the expression is trivially independent of the symbols of interest (i.e., no symbol from `symbols`/not in `exclude` appears in the expression — the equation is vacuously satisfied or a tautology); `(0, 0)` means the expression depends on symbols but no valid first-degree root exists among them (the unknowns appear only non-linearly); `(symbol, solution)` means a first-degree isolation succeeded; `(n, d)` returns the raw numerator and denominator when no linear isolation was possible. The `(0, 1)` vs `(0, 0)` distinction — trivially independent vs. unsolvable — is the key design feature of this function's return protocol. This first-degree isolation and independence-vs-unsolvability classification is entirely in `solve_linear` in `solvers.py`, NOT in `solveset()` in `solveset.py` (which returns SymPy set objects rather than coded tuples). Note: `solve()` does NOT strictly validate that its symbol arguments are proper `Symbol` objects — for strict validation of unknowns (raising `ValueError` for numeric or non-symbol entries), see `linsolve()` in `solveset.py`. Also contains `checksol()` for verifying whether a candidate solution satisfies an equation — it returns `True`/`False`/`None`, where `None` means the check was inconclusive (it does NOT raise errors for indeterminate cases; contrast with `solveset()` in `solveset.py` which raises `NotImplementedError` for undetermined constant-zero relationships). Does NOT contain `dsolve` (see `ode.py`) or `linsolve` (see `solveset.py`). Also contains `_simple_dens`, which structurally extracts denominator bases from expressions (collecting bases of negative-exponent powers) — this is a static/structural extraction, NOT substitution-based singularity detection; for checking whether substituting a candidate root into an expression causes any subexpression to blow up (recursive substitution-based singularity validation), see `domain_check` in `solveset.py`. Contains `_tsolve` for transcendental equation solving, which includes the top-level Lambert W (product-logarithm) pattern recognition logic — it filters the equation's generators into exponential/logarithmic terms vs. polynomial terms, zeroes out the exponential parts to isolate and factor the polynomial remainder, then recombines the factored polynomial with the exponential terms to produce a form amenable to Lambert W reduction, before dispatching to `bivariate.py` for the actual Lambert W solving. If the Lambert W dispatch fails and there are exactly two generators, `_tsolve` falls back to bivariate substitution decomposition. This generator-separation and equation-restructuring logic is entirely within `_tsolve` in `solvers.py`, NOT in `_invert` or any function in `solveset.py`. |
| `solveset.py` | Set-based equation solving with `solveset()`, `linsolve()`, `nonlinsolve()`, and `linear_eq_to_matrix()`, operating over real or complex domains and returning solutions as SymPy sets. `linear_eq_to_matrix()` converts a list of linear equations and a list of symbols into augmented matrix form (A, b): it iterates over each equation, performs type dispatch on each entry — if the equation is an explicit `Equality` relational object (e.g., `Eq(lhs, rhs)`), it converts it to `lhs - rhs` before processing; plain expressions are used as-is — then extracts each symbol's coefficient and the constant term (`as_coeff_add`) to build the matrix row by row. This Equality-to-expression conversion and coefficient extraction for building augmented matrices is entirely in `linear_eq_to_matrix` in `solveset.py`, NOT in `solve()` in `solvers.py`. Also contains `domain_check()` for validating candidate roots against singularities: it recursively walks all subexpressions of the original equation, substituting the candidate point, and returns `False` if any subexpression becomes infinite — this catches division-by-zero cases that whole-expression substitution would miss. Important caveat: `domain_check` relies on the original unsimplified form of the equation, so automatic algebraic simplification (e.g., `x/x` → `1`) can hide singularities before the check runs; use `evaluate=False` to preserve the original structure. This singularity validation is distinct from denominator extraction (`_simple_dens`) in `solvers.py`. `solveset()` performs upfront edge-case handling before dispatching: boolean constants (True/False), constant expressions with no variables (checking `Eq(f, 0)` and raising `NotImplementedError` if the zero-equality relationship is unknown), auto-detection of the solve variable for univariate equations, and strict `Symbol` type validation on the unknown (raising `ValueError` for non-Symbol inputs). For constant/variable-free expressions that cannot be determined equal to zero, `solveset()` raises `NotImplementedError` — contrast with `checksol()` in `solvers.py`, which returns `None` for indeterminate cases without raising. Contains internal helpers for specific equation types: `_solve_trig` handles periodic/trigonometric equations by rewriting them in complex exponential form (`exp(I*symbol)`), substituting with a dummy variable to obtain an algebraic equation, solving that, and inverting back — if the substitution fails to eliminate the original variable, it returns a `ConditionSet` rather than raising an error; `_solve_as_rational` handles rational functions; `_solve_as_poly` uses polynomial root-finding techniques. `linsolve()` is the primary solver for simultaneous linear equation systems — accepts augmented matrices, (A, b) pairs, or equation lists and solves via Gauss-Jordan elimination. For underdetermined systems (more unknowns than independent constraints), `linsolve` returns parametric solutions where free variables appear as themselves in the solution tuple (e.g., `{(z - 1, -2*z + 2, z)}` means `z` is a free parameter that can take arbitrary values). For fully degenerate systems (all-zero coefficient matrix), `linsolve` returns the input symbols unchanged as the solution (e.g., `{(x, y)}`), representing that all variables are free. This underdetermined/degenerate linear system handling is in `linsolve` in `solveset.py`, NOT in `solve_linear_system` or `_solve_system` in `solvers.py`. Performs strict input validation on the unknowns argument: checks that each entry is a valid `Symbol` object (raising `ValueError` with a descriptive message for numeric, string, or other non-symbol entries passed as unknowns). Also validates non-empty systems and requires symbols to be provided. Prefer `linsolve` over the older `solve_linear_system` in `solvers.py`. Note: `_invert()` in this file handles algebraic inversion of single expressions (rewriting `f(x) = y` as `x = g(y)`), dispatching to `_invert_real` or `_invert_complex` based on domain. `_invert_real` recursively inverts real-valued expressions by type (Abs, Add, Mul, Pow, trig/hyperbolic functions): for power expressions `x**w`, it branches on whether the exponent is rational vs. irrational — when rational, it further inspects the numerator of the exponent: if the numerator is even, it includes both the positive and negative real roots in the solution set (union of `res` and `imageset(-n, res)`), accounting for both sign possibilities of the base (since `(-a)**(p/q) == a**(p/q)` when `p` is even); if the numerator is odd (or ±1), only the direct real root is returned. When the exponent is irrational (non-rational) and the base is not confirmed positive, it raises `ValueError` ("x**w where w is irrational is not defined for negative x"), enforcing a sign-of-base check specific to real-valued function inversion. This base-sign validation during power inversion is entirely in `_invert_real` in `solveset.py`, NOT in `solvers.py` (which contains `_as_base_q` for decomposing exponent rational parts, unrelated to inversion or base-sign checking). `_invert` does NOT perform generator classification, equation restructuring, or Lambert W / product-logarithm pattern recognition (that logic lives in `_tsolve` in `solvers.py`), and it does NOT handle multi-variable sequential solving or dependency tracking across unknowns (for that, see `_solve()` in `solvers.py`). Trigonometric/periodic equation solving via complex exponential substitution lives here in `_solve_trig`, NOT in `solvers.py`. |
| `ode.py` | Ordinary differential equation solver (`dsolve`) supporting separable, homogeneous, exact, linear, Bernoulli, Lie group, Liouville, power series, and nth-order constant-coefficient methods (including the "guessing"/undetermined-coefficients method, which builds candidate basis terms by iteratively differentiating the non-homogeneous term, stripping multiplicative scalar factors, and collecting unique terms until a fixed point is reached — this trial-set generation is distinct from recurrence relation solving in `recurr.py`), plus ODE classification (`classify_ode`) and solution checking. Classification includes parsing and validating initial/boundary conditions — distinguishing derivative conditions (Subs objects) from function-value conditions (AppliedUndef), and preprocessing to normalize the leading derivative coefficient. Also handles **systems of coupled ODEs** — both nonlinear two-equation first-order systems (autonomous, separable-product forms where each RHS factors into univariate functions times a shared factor, enabling conserved-quantity / first-integral computation) and **linear systems of 2 or 3 first-order coupled equations** with constant or variable coefficients. The three-equation first-order linear solver (`sysode_linear_3eq_order1`) dispatches to specialized type solvers; in particular, triangular (lower-triangular) systems where each successive equation introduces one more dependent variable are solved via **forward substitution** — solving the first equation alone, substituting into the second, then the third. **Two-equation second-order linear systems** (`sysode_linear_2eq_order2`) are also handled: this dispatcher normalizes the extracted coefficients from each equation (dividing through by the leading second-derivative coefficient `fc[i,func[i],2]`), builds a coefficient dictionary (`r['a1']`, `r['b1']`, ..., `r['e2']`), then dispatches to one of 11 type-specific sub-handlers (`_linear_2eq_order2_type1` through `_linear_2eq_order2_type11`) based on `match_['type_of_equation']`, including transformation-based reductions to first-order form. This coupled-ODE coefficient normalization and type dispatch is unrelated to algebraic polynomial system solving in `polysys.py`. These coupled-system solvers are in `ode.py`, NOT in `solvers.py` (which handles algebraic/transcendental equations, not differential equations). Contains internal helpers for Lie symmetry analysis, including utilities that strip unevaluated symbolic function calls from expressions (handling Add, Mul, Pow cases) and `infinitesimals()` for computing Lie group infinitesimal generators. See `deutils.py` for lower-level ODE/PDE utilities (equation preprocessing, order computation); see `decompogen.py` for general functional decomposition (unrelated to ODE systems). |
| `pde.py` | Partial differential equation solver (`pdsolve`) for first-order linear PDEs, with classification (`classify_pde`) and variable separation utilities (`pde_separate`, `pde_separate_add`, `pde_separate_mul`). `classify_pde` uses a two-pass pattern-matching strategy for first-order two-variable equations: it first attempts matching with Wild patterns that exclude the independent variables (identifying constant-coefficient cases — homogeneous or general), and if that match fails, retries with looser Wild patterns that only exclude the function and its derivatives (allowing spatially-varying coefficients, identifying variable-coefficient cases). This fallback mechanism is how the system distinguishes constant-coefficient from variable-coefficient PDEs. The variable separation functions split a multi-variable PDE into single-variable components: `pde_separate` is the main routine that accepts a strategy parameter ('add' or 'mul'), substitutes separated function products/sums into the equation, and delegates to an internal `_separate` helper — it also contains the strategy validation logic (checking whether the provided strategy is valid). `pde_separate_add` and `pde_separate_mul` are convenience wrappers. Also contains `checkpdesol` for verifying PDE solutions. Note: PDE classification and variable separation logic is entirely in `pde.py`, NOT in `ode.py` (which handles ODE classification via `classify_ode` and ODE system classification via `classify_sysode` — the latter classifies coupled ODE systems by type/order but does NOT perform variable separation or splitting of multi-variable equations into single-variable components). |
| `recurr.py` | Recurrence relation (difference equation) solver providing `rsolve()` and lower-level routines (`rsolve_poly`, `rsolve_ratio`, `rsolve_hyper`) for linear inhomogeneous recurrences with polynomial or rational coefficients. |
| `polysys.py` | Solvers for systems of **algebraic** polynomial equations (NOT differential equations) using Groebner bases, including specialized handling of bivariate biquadratic (degree ≤ 2 in each variable) algebraic systems via `solve_biquadratic`. These are purely algebraic equation systems — for coupled systems of ordinary differential equations (including second-order linear ODE pairs), see `ode.py`. |
| `inequalities.py` | Tools for solving polynomial, rational, and absolute-value inequalities and reducing systems of inequalities to solution sets. For rational inequalities (systems of fractional algebraic comparisons with numerator/denominator pairs), `solve_rational_inequalities` handles denominator-zero exclusion: it multiplies numerator by denominator to determine the sign of the fraction, solves the resulting polynomial inequality, then explicitly computes the zeros of the denominator and subtracts them from the solution intervals — ensuring that points where the denominator vanishes are excluded from the final result. This denominator-exclusion mechanism for inequality/comparison solving is specific to `inequalities.py` and is distinct from both `domain_check` in `solveset.py` (which validates individual candidate roots against singularities for equation solving) and `_simple_dens` in `solvers.py` (which only performs static structural extraction of denominator bases without computing or excluding zero points from solution intervals). Also contains `solve_poly_inequality` for single polynomial comparisons using root-multiplicity sign tracking — importantly, `solve_poly_inequality` handles the edge case of constant polynomials (expressions with no symbolic variables): if the polynomial `is_number`, it evaluates the relational comparison against zero and returns the full real line (`S.Reals`) if true, the empty set if false, or raises `NotImplementedError` with "could not determine truth value" if the truth value is indeterminate. This constant-expression indeterminacy handling is in `solve_poly_inequality` in `inequalities.py`, NOT in `solveset()` in `solveset.py` (which has its own separate constant-expression check for equation solving). Also contains `reduce_inequalities` as the top-level entry point for reducing systems of inequalities. `reduce_inequalities` performs important symbol preprocessing: symbols with no explicit real/complex assumption (`is_real is None`) are **replaced with real Dummy symbols** before processing, ensuring the inequality solver operates in a real domain — symbols explicitly marked as non-real raise a `TypeError`. It also prefilters inequalities (short-circuiting on boolean constants) and dispatches to the internal `_reduce_inequalities` helper, which categorizes each inequality by generator type into polynomial (handled by `reduce_rational_inequalities`), absolute-value (handled by `reduce_abs_inequalities`), or other (handled by `_solve_inequality`). This symbol-recasting and assumption-handling logic is entirely in `inequalities.py`, NOT in `solveset.py`. |
| `diophantine.py` | Solver for Diophantine equations (integer-valued polynomial equations) covering linear, binary quadratic (general second-degree two-variable: Ax²+Bxy+Cy²+Dx+Ey+F=0), ternary quadratic, Pythagorean, and sum-of-powers forms, with classification and parametric solution support. The main `diophantine()` entry-point function handles rational expressions (equations expressed as a ratio where the denominator contains unknowns): it splits the equation into numerator and denominator via `as_numer_denom()`, recursively solves both parts as separate Diophantine equations, removes denominator solutions from numerator solutions (set difference), then further filters remaining solutions by substituting back into the denominator to verify it doesn't evaluate to zero — this two-stage filtering (set subtraction plus substitution verification) ensures returned integer solutions never make the denominator vanish. This rational-expression denominator-exclusion logic is entirely within the `diophantine()` function in `diophantine.py`, NOT in `_simple_dens` in `solvers.py` (which only performs static structural extraction of denominator bases without solving or substitution-based verification), and NOT in `domain_check` in `solveset.py` (which validates individual candidate roots via recursive substitution-based singularity detection but does not solve the denominator as a separate Diophantine equation or perform set-difference filtering — `domain_check` is for general equation solving, not integer-valued polynomial equations). The binary quadratic solver branches on the discriminant (B²−4AC) into four cases: simple-hyperbolic, parabolic, perfect-square discriminant (recursive substitution reduction), and the general case which transforms the equation into a generalized Pell-type form (X²−DY²=N) via a coordinate-change matrix. The transformation to this difference-of-squares normal form is performed **recursively**: a dedicated internal function eliminates one term at a time — first the cross-product (xy) term, then the linear x term, then the linear y term — calling itself after each elimination step and **composing affine coordinate-change matrices** (a 2×2 linear part and a 2×1 translation) at each recursive return, so the final result is the accumulated product of all intermediate affine transforms. This recursive term-elimination and matrix-composition strategy for reducing a general second-degree equation to standard form is entirely in `diophantine.py`, NOT in `bivariate.py` (which handles transcendental/substitution decomposition of two-variable expressions, not quadratic-form reduction or matrix-based coordinate changes). In the general case, when the transformation matrix P has fractional (rational, non-integer) entries, the solver computes the LCM L of the denominators of P and Q, then iterates the fundamental Pell solution (T, U) to find the smallest power k such that T_k ≡ 1 (mod L) and U_k ≡ 0 (mod L), ensuring that back-substitution through the rational transformation matrix always yields integer solutions. |
| `decompogen.py` | General functional decomposition of expressions, decomposing `f(x)` into a composition chain `f_1(f_2(...f_n(x)))` for both polynomial and non-polynomial functions. Unrelated to ODE/PDE solving or decomposing differential equations into separable/factorable forms — for that, see `ode.py`. |
| `bivariate.py` | Lower-level helper routines for two-variable **transcendental** equation solving (NOT integer/Diophantine equations): (1) Lambert W (product-logarithm) equation reduction for transcendental functions (LambertW, exp, log), called by `_tsolve` in `solvers.py` after generator classification; and (2) `bivariate_type()`, which classifies a two-variable expression into composite substitution forms — testing whether `f(x, y)` can be decomposed as `P(u(x,y))` where `u` is one of `x*y`, `x+y`, `x*y+x`, or `x*y+y` — and returns the substitution expression, the reduced univariate polynomial, and a dummy variable, enabling reduction of a bivariate equation to a single-variable problem. This bivariate-type decomposition is specific to two-variable substitution patterns and is distinct from the general single-variable functional decomposition in `decompogen.py`. Does NOT handle quadratic forms, integer constraints, coordinate-change matrices, or Pell-type equation reductions — for two-variable integer (Diophantine) equations, see `diophantine.py`. See also `solvers.py` for the higher-level pattern recognition and dispatch logic. |
| `deutils.py` | Shared utility functions for ODE and PDE solvers, including `_preprocess` for preparing differential equation expressions (extracting function and variable), `ode_order` for computing differential equation order, and `_desolve` as a common dispatch wrapper used by both `dsolve` (ODE) and `pdsolve` (PDE). `_desolve` is the shared helper that coordinates equation solving: it preprocesses the equation, selects the appropriate classifier (`classify_ode` or `classify_pde`) based on the equation type, and manages hint resolution. Crucially, `_desolve` contains an internal pass-through optimization for recursive calls — when the `classify` kwarg is set to `False`, it skips calling the classifier entirely and instead reconstructs the hints dictionary directly from previously computed results passed through kwargs (match, order, default hint), avoiding redundant re-classification of the equation type during recursive solving. This classify-skip mechanism is the primary way the ODE/PDE solving pipeline avoids repeated work. `_preprocess` handles hint-based derivative evaluation: when `hint` is `None`, it skips all differentiation and returns the expression unchanged (early return); otherwise it selectively applies `.doit()` based on the hint suffix and variable intersection. `_preprocess` does NOT parse or validate initial/boundary conditions — initial condition parsing (distinguishing derivative conditions from function-value conditions, extracting boundary values) is performed by `classify_ode` in `ode.py`. Does NOT contain Lie symmetry helpers or expression manipulation for stripping function calls — those are in `ode.py`. |
| `benchmarks/bench_solvers.py` | Performance benchmark for `solve_linear_system` on a trivial identity-matrix system. |
