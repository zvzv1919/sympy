# sympy/solvers — Catalog

> Part of [SymPy](../catalog.md). Equation solving: algebraic, ODE, PDE, recurrence, inequality, and Diophantine solvers.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package init that re-exports the public API from submodules (solve, dsolve, pdsolve, rsolve, diophantine, solveset, etc.). |
| `solvers.py` | Core general-purpose equation-solving module providing `solve()` for algebraic/transcendental equations, `nsolve()` for numerical solving, `checksol()` for solution verification, and helpers for linear systems. `solve()` preprocesses equations (real/imaginary decomposition, symbol canonicalization, equation filtering) and dispatches to internal solvers. The equation-filtering step removes equations that have no symbols of interest: zero-valued constant equations are silently dropped, nonzero constant equations cause an immediate empty-list return (no solution exists), and non-constant symbol-free expressions are excluded to allow partial solutions. Includes `minsolve_linear_system` (sparsest solution for underdetermined linear systems), `solve_undetermined_coeffs` (polynomial coefficient matching). Internal `_solve` handles piecewise/conditional (branched) expressions by solving each branch independently and then filtering candidates: a candidate root is discarded if it satisfies the condition of any earlier branch (branch-priority domain check, preventing solutions that belong to a preceding piece from leaking through); it also handles polynomial generator analysis and change-of-variable strategies. Internal `_invert` recursively peels algebraic layers to isolate unknowns without domain awareness. Internal `_tsolve` handles transcendental equations (powers, logs, exponentials) but delegates all Lambert W-type equation solving (log+linear combinations, branch selection) to `bivariate.py` — it does not contain Lambert W case-splitting or solution logic itself. Internal `_solve_system` handles systems of equations. Note: does NOT handle Diophantine (integer) equation solving (see `diophantine.py`), set-based solving or inequality domain enforcement (see `solveset.py`), or bivariate composite classification (see `bivariate.py`). |
| `solveset.py` | Set-based equation solving with `solveset()` as the main entry point, plus `linsolve()`, `nonlinsolve()`, and `linear_eq_to_matrix()`, operating over real or complex domains and returning solutions as SymPy sets. **`solveset()` handles constant (variable-free) expressions early**: if the expression has no free symbols, it checks `Eq(f, 0)` — returning the full domain if true, EmptySet if false, or raising NotImplementedError if the zero-equality relationship is ambiguous/undetermined. **`solveset()` enforces domain restrictions for inequalities**: for complex domain it raises NotImplementedError immediately; for real domain it delegates to `solve_univariate_inequality` from `inequalities.py`, falling back to ConditionSet on failure. Internal `_solveset` dispatches to domain-specific solvers and performs post-solve validation (exempting RootOf objects). Provides `domain_check(f, symbol, p)` for validating candidate solutions against expression domains. `linsolve` solves systems of linear equations (given as equations, Matrix, or augmented matrix) via Gauss-Jordan elimination; for underdetermined systems it maps internally generated free parameters back to the caller's original unknown symbols so the infinite family of solutions is expressed in the user's variables. Internal `_solve_as_poly` solves equations using polynomial techniques (direct polynomial root-finding or change-of-variable reduction); its post-processing simplifies complex-valued solutions in discrete (finite) result sets by expanding them into real+imaginary form, but skips this simplification when any solution contains free symbols or is a RootOf object, since expanding symbolic solutions would make them more complicated. Internal helpers: `_invert_real` (domain-aware real inversion with sign handling for even exponents), `_solve_radical` (radical removal via `unrad`), `_solve_abs` (absolute value equations via case splitting), `_solve_trig` (solves periodic trigonometric/circular function equations by rewriting them into complex exponential form, substituting `y = exp(I*symbol)` to convert the equation into an algebraic polynomial in y, solving that polynomial, then inverting the substitution to recover solutions — this is the primary handler for trig-to-algebraic transformation). |
| `ode.py` | Ordinary differential equation (ODE / derivative equation) solver. `dsolve` is the main entry point for solving single-variable derivative equations; it uses a classification-first dispatch architecture where `classify_ode` analyzes the equation and returns an ordered tuple of applicable strategy hints without attempting to solve, and `dsolve` by default selects the first hint in this tuple — the ordering of hints in the tuple determines which strategy is applied when multiple approaches could work. Supports separable, homogeneous, exact, linear, Bernoulli, Lie group, Liouville, power series, and nth-order constant-coefficient methods (including undetermined coefficients with trial-term generation via iterative differentiation until the term set stabilizes, and variation of parameters), plus solution verification via `checkodesol`. The Lie group method (`ode_lie_group`) converts a first-order ODE to new coordinates via PDE solving; it contains a recursion guard that skips any infinitesimal pair whose eta/xi ratio simplifies to the ODE's right-hand side `h`, since the resulting PDE would require solving the original ODE again (ODE↔PDE infinite loop). Includes multiple Lie symmetry heuristics for finding infinitesimal generators: one assumes xi and eta are two-variable polynomials in x and y, computes the maximum polynomial degree from the total degree of the determining PDE's numerator, then iteratively constructs polynomial ansätze of increasing degree, substitutes into the PDE, collects monomial coefficients to form a linear system, solves for non-trivial coefficients, and scales free parameters to 1; another heuristic finds an auxiliary polynomial chi(x,y) satisfying a related PDE, then recovers xi and eta via polynomial division by h. |
| `pde.py` | Partial differential equation solver (`pdsolve`) for multi-variable (e.g. f(x,y)) first-order linear PDEs with constant or variable coefficients, with PDE-specific classification (`classify_pde`) and additive/multiplicative variable separation utilities. `classify_pde` returns an ordered tuple of applicable PDE-solving hints; when the equation has zero order (no derivatives of the unknown function present), it returns early with an empty tuple (or a dict with `'default': None` in dict mode) — no hints apply to purely algebraic expressions. Supports an 'all' meta-hint that iterates over every classification method, storing the exception object (e.g., NotImplementedError) as the dictionary value for any strategy that fails rather than raising it. `_handle_Integral` post-processes PDE solutions containing unevaluated integrals: hints ending with '_Integral' return the raw integral form untouched, the first-order linear constant-coefficient hint triggers full `doit()` evaluation and `simplify()`, and all other hint types return the expression unchanged. `checkpdesol` verifies whether a candidate expression satisfies a given PDE by substituting it in and simplifying; when no dependent function is provided, it first tries `_preprocess` on the equation, and if that fails (ValueError), falls back to extracting applied undefined functions from the solution's atoms — raising ValueError if it cannot find exactly one unique function. When the solution is not explicitly isolated for the dependent function, it attempts to solve for it, and if multiple roots result, recursively checks each one independently. |
| `recurr.py` | Recurrence relation (difference equation) solver providing `rsolve()` and lower-level routines (`rsolve_poly`, `rsolve_ratio`, `rsolve_hyper`) for linear inhomogeneous recurrences with polynomial or rational coefficients. |
| `polysys.py` | Solvers for *systems* (multivariate) of polynomial equations using Groebner bases, including specialized handling of bivariate biquadratic systems. Does not handle univariate polynomial root-finding or fallback logic (see `solvers.py`). |
| `inequalities.py` | Downstream solver for polynomial, rational, and absolute-value inequalities, called by `solveset()` after domain validation. Does NOT enforce domain restrictions or raise NotImplementedError for complex-domain inequalities (that is done by `solveset()` in `solveset.py`). When `solve_univariate_inequality` encounters an unsupported inequality type, it raises NotImplementedError — the fallback (returning a ConditionSet) is handled by the caller `solveset()` in `solveset.py`, not here. The system-level reducer preprocesses each input: Relational inputs are normalized to `lhs - rhs ≥/≤/= 0`; plain symbolic expressions are wrapped as `Eq(expr, 0)`; boolean True is dropped, False short-circuits. `solve_univariate_inequality` solves single-variable real-valued comparisons by substituting a real-constrained dummy, then partitioning the real line using roots and singularities to build the solution set. |
| `diophantine.py` | Solver for Diophantine equations (integer-valued polynomial equations) covering linear, quadratic, Pythagorean, and sum-of-powers forms, with classification and parametric solution support. The main `diophantine()` entry point handles expressions with unknowns in the denominator: it splits the equation via `as_numer_denom()`, independently solves the numerator and denominator as Diophantine equations, removes denominator-vanishing solutions by set subtraction, and further filters remaining solutions by substituting back into the denominator to confirm it is non-zero — ensuring no returned solution makes the original expression undefined. |
| `decompogen.py` | General functional decomposition of expressions, decomposing `f(x)` into a composition chain `f_1(f_2(...f_n(x)))` for both polynomial and non-polynomial functions. |
| `bivariate.py` | Bivariate equation helpers used internally by `solve()`: includes `bivariate_type` for classifying two-variable composite expressions and Lambert W-type transcendental solvers. Provides `_linab` which decomposes an expression into the form `a*X + b` where `X` is symbol-dependent and `a`, `b` are independent, with sign normalization that negates both `a` and `X` when the dependent factor has a negative leading sign. Core function `_solve_lambert` is where all Lambert W-type equation classification and case-splitting happens: it handles log-dominant terms (where the main transcendental is a logarithm) and exp-dominant terms separately, with distinct branching when lhs is a product vs. a sum; notably, when the dominant term is a log and lhs is a sum, the log-difference expression is computed differently depending on whether rhs is zero (`log(other) - log(other - lhs)`) or nonzero (`log(lhs - other) - log(rhs - other)`). `_lambert` is the low-level solver for equations already in the canonical form `a*log(b*X+c) + d*X + f = 0` (a mix of one logarithmic and one linear term in the unknown); it evaluates both real branches of the LambertW function (k=0 and k=-1), keeping the k=-1 solution only when it is real; it also handles a nested-logarithm edge case where the non-log remainder is itself a negated log — unwrapping one log layer and rewriting accordingly. Also provides `bivariate_type` which classifies a two-variable expression into one of four composite substitution forms — `x*y`, `x+y`, `a*x*y+b*y`, or `a*x*y+b*x` — by attempting variable substitutions and checking whether the result is free of both variables; for the product-plus-single-variable pattern (`a*x*y+b*y`), if the substitution fails for the initial variable ordering it swaps x and y and retries, implicitly covering the symmetric `a*x*y+b*x` case. |
| `deutils.py` | Shared utility functions for ODE and PDE (differential equation) solvers only, including `_preprocess` which evaluates derivatives not involving the target function (not general equation filtering — that is in `solvers.py`'s `solve()`), `ode_order` for computing differential equation order, and `_desolve` as the common solving dispatch engine called by both `dsolve` and `pdsolve`. `_desolve` handles all hint meta-options ('all', 'all_Integral', 'best'): it invokes the classifier, iterates over matching hints, and collects results. For the 'all_Integral' meta-hint, `_desolve` filters out non-integral strategy variants and also explicitly excludes special-case strategies that lack an '_Integral' counterpart (e.g. power series, Lie group, homogeneous coeff best). |
| `benchmarks/bench_solvers.py` | Performance benchmark for `solve_linear_system` on a trivial identity-matrix system. |
