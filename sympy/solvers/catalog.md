# sympy/solvers — Catalog

> Part of [SymPy](../catalog.md). Equation solving: algebraic, ODE, PDE, recurrence, inequality, and Diophantine solvers.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package init that re-exports the public API from submodules (solve, dsolve, pdsolve, rsolve, diophantine, solveset, etc.). |
| `solvers.py` | Core equation-solving module providing `solve()` for algebraic/transcendental equations, `nsolve()` for numerical solving, and legacy helpers for linear systems (`solve_linear_system`, which does NOT validate that unknowns are proper symbols — it assumes valid symbol inputs) and undetermined coefficients. The internal `_solve()` function handles multi-symbol solving: when multiple unknowns are given, it first identifies a parametric free variable from `free_symbols` (a variable present in both the independent and dependent parts of the expression) and attempts coefficient matching via `solve_undetermined_coeffs` using that parameter, then falls back to per-variable linear resolution (`solve_linear`) for each symbol one at a time, discarding any solution whose expression depends on a previously solved variable (circular-dependency check), and falling back to non-linear solving for remaining symbols. This parametric-variable identification and coefficient-matching logic is unrelated to the bivariate substitution decomposition in `bivariate.py`. Note: `solve()` does NOT strictly validate that its symbol arguments are proper `Symbol` objects — for strict validation of unknowns (raising `ValueError` for numeric or non-symbol entries), see `linsolve()` in `solveset.py`. Also contains `checksol()` for verifying whether a candidate solution satisfies an equation — it returns `True`/`False`/`None`, where `None` means the check was inconclusive (it does NOT raise errors for indeterminate cases; contrast with `solveset()` in `solveset.py` which raises `NotImplementedError` for undetermined constant-zero relationships). Does NOT contain `dsolve` (see `ode.py`) or `linsolve` (see `solveset.py`). Contains `_tsolve` for transcendental equation solving, which includes the top-level Lambert W (product-logarithm) pattern recognition logic — it filters the equation's generators into exponential/logarithmic terms vs. polynomial terms, zeroes out the exponential parts to isolate and factor the polynomial remainder, then recombines the factored polynomial with the exponential terms to produce a form amenable to Lambert W reduction, before dispatching to `bivariate.py` for the actual Lambert W solving. If the Lambert W dispatch fails and there are exactly two generators, `_tsolve` falls back to bivariate substitution decomposition. This generator-separation and equation-restructuring logic is entirely within `_tsolve` in `solvers.py`, NOT in `_invert` or any function in `solveset.py`. |
| `solveset.py` | Set-based equation solving with `solveset()`, `linsolve()`, `nonlinsolve()`, and `linear_eq_to_matrix()`, operating over real or complex domains and returning solutions as SymPy sets. Also contains `domain_check()` for validating candidate roots against singularities: it recursively walks all subexpressions of the original equation, substituting the candidate point, and returns `False` if any subexpression becomes infinite — this catches division-by-zero cases that whole-expression substitution would miss. Important caveat: `domain_check` relies on the original unsimplified form of the equation, so automatic algebraic simplification (e.g., `x/x` → `1`) can hide singularities before the check runs; use `evaluate=False` to preserve the original structure. This singularity validation is distinct from denominator extraction (`_simple_dens`) in `solvers.py`. `solveset()` performs upfront edge-case handling before dispatching: boolean constants (True/False), constant expressions with no variables (checking `Eq(f, 0)` and raising `NotImplementedError` if the zero-equality relationship is unknown), auto-detection of the solve variable for univariate equations, and strict `Symbol` type validation on the unknown (raising `ValueError` for non-Symbol inputs). For constant/variable-free expressions that cannot be determined equal to zero, `solveset()` raises `NotImplementedError` — contrast with `checksol()` in `solvers.py`, which returns `None` for indeterminate cases without raising. Contains internal helpers for specific equation types: `_solve_trig` handles periodic/trigonometric equations by rewriting them in complex exponential form (`exp(I*symbol)`), substituting with a dummy variable to obtain an algebraic equation, solving that, and inverting back — if the substitution fails to eliminate the original variable, it returns a `ConditionSet` rather than raising an error; `_solve_as_rational` handles rational functions; `_solve_as_poly` uses polynomial root-finding techniques. `linsolve()` is the primary solver for simultaneous linear equation systems — accepts augmented matrices, (A, b) pairs, or equation lists and solves via Gauss-Jordan elimination. Performs strict input validation on the unknowns argument: checks that each entry is a valid `Symbol` object (raising `ValueError` with a descriptive message for numeric, string, or other non-symbol entries passed as unknowns). Also validates non-empty systems and requires symbols to be provided. Prefer `linsolve` over the older `solve_linear_system` in `solvers.py`. Note: `_invert()` in this file handles algebraic inversion of single expressions (rewriting `f(x) = y` as `x = g(y)`) — it does NOT perform generator classification, equation restructuring, or Lambert W / product-logarithm pattern recognition (that logic lives in `_tsolve` in `solvers.py`), and it does NOT handle multi-variable sequential solving or dependency tracking across unknowns (for that, see `_solve()` in `solvers.py`). Trigonometric/periodic equation solving via complex exponential substitution lives here in `_solve_trig`, NOT in `solvers.py`. |
| `ode.py` | Ordinary differential equation solver (`dsolve`) supporting separable, homogeneous, exact, linear, Bernoulli, Lie group, Liouville, power series, and nth-order constant-coefficient methods (including the "guessing"/undetermined-coefficients method, which builds candidate basis terms by iteratively differentiating the non-homogeneous term, stripping multiplicative scalar factors, and collecting unique terms until a fixed point is reached — this trial-set generation is distinct from recurrence relation solving in `recurr.py`), plus ODE classification (`classify_ode`) and solution checking. Classification includes parsing and validating initial/boundary conditions — distinguishing derivative conditions (Subs objects) from function-value conditions (AppliedUndef), and preprocessing to normalize the leading derivative coefficient. Also handles **systems of coupled ODEs** — both nonlinear two-equation first-order systems (autonomous, separable-product forms where each RHS factors into univariate functions times a shared factor, enabling conserved-quantity / first-integral computation) and **linear systems of 2 or 3 first-order coupled equations** with constant or variable coefficients. The three-equation first-order linear solver (`sysode_linear_3eq_order1`) dispatches to specialized type solvers; in particular, triangular (lower-triangular) systems where each successive equation introduces one more dependent variable are solved via **forward substitution** — solving the first equation alone, substituting into the second, then the third. **Two-equation second-order linear systems** (`sysode_linear_2eq_order2`) are also handled: this dispatcher normalizes the extracted coefficients from each equation (dividing through by the leading second-derivative coefficient `fc[i,func[i],2]`), builds a coefficient dictionary (`r['a1']`, `r['b1']`, ..., `r['e2']`), then dispatches to one of 11 type-specific sub-handlers (`_linear_2eq_order2_type1` through `_linear_2eq_order2_type11`) based on `match_['type_of_equation']`, including transformation-based reductions to first-order form. This coupled-ODE coefficient normalization and type dispatch is unrelated to algebraic polynomial system solving in `polysys.py`. These coupled-system solvers are in `ode.py`, NOT in `solvers.py` (which handles algebraic/transcendental equations, not differential equations). Contains internal helpers for Lie symmetry analysis, including utilities that strip unevaluated symbolic function calls from expressions (handling Add, Mul, Pow cases) and `infinitesimals()` for computing Lie group infinitesimal generators. See `deutils.py` for lower-level ODE/PDE utilities (equation preprocessing, order computation); see `decompogen.py` for general functional decomposition (unrelated to ODE systems). |
| `pde.py` | Partial differential equation solver (`pdsolve`) for first-order linear PDEs, with classification (`classify_pde`) and variable separation utilities (`pde_separate`, `pde_separate_add`, `pde_separate_mul`). `classify_pde` uses a two-pass pattern-matching strategy for first-order two-variable equations: it first attempts matching with Wild patterns that exclude the independent variables (identifying constant-coefficient cases — homogeneous or general), and if that match fails, retries with looser Wild patterns that only exclude the function and its derivatives (allowing spatially-varying coefficients, identifying variable-coefficient cases). This fallback mechanism is how the system distinguishes constant-coefficient from variable-coefficient PDEs. The variable separation functions split a multi-variable PDE into single-variable components: `pde_separate` is the main routine that accepts a strategy parameter ('add' or 'mul'), substitutes separated function products/sums into the equation, and delegates to an internal `_separate` helper — it also contains the strategy validation logic (checking whether the provided strategy is valid). `pde_separate_add` and `pde_separate_mul` are convenience wrappers. Also contains `checkpdesol` for verifying PDE solutions. Note: PDE classification and variable separation logic is entirely in `pde.py`, NOT in `ode.py` (which handles ODE classification via `classify_ode` and ODE system classification via `classify_sysode` — the latter classifies coupled ODE systems by type/order but does NOT perform variable separation or splitting of multi-variable equations into single-variable components). |
| `recurr.py` | Recurrence relation (difference equation) solver providing `rsolve()` and lower-level routines (`rsolve_poly`, `rsolve_ratio`, `rsolve_hyper`) for linear inhomogeneous recurrences with polynomial or rational coefficients. |
| `polysys.py` | Solvers for systems of **algebraic** polynomial equations (NOT differential equations) using Groebner bases, including specialized handling of bivariate biquadratic (degree ≤ 2 in each variable) algebraic systems via `solve_biquadratic`. These are purely algebraic equation systems — for coupled systems of ordinary differential equations (including second-order linear ODE pairs), see `ode.py`. |
| `inequalities.py` | Tools for solving polynomial, rational, and absolute-value inequalities and reducing systems of inequalities to solution sets. For rational inequalities (numerator/denominator pairs), `solve_rational_inequalities` handles denominator-zero exclusion: it multiplies numerator by denominator to determine the sign of the fraction, solves the resulting polynomial inequality, then explicitly computes the zeros of the denominator and subtracts them from the solution intervals — ensuring that points where the denominator vanishes are excluded from the final result. This denominator-exclusion mechanism is specific to inequality solving and is distinct from `domain_check` in `solveset.py` (which validates individual candidate roots against singularities for equation solving). Also contains `solve_poly_inequality` for single polynomial comparisons using root-multiplicity sign tracking, and `reduce_inequalities` as the top-level entry point for reducing systems of inequalities. `reduce_inequalities` performs important symbol preprocessing: symbols with no explicit real/complex assumption (`is_real is None`) are **replaced with real Dummy symbols** before processing, ensuring the inequality solver operates in a real domain — symbols explicitly marked as non-real raise a `TypeError`. It also prefilters inequalities (short-circuiting on boolean constants) and dispatches to the internal `_reduce_inequalities` helper, which categorizes each inequality by generator type into polynomial (handled by `reduce_rational_inequalities`), absolute-value (handled by `reduce_abs_inequalities`), or other (handled by `_solve_inequality`). This symbol-recasting and assumption-handling logic is entirely in `inequalities.py`, NOT in `solveset.py`. |
| `diophantine.py` | Solver for Diophantine equations (integer-valued polynomial equations) covering linear, quadratic, Pythagorean, and sum-of-powers forms, with classification and parametric solution support. |
| `decompogen.py` | General functional decomposition of expressions, decomposing `f(x)` into a composition chain `f_1(f_2(...f_n(x)))` for both polynomial and non-polynomial functions. Unrelated to ODE/PDE solving or decomposing differential equations into separable/factorable forms — for that, see `ode.py`. |
| `bivariate.py` | Lower-level helper routines for two-variable equation solving: (1) Lambert W (product-logarithm) equation reduction for transcendental functions (LambertW, exp, log), called by `_tsolve` in `solvers.py` after generator classification; and (2) `bivariate_type()`, which classifies a two-variable expression into composite substitution forms — testing whether `f(x, y)` can be decomposed as `P(u(x,y))` where `u` is one of `x*y`, `x+y`, `x*y+x`, or `x*y+y` — and returns the substitution expression, the reduced univariate polynomial, and a dummy variable, enabling reduction of a bivariate equation to a single-variable problem. This bivariate-type decomposition is specific to two-variable substitution patterns and is distinct from the general single-variable functional decomposition in `decompogen.py`. See also `solvers.py` for the higher-level pattern recognition and dispatch logic. |
| `deutils.py` | Shared utility functions for ODE and PDE solvers, including `_preprocess` for preparing differential equation expressions (extracting function and variable), `ode_order` for computing differential equation order, and `_desolve` as a common dispatch wrapper used by both `dsolve` (ODE) and `pdsolve` (PDE). `_desolve` is the shared helper that coordinates equation solving: it preprocesses the equation, selects the appropriate classifier (`classify_ode` or `classify_pde`) based on the equation type, and manages hint resolution. Crucially, `_desolve` contains an internal pass-through optimization for recursive calls — when the `classify` kwarg is set to `False`, it skips calling the classifier entirely and instead reconstructs the hints dictionary directly from previously computed results passed through kwargs (match, order, default hint), avoiding redundant re-classification of the equation type during recursive solving. This classify-skip mechanism is the primary way the ODE/PDE solving pipeline avoids repeated work. `_preprocess` handles hint-based derivative evaluation: when `hint` is `None`, it skips all differentiation and returns the expression unchanged (early return); otherwise it selectively applies `.doit()` based on the hint suffix and variable intersection. `_preprocess` does NOT parse or validate initial/boundary conditions — initial condition parsing (distinguishing derivative conditions from function-value conditions, extracting boundary values) is performed by `classify_ode` in `ode.py`. Does NOT contain Lie symmetry helpers or expression manipulation for stripping function calls — those are in `ode.py`. |
| `benchmarks/bench_solvers.py` | Performance benchmark for `solve_linear_system` on a trivial identity-matrix system. |
