# SymPy — Catalog

SymPy is a pure-Python library for symbolic mathematics. It aims to be a full-featured computer algebra system (CAS) while keeping its code simple, comprehensible, and easily extensible. Its only hard dependency is mpmath (arbitrary-precision arithmetic). This version is **1.1.2.dev**.

| [assumptions/](assumptions/catalog.md) | Assumption *query handlers* (`AskHandler` classes) that evaluate predicates like `Q.positive`, `Q.finite`, `Q.imaginary` on composite expressions by dispatching on expression type (Add, Mul, Pow, exp, log). For example, `AskFiniteHandler.Pow` decides boundedness of exponentiation by checking base magnitude vs unity and exponent sign — **not** `functions/elementary/exponential.py` `ExpBase._eval_is_finite` which handles the `exp`-specific finiteness check (returns True for negative-infinite argument, False for positive-infinite). Also `assumptions/handlers/common.py` has `TautologicalHandler` which evaluates truth values of boolean connectives within the assumption system — `TautologicalHandler.Implies` reduces logical implication to disjunction (`~p | q`) before evaluation — **not** `core/facts.py` `Prover._process_rule` which processes static inference rules. Also `assumptions/handlers/sets.py` has `AskImaginaryHandler.log` with a special-case workaround: when the argument is `exp(I)` or `exp(-I)`, directly returns True for imaginary instead of relying on the nonpositive check which fails for these cases — **not** `functions/elementary/exponential.py` `exp.eval`. Also `assumptions/handlers/sets.py` has `AskRealHandler.Mul` which tracks realness of a product via XOR toggle when imaginary factors are found — if any factor is confirmed as **neither real nor imaginary**, it breaks out of the for-else loop returning None (indeterminate) — **not** `core/mul.py` `Mul._eval_is_real`. Also `assumptions/handlers/sets.py` has `AskAntiHermitianHandler.Mul` which checks whether a product of operators is anti-Hermitian — counts non-commutative factors and **bails out returning None** (indeterminate) if more than one factor is non-commutative, only yielding a definite answer when at most one non-commutative term is present — **not** `physics/quantum/anticommutator.py` `AntiCommutator.eval`. Also `assumptions/handlers/order.py` has `AskPositiveHandler.Add` which determines whether a sum is strictly positive — iterates over summands counting those that are non-negative (but not confirmed strictly positive), and returns True only when **all** terms are non-negative and at least one is strictly positive (`nonneg < len(expr.args)`) — **not** `core/add.py` `Add._eval_is_positive` which uses `_monotonic_sign` and infinite-term analysis. Also `assumptions/handlers/order.py` has `AskNegativeHandler._number` which checks strict negativity of numeric expressions — splits into real/imaginary parts, and when the imaginary part is symbolically nonzero but numerically evaluates to zero, still proceeds to check the real part rather than returning False — also guards against insufficient precision (`_prec == 1`) by returning None instead of making a comparison — **not** `core/relational.py` `Relational._eval_simplify`. Also `assumptions/refine.py` has `refine_Pow` for simplifying power expressions under assumptions — when the base is -1 and the exponent is a sum, classifies each additive term as even/odd, removes even terms, and adjusts the numerical coefficient differently depending on whether an **odd** count of odd terms (coeff+1 mod 2) vs **even** count (coeff mod 2) is present — **not** `core/power.py` `Pow._eval_refine`. Also `assumptions/refine.py` has `refine_atan2` which simplifies the two-argument inverse tangent under sign assumptions — dispatches on all sign combinations of both arguments (both negative → atan(y/x) - π, positive y + negative x → atan(y/x) + π, both zero → NaN, etc.) — **not** `functions/elementary/trigonometric.py` `atan2.eval` which handles standard evaluation without assumption context. Also `assumptions/handlers/matrices.py` has matrix property inference handlers (`AskFullRankHandler`, `AskOrthogonalHandler`, `AskUnitaryHandler`, `AskPositiveDefiniteHandler`, `AskUpperTriangularHandler`, `AskLowerTriangularHandler`, `AskDiagonalHandler`) that determine properties like full-rank, orthogonality, unitarity, and triangularity for compound matrix expressions (MatMul, Transpose, MatrixSlice) — e.g. `AskFullRankHandler.MatrixSlice` infers full-rank from the parent matrix's orthogonality rather than checking rank directly; `AskLowerTriangularHandler.MatrixSlice` and `AskUpperTriangularHandler.MatrixSlice` return None (indeterminate) when the submatrix slice is off-diagonal, and only delegate to the parent matrix's triangularity when on-diagonal — **not** `matrices/matrices.py` `MatrixBase.rank` which computes numeric rank, **not** `matrices/matrices.py` `MatrixBase.extract` which performs submatrix extraction without property inference. Also `ask.py` has `AssumptionKeys` class with `predicate_memo` (memoize_property)-decorated properties that return singleton `Predicate` objects for each query key (e.g. `Q.rational` defines membership in the rationals — numbers expressible as quotient of integers, `Q.fullrank` defines full-rank as all rows/columns linearly independent with nonzero determinant for square matrices, `Q.square`, `Q.diagonal`, `Q.orthogonal`, `Q.invertible`, `Q.hermitian`) — these **define** the predicate objects, **not** `core/assumptions.py` which defines the *rules* (`_assume_rules`), **not** `matrices/matrices.py` which implements the *computation* of rank/determinant. Also `ask.py` has `get_known_facts()` which defines the **lattice of logical entailment rules** between number-theoretic and set-membership properties (e.g. `integer → rational → algebraic → complex`, `transcendental ↔ complex ∧ ¬algebraic`, `prime ↔ integer ∧ positive ∧ ¬composite`, `zero → even`) — **not** `core/facts.py` which provides the low-level `FactRules` inference engine. Also `ask_generated.py` has `get_known_facts_dict()` (precomputed transitive-closure mapping from each predicate to the full set of predicates it implies, e.g. `Q.even → {Q.algebraic, Q.complex, Q.even, Q.extended_real, Q.hermitian, Q.integer, Q.rational, Q.real}`) and `get_known_facts_cnf()` (clausal/CNF form of the same rules) — these are auto-generated compressed representations of the entailment lattice, **not** `core/assumptions.py` `_assume_rules` which is the old-style per-object assumption system. **Not** where assumption *rules/facts* are defined — the implication/equivalence rules (e.g. `integer -> rational`, `zero -> even & finite`) and the `_assume_rules`/`_assume_defined` fact sets live in `core/assumptions.py`. Also `assumptions/handlers/sets.py` has `AskRationalHandler.Pow` which determines whether a power expression is rational — when the exponent is an integer, delegates to base rationality; when the exponent is rational and the base is **prime**, returns False (irrational, since roots of primes are irrational) — **not** `functions/elementary/exponential.py` `ExpBase._eval_is_rational`. **Not** `core/cache.py` which provides general-purpose caching (`cacheit`). |

| `abc.py` | Exports all single Latin and Greek letters as pre-defined `Symbol` objects for convenient interactive use (`from sympy.abc import x, y`) |
| `conftest.py` | Pytest configuration: pytest-level `--split` hook (`process_split` for dividing collected pytest items), cache clearing between modules, architecture/ground-type reporting, and disabled-module skipping. **Note**: the primary test file selection, slow-mode shuffling with fixed seed, and `split` partitioning logic is in `utilities/runtests.py` `test`/`_test` — conftest.py only handles the pytest adapter layer. |
| `galgebra.py` | Deprecated stub that raises `ImportError` directing users to the standalone `galgebra` package |
| `release.py` | Defines the version string `__version__ = "1.1.2.dev"` |
| `this.py` | Easter egg — prints "The Zen of SymPy" (ROT-13 encoded aphorisms about the project's philosophy) |
