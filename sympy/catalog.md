# SymPy — Catalog

SymPy is a pure-Python library for symbolic mathematics. It aims to be a full-featured computer algebra system (CAS) while keeping its code simple, comprehensible, and easily extensible. Its only hard dependency is mpmath (arbitrary-precision arithmetic). This version is **1.1.2.dev**.

## Subdirectories

| Directory | Description |
|-----------|-------------|
| [algebras/](algebras/catalog.md) | Abstract algebra structures (e.g. quaternions) |
| [assumptions/](assumptions/catalog.md) | Assumption *query handlers* (`AskHandler` classes) that evaluate predicates like `Q.positive`, `Q.finite`, `Q.imaginary` on composite expressions by dispatching on expression type (Add, Mul, Pow, exp, log). For example, `AskFiniteHandler.Pow` decides boundedness of exponentiation by checking base magnitude vs unity and exponent sign. Also `ask.py` has `AssumptionKeys` class with `predicate_memo` (memoize_property)-decorated properties that return singleton `Predicate` objects — memoization guarantees exactly one object per query key (e.g. Q.orthogonal, Q.invertible, Q.hermitian) so that assumption handlers are registered on unique objects. `Q.orthogonal` defines the property M^T M = I and notes it implies invertibility. **Not** where assumption *rules/facts* are defined — the implication/equivalence rules (e.g. `integer -> rational`, `zero -> even & finite`) and the `_assume_rules`/`_assume_defined` fact sets live in `core/assumptions.py`. **Not** `core/cache.py` which provides general-purpose caching (`cacheit`). |
| [benchmarks/](benchmarks/catalog.md) | Performance benchmarks for SymPy internals. `bench_meijerint.py` contains string-form benchmark expressions for Meijer G-function integration including Mellin, Laplace, Fourier, and inverse Fourier transforms with different sign assumptions (positive, negated-positive, negative symbols) on the output variable. |
| [calculus/](calculus/catalog.md) | Calculus operations: finite differences (`finite_diff.py` with `as_finite_diff`), singularities, continuity utilities, and `calculus/util.py` with `continuous_domain` (determines intervals where a function is continuous by constraining the domain: requires square-root bases ≥ 0, logarithm arguments > 0, then removes singularities — **not** `solvers/solveset.py` `domain_check`), `AccumulationBounds` (`AccumBounds.__lt__` returns True/False/None three-valued logic for range ordering — None when ranges overlap, `__contains__` for membership testing — **not** `sets/sets.py` `Set.contains`, **not** `plotting/intervalmath/interval_arithmetic.py` `interval` which is a separate interval class for plotting), `not_empty_in` (finding non-empty domain portions). See also `series/` for limits and `core/expr.py` for the `series()` method. |
| [categories/](categories/catalog.md) | Category theory: objects, morphisms (`NamedMorphism.__new__`, `Morphism.__mul__` for abstract morphism composition), diagrams, and Xy-pic diagram drawing. **Not** for ring-module homomorphisms — those are in `polys/agca/homomorphisms.py`. |
| [codegen/](codegen/catalog.md) | Code generation **infrastructure**: abstract syntax tree nodes (`ast.py` with `Assignment`, `CodeBlock`, `Variable`, `Type`), code wrappers, and algorithm-to-code translation scaffolding. **Not** where language-specific code *printers* live — Julia/Octave/Fortran/C/LLVM/Rust/JS/GLSL printers are in `printing/`. **Not** the higher-level routine-generation API — `make_routine` and `CCodeGen`/`FCodeGen` live in `utilities/codegen.py`. |
| [combinatorics/](combinatorics/catalog.md) | Discrete structures and group theory: `Permutation`, `PermutationGroup` (with `is_subgroup`, orbit/stabilizer algorithms), `Polyhedron` (3D solid symmetry groups), `free_group.py` (`FreeGroup.contains`), `Partition`/`IntegerPartition` (`partitions.py` with `Partition.__eq__`, `random_integer_partition` which raises ValueError for n < 1 — **not** `utilities/enumerative.py` which has `PartComponent` for low-level multiset partition enumeration), Graycode, and tensor canonicalization (`tensor_can.py` with `canonicalize` and `double_coset_can_rep` — reduces free indices, solves double-coset representative problem on dummy indices with metric-symmetry-aware orbit computation (splits even/odd index positions when metric lacks interchange symmetry), lifts solution back — **not** `tensor/index_methods.py` `get_contraction_structure`, **not** `tensor/tensor.py`). **Not** for combinatorial *number sequences* or *counting functions* — those live in `functions/combinatorial/`. |
| [concrete/](concrete/catalog.md) | Concrete mathematics: symbolic sums (`summations.py` with `Sum._eval_derivative`, `Sum.is_convergent` with integral/Dirichlet tests, `Sum.is_absolutely_convergent` which simply delegates to `is_convergent` on absolute-valued terms, `Sum.euler_maclaurin`, `telescopic` for detecting and evaluating collapsing/canceling sums via two-phase approach: pattern matching then equation solving, with validation that match results are integers — **not** `series/formal.py`), products, `gosper.py` (`gosper_sum` for Gosper's algorithm), `guess.py` (`find_simple_recurrence_vector` for detecting linear recurrence relations in number sequences with sign normalization when all remaining elements are zero — **not** `series/sequences.py` `SeqBase.find_linear_recurrence`), and the `ExprWithLimits` base class (`expr_with_limits.py` with `ExprWithLimits._eval_subs` for substitution in bounded expressions — **not** `core/basic.py` `Basic._eval_subs`). |
| [core/](core/catalog.md) | Core symbolic engine: `Symbol`, `Number`, `Expr`, `Add`, `Mul`, `Pow`, caching, evaluation, and compatibility. `core/exprtools.py` has `factor_nc` for noncommutative factoring, `_monotonic_sign` (determines whether a multivariate expression has a definite sign by substituting sign-representative placeholder values including epsilon for boundary cases, then cleaning up); `core/sympify.py` has `kernS` (prevents automatic distribution of numeric coefficients over parenthesized sums during string-to-expression conversion by inserting dummy placeholder symbols — **not** `parsing/sympy_parser.py`); `core/assumptions.py` has the master `_assume_rules` fact table and `_assume_defined` set (including the standalone 'polar' property with no inference rules); `core/power.py` has `Pow._eval_as_leading_term`, `Pow._eval_nseries` (handles reciprocal/negative-power series via iterative geometric-series-like expansion that multiplies by (-rest) to build terms, with carefully computed loop bounds — **not** `polys/ring_series.py` `_series_inversion1`), `Pow._eval_subs` (handles partial exponent substitution — when the exponent is an Add, splits matched and unmatched terms into a product), `integer_nthroot` (integer nth root via Newton's method with OverflowError fallback using log-base-2 and bit shifting — **not** `polys/ring_series.py`); `core/compatibility.py` has `ordered()` (canonical ordering function — **not** in `utilities/iterables.py`); `core/basic.py` has `Basic.__eq__`, `Basic._eval_subs`, `Basic.replace` (pattern-based subexpression substitution with `exact` flag that controls whether Wild placeholders can match zero to avoid non-intuitive results — **not** `unify/core.py`); `core/evalf.py` has arbitrary-precision numerical evaluation functions including `evalf_trig` (handles catastrophic cancellation for sin/cos of large arguments by iteratively increasing working precision near roots of periodic functions — **not** `functions/elementary/trigonometric.py` which defines the symbolic function classes). |
