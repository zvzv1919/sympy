# sympy/vector — Catalog

> Part of [SymPy](../catalog.md). Vector algebra and calculus in curvilinear coordinate systems.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Public API surface for the vector module; re-exports all core classes and helper functions (Vector, Dyadic, CoordSys3D, Del, Point, orienters, operators, etc.). |
| `basisdependent.py` | Abstract base classes (`BasisDependent`, `BasisDependentAdd`, `BasisDependentMul`, `BasisDependentZero`) providing the shared core constructors and arithmetic for all coordinate-dependent quantities (vectors and dyadics). `BasisDependentMul.__new__` is the central scalar-times-directional multiplication constructor: it counts non-scalar operands and raises `ValueError` if more than one directional quantity appears (preventing e.g. two vectors or two dyadics from being multiplied together), handles zero, and distributes scalar multiplication over sums (`BasisDependentAdd`). `BasisDependentAdd.__new__` collects and merges like-basis components, removes zeros, and coerces generic `Mul`/`Add` into the appropriate domain subclass. The concrete subclasses (`VectorMul`, `DyadicMul`, etc.) in `vector.py` and `dyadic.py` inherit these constructors without overriding them. Division (`__div__`) is defined here but delegates entirely to a subclass-specific `_div_helper` (e.g., `_vect_div` in `vector.py`). |
| `coordsysrect.py` | Defines `CoordSys3D` (and deprecated `CoordSysCartesian`), the 3-D coordinate system class. This is the primary file for creating new oriented coordinate systems: `orient_new_body` creates a new coordinate system from an existing one by applying three successive body-fixed (intrinsic) rotations covering both Euler angle and Tait-Bryan angle sequences; `orient_new_space` does the same with space-fixed (extrinsic) rotations; `orient_new_axis` orients about a single arbitrary axis; `orient_new_quaternion` orients via quaternion parameters. All orient_new_* methods delegate rotation-matrix construction to orienters in `orienters.py` but the coordinate-system creation, origin management, and the user-facing API for building new frames live here. The `orient_new` core factory accepts an `Orienter` or iterable of orienters and composes their rotation matrices; it applies `trigsimp` for canonical form only when a single orienter is given — when an iterable of multiple orienters is provided, the composed matrix is NOT simplified, creating an asymmetry that can cause equivalent coordinate systems to compare differently. `rotation_matrix()` retrieves and composes pre-built DCMs along the frame tree. `scalar_map()` returns a substitution dictionary mapping base scalars between frames. Also handles curvilinear coordinate transformations and origin management. |
| `deloperator.py` | Implements the `Del` (nabla) vector differential operator with gradient, divergence, and curl methods that each eagerly compute and return a fully evaluated Vector or scalar expression (not callables). The divergence (`dot`) method uses a module-level helper `_diff_conditional` that avoids creating unnecessary `Derivative` expressions: it first re-expresses the component in the target system, checks whether the coordinate variable actually appears in the expression, and returns zero immediately if not — in contrast, the gradient method always wraps every component in a `Derivative`. The curl (`cross`) method also always creates `Derivative` instances without this conditional check. Note: the deferred-computation pattern where dotting a Vector with Del returns a callable closure (directional derivative operator) is implemented in `Vector.dot` in `vector.py`, not here. |
| `dyadic.py` | Defines the `Dyadic` class hierarchy (`BaseDyadic`, `DyadicAdd`, `DyadicMul`, `DyadicZero`) for representing and manipulating dyadic tensors; `DyadicMul`/`DyadicAdd` inherit their `__new__` constructors (including multiplication validation and sum distribution) from `BasisDependentMul`/`BasisDependentAdd` in `basisdependent.py` and add no constructor logic of their own. `Dyadic.dot` computes Dyadic·Vector (right-multiplying a dyadic by a vector, short-circuits when the right operand is a zero vector) or Dyadic·Dyadic; it does NOT handle Vector·Dyadic (left-multiplying a vector into a dyadic) — that dispatch lives in `Vector.dot` in `vector.py`. Includes `to_matrix` for converting a dyadic to a numeric SymPy Matrix (not for computing vector cross products). |
| `functions.py` | Utility functions for vector analysis: `express` (the top-level orchestrator for re-expressing a Vector, Dyadic, or scalar in another coordinate frame — for Vectors it performs a two-step process: first collects foreign coordinate systems and substitutes their base scalars via scalar_map when variables=True, then applies rotation matrices to transform each foreign-frame component into the target basis (note: the per-frame grouping of components used internally by `express` relies on `Vector.separate` in `vector.py`); for Dyadics it allows specifying two different target frames), `matrix_to_vector` (converts a 3×1 numeric column matrix into a Vector by pairing each element with the corresponding basis direction of a given coordinate system), `is_conservative` and `is_solenoidal` (check whether a vector field is curl-free or divergence-free respectively; both short-circuit to return True immediately for the zero vector without computing curl/divergence, and raise TypeError for non-Vector inputs), `scalar_potential`, `scalar_potential_difference`, `directional_derivative`, and `laplacian`. |
| `operators.py` | Defines unevaluated symbolic operator classes (`Gradient`, `Divergence`, `Curl`) and their evaluated counterparts (`gradient`, `divergence`, `curl`). |
| `orienters.py` | Orienter classes (`AxisOrienter`, `BodyOrienter`, `SpaceOrienter`, `QuaternionOrienter`) that each construct a single 3×3 direction-cosine matrix (DCM) from rotation parameters — these are pure rotation-matrix builders and do not create coordinate systems (coordinate system creation lives in `coordsysrect.py`). `ThreeAngleOrienter.__new__` uses a class-level `_in_order` flag — `BodyOrienter` sets `_in_order = True` causing forward-order multiplication (`_rot(a1)*_rot(a2)*_rot(a3)`), while `SpaceOrienter` sets `_in_order = False` causing reverse-order multiplication (`_rot(a3)*_rot(a2)*_rot(a1)`); the result is then transposed to produce the final DCM. Also validates rotation order strings (converts X/Y/Z to 1/2/3, checks against approved Euler/Tait-Bryan sequences). `_rot` builds elementary single-axis rotation matrices. |
| `point.py` | Defines the `Point` class representing a point in 3-D space, with methods for computing position vectors between points (`position_wrt`), creating child points (`locate_new`), and returning scalar coordinate tuples of a point in a given frame (`express_coordinates` — returns a tuple of numbers, not a Vector). |
| `scalar.py` | Defines `BaseScalar`, the coordinate symbol (base scalar) class attached to a `CoordSys3D`. Implements derivative evaluation (`_eval_derivative`): returns 1 when differentiating a coordinate component with respect to itself, 0 otherwise — this is where symbolic differentiation of individual coordinate scalars is resolved. Also provides custom pretty-printing and LaTeX support. |
| `vector.py` | Defines the `Vector` class hierarchy (`BaseVector`, `VectorAdd`, `VectorMul`, `VectorZero`, `Cross`, `Dot`) with dot/cross product operations, outer product support, and the `separate` method (decomposes a vector spanning multiple reference frames into a dict mapping each `CoordSys3D` to its constituent `Vector` by grouping and accumulating components per frame). `Vector.dot` is the central dot-product dispatcher: it handles Vector·Vector (returns scalar), Vector·Dyadic (left-multiplying a vector into a rank-2 tensor — short-circuits to `Vector.zero` when self is `VectorZero` without iterating; otherwise iterates over the dyadic's basis-pair components, dots the first element of each pair with self, and accumulates weighted results as a Vector), and Vector·Del (returns a Python callable/closure that computes the directional derivative of a field along the vector; handles both scalar and vector-valued fields — notably, when the derivative result is zero and the input is a Vector, it returns `Vector.zero` instead of scalar `0`). Also contains `_vect_div`, the division validation and dispatch helper that raises `TypeError` for vector-by-vector division, `ValueError` for division by zero, and returns a `VectorMul` for valid scalar division. The cross product implementation uses a custom inline 3×3 determinant helper (not SymPy's Matrix, which cannot hold basis-dependent vector elements) and iterates over coordinate systems to handle operands from different reference frames. Also handles cross products with dyadics by iterating over dyadic basis-pair components. |
