# sympy/vector — Catalog

> Part of [SymPy](../catalog.md). Vector algebra and calculus in curvilinear coordinate systems.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Public API surface for the vector module; re-exports all core classes and helper functions (Vector, Dyadic, CoordSys3D, Del, Point, orienters, operators, etc.). |
| `basisdependent.py` | Abstract base class `BasisDependent` providing shared arithmetic operators (`__add__`, `__sub__`, `__mul__`, `__div__`, and their reflected/right-hand counterparts `__radd__`, `__rsub__`, `__rmul__`, `__rdiv__`), simplification (`simplify`, `trigsimp`), evaluation (`evalf`), and calculus helpers (`_eval_derivative`, `_eval_Integral`) for vectors and dyadics. Division *of* a vector/dyadic by a scalar is delegated to subclass `_div_helper` (see `dyadic.py::_dyad_div` and `vector.py::_vect_div`), but the **reflected division** operator `__rdiv__` / `__rtruediv__` (where a vector or dyadic appears as the *divisor* on the right-hand side, e.g. `scalar / vector`) is handled here — it *returns* a `TypeError` instance rather than raising it. This is the authoritative location for all reflected-operator and shared arithmetic behavior on basis-dependent quantities. |
| `coordsysrect.py` | Defines `CoordSys3D` (and deprecated `CoordSysCartesian`), the 3-D Cartesian coordinate system class. Owns the `rotation_matrix` method that computes direction cosine matrices (DCMs) between any two frames by traversing the parent-chain tree and composing intermediate transformations. Also provides `orient_new_*` factory methods (`orient_new_axis`, `orient_new_body`, `orient_new_space`, `orient_new_quaternion`) that **create a new derived reference frame** from an existing one using various rotation parameterizations: axis-angle, body-fixed (Tait-Bryan / Euler intrinsic) rotations about the moving frame's axes, space-fixed (extrinsic) rotations about the original parent frame's axes, and quaternion (four-parameter finite-rotation about a unit axis, parameterized as cos(θ/2) and λ·sin(θ/2) components — the classical Euler–Rodrigues / half-angle representation). This is the authoritative file for any question about *constructing or orienting a new coordinate system* **and** for understanding *how* the different rotation parameterizations (body-fixed vs space-fixed vs axis-angle vs quaternion) conceptually differ. The docstrings in this file contain the **mathematical definitions** of each parameterization (e.g., q0 = cos(θ/2), q1 = λ_x sin(θ/2), q2 = λ_y sin(θ/2), q3 = λ_z sin(θ/2) for the quaternion/finite-rotation case; angle sequences and axis-selection rules for body/space rotations), **step-by-step equivalence examples** showing which reference frame's unit vectors each successive rotation is applied about, and explicit **See Also cross-references** between `orient_new_space` and `orient_new_body` that clarify how they relate. In particular, the `orient_new_space` docstring explains that space-fixed (extrinsic) rotations always rotate about the *parent* frame's fixed unit vectors (N.i, N.j, N.k), while the `orient_new_body` docstring explains that body-fixed (intrinsic / Euler-angle) rotations rotate about the *moving* frame's axes — this conceptual distinction is documented here, not in `orienters.py`. Note: while this file owns the rotation conventions and their documentation, the low-level detail of how the composite direction-cosine matrix is assembled (forward vs reverse matrix-multiplication order) lives in `orienters.py`. |
| `deloperator.py` | Implements the `Del` (nabla) vector differential operator class and a module-level helper `_diff_conditional`. The `Del` class provides `gradient`, `dot` (divergence), and `cross` (curl) methods that apply the operator to a given field directly. The `dot` method computes divergence by extracting each component via `vect.dot(unit_vector)` and passing it through `_diff_conditional`. The module-level function `_diff_conditional(expr, base_scalar)` is the **conditional differentiation helper**: it first re-expresses the expression in the coordinate system that `base_scalar` belongs to, then checks whether the base scalar actually appears among the atoms of the re-expressed form; if present, it returns a `Derivative`; if absent, it **skips partial differentiation entirely and returns zero** (`S(0)`). This is the authoritative location for the logic that decides whether to differentiate or short-circuit to zero during divergence computation. Note: when the nabla operator appears as an *operand* of a dot or cross product with a `Vector` (e.g., `v & C.delop`), the dispatch lives in `vector.py`'s `Vector.dot`/`Vector.cross`, but the actual differentiation logic and zero-skipping lives here. |
| `dyadic.py` | Defines the `Dyadic` class hierarchy (`BaseDyadic`, `DyadicAdd`, `DyadicMul`, `DyadicZero`) for representing and manipulating dyadic tensors. Contains `_dyad_div`, the forward-division helper that handles dividing a dyadic *by* a scalar (and raises `TypeError` for dyadic÷dyadic). `Dyadic.cross` handles `Dyadic × Vector` (dyadic on the left), while the reverse direction `Vector × Dyadic` (vector on the left, including zero-vector short-circuiting) is dispatched from `vector.py::Vector.cross`. Note: the *reflected* division operator (where a dyadic is the divisor, e.g. `scalar / dyadic`) is defined in `basisdependent.py::BasisDependent.__rdiv__`, not here. |
| `functions.py` | Utility functions for vector analysis: `express` (re-express a vector/dyadic/scalar entirely in a single target coordinate system), `orthogonalize` (Gram-Schmidt process to make a sequence of vectors mutually orthogonal/orthonormal — detects linearly dependent inputs by checking if a projected term simplifies to zero, with a noted performance concern around `simplify`), `matrix_to_vector`, `_path` (tree traversal to find the common ancestor between two coordinate systems or points), `is_conservative`, `is_solenoidal`, `scalar_potential`, `scalar_potential_difference`, `directional_derivative`, and `laplacian`. Note: `express` converts to one frame; to decompose a vector into per-frame constituents without re-expressing, see `vector.py::Vector.separate`. |
| `operators.py` | Defines unevaluated symbolic operator classes (`Gradient`, `Divergence`, `Curl`) and their evaluated counterparts (`gradient`, `divergence`, `curl`). |
| `orienters.py` | Orienter classes (`AxisOrienter`, `BodyOrienter`, `SpaceOrienter`, `QuaternionOrienter`) that each compute a single rotation matrix for one orientation step. These are low-level building blocks—they do **not** create new coordinate systems, new reference frames, or compose multi-step DCMs between arbitrary frames. **This file owns the low-level matrix-multiplication mechanics** (forward vs reverse product order) that distinguish intrinsic from extrinsic rotations at the linear-algebra level. The `ThreeAngleOrienter` superclass validates rotation-order strings and builds the composite direction cosine matrix from three successive single-axis rotations; a boolean class flag controls whether the individual rotation matrices are multiplied in forward order (intrinsic/body-fixed: R1·R2·R3) or reverse order (extrinsic/space-fixed: R3·R2·R1). `BodyOrienter` and `SpaceOrienter` are thin subclasses that each set this flag to select the appropriate multiplication convention. Questions specifically about rotation-order validation, parsing, or the matrix-product assembly order should look here. For creating/constructing a new coordinate-system frame via these rotation types, see `coordsysrect.py` which owns the `orient_new_*` factory methods. |
| `point.py` | Defines the `Point` class representing a point in 3-D space, with methods for computing displacement (position) vectors between points and creating new points. The `position_wrt` method computes the position vector of one Point relative to another by traversing the point tree (via `_path` from `functions.py`); critically, it also accepts a `CoordSysCartesian`/`CoordSys3D` object as the "other" argument, silently converting it to that coordinate system's origin point before computing the displacement — this type-dispatch edge case is handled here, not in `vector.py`. `locate_new` creates a new child point at a given vector offset from the current point. Questions about relative position/displacement between spatial locations, or about passing a coordinate system where a point is expected, belong here. See `vector.py` for vector arithmetic/projection operations that do **not** involve the point tree. |
| `scalar.py` | Defines `BaseScalar`, the coordinate symbol (base scalar) class attached to a `CoordSys3D`, with custom pretty-printing and LaTeX support. |
| `vector.py` | Defines the `Vector` class hierarchy (`BaseVector`, `VectorAdd`, `VectorMul`, `VectorZero`, `Cross`, `Dot`) with dot/cross product operations, outer product, projection, matrix conversion (`to_matrix`), and the `separate` method that decomposes a vector spanning multiple reference frames into a per-frame mapping of constituent parts. `Vector.dot` is the **primary dispatch point** for inner-product operations involving vectors, dyadics, *and* the Del (nabla) operator — when a vector is dotted with a `Del` instance, `Vector.dot` returns a directional-derivative closure that includes type-consistency logic (e.g., ensuring a zero result on a vector-valued field returns the zero *vector* object rather than scalar zero). `Vector.cross` is the **primary dispatch point** for cross products of a vector with another vector, a Dyadic (rank-2 tensor), or the Del operator — when the other operand is a `Dyadic`, `Vector.cross` iterates through the dyadic's components and builds the output dyadic, with a special short-circuit that returns the zero dyadic immediately when the vector is `VectorZero`. For re-expressing a vector entirely in one frame, see `functions.py::express`. |
