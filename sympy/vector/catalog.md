# sympy/vector — Catalog

> Part of [SymPy](../catalog.md). Vector algebra and calculus in curvilinear coordinate systems.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Public API surface for the vector module; re-exports all core classes and helper functions (Vector, Dyadic, CoordSys3D, Del, Point, orienters, operators, etc.). |
| `basisdependent.py` | Abstract base class `BasisDependent` providing shared arithmetic (add, mul, sub), simplification, and printing logic for vectors and dyadics. Division (`__div__`) is defined here but delegates entirely to a subclass-specific `_div_helper` (e.g., `_vect_div` in `vector.py`). |
| `coordsysrect.py` | Defines `CoordSys3D` (and deprecated `CoordSysCartesian`), the 3-D coordinate system class. Owns `rotation_matrix()` which retrieves and composes pre-built DCMs along the frame tree (parent/child shortcuts and tree traversal) — it does not construct DCMs from rotation parameters itself (that is done by orienter classes in `orienters.py`). `rotation_matrix()` raises `TypeError` if the argument is not a `CoordSysCartesian` instance. Also provides `scalar_map()` which returns a raw substitution dictionary mapping one frame's base scalars to expressions in another frame's variables — it is a low-level helper consumed by `express()` in `functions.py`, not itself a vector/dyadic re-expression routine. The `orient_new` method is the core factory that accepts either a single `Orienter` or an iterable of orienters and composes their rotation matrices; notably it applies `trigsimp` only for the single-orienter case but not when composing multiple orienters. `orient_new_axis`, `orient_new_body`, `orient_new_space`, `orient_new_quaternion`, and `locate_new` are the public API factory methods that actually create new coordinate system instances (not just rotation matrices) — e.g., `orient_new_quaternion` accepts four half-angle parameters and returns a fully constructed new `CoordSysCartesian`. `orient_new_body` handles body-fixed (Euler/Tait-Bryan) rotations via three successive angles and a rotation-order string, and documents the constraints on valid rotation sequences (must be length 3, expressed as XYZ or 123, no consecutive repeated axis — e.g. 'XYX' is valid but 'XXY' is not). Also handles curvilinear coordinate transformations and origin management. |
| `deloperator.py` | Implements the `Del` (nabla) vector differential operator with gradient, divergence, and curl methods. |
| `dyadic.py` | Defines the `Dyadic` class hierarchy (`BaseDyadic`, `DyadicAdd`, `DyadicMul`, `DyadicZero`) for representing and manipulating dyadic tensors. `Dyadic.dot` computes Dyadic·Vector (right-multiplying a dyadic by a vector) or Dyadic·Dyadic; it does NOT handle Vector·Dyadic (left-multiplying a vector into a dyadic) — that dispatch lives in `Vector.dot` in `vector.py`. Includes `to_matrix` for converting a dyadic to a numeric SymPy Matrix (not for computing vector cross products). |
| `functions.py` | Utility functions for vector analysis: `express` (the top-level orchestrator for re-expressing a Vector, Dyadic, or scalar in another coordinate frame — for Vectors it performs a two-step process: first collects foreign coordinate systems and substitutes their base scalars via scalar_map when variables=True, then separates the vector by coordinate system and applies rotation matrices to transform each foreign-frame component into the target basis; for Dyadics it allows specifying two different target frames), `matrix_to_vector` (converts a 3×1 numeric column matrix into a Vector by pairing each element with the corresponding basis direction of a given coordinate system), `is_conservative` and `is_solenoidal` (check whether a vector field is curl-free or divergence-free respectively; both short-circuit to return True immediately for the zero vector without computing curl/divergence, and raise TypeError for non-Vector inputs), `scalar_potential`, `scalar_potential_difference`, `directional_derivative`, and `laplacian`. |
| `operators.py` | Defines unevaluated symbolic operator classes (`Gradient`, `Divergence`, `Curl`) and their evaluated counterparts (`gradient`, `divergence`, `curl`). |
| `orienters.py` | Orienter classes (`AxisOrienter`, `BodyOrienter`, `SpaceOrienter`, `QuaternionOrienter`) that each construct a single 3×3 direction-cosine matrix (DCM) from rotation parameters — these are pure rotation-matrix factories and do NOT create new coordinate systems. `BodyOrienter`/`SpaceOrienter` (via `ThreeAngleOrienter`) internally pre-multiply three elementary rotation matrices into one DCM. Also contains the `_rot` helper that builds elementary single-axis DCMs. The resulting matrices are consumed by `CoordSys3D.orient_new()` in `coordsysrect.py`, which is the actual factory for creating new oriented coordinate systems. |
| `point.py` | Defines the `Point` class representing a point in 3-D space, with methods for computing position vectors between points (`position_wrt`), creating child points (`locate_new`), and returning scalar coordinate tuples of a point in a given frame (`express_coordinates` — returns a tuple of numbers, not a Vector). |
| `scalar.py` | Defines `BaseScalar`, the coordinate symbol (base scalar) class attached to a `CoordSys3D`. Implements derivative evaluation (`_eval_derivative`): returns 1 when differentiating a coordinate component with respect to itself, 0 otherwise — this is where symbolic differentiation of individual coordinate scalars is resolved. Also provides custom pretty-printing and LaTeX support. |
| `vector.py` | Defines the `Vector` class hierarchy (`BaseVector`, `VectorAdd`, `VectorMul`, `VectorZero`, `Cross`, `Dot`) with dot/cross product operations and outer product support. `Vector.dot` is the central dot-product dispatcher: it handles Vector·Vector (returns scalar), Vector·Dyadic (left-multiplying a vector into a rank-2 tensor — iterates over the dyadic's basis-pair components, dots the first element of each pair with self, and accumulates weighted results as a Vector), and Vector·Del (returns a Python callable/closure that computes the directional derivative of a scalar field along the vector). Also contains `_vect_div`, the division validation and dispatch helper that raises `TypeError` for vector-by-vector division, `ValueError` for division by zero, and returns a `VectorMul` for valid scalar division. The cross product implementation uses a custom inline 3×3 determinant helper (not SymPy's Matrix, which cannot hold basis-dependent vector elements) and iterates over coordinate systems to handle operands from different reference frames. Also handles cross products with dyadics by iterating over dyadic basis-pair components. |
