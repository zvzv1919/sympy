# sympy/logic — Catalog

> Part of [SymPy](../catalog.md). Boolean algebra, propositional logic, satisfiability (DPLL), and inference.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports core Boolean operations (And, Or, Not, Xor, Implies, etc.), normal-form converters (to_cnf, to_dnf, to_nnf), and the `satisfiable` function. |
| `boolalg.py` | Core Boolean algebra module defining the `Boolean` base class and all gate classes (And, Or, Not, Xor, Nand, Nor, Implies, Equivalent, ITE), plus normal-form conversions (to_cnf, to_dnf, to_nnf), simplification, and truth tables. Also contains the **Quine-McCluskey truth-table minimization pipeline**: `SOPform` and `POSform` take a list of true-output (minterm) input combinations and optional don't-care conditions, derive the complement terms by enumerating all binary input combinations, then apply `_simplified_pairs` and `_rem_redundancy` to produce minimized sum-of-products or product-of-sums expressions. Additionally provides **structural variable-signature utilities**: `_finger` computes a 5-element numerical tuple per free variable in a propositional formula — counting how often each variable appears plain vs negated, inside vs outside compound (And/Or) operators, plus a weighted argument-count sum — to partition variables into equivalence classes by structural role; `bool_map` uses these signatures to find a variable-correspondence mapping between two logically equivalent formulas. This is the module for constructing minimal CNF/DNF from truth tables and for structural variable analysis — not the DPLL solvers in `algorithms/`. Note: `Or._new_args_filter` is a low-level constructor filter for canonicalizing Or node arguments (flattening nested Ors, absorbing identity/annihilator values) — it does **not** perform SAT-solving clause simplification; for the two-rule clause reduction that removes satisfied clauses and deletes falsified literals during satisfiability search, see `unit_propagate` in `algorithms/dpll.py`. Note: `to_cnf` only performs the syntactic conversion to conjunctive normal form; any **post-conversion satisfiability checks** (such as detecting trivially false clauses among the conjuncts and short-circuiting before search) are handled by the solver entry points in `algorithms/dpll.py` and `algorithms/dpll2.py`. Note: `inference.py` handles literal extraction (`literal_symbol`) and satisfiability delegation, **not** structural signature computation. |
| `inference.py` | Propositional logic inference providing `satisfiable` (a thin dispatcher that delegates to DPLL backends in `algorithms/` — the actual generator logic for enumerating all models and yielding `False` on unsatisfiability lives in `algorithms/dpll2.py`'s `_all_models`), `valid`, `entails`, `pl_true`, `literal_symbol`, and a simple `PropKB` knowledge base. **`pl_true`** is the dedicated function for evaluating a propositional formula under a (possibly partial) truth-value assignment: it first substitutes the known variable values into the expression; if the result resolves to True/False it returns immediately, but if the assignment is **partial** and substitution alone is insufficient, it returns `None` (indeterminate). With the `deep` flag enabled, `pl_true` goes further — it attempts to resolve the residual (partially-substituted) expression by checking its validity or unsatisfiability (delegating back to `valid`/`satisfiable`), so it can sometimes determine the truth value even when not all variables are assigned. This partial-assignment evaluation with optional deeper reasoning lives here in `inference.py`, **not** in the DPLL solvers in `algorithms/` — those solvers perform satisfiability search via backtracking/propagation, but do not provide a "evaluate formula under a given partial assignment" API. |
| `algorithms/dpll.py` | Original DPLL **satisfiability solver** (checks whether a given Boolean formula is satisfiable and returns a model) using **recursive backtracking**. The entry point first converts the input expression to CNF (via `to_cnf` from `boolalg.py`) and then performs an **early trivial-unsatisfiability short-circuit**: if the resulting conjuncts contain a `False` literal (e.g., from a contradictory expression like `A & ~A`), it returns `False` immediately *before* any search or propagation begins — this pre-search pruning of trivially false clauses lives here, not in `boolalg.py`. After that guard, deterministic simplifications run (unit-clause forced-assignment propagation and pure-symbol/single-polarity elimination), then it picks an unassigned variable, recursively tries `True` then `False` via short-circuit OR, and backtracks on failure. Does **not** construct or minimize normal forms from truth tables — see `boolalg.py` for that. Provides both symbolic (`dpll`) and integer-representation (`dpll_int_repr`) recursive variants. Contains the **`unit_propagate` helper function** which implements the classical two-rule simplification when a single-literal clause determines a variable's truth value: **(1)** every OR-clause containing that literal is removed entirely (it is already satisfied), and **(2)** in every remaining OR-clause that contains the negation of that literal, the negated literal is deleted (since it is false, it cannot contribute to satisfying the clause). This is the SAT-solving clause-level simplification that reduces the clause set during search — it is **not** the same as `Or._new_args_filter` in `boolalg.py`, which only handles structural/canonical construction of Or nodes. Also contains **standalone helper functions** for integer-representation clause evaluation: `pl_true_int_repr` is a lightweight clause truth evaluator that iterates literals in a clause set, looks each up in a partial `model` dict, and guards negated-literal lookup with an explicit `if p is not None` check so that unassigned variables yield `None` (indeterminate) rather than incorrectly negating `None`; `unit_propagate_int_repr` and `find_pure_symbol_int_repr` are similarly self-contained helpers. These helpers are **not** present in `dpll2.py`, which uses a fundamentally different watched-literal architecture. |
| `algorithms/dpll2.py` | Improved DPLL solver (`SATSolver` class) using an **iterative** (non-recursive) search loop with clause learning, watched-literal (sentinel) scheme, and VSIDS branching heuristic; supports enumerating all models. Contains the **`_all_models` generator helper** that wraps the solver's model iterator: it yields each satisfying assignment and tracks whether any model was produced — when the solver exhausts without finding any solution, `_all_models` yields a single `False` to signal unsatisfiability, making this the module that implements the "yield False when no valid assignment exists" behavior for all-models enumeration (the public `satisfiable` in `inference.py` merely delegates here). Propagation is **queue-driven**: `_unit_prop` pops literals from `_unit_prop_queue` and checks each against already-assigned opposites — when a conflict is found (negation already in `var_settings`) it marks the theory unsatisfied, clears the queue, and returns `False`. `_simplify` loops unit propagation and pure-literal passes until no further changes occur. Backtracking is handled by flipping variable assignments inside `_find_model`'s loop, not by recursive calls. Does **not** contain standalone clause truth-evaluation helpers like `pl_true_int_repr` — for the lightweight integer-based clause evaluator with explicit None-guarding logic, see `algorithms/dpll.py`. |
| `utilities/__init__.py` | Utilities sub-package init; re-exports `load_file` from the DIMACS module. |
| `utilities/dimacs.py` | Parser for the DIMACS CNF file format; converts DIMACS text or files into SymPy Boolean expressions (conjunctions of clauses). |
