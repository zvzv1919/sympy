# sympy/core — Catalog

> Part of [SymPy](../catalog.md). Core symbolic engine: basic objects (Symbol, Number, Expr, Add, Mul, Pow), caching, evaluation, and compatibility.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports all public core classes (Symbol, Expr, Add, Mul, Pow, Number, etc.) and exposes singleton constants like Catalan, EulerGamma, and GoldenRatio. |
| `add.py` | Implements the `Add` class for symbolic addition, including canonical ordering, flattening of nested sums, and the `_unevaluated_Add` helper. |
| `alphabets.py` | Defines the `greeks` tuple containing the names of the 24 Greek letters used for symbol rendering. |
| `assumptions.py` | Assumption system machinery: `StdFactKB`, `ManagedProperties` metaclass, and the `BasicMeta` metaclass that attach `.is_*` assumption attributes (e.g. `is_real`, `is_integer`) to symbolic objects. Also defines `_assume_rules`, the master set of implication/equivalence rules encoding the mathematical property hierarchy (e.g., integer→rational→real→complex→commutative, zero→even&finite, prime→integer&positive, irrational==real&!rational, etc.). The actual rule *definitions* live here; `facts.py` only provides the compilation/inference engine (`FactRules`/`FactKB`) that consumes them. |
| `backend.py` | Backend selector that imports core symbols from either SymEngine (if `USE_SYMENGINE=1`) or SymPy itself, providing a unified interface for downstream modules. |
| `basic.py` | Defines `Basic`, the root base class for all SymPy objects, with core infrastructure for args storage, substitution, traversal, pattern matching, and canonical comparison. Also provides `rcall`/`_recursive_call` for recursively applying arguments through an expression tree (with a special guard that returns plain symbolic variables unchanged instead of invoking them, to prevent accidental transformation into undefined functions), and `_compare_pretty` for display-oriented term ordering (ensures big-O / asymptotic `Order` terms always sort last, and compares power expressions by exponent via pattern matching). These expression-tree call and display-ordering utilities live here on `Basic`, not in `function.py` or `add.py`. Also provides the module-level `_aresame` function for checking structural identity (not mathematical equality) of two expressions — it walks both expression trees in parallel using `preorder_traversal` and `zip_longest`, comparing both value and type at each node, so e.g. `Float(2.0)` and `Integer(2)` are structurally different even though they are mathematically equal. This structural-identity check lives here, not in `numbers.py` or `expr.py`. Also defines the `Atom` class (parent for atomic/leaf expressions like Symbol, Number) with simple `matches`, `xreplace`, and `doit` implementations. |
| `cache.py` | Caching facility providing the `cacheit` decorator and a global `CACHE` registry; uses `fastcache` when available, falling back to `lru_cache`. |
| `compatibility.py` | Python 2/3 compatibility layer providing unified imports for `string_types`, `integer_types`, `range`, `reduce`, `exec_`, `with_metaclass`, `lru_cache`, `ordered`, and other cross-version utilities. Also provides `as_int`, a strict integer coercion function that converts a value to a builtin `int` and then verifies equality with the original — raises `ValueError` for non-integral inputs like irrational numbers or non-integer floats (e.g., `as_int(sqrt(10))` fails). This strict numeric-to-integer conversion lives here, not in `sympify.py` or `numbers.py`. Also provides `default_sort_key`, a universal sorting key function that produces structured tuple keys for any object (including non-symbolic Python objects), used as a fallback when objects lack a `sort_key` method. |
| `containers.py` | Symbolic container classes `Tuple` and `Dict` that subclass `Basic`, enabling SymPy-aware tuples and dictionaries with support for substitution and sympification. |
| `core.py` | The core's core: defines `ordering_of_classes` for canonical class-level type ordering (used by `BasicMeta.__cmp__` to compare *types*, not expression values) and the `Registry` base class used by the singleton mechanism. For expression-level sort keys and ordering of symbolic values, see `expr.py::Expr.sort_key`. |
| `coreerrors.py` | Defines core exception classes: `BaseCoreError` and `NonCommutativeExpression`. |
| `decorators.py` | Core decorators including `deprecated` (deprecation warnings), `_sympifyit` (auto-sympification of method arguments), and `call_highest_priority` (operator dispatch by `_op_priority`). |
| `evaluate.py` | Provides the `evaluate` and `distribute` context managers and their backing `global_evaluate`/`global_distribute` flags to control automatic expression evaluation. |
| `evalf.py` | Adaptive numerical evaluation engine using mpmath; implements `EvalfMixin`, the `N()` function, and internal helpers for arbitrary-precision floating-point arithmetic. |
| `expr.py` | Defines `Expr`, the base class for algebraic expressions, providing arithmetic operators, series expansion, differentiation hooks, `as_numer_denom`, `as_coeff_Add/Mul`, `extract_multiplicatively` (attempts to cleanly divide out a factor — for Add requires ALL terms to be divisible, returning None if any single term fails; for Mul only needs ONE factor to be divisible; for Pow subtracts exponents), `extract_additively`, and many expression-analysis methods. The extract_multiplicatively/extract_additively factor-extraction logic lives here on Expr, not in `add.py` or `mul.py`. Includes `sort_key` (expression ordering key generation, with special branching for Dummy placeholders vs other Atom types), `is_constant` (constancy checking via numerical evaluation and differentiation, with a defensive assertion that numeric expressions must have no free symbols), and `_diff_wrt`. Also provides `args_cnc`, which decomposes a product (Mul) into [commutative factors, non-commutative factors] while maintaining ordering — by default splits a leading negative number like -2 into [-1, 2] (controlled by `split_1` flag), and optionally returns commutative factors as a set with duplicate detection. This commutative/non-commutative factor separation lives here on `Expr`, not in `exprtools.py` or `mul.py`. Also provides `coeff`, which extracts the coefficient of `x**n` from an expression — for non-commutative expressions, it can return the left or right coefficient, and when multiple terms contain the target factor but no common prefix/suffix exists across all terms, it returns zero rather than attempting an ambiguous extraction. Also provides `as_coefficient`, which separates an expression into a product of a given factor and a factor-free coefficient (returns None if not cleanly separable). These coefficient-extraction methods live here, not in `exprtools.py`. Also provides `as_independent`, which separates an expression into parts dependent/independent of given symbols — for Add it sifts terms, for Mul it sifts commutative factors and then handles non-commutative factors by stopping at the first dependent nc factor and grouping all subsequent nc factors as dependent (preserving ordering constraints). This dependency-separation logic lives here on `Expr`, not in `mul.py` or `add.py`. Also provides base-class fallback implementations of `as_coeff_add` and `as_coeff_mul` (lowercase) that handle dependency-independence splitting for generic (non-Add/non-Mul) expressions. Also defines `AtomicExpr` and `UnevaluatedExpr`. Note: expression-level sort keys live here; class-level type ordering is in `core.py`. |
| `exprtools.py` | Tools for manipulating large commutative expressions: `gcd_terms`, `_gcd_terms` (helper that computes GCD of a sum's term components, returning `(content, numer, denom)` — returns `(Zero, Zero, One)` when all inputs are zero/falsy), `factor_terms`, `factor_nc`, `Factors` (sparse exponent-map representation of products with `mul`/`div`/`quo`/`rem` operations) and `Term` (efficient `coeff*(numer/denom)` representation with normalization that extracts primitive content from Add bases), and monotonic-sign analysis. Also provides `decompose_power` and `decompose_power_rat`, which split a power expression into (base, integer_exponent) or (base, rational_exponent) — when the exponent is numeric but non-rational (e.g., an irrational float), they fall back to returning the whole expression as base with exponent 1. This power-decomposition logic lives here, not in `power.py`. Also provides `_mask_nc`, which replaces non-commutative objects with placeholder symbols so commutative-only algorithms (like polynomial factoring) can be applied — when there is exactly one nc entity it is replaced with a commutative placeholder, but when multiple exist they are kept as non-commutative placeholders and the caller must handle ordering. This nc-masking logic lives here, not in `mul.py`. `Factors.div` handles division of factored power representations, including a fallback for symbolic exponents: when clean additive extraction fails, it splits exponents into numeric (`as_coeff_Add`) and symbolic parts for partial cancellation. GCD-of-terms computation and term-level arithmetic live here, not in `add.py`. This exponent-map arithmetic lives here, not in `power.py`. Note: per-expression coefficient extraction (e.g., extracting the coefficient of a factor from a sum) and commutative/non-commutative factor separation of a single product are in `expr.py` (`coeff`, `as_coefficient`, `args_cnc`), not here; this module handles bulk term-level GCD and factored-representation arithmetic. |
| `facts.py` | Rule-based deduction system: compiles alpha (single-premise) and beta (conjunction/multi-condition) implication rules and performs runtime inference via `FactRules` and `FactKB` for the assumption system. Key compilation step is `apply_beta_to_alpha_route`, which folds multi-condition (AND-based) beta rules into single-premise alpha implication chains using a fixed-point loop — when all conjuncts of a beta rule are already derivable from a single trigger, the beta's conclusion is absorbed into that trigger's alpha chain. Also provides `rules_2prereq` for building reverse prerequisite mappings. The rule compilation and folding logic lives here; the actual mathematical property rule *definitions* (e.g., integer→rational→real→complex→commutative) are in `assumptions.py`, which passes them to `FactRules` for compilation. |
| `function.py` | Implements `Function`, `FunctionClass`, `Application`, `WildFunction` (wildcard pattern-matcher for functions — its `matches` method checks whether an expression is a callable `Function`/`AppliedUndef` with matching argument count, returning `None` for non-callable expressions like plain symbols or numbers), `Lambda`, `Derivative`, `Subs`, all `expand_*` helpers, `count_ops`, and `nfloat` (converts Rationals to Floats in expressions while preserving integer exponents by default; when the `exponent` flag is True, it must post-process integer exponents in Pow nodes manually because `Pow._eval_evalf` special-cases Integer exponents and skips converting them — this workaround lives here, not in `evalf.py`). The `expand_power_base` wrapper distributes exponents over product factors (e.g. `(a*b)**n → a**n * b**n`) but deliberately leaves additive terms (sums) untouched — `((x+y)*z)**2` becomes `z**2*(x+y)**2`, not fully expanded. This power-base splitting logic lives here (delegating to `Pow._eval_expand_power_base` in `power.py`), not in `mul.py`. Defines the framework for both defined and undefined symbolic functions. `Subs` (unevaluated substitution) validates that no variable appears more than once in the substitution list (raises `ValueError` for duplicates) and handles placeholder symbol naming collisions in its constructor. This substitution validation and collision-avoidance logic lives here, not in `expr.py`, `symbol.py`, or `basic.py`. |
| `logic.py` | Internal propositional logic primitives (`And`, `Or`, `Not`, `Logic`) and fuzzy logic helpers (`fuzzy_and`, `fuzzy_or`, `fuzzy_not`, `_fuzzy_group`), primarily used by the facts/assumption engine. |
| `mod.py` | Implements the `Mod` function for symbolic modulo operations, following Python's sign convention for the remainder. |
| `mul.py` | Implements the `Mul` class for symbolic multiplication, including flattening, canonical ordering, coefficient extraction, product expansion (`_eval_expand_mul` with non-commutative factor wrapping into `Basic` containers for correct distribution over addition), and the `_unevaluated_Mul` and `_keep_coeff` helpers. Note: `Mul.flatten` handles canonical combination of factors during Mul construction, but per-type arithmetic (e.g. Integer*Rational with GCD reduction) is dispatched to the dunder methods in `numbers.py`, not here. Splitting `(a*b)**n` into `a**n * b**n` is handled by `expand_power_base` in `function.py` / `Pow._eval_expand_power_base` in `power.py`, not by Mul. Separation of commutative/non-commutative parts in trace construction is in `trace.py`, not here. Separating an expression into variable-dependent and variable-independent parts (including non-commutative ordering preservation) is handled by `Expr.as_independent` in `expr.py`, not here. Masking non-commutative objects with placeholder symbols for commutative algorithms is handled by `_mask_nc` in `exprtools.py`, not here. |
| `multidimensional.py` | Provides the `vectorize` decorator that enables scalar functions to operate element-wise on nested iterables/arrays. |
| `numbers.py` | Numeric types hierarchy: `Number`, `Integer`, `Rational`, `Float`, `AlgebraicNumber`, and singleton constants (`Zero`, `One`, `Half`, `NegativeOne`, `Infinity`, `NegativeInfinity`, `NaN`, `ImaginaryUnit`, `Pi`, `Exp1`, `GoldenRatio`, `Catalan`, `EulerGamma`). The base `Number` class provides arithmetic dunder methods (`__div__`/`__truediv__`, `__mul__`, etc.) with special-case handling: e.g., `Number.__div__` returns `Zero` when dividing by `Infinity` or `NegativeInfinity`, and returns `NaN` when dividing by `NaN`. Each numeric subclass implements its own arithmetic dunder methods with type-specific optimizations — e.g., `Integer.__mul__` when multiplying by a `Rational` constructs a reduced fraction using `igcd` between the integer's value and the fraction's denominator, keeping results in lowest terms; `Integer.__add__`/`__sub__` similarly produce pre-reduced `Rational` results. This per-type arithmetic dispatch lives here, not in `mul.py` or `add.py`. The `Infinity` and `NegativeInfinity` singletons also implement their own arithmetic dunder methods (`__add__`, `__sub__`, `__mul__`, `__div__`) with Float-specific dispatch — e.g., `NegativeInfinity.__sub__` returns `Float('nan')` when subtracting `Float('-inf')` (indeterminate form), and `Float('-inf')` for other floats; these infinity-specific arithmetic methods live here, not in `expr.py`. Each numeric type and singleton implements its own rich comparison operators (`__gt__`, `__ge__`, `__lt__`, `__le__`, `__eq__`); e.g., `Infinity`/`NegativeInfinity` define comparison logic that distinguishes finite reals from other unbounded values, and `Rational` comparisons use cross-multiplication. The `NaN` singleton has a distinctive `__eq__` that returns True for identity (structural equality: `nan == nan` is True) while `_eval_Eq` returns False (mathematical equality: `Eq(nan, nan)` is False) — this structural-vs-mathematical equality split is defined here, not in `basic.py`. Each numeric subclass also implements `_eval_power` with type-specific exponentiation logic — e.g., `Rational._eval_power` handles negative fractions raised to infinity (returning `oo + oo*I` when absolute value > 1, due to oscillating sign), rational exponents splitting numerator/denominator into separate powers, and non-rational numeric exponents falling back to evalf; singleton constants like `NegativeOne._eval_power` handle rational exponents with denominator 2 via ImaginaryUnit; `ImaginaryUnit._eval_power` uses mod-4 cyclic reduction for integer exponents (`I**0→1, I**1→I, I**2→-1, I**3→-I`) but for non-integer numeric exponents (rationals, floats) falls back to `(-1)**(expt/2)` instead of using the cycle; `Float._eval_power` handles negative float bases raised to unit-numerator odd-denominator rational exponents (like 1/3, 1/5) by factoring out `(-1)**expt` and computing the power of the positive value, avoiding complex results for cube roots of negatives; `Infinity.__pow__`/`NegativeInfinity.__pow__` handle parity of integer exponents. Float and ImaginaryUnit power evaluation lives here, not in `power.py`. Also provides `igcd`, `ilcm`, `comp`, and `mod_inverse`. Base-class numeric arithmetic operators live here, not in `mul.py`; see `core/power.py` for the general `Pow` class; numeric-specific power evaluation lives here. |
| `operations.py` | Defines `AssocOp` (abstract base for associative operations like Add and Mul) and `LatticeOp` (base for lattice operations like Max and Min). |
| `power.py` | Implements `Pow` for symbolic exponentiation, including `_eval_expand_power_base` which distributes `(a*b)**n` into `a**n * b**n` with special handling for imaginary-unit factors (grouping by count mod 4, absorbing resulting -1 into existing negative bases), non-commutative factor repetition, and sign/polarity sifting of commutative bases. Also provides `integer_nthroot` and `isqrt` integer root utilities. Power-base expansion with imaginary-unit consolidation lives here, not in `mul.py`. |
| `relational.py` | Relational comparison classes (symbolic relational objects): `Relational` base, `Equality` (Eq), `Unequality` (Ne), `StrictLessThan` (Lt), `LessThan` (Le), `StrictGreaterThan` (Gt), `GreaterThan` (Ge). These represent unevaluated relational expressions; the rich comparison dunder methods (`__lt__`, `__gt__`, etc.) for specific numeric types like `Infinity`/`NegativeInfinity` are in `numbers.py`. |
| `rules.py` | Defines the `Transform` class, an immutable mapping used as a generic transformation/replacement rule. |
| `singleton.py` | Singleton mechanism: `SingletonRegistry` (accessed as `S`) and the `Singleton` metaclass that ensure unique instances of frequently used objects like `S.Zero`, `S.One`, `S.Half`. |
| `symbol.py` | Defines `Symbol`, `Wild`, and `Dummy` symbolic variable classes, plus the `symbols` and `var` convenience functions for bulk symbol creation. |
| `sympify.py` | The `sympify` function that converts Python objects (ints, floats, strings, etc.) into SymPy objects, along with `SympifyError`, `CantSympify`, `kernS`, and the `converter` registry. |
| `trace.py` | Implements the `Tr` class for symbolic trace operations on non-commutative expressions. `Tr.__new__` performs smart construction: distributes trace over addition, and for product (Mul) arguments separates commutative (scalar) factors from non-commutative factors using `args_cnc()`, pulling scalars outside the trace (e.g., `Tr(a*A)` becomes `a*Tr(A)` when `a` is commutative). Also handles Matrix inputs by delegating to `Matrix.trace()`, and scalar Power expressions by returning them directly. This commutative/non-commutative separation during trace construction lives here, not in `mul.py`. Supports cyclic permutation of arguments. |
| `benchmarks/bench_arit.py` | Benchmarks for basic arithmetic operations (negation, Add, Mul) on symbolic expressions. |
| `benchmarks/bench_assumptions.py` | Benchmarks for assumption property lookups (`is_integer`, `is_irrational`). |
| `benchmarks/bench_basic.py` | Benchmarks for Basic operations: method lookup, singleton access, and Symbol equality. |
| `benchmarks/bench_expand.py` | Benchmarks for `expand()` including polynomial expansion and complex number expansion. |
| `benchmarks/bench_numbers.py` | Benchmarks for numeric operations: Integer/Rational creation, arithmetic, `integer_nthroot`, `igcd`, and evalf. |
| `benchmarks/bench_sympify.py` | Benchmarks for `sympify` conversion of integers and Symbol objects. |
