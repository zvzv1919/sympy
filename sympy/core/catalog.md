# sympy/core — Catalog

> Part of [SymPy](../catalog.md). Core symbolic engine: basic objects (Symbol, Number, Expr, Add, Mul, Pow), caching, evaluation, and compatibility.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports all public core classes (Symbol, Expr, Add, Mul, Pow, Number, etc.) and exposes singleton constants like Catalan, EulerGamma, and GoldenRatio. |
| `add.py` | Implements the `Add` class for symbolic addition, including canonical ordering, flattening of nested sums, and the `_unevaluated_Add` helper. Also provides `primitive()` (extracts the greatest common rational factor from a sum, with special handling to skip terms with zero denominators when ComplexInfinity is present) and `as_content_primitive()` (recursive content extraction with optional radical factoring and a `clear` flag that controls whether denominators are distributed into terms). |
| `alphabets.py` | Defines the `greeks` tuple containing the names of the 24 Greek letters used for symbol rendering. |
| `assumptions.py` | Assumption system machinery: `StdFactKB`, `ManagedProperties` metaclass, and the `BasicMeta` metaclass that attach `.is_*` assumption attributes (e.g. `is_real`, `is_integer`) to symbolic objects. |
| `backend.py` | Backend selector that imports core symbols from either SymEngine (if `USE_SYMENGINE=1`) or SymPy itself, providing a unified interface for downstream modules. |
| `basic.py` | Defines `Basic`, the root base class for all SymPy objects, with core infrastructure for args storage, traversal, pattern matching, and canonical comparison. Provides `preorder_traversal` (depth-first expression tree walk that, when no sorting is requested, uses the raw `_argset` attribute of LatticeOp nodes like And/Or to avoid unnecessary sorting of set-stored children). Provides `subs()` (expression substitution that silently drops old/new pairs whose values cannot be sympified to symbolic types, and supports simultaneous mode), the internal `_subs` method (recursive substitution engine whose `fallback` function rebuilds the expression from substituted args — includes a special guard for simultaneous substitution of Mul expressions: when the reconstructed result changes algebraic type, e.g. a two-factor product simplifies to a non-Mul, it manually separates numeric coefficients and rebuilds unevaluated to prevent collapse), `replace()` (wildcard/callable-based replacement with simultaneous mode that creates Dummy placeholders defaulting commutativity to True when the replacement's `is_commutative` is None), `find()`, `count()`, and `matches()`. |
| `cache.py` | Caching facility providing the `cacheit` decorator and a global `CACHE` registry; uses `fastcache` when available, falling back to `lru_cache`. |
| `compatibility.py` | Python 2/3 compatibility layer providing unified imports for `string_types`, `integer_types`, `range`, `reduce`, `exec_`, `with_metaclass`, `lru_cache`, `ordered`, and other cross-version utilities. |
| `containers.py` | Symbolic container classes `Tuple` and `Dict` that subclass `Basic`, enabling SymPy-aware tuples and dictionaries with support for substitution and sympification. |
| `core.py` | The core's core: defines `ordering_of_classes` for canonical ordering of symbolic types and the `Registry` base class used by the singleton mechanism. |
| `coreerrors.py` | Defines core exception classes: `BaseCoreError` and `NonCommutativeExpression`. |
| `decorators.py` | Core decorators including `deprecated` (deprecation warnings), `_sympifyit` (auto-sympification of method arguments), and `call_highest_priority` (operator dispatch by `_op_priority`). |
| `evaluate.py` | Provides the `evaluate` and `distribute` context managers and their backing `global_evaluate`/`global_distribute` flags to control automatic expression evaluation. |
| `evalf.py` | Adaptive numerical evaluation engine using mpmath; implements `EvalfMixin`, the `N()` function, and internal helpers for arbitrary-precision floating-point arithmetic. |
| `expr.py` | Defines `Expr`, the base class for algebraic expressions, providing arithmetic operators, series expansion, differentiation hooks, `sort_key()` (computes an ordering key for expressions — Dummy symbols use a recursive sort key call while other atoms use their string representation), `as_numer_denom`, `as_coeff_Add`/`as_coeff_Mul` (base-class versions that provide generic coefficient splitting — `Mul` overrides these with its own `as_coeff_mul` in `mul.py`), `coeff(x)` (extracts the coefficient of a given factor from a sum, with special noncommutative handling: searches for common prefixes/suffixes among NC parts and falls back to single-match mode where if more than one term matches the target pattern it returns Zero rather than combining results), `as_coefficient` (separates self into expr-free coefficient times expr, or None), `as_coefficients_dict` (returns a term→Rational-coefficient mapping; for non-Add expressions treats the whole expression as a single term, falling back to coefficient 1 when the leading multiplicative factor is irrational), `as_independent` (splits an expression into variable-dependent and variable-independent parts; for products, preserves non-commutative factor ordering by grouping all non-commutative factors after the first dependent one into the dependent part), canonical sign selection (`could_extract_minus_sign`), `extract_additively`, `extract_multiplicatively` (factors out a constant from an expression — for sums, all terms must be divisible or it fails), sign-determination methods `_eval_is_positive`/`_eval_is_negative` (uses low-precision numerical evaluation with fallback to minimal polynomial when floating-point yields no significant digits), Python type-conversion methods `__int__`/`__float__`/`__complex__` (the `__int__` implementation rounds to extra digits and performs an off-by-one correction when the rounded value lands exactly on an integer but the original expression differs), the `_random` method (evaluates an expression by substituting free symbols with random complex values, using progressive precision escalation — if initial low-precision evaluation yields zero significant digits, iteratively increases precision up to the system maximum to recover meaningful results), and many other expression-analysis methods. Also defines `AtomicExpr` and `UnevaluatedExpr`. |
| `exprtools.py` | Tools for manipulating large commutative expressions: `gcd_terms`, `factor_terms`, `factor_nc` (factors sums containing non-commutative symbols by extracting common NC prefixes/suffixes; when no common prefix/suffix exists, falls back to extracting the minimum integer power of a shared base from the leading/trailing NC factor of each term; then uses Dummy substitution and permutation search to find a valid non-commutative ordering of the factored product), `decompose_power` (restructures compound exponents like `x**(2*y/3)` into `(x**(y/3), 2)` by extracting the integer numerator from rational-times-symbolic exponents and folding the denominator into the base), `Factors` class (dictionary-based multiplicative decomposition; `Factors.as_expr` converts the internal dict of base→exponent pairs back into a symbolic expression, with type-aware exponent handling: Python int exponents are wrapped via `Integer`, `Rational` exponents use `_keep_coeff`, and general symbolic exponents are multiplied directly; `normal` method cancels shared base-power pairs using multi-strategy symbolic exponent differencing — numeric check, additive extraction, then coefficient-based partial cancellation — optimized for few overlapping bases) / `Term` decomposition, and monotonic-sign analysis. |
| `facts.py` | Rule-based deduction system: compiles alpha/beta implication rules and performs runtime inference via `FactRules` and `FactKB` for the assumption system. |
| `function.py` | Implements `Function`, `FunctionClass`, `Lambda`, `Derivative`, `Subs`, and all `expand_*` helpers. Defines the framework for both defined and undefined symbolic functions. `Function.__new__` uses `_should_evalf` to decide whether to automatically produce a numerical approximation — `_should_evalf` pattern-matches complex arguments (a+b*I) and returns the max float precision if either component is a Float. Provides `count_ops(expr, visual)` which tallies arithmetic operations in an expression (with correction logic for sums where the leading term is negative, e.g. `-x + y` counts as SUB not ADD). Also provides `nfloat(expr, n, exponent)` which converts all Rationals in an expression to Floats; when `exponent=True`, integer exponents require a separate replacement pass because `Pow._eval_evalf` special-cases Integer exponents and leaves them unconverted. |
| `logic.py` | Internal propositional logic primitives (`And`, `Or`, `Not`, `Logic`) and fuzzy logic helpers (`fuzzy_and`, `fuzzy_or`, `fuzzy_not`, `_fuzzy_group`), primarily used by the facts/assumption engine. |
| `mod.py` | Implements the `Mod` function for symbolic modulo operations, following Python's sign convention for the remainder. |
| `mul.py` | Implements the `Mul` class for symbolic multiplication. `Mul.flatten` performs canonical flattening of products: extracts GCD of integer bases raised to rational exponents and recombines them (e.g. `2**(1/3)*6**(1/4)` → `2**(7/12)*3**(1/4)`), resolves accumulated fractional exponents on negative unity into sign flips and imaginary-unit contributions, and handles infinity/zoo coefficient simplification. Provides `Mul.as_coeff_mul` (Mul-specific override that extracts the leading numeric coefficient from a product — when `rational=True` (the default), a negative non-rational leading factor like a negative Float is not returned as the coefficient; instead S.NegativeOne is extracted and the negated factor is kept in the remaining args), `Mul.as_coeff_Mul` (wrapper returning coeff and remaining Mul expression). Also provides canonical term ordering within products, and the `_unevaluated_Mul` and `_keep_coeff` helpers. Does not handle sign canonicalization between `{e, -e}` (see `Expr.could_extract_minus_sign` in `expr.py`). |
| `multidimensional.py` | Provides the `vectorize` decorator that enables scalar functions to operate element-wise on nested iterables/arrays. |
| `numbers.py` | Numeric types hierarchy: `Number`, `Integer`, `Rational`, `Float`, `AlgebraicNumber`, and singleton constants (`Zero`, `One`, `Half`, `NegativeOne`, `Infinity`, `NegativeInfinity`, `ComplexInfinity`, `NaN`, `ImaginaryUnit`, `Pi`, `Exp1`, `GoldenRatio`, `Catalan`, `EulerGamma`). The `Number` base class defines `__mul__`/`__add__`/`__sub__` with explicit handling for infinity operands (e.g., finite*Infinity returns signed infinity based on the finite value's sign; zero*Infinity returns NaN). Each numeric type implements its own `_eval_power` for type-specific exponentiation (e.g., `Zero._eval_power` strips leading numeric coefficients from product exponents — returning zoo**terms when the coefficient is negative and self**terms otherwise; `Integer._eval_power` branches on whether a negative exponent's denominator is 1 vs. greater than 1 to handle sign differently; `ComplexInfinity` returns NaN for zero/itself exponents, zoo for positive, zero for negative; `Infinity`/`NegativeInfinity` handle sign-dependent power results; `ImaginaryUnit` uses mod-4; `Rational` separates sign from magnitude for negative-base fractional exponents). `Rational` implements its own ordering comparison operators (`__gt__`, `__ge__`, `__lt__`, `__le__`) that use cross-multiplication for rational-vs-rational, mpf comparison for floats, and for symbolic real-valued operands clears the denominator by transforming `p/q > expr` into `p > q*expr` before delegating to `Expr`. Infinity types (`Infinity`, `NegativeInfinity`) also implement their own ordering comparison operators with special-case logic for comparing against other infinite quantities. `Float.__eq__` implements equality comparison that short-circuits to False when the other operand is an irrational `NumberSymbol` (like pi or E), preventing false positives from numerical precision matching. `NaN` distinguishes structural equality (`__eq__` returns True for `nan == nan` via identity check) from mathematical equality (`_eval_Eq` always returns False, so `Eq(nan, nan)` is False). `Float` also provides `epsilon_eq` for approximate equality comparison with a configurable tolerance. Also provides per-type arithmetic dunders (`__divmod__`, `__rdivmod__`, etc.) with error handling for non-convertible operands, plus `igcd`, `ilcm`, `comp`, and `mod_inverse`. |
| `operations.py` | Defines `AssocOp` (abstract base for associative operations like Add and Mul) and `LatticeOp` (base for lattice operations like Max and Min). `AssocOp._eval_evalf` handles numerical evaluation of sums/products by splitting into numeric-independent and dependent parts — includes a recursion guard that skips the split when the extracted numeric-independent part is itself an AssocOp Function, falling through to a generic per-arg evaluation path to prevent infinite recursion. |
| `power.py` | Implements the generic `Pow` class for symbolic exponentiation (construction, canonicalization, and evaluation dispatch), but type-specific power logic for concrete numeric types lives in `numbers.py`. Also provides `integer_nthroot` and `isqrt` integer root utilities. |
| `relational.py` | Relational comparison classes: `Relational` base, `Equality` (Eq), `Unequality` (Ne), `StrictLessThan` (Lt), `LessThan` (Le), `StrictGreaterThan` (Gt), `GreaterThan` (Ge). These are symbolic relation constructors; type-specific equality behavior (Python `__eq__`, `_eval_Eq`) is implemented on individual types in `numbers.py`, not here. |
| `rules.py` | Defines the `Transform` class, an immutable dictionary-like wrapper around a callable function with an optional filter predicate controlling membership. `__getitem__` raises KeyError when the predicate fails, `__contains__` delegates to the predicate, and `get()` provides safe retrieval with a default value. Used as a generic transformation/replacement rule. |
| `singleton.py` | Singleton mechanism: `SingletonRegistry` (accessed as `S`) and the `Singleton` metaclass that ensure unique instances of frequently used objects like `S.Zero`, `S.One`, `S.Half`. |
| `symbol.py` | Defines `Symbol`, `Wild`, and `Dummy` symbolic variable classes, plus the `symbols` and `var` convenience functions for bulk symbol creation. |
| `sympify.py` | The `sympify` function that converts Python objects (ints, floats, strings, etc.) into SymPy objects, along with `SympifyError`, `CantSympify`, `kernS`, and the `converter` registry. |
| `trace.py` | Implements the `Tr` class for symbolic trace operations on non-commutative expressions, with support for cyclic permutation of arguments. |
| `benchmarks/bench_arit.py` | Benchmarks for basic arithmetic operations (negation, Add, Mul) on symbolic expressions. |
| `benchmarks/bench_assumptions.py` | Benchmarks for assumption property lookups (`is_integer`, `is_irrational`). |
| `benchmarks/bench_basic.py` | Benchmarks for Basic operations: method lookup, singleton access, and Symbol equality. |
| `benchmarks/bench_expand.py` | Benchmarks for `expand()` including polynomial expansion and complex number expansion. |
| `benchmarks/bench_numbers.py` | Benchmarks for numeric operations: Integer/Rational creation, arithmetic, `integer_nthroot`, `igcd`, and evalf. |
| `benchmarks/bench_sympify.py` | Benchmarks for `sympify` conversion of integers and Symbol objects. |
