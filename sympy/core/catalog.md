# sympy/core — Catalog

> Part of [SymPy](../catalog.md). Core symbolic engine: basic objects (Symbol, Number, Expr, Add, Mul, Pow), caching, evaluation, and compatibility.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; re-exports all public core classes (Symbol, Expr, Add, Mul, Pow, Number, etc.) and exposes singleton constants like Catalan, EulerGamma, and GoldenRatio. |
| `add.py` | Implements the `Add` class for symbolic addition, including canonical ordering, flattening of nested sums, and the `_unevaluated_Add` helper. Also provides `primitive()` (extracts the greatest common rational factor from a sum, with special handling to skip terms with zero denominators when ComplexInfinity is present) and `as_content_primitive()` (recursive content extraction with optional radical factoring and a `clear` flag that controls whether denominators are distributed into terms). |
| `alphabets.py` | Defines the `greeks` tuple containing the names of the 24 Greek letters used for symbol rendering. |
| `assumptions.py` | Assumption system machinery: `StdFactKB`, `ManagedProperties` metaclass, and the `BasicMeta` metaclass that attach `.is_*` assumption attributes (e.g. `is_real`, `is_integer`) to symbolic objects. |
| `backend.py` | Backend selector that imports core symbols from either SymEngine (if `USE_SYMENGINE=1`) or SymPy itself, providing a unified interface for downstream modules. |
| `basic.py` | Defines `Basic`, the root base class for all SymPy objects, with core infrastructure for args storage, traversal, pattern matching, and canonical comparison. Also defines the module-level `_aresame` function for strict structural identity comparison of two expression trees (not mathematical equality) — walks both trees in parallel via preorder traversal checking both value and type at each node, with special-case handling for user-defined callable expressions (`UndefinedFunction`/`AppliedUndef`) where it falls back to comparing classification keys instead of direct equality. Provides `preorder_traversal` (depth-first expression tree walk that, when no sorting is requested, uses the raw `_argset` attribute of LatticeOp nodes like And/Or to avoid unnecessary sorting of set-stored children). Provides `subs()` (expression substitution that silently drops old/new pairs whose values cannot be sympified to symbolic types, and supports simultaneous mode), the internal `_subs` method (recursive substitution engine whose `fallback` function rebuilds the expression from substituted args — includes a special guard for simultaneous substitution of Mul expressions: when the reconstructed result changes algebraic type, e.g. a two-factor product simplifies to a non-Mul, it manually separates numeric coefficients and rebuilds unevaluated to prevent collapse), `replace()` (wildcard/callable-based replacement with simultaneous mode that creates Dummy placeholders defaulting commutativity to True when the replacement's `is_commutative` is None), `find()`, `count()`, and `matches()`. |
| `cache.py` | Caching facility providing the `cacheit` decorator and a global `CACHE` registry; thin wrapper that selects `fastcache` when available, otherwise delegates to the backported `lru_cache` implementation in `compatibility.py`. Does not contain cache key construction or eviction logic itself. |
| `compatibility.py` | Python 2/3 compatibility layer providing unified imports for `string_types`, `integer_types`, `range`, `reduce`, `exec_`, `with_metaclass`, `ordered`, and other cross-version utilities. Also provides the `iterable` function (checks whether an object is iterable in the SymPy sense — if the object has a `_iterable` boolean attribute, that value is returned directly, completely bypassing both the `iter()` check and the type-exclusion check for dicts/strings; otherwise falls back to `iter()` and then applies the `exclude` type filter) and `is_sequence`. Contains a full backported `lru_cache` decorator implementation (used when Python < 3.3) with three caching branches (no-cache, unbounded, and size-limited with circular doubly-linked-list eviction). The size-limited branch catches `TypeError` from unhashable arguments and falls back to uncached direct calls. Also provides `_make_key` which constructs hashable cache keys from positional/keyword arguments — optimizes the single-primitive-argument case (int, str, frozenset, NoneType) by returning the raw argument directly instead of wrapping in `_HashedSeq`. |
| `containers.py` | Symbolic container classes `Tuple` and `Dict` that subclass `Basic`, enabling SymPy-aware tuples and dictionaries with support for substitution and sympification. |
| `core.py` | The core's core: defines `ordering_of_classes` for canonical ordering of symbolic types and the `Registry` base class used by the singleton mechanism. |
| `coreerrors.py` | Defines core exception classes: `BaseCoreError` and `NonCommutativeExpression`. |
| `decorators.py` | Core decorators including `deprecated` (deprecation warnings), `_sympifyit` (auto-sympification of method arguments), and `call_highest_priority` (operator dispatch by `_op_priority`). |
| `evaluate.py` | Provides the `evaluate` and `distribute` context managers and their backing `global_evaluate`/`global_distribute` flags to control automatic expression evaluation. |
| `evalf.py` | Adaptive numerical evaluation engine using mpmath; implements `EvalfMixin`, the `N()` function, and internal helpers for arbitrary-precision floating-point arithmetic. |
| `expr.py` | Defines `Expr`, the base class for algebraic expressions, providing arithmetic operators, series expansion, differentiation hooks, `sort_key()` (computes an ordering key for expressions — Dummy symbols use a recursive sort key call while other atoms use their string representation), `as_numer_denom`, `as_coeff_Add`/`as_coeff_Mul` (base-class versions that provide generic coefficient splitting — `Mul` overrides these with its own `as_coeff_mul` in `mul.py`), `coeff(x)` (extracts the coefficient of a given factor from a sum, with special noncommutative handling: searches for common prefixes/suffixes among NC parts and falls back to single-match mode where if more than one term matches the target pattern it returns Zero rather than combining results), `as_coefficient` (separates self into expr-free coefficient times expr, or None), `as_coefficients_dict` (returns a term→Rational-coefficient mapping; for non-Add expressions treats the whole expression as a single term, falling back to coefficient 1 when the leading multiplicative factor is irrational), `as_independent` (splits an expression into variable-dependent and variable-independent parts; for products, preserves non-commutative factor ordering by grouping all non-commutative factors after the first dependent one into the dependent part), `as_terms` (decomposes a sum into a list of structured term representations — each term gets a coefficient split into (real, imag) float parts, a monomial tuple indexed by sorted commutative generator bases, and a tuple of non-commutative factors; catches TypeError when a numeric factor cannot be cast to Python `complex`, falling through to treat it as a commutative or non-commutative symbolic part instead of folding into the coefficient; used for canonical term ordering), `primitive` (extracts the positive Rational that can be non-recursively factored from every term — calls `as_coeff_Mul(rational=True)` and negates both coefficient and remainder when the coefficient is negative, guaranteeing the extracted factor is always positive), `is_polynomial` / `_eval_is_polynomial` (checks if the expression is an exact finite-degree polynomial in given symbols — returns False for symbolic exponents even if marked as nonneg integers, and does not attempt simplification), `is_rational_function` (analogous check for ratio of two polynomials), `extract_branch_factor` (decomposes a product of polar-form complex exponentials into a residual factor and a winding number around the origin — collects `exp_polar` arguments, separates multiples of pi*I, uses ceiling to round to nearest even integer for the branch factor, optionally extracts half-integer winding numbers), canonical sign selection (`could_extract_minus_sign`), `extract_additively` (subtracts a value from an expression only when all affected numerical coefficients decrease in absolute value toward zero — for pure numbers checks that the difference preserves sign direction and has smaller magnitude; for sums extracts term-by-term checking each coefficient; returns None if the subtraction would overshoot any coefficient past zero), `extract_multiplicatively` (factors out a constant from an expression — when the divisor is a sum (Add), preprocesses it by calling `primitive()` to extract the rational content and reconstructing as an unevaluated Mul before falling through to recursive Mul extraction; for infinite values like NegativeInfinity, determines the result sign based on the sign of the factor being extracted: extracting a negative factor from -oo yields +oo, extracting a positive factor yields -oo, and unknown sign returns None; for sums, all terms must be divisible or it fails), sign-determination methods `_eval_is_positive`/`_eval_is_negative` (uses low-precision numerical evaluation with fallback to minimal polynomial when floating-point yields no significant digits), Python type-conversion methods `__int__`/`__float__`/`__complex__` (the `__int__` implementation rounds to extra digits and performs an off-by-one correction when the rounded value lands exactly on an integer but the original expression differs), the `_random` method (evaluates an expression by substituting free symbols with random complex values, using progressive precision escalation — if initial low-precision evaluation yields zero significant digits, iteratively increases precision up to the system maximum to recover meaningful results), `is_constant` (determines whether an expression is constant with respect to given variables by numerical evaluation at multiple points — if substituting all symbols with zero produces NaN or raises ZeroDivisionError, falls back to random numerical evaluation; compares values at different substitution points and uses differentiation as a final check), and many other expression-analysis methods. Also defines the module-level `_mag` helper (computes the base-10 order of magnitude of a numerical value — uses `math.log10` with a fallback to multi-precision `mpf_log` when log10 overflows, plus an off-by-one correction), `AtomicExpr`, and `UnevaluatedExpr`. |
| `exprtools.py` | Tools for manipulating large commutative expressions: `gcd_terms`, `factor_terms`, `factor_nc` (factors sums containing non-commutative symbols by extracting common NC prefixes/suffixes; when no common prefix/suffix exists, falls back to extracting the minimum integer power of a shared base from the leading/trailing NC factor of each term; then uses Dummy substitution and permutation search to find a valid non-commutative ordering of the factored product), `decompose_power` (restructures compound exponents like `x**(2*y/3)` into `(x**(y/3), 2)` by extracting the integer numerator from rational-times-symbolic exponents and folding the denominator into the base), `Factors` class (dictionary-based multiplicative decomposition; `Factors.as_expr` converts the internal dict of base→exponent pairs back into a symbolic expression, with type-aware exponent handling: Python int exponents are wrapped via `Integer`, `Rational` exponents use `_keep_coeff`, and general symbolic exponents are multiplied directly; `normal` method cancels shared base-power pairs using multi-strategy symbolic exponent differencing — numeric check, additive extraction, then coefficient-based partial cancellation — optimized for few overlapping bases) / `Term` decomposition, and monotonic-sign analysis. |
| `facts.py` | Rule-based deduction system: compiles alpha/beta implication rules and performs runtime inference via `FactRules` and `FactKB` for the assumption system. |
| `function.py` | Implements `Function`, `FunctionClass`, `WildFunction`, `Lambda`, `Derivative`, `Subs`, and all `expand_*` helpers. Defines the framework for both defined and undefined symbolic functions. `WildFunction` is a wildcard for matching applied functions in pattern matching — its `matches` method returns None if the expression is not a `Function` or `AppliedUndef` instance (e.g., a plain Symbol), and also checks that the argument count is within the allowed `nargs` set. Provides `_getnargs`/`_getnargs_new` which introspect a callable's parameter signature via `inspect.signature` to determine the range of accepted positional argument counts — returns a single integer when all parameters are required, or a tuple range when some have defaults; used by `FunctionClass` to set `_nargs`. `Derivative._sort_variables` sorts differentiation variables into canonical order while respecting non-commutativity between symbols and non-symbols (applied functions): symbols are sorted among themselves and non-symbols among themselves, but the boundary between consecutive symbol/non-symbol groups is preserved because cross-type derivatives don't commute. `Subs.__new__` resolves naming collisions when generating underscore-prefixed placeholder symbols — if a newly created placeholder already exists as a free symbol in the expression with a different substitution target, it prepends additional underscores and retries in a loop until no clash remains. `Subs._eval_subs` guards bound variables from external substitution — if the symbol being replaced is one of the Subs' bound placeholder variables, the method returns self unchanged to preserve the deferred evaluation. `Function.__new__` uses `_should_evalf` to decide whether to automatically produce a numerical approximation — `_should_evalf` pattern-matches complex arguments (a+b*I) and returns the max float precision if either component is a Float. Provides `count_ops(expr, visual)` which tallies arithmetic operations in an expression (with correction logic for sums where the leading term is negative, e.g. `-x + y` counts as SUB not ADD). Also provides `nfloat(expr, n, exponent)` which converts all Rationals in an expression to Floats; when `exponent=True`, integer exponents require a separate replacement pass because `Pow._eval_evalf` special-cases Integer exponents and leaves them unconverted. |
| `logic.py` | Internal propositional logic primitives (`And`, `Or`, `Not`, `Logic`) and fuzzy logic helpers (`fuzzy_and`, `fuzzy_or`, `fuzzy_not`, `_fuzzy_group`), primarily used by the facts/assumption engine. |
| `mod.py` | Implements the `Mod` function for symbolic modulo operations, following Python's sign convention for the remainder. `Mod.eval` performs extensive simplification: extracts GCD of the two operands via `gcd`/`gcd_terms`, simplifies sum-type dividends term-by-term, and handles non-Rational (floating-point) leading coefficients specially — when both dividend and divisor are products with float coefficients (e.g. `Mod(0.6*x, 0.3*y)`), extracts those coefficients via `as_coeff_Mul`, computes their remainder, and if zero, factors the divisor's coefficient out as a multiplier (yielding `0.3*Mod(2*x, y)`). Also denests nested Mod expressions and applies minus-sign extraction. |
| `mul.py` | Implements the `Mul` class for symbolic multiplication. Provides `_eval_is_zero` which determines whether a product is zero by tracking both zero and infinite (non-finite) factors — when both a zero factor and an infinite factor coexist, returns None (indeterminate, since 0*oo is NaN) rather than True or False. `Mul.flatten` performs canonical flattening of products: extracts GCD of integer bases raised to rational exponents and recombines them (e.g. `2**(1/3)*6**(1/4)` → `2**(7/12)*3**(1/4)`), resolves accumulated fractional exponents on negative unity into sign flips and imaginary-unit contributions (only during product flattening, not during power-base expansion which lives in `power.py`), and handles infinity/zoo coefficient simplification. Provides `Mul.as_coeff_mul` (Mul-specific override that extracts the leading numeric coefficient from a product — when `rational=True` (the default), a negative non-rational leading factor like a negative Float is not returned as the coefficient; instead S.NegativeOne is extracted and the negated factor is kept in the remaining args), `Mul.as_coeff_Mul` (wrapper returning coeff and remaining Mul expression). Also provides `as_content_primitive` (extracts the positive Rational content from a product by recursively extracting content from each factor; deliberately uses `self.func(*args)` rather than `_from_args` to reconstruct the primitive part, so that identical factors get properly combined, e.g. `(2+2*x)*(3+3*x)` yields `(6, (1+x)**2)` not `(6, (1+x)*(1+x))`), canonical term ordering within products, the `_unevaluated_Mul` and `_keep_coeff` helpers, and `Mul._eval_subs` (product substitution engine that breaks expressions into commutative/non-commutative factor dictionaries, performs coefficient extraction with multiplicity, and includes early-abort checks — notably returns immediately when the pattern's leading coefficient is rational but the expression's leading coefficient is non-rational). Provides `Mul._eval_evalf` for numerical evaluation of products — includes a special branch when the leading coefficient is negative one: if the remaining expression after extracting -1 is itself a Mul, delegates to `AssocOp._eval_evalf` and negates; if the remainder is a single non-Mul term (e.g. a symbolic function like `-sin(1)`), calls `_eval_evalf` on that term directly and negates. Does not handle sign canonicalization between `{e, -e}` (see `Expr.could_extract_minus_sign` in `expr.py`). |
| `multidimensional.py` | Provides the `vectorize` decorator that enables scalar functions to operate element-wise on nested iterables/arrays. |
| `numbers.py` | Numeric types hierarchy: `Number`, `Integer`, `Rational`, `Float`, `AlgebraicNumber`, and singleton constants (`Zero`, `One`, `Half`, `NegativeOne`, `Infinity`, `NegativeInfinity`, `ComplexInfinity`, `NaN`, `ImaginaryUnit`, `Pi`, `Exp1`, `GoldenRatio`, `Catalan`, `EulerGamma`). **This is the authoritative location for all number-type `_eval_power` methods** — every concrete numeric class defines its own `_eval_power` here for type-specific exponentiation dispatch (not in `power.py`). The `Number` base class defines `__mul__`/`__add__`/`__sub__` with explicit handling for infinity operands (e.g., finite*Infinity returns signed infinity based on the finite value's sign; zero*Infinity returns NaN). `_eval_power` implementations: `Zero._eval_power` strips leading numeric coefficients from product exponents — returning zoo**terms when the coefficient is negative and self**terms otherwise; `Integer._eval_power` simplifies integer-to-fractional-exponent by factoring the integer base into primes, extracting perfect roots from the prime factorization (e.g. `(2**12)**(1/10)` → `2*(2**2)**(1/10)` by divmod of each prime's exponent by the root denominator), reducing remaining exponents by their shared GCD, and also branches on whether a negative exponent's denominator is 1 vs. greater than 1 to handle sign differently; `ComplexInfinity` returns NaN for zero/itself exponents, zoo for positive, zero for negative; `Infinity`/`NegativeInfinity` handle sign-dependent power results — `NegativeInfinity._eval_power` checks exponent parity for positive integers: odd exponents yield -oo, even exponents yield +oo; `NegativeOne._eval_power` returns I**p when the rational exponent has denominator exactly 2 (e.g. (-1)**(3/2) → I**3), and for general rational exponents decomposes via divmod into integer and fractional parts and recurses; `ImaginaryUnit` uses mod-4; `Rational._eval_power` handles negative-base negative-exponent cases by inverting the fraction and factoring out (-1) raised to the fractional part, and for positive rational bases with rational exponents splits into numerator and denominator powers. `Rational` implements its own ordering comparison operators (`__gt__`, `__ge__`, `__lt__`, `__le__`) that use cross-multiplication for rational-vs-rational, mpf comparison for floats, and for symbolic real-valued operands clears the denominator by transforming `p/q > expr` into `p > q*expr` before delegating to `Expr`. Infinity types (`Infinity`, `NegativeInfinity`) implement their own arithmetic operators (`__add__`, `__sub__`, `__mul__`, `__div__`) that override the `Number` base class versions — these perform type-preserving dispatch: when the other operand is a `Float`, the result is returned as `Float('inf')` or `Float('-inf')` rather than the symbolic singletons `S.Infinity`/`S.NegativeInfinity`; when the other operand is a non-Float `Number`, the symbolic singleton is returned. `Infinity.__mul__` handles zero specially: both exact zero (identity check) and floating-point zero (equality check in the Float branch) return NaN, but the dispatch path differs — exact zero is caught by an early identity check before the Float branch. They also implement their own ordering comparison operators with special-case logic for comparing against other infinite quantities. `Float.__eq__` implements equality comparison that short-circuits to False when the other operand is an irrational `NumberSymbol` (like pi or E), preventing false positives from numerical precision matching. `NaN` distinguishes structural equality (`__eq__` returns True for `nan == nan` via identity check) from mathematical equality (`_eval_Eq` always returns False, so `Eq(nan, nan)` is False). `Float` also provides `epsilon_eq` for approximate equality comparison with a configurable tolerance. Also provides per-type arithmetic dunders (`__divmod__`, `__rdivmod__`, etc.) with error handling for non-convertible operands, plus `igcd`, `ilcm`, `comp`, and `mod_inverse`. |
| `operations.py` | Defines `AssocOp` (abstract base for associative operations like Add and Mul) and `LatticeOp` (base for lattice operations like Max and Min). `AssocOp._new_rawargs` reconstructs an associative operation from raw arguments without full re-evaluation — a fast path that skips flattening but includes a safety mechanism for commutativity: if the original expression was non-commutative, commutativity is recomputed (via `_from_args`) unless the caller explicitly passes `reeval=False`. `AssocOp._matches_commutative` is the core pattern-matching engine for commutative associative operations (Add/Mul): separates pattern arguments into "exact" parts (concrete sub-expressions without wildcards) and "wild" parts (containing Wild/WildFunction placeholders), subtracts exact parts from the target expression, then attempts to match the remaining wild parts against the residual. `AssocOp._eval_evalf` handles numerical evaluation of sums/products by splitting into numeric-independent and dependent parts — includes a recursion guard that skips the split when the extracted numeric-independent part is itself an AssocOp Function, falling through to a generic per-arg evaluation path to prevent infinite recursion. |
| `power.py` | Implements the generic `Pow` class for symbolic exponentiation (construction, canonicalization, and evaluation dispatch). Does NOT contain `_eval_power` methods for concrete number types — all number-specific power evaluation (Integer, Rational, NegativeOne, Zero, Infinity, ImaginaryUnit, etc. raising to various exponent types) is in `numbers.py`. Provides multinomial expansion of sums raised to integer powers `(a+b+...)**n` via `_eval_expand_multinomial` — includes an efficient algorithm for expanding integer powers of complex numbers `(a+b*I)**n` when both real and imaginary parts are rational, using binary exponentiation (repeated squaring) on integer-converted numerators with denominator factoring to handle non-integer rational components. Also provides power-base expansion that distributes an exponent over a product of factors `(a*b*c)**n → a**n * b**n * c**n`, including special handling for repeated imaginary-unit factors in the base: counts occurrences modulo 4 and reduces them (e.g., two imaginary units become -1, which is absorbed into existing negative factors when possible). Also separates commutative base factors into nonnegative, negative, and other categories to correctly handle sign distribution under non-integer exponents. `Pow._eval_evalf` handles numerical evaluation of power expressions — includes a special case for negative exponents with non-real bases: rewrites using the conjugate (`base.conjugate() / |base|^2`) and negates the exponent to avoid precision issues with complex-valued negative-power evaluation. Also provides `integer_nthroot` and `isqrt` integer root utilities. |
| `relational.py` | Relational comparison classes: `Relational` base, `Equality` (Eq), `Unequality` (Ne), `StrictLessThan` (Lt), `LessThan` (Le), `StrictGreaterThan` (Gt), `GreaterThan` (Ge). These are symbolic relation constructors; type-specific equality behavior (Python `__eq__`, `_eval_Eq`) is implemented on individual types in `numbers.py`, not here. |
| `rules.py` | Defines the `Transform` class, an immutable dictionary-like wrapper around a callable function with an optional filter predicate controlling membership. `__getitem__` raises KeyError when the predicate fails, `__contains__` delegates to the predicate, and `get()` provides safe retrieval with a default value. Used as a generic transformation/replacement rule. |
| `singleton.py` | Singleton mechanism: `SingletonRegistry` (accessed as `S`) and the `Singleton` metaclass that ensure unique instances of frequently used objects like `S.Zero`, `S.One`, `S.Half`. `SingletonRegistry.__getattr__` implements deferred/lazy instantiation: classes are registered during import into a pending dictionary, and actual object creation is deferred until first attribute access — on first lookup, `__getattr__` instantiates the class, installs the result as a real attribute via `__setattr__` (so subsequent lookups bypass `__getattr__` entirely), and removes the class from the pending dictionary. |
| `symbol.py` | Defines `Symbol`, `Wild`, and `Dummy` symbolic variable classes, plus the `symbols` and `var` convenience functions for bulk symbol creation. `var` creates symbols via `symbols()` and injects them into the caller's global namespace — for `Basic` instances it uses `.name` as the variable name, but for `FunctionClass` instances (e.g., when `cls=Function` is passed) it uses `.__name__` instead; a recursive `traverse` helper handles nested tuples of mixed types. `Wild.matches` implements pattern-matching for placeholder variables: rejects a candidate expression if it contains any sub-expression in the `exclude` list, then rejects if any callable in the `properties` list returns False for the candidate; only if both checks pass does it accept the match and update the replacement dictionary. |
| `sympify.py` | The `sympify` function that converts Python objects (ints, floats, strings, etc.) into SymPy objects, along with `SympifyError`, `CantSympify`, `kernS`, and the `converter` registry. |
| `trace.py` | Implements the `Tr` class for symbolic trace operations on non-commutative expressions, with support for cyclic permutation of arguments. |
| `benchmarks/bench_arit.py` | Benchmarks for basic arithmetic operations (negation, Add, Mul) on symbolic expressions. |
| `benchmarks/bench_assumptions.py` | Benchmarks for assumption property lookups (`is_integer`, `is_irrational`). |
| `benchmarks/bench_basic.py` | Benchmarks for Basic operations: method lookup, singleton access, and Symbol equality. |
| `benchmarks/bench_expand.py` | Benchmarks for `expand()` including polynomial expansion and complex number expansion. |
| `benchmarks/bench_numbers.py` | Benchmarks for numeric operations: Integer/Rational creation, arithmetic, `integer_nthroot`, `igcd`, and evalf. |
| `benchmarks/bench_sympify.py` | Benchmarks for `sympify` conversion of integers and Symbol objects. |
