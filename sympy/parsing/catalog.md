# sympy/parsing — Catalog

> Part of [SymPy](../catalog.md). Translates strings (Python-like, Mathematica, Maxima) into SymPy expressions.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; contains only a docstring describing the parsing package. |
| `sympy_parser.py` | The main SymPy expression parser: applies a configurable pipeline of **semantic token-level** transformations (`auto_symbol`, `auto_number`, `factorial_notation`, `implicit_multiplication`, `implicit_application`, `convert_xor`, `convert_equals_signs`, `split_symbols`, `function_exponentiation`, `rationalize`, `lambda_notation`) before evaluation, anchored by the `parse_expr` function, `stringify_expr`/`eval_expr` helpers, and the `EvaluateFalseTransformer` AST rewriter. These transformations **insert or rewrite tokens** in the token stream (e.g. `implicit_multiplication` inserts `*` operator tokens between adjacent symbols) — they do **not** handle whitespace insertion or source-text reconstruction from token tuples (for that, see `sympy_tokenize.py`'s `Untokenizer`). The `auto_symbol` transformation converts undefined names to `Symbol()` calls at the **token** level, inspecting previous/next tokens to skip keyword arguments (e.g. `f(x=2)` — detected by checking for `(`/`,` before the name and `=` after), attribute access, Python keywords, and known callables. Uses `_re_repeated` to **convert** already-tokenized repeating-decimal strings into `Rational` values during the `auto_number` transformation — this is post-tokenization conversion, **not** where the regex patterns for numeric literal recognition or the lexical analysis of recurring decimals are defined (see `sympy_tokenize.py` for that). See also: `ast_parser.py` for an alternative AST-based symbol wrapping approach that does **not** perform token-level keyword-argument detection. |
| `sympy_tokenize.py` | A customised fork of Python's `tokenize` module that is the **lexical analyzer** and the **sole location where regex patterns for numeric literal recognition are defined**. Defines all token-level regular expressions for integers, floats, and imaginary numbers via helper functions (`group`, `any`, `maybe`) and module-level regex variables (`Intnumber`, `Floatnumber`, `Imagnumber`, `Number`, etc.). Critically, this is where the **recurring (repeating) decimal fraction notation** is recognised: the `Repeatedfloat` pattern (`r'\d*\.\d*\[\d+\]'`) matches bracket-based repeating decimals like `0.1[6]` (meaning 0.1666…) at the lexer level. Also adds `!`/`!!` (factorial) operators. Provides `generate_tokens`, `untokenize`, the `TokenError` exception, and the `Untokenizer` class. The `Untokenizer` class is responsible for **reconstructing source text from token streams**: its `untokenize` method handles full 5-element token tuples (using position info), while its `compat` method handles the **backward-compatible 2-element (type, value) tuple** path — inserting spaces after NAME/NUMBER tokens, inserting a space between two **consecutive STRING literals**, and tracking indentation state via INDENT/DEDENT tokens. This is the only module that handles token-to-source-text reconstruction and inter-token spacing logic. See also: `sympy_parser.py` for post-tokenization *conversion* (not recognition) of repeating decimals into `Rational` values. |
| `ast_parser.py` | Uses Python's `ast` module to parse a string into a SymPy expression, providing the `Transform` `NodeTransformer` subclass (which wraps numeric literals in `Integer`/`Float` and undefined names in `Symbol` at the **AST** level) and a `parse_expr` entry-point function. The `visit_Name` method performs only **simple dictionary lookups** (local_dict, global_dict) to decide whether to wrap a name — it does **not** inspect surrounding syntax context like dot operators, keyword arguments (`f(x=2)`), or adjacent tokens. For context-aware identifier wrapping that skips attribute access (dot operator), keyword arguments, Python keywords, and known callables, see `auto_symbol` in `sympy_parser.py`. |
| `mathematica.py` | Translates Mathematica-syntax strings into SymPy expressions via a regex-based recursive-descent `parse` function and helper translators, with `mathematica` as the public entry point. |
| `maxima.py` | Converts Maxima CAS expressions into SymPy objects using regex substitutions and the `MaximaHelpers` class (wrapping `expand`, `float`, `trigexpand`, `sum`, `product`, `csc`, `sec`), exposed through the `parse_maxima` function. Handles **colon-based variable binding** (Maxima assignment syntax like `x: 2+3`): extracts the target variable name via regex, strips the assignment prefix before parsing, and optionally persists the result into a caller-provided `globals` namespace dictionary. This is the only parser in the package that handles colon-delimited variable assignment. |
