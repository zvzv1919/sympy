# sympy/parsing — Catalog

> Part of [SymPy](../catalog.md). Translates strings (Python-like, Mathematica, Maxima) into SymPy expressions.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package entry point; contains only a docstring describing the parsing package. |
| `sympy_parser.py` | Token-level SymPy expression parser: applies a configurable pipeline of semantic token transformations to convert tokenized Python into SymPy expressions. Key transformations include `auto_number`, `auto_symbol`, `implicit_multiplication`, `implicit_application`, `convert_xor`, `convert_equals_signs`, `split_symbols`, `function_exponentiation`, `rationalize`, `factorial_notation`, and `lambda_notation`. Anchored by `parse_expr`, `stringify_expr`/`eval_expr` helpers, and the `EvaluateFalseTransformer` AST rewriter. Concerned with semantic interpretation of tokens (e.g. wrapping numbers in `Integer`/`Float`, inserting `Symbol` calls), NOT with lexical scanning or source text reconstruction. |
| `sympy_tokenize.py` | Low-level lexical scanner AND source-text reconstructor (fork of Python `tokenize`). **Tokenization**: `generate_tokens` breaks a character stream into raw typed tokens (NAME, NUMBER, STRING, OP, etc.) using regex patterns (`group`, `any`, `maybe` helpers) including `Repeatedfloat` for bracket-notation repeating decimals and `!`/`!!` factorial operators; tracks parenthesis nesting, indentation (INDENT/DEDENT), backslash continuation. **Untokenization / source reconstruction**: `untokenize`/`Untokenizer` reassembles source code from token sequences. `Untokenizer.untokenize` detects whether tokens are full 5-element `(type, value, start, end, line)` tuples (using positional info) or degraded 2-element `(type, value)` tuples (falling back to `Untokenizer.compat`). The `compat` method heuristically inserts whitespace: appends a space after each NAME/NUMBER token to prevent identifier/number merging, and prepends a space before STRING tokens that follow another STRING to avoid implicit concatenation. This is the file for any question about reconstructing/reassembling source text from tokens, or about spacing rules between adjacent lexical units without positional data. |
| `ast_parser.py` | AST-based string-to-SymPy parser (alternative to the token-level `sympy_parser.py`). Uses Python's `ast` module to parse and then rewrites the AST via `Transform(NodeTransformer)`. Central identifier-resolution logic lives in `visit_Name`: it checks local_dict membership, then global_dict membership (passing through only `Basic` instances, types, or callables), exempts boolean literals `'True'`/`'False'`, and wraps everything else in `Symbol(...)` — this is the core decision point for whether an identifier becomes an existing object or a new symbolic variable. Also provides `visit_Num` (wraps int/float in `Integer`/`Float`) and `visit_Lambda`. Exposed via its own `parse_expr(s, local_dict)` function. |
| `mathematica.py` | Translates Mathematica-syntax strings into SymPy expressions via a regex-based recursive-descent `parse` function and helper translators, with `mathematica` as the public entry point. |
| `maxima.py` | Converts Maxima CAS expressions into SymPy objects using regex substitutions and the `MaximaHelpers` class (wrapping `expand`, `float`, `trigexpand`, `sum`, `product`, `csc`, `sec`), exposed through the `parse_maxima` function. |
