# sympy/tensor — Catalog

> Part of [SymPy](../catalog.md). Tensor algebra: indexed objects, index conventions, and multi-dimensional array operations.

## Python Files

| File | Summary |
|------|---------|
| `__init__.py` | Package initializer; exports `IndexedBase`, `Idx`, `Indexed`, index-method helpers, and all N-dim array classes and operations. |
| `indexed.py` | Defines `IndexedBase`, `Indexed`, and `Idx` classes for representing indexed objects (e.g. matrix elements `M[i, j]`) with optional shape and range information. `IndexedBase.__getitem__` performs **rank-mismatch validation**: when the base has a declared shape (number of dimensions), it checks whether the count of supplied subscript arguments matches that declared dimensionality — for a sequence of indices it compares `len(shape)` vs `len(indices)`, and for a single (non-sequence) index it verifies the declared rank is exactly 1 — raising `IndexException("Rank mismatch.")` on failure. This is distinct from the index-count validation in `array/ndim_array.py` (`_parse_index`), which validates element access on concrete numeric `NDimArray` objects; `indexed.py` operates on purely symbolic array bases before any numeric data exists. Note: `IndexedBase.__getitem__` does NOT auto-fill missing indices — it only raises an error on mismatch. For auto-filling missing subscript slots (so a high-rank object can behave like a vector or matrix during contraction), see `TensorHead` in `tensor.py`. |
| `index_methods.py` | Provides purely symbolic/structural analysis functions for `IndexedBase`/`Indexed` expressions only (not abstract tensor algebra classes like `TensMul`/`TensAdd`): `get_indices` determines free and dummy indices by dispatching to expression-type-specific helpers — `_get_indices_Add` enforces that every term in a symbolic addition shares the same set of free (non-contracted) subscript labels (allowing scalar broadcast) and raises `IndexConformanceException` when they don't match; `_get_indices_Mul` handles products with implicit Einstein summation; `_get_indices_Pow` collects indices from base and exponent as a union without cross-contraction. Also provides `get_contraction_structure` which maps out implicit summation patterns (does not perform numerical contractions and does not define internal tuple-based storage formats for index bookkeeping — for the internal data structure that encodes free/dummy indices as triplets/4-tuples see `TIDS` in `tensor.py`). Does NOT handle index-label generation, dummy-name collision avoidance, post-substitution dummy recognition (i.e. when a user *calls* a tensor-product object like `t(i1)` with replacement indices that include repeated/contracted pairs and the system must rebuild the expression so those pairs become summation dummies — that callable logic lives in `TensMul.__call__` in `tensor.py`), or equality comparison for abstract tensors — for all of those see `TIDS.get_indices` and `TensMul.equals` in `tensor.py`. For extracting ordered multiplication chains, closed loops (traces), and transposition constraints from contracted abstract tensor components, see `get_lines` in `tensor.py`. |
| `tensor.py` | Implements tensors with abstract index notation (Penrose formalism), including tensor index types, symmetries, canonicalization via the Butler-Portugal algorithm, and Einstein summation. Core classes: `TensMul` (tensor products) with arithmetic operations (multiply, divide — division by a tensor raises `ValueError`) and an `equals` method that canonicalizes both operands via `canon_bp()` then compares structured tuples of (coefficient, components, sorted free indices, sorted dummy indices) — when comparing against a non-tensor scalar (not zero) it asserts the product has no tensor components before doing a plain coefficient comparison; `TensAdd` (tensor sums) with equality comparison that short-circuits when the other operand has a zero scalar coefficient; and `TIDS` (tensor-index data structure) which internally encodes free (uncontracted) indices as **triplets** `(TensorIndex, position_in_component, component_number)` and dummy (contracted) indices as **4-tuples** `(pos1, pos2, component1, component2)` — the original TensorIndex is not stored for dummies since it is no longer needed. Its `get_indices` method reconstructs the full index list for multi-component expressions, generating fresh dummy-index labels while scanning existing free indices to start the counter above any that follow the same naming convention (avoiding name collisions), and whose `mul` method detects matching covariant/contravariant index pairs across two operands for automatic dummy-index contraction and raises `ValueError` if two same-variance indices are mistakenly paired. Also handles numerical component data via a lazy-evaluation layer (`_TensorDataLazyEvaluator`) that: parses raw data into numpy ndarrays — with a special branch: if the input is a two-element sequence whose first element is callable, it treats the pair as `(function, shape)` and builds the array via `numpy.fromfunction` (sympifying the results), otherwise it vectorizes `sympify` over a plain `numpy.array`; attaches numpy arrays to tensor heads; when multiplying two multi-indexed quantities, identifies matching covariant/contravariant index pairs across their free-index lists and delegates the axis-wise summation to `numpy.tensordot` (Einstein-summation-style contraction on raw ndarrays — distinct from the symbolic `tensorcontraction` in `array/arrayop.py` which operates on `NDimArray` objects); computes scalar magnitudes by contracting component arrays with associated bilinear-form (metric) data; and supports exponentiation of tensors with numeric components via iterative metric contraction and root extraction. Also provides `get_lines`, which extracts ordered multiplication chains (lines), closed loops (traces), and remaining elements from contracted multi-component tensor expressions by following dummy-index pairs of a given index type through components; an inner helper merges chain segments sharing endpoints, raises `ValueError` if a component carries more than two indices of the requested type, and raises `NotImplementedError` when contracted pairs occupy the same relative slot position (which would require a transposition flag) — this is distinct from `get_contraction_structure` in `index_methods.py`, which maps out implicit-summation patterns for `IndexedBase`/`Indexed` expressions only. Additionally, `TensExpr` provides a `get_matrix` method that converts rank-1 or rank-2 tensor component data into a SymPy `Matrix`, raising `NotImplementedError` ("missing multidimensional reduction to matrix") for tensors with rank > 2 — this is separate from the `tomatrix` method on `NDimArray` subclasses in `array/`. **Tensor objects are callable** (`TensMul.__call__`): invoking (calling) a tensor-product expression with new index arguments substitutes its free indices and, if the replacement indices contain repeated (contracted) covariant/contravariant pairs, automatically reconstructs the expression so those pairs are properly recognized as summation dummies (rather than remaining as named free indices) — this is the mechanism that ensures dummy recognition after index substitution. **Tensor heads are also callable with auto-fill for missing indices** (`TensorHead`): when a tensor head (a symbolic multi-dimensional quantity with a declared rank) is called with *fewer* subscript labels than its rank requires, its internal validation decides which trailing slot positions to auto-fill so the object can behave like a vector (1 missing slot) or a two-dimensional matrix (2 missing slots) during contraction — this auto-matrix-index mechanism lives entirely in `tensor.py` (not in `indexed.py`); `True` can also be passed as a placeholder for auto-filled slots when the full number of indices is provided. This is distinct from `IndexedBase.__getitem__` in `indexed.py`, which simply raises an error on rank mismatch for symbolic array bases and has no auto-fill behavior. Note: this module is for *abstract* tensor algebra — for numeric N-dimensional array operations see `array/` subpackage; for symbolic index analysis of `IndexedBase` expressions see `index_methods.py`. |
| `array/__init__.py` | Package initializer for the N-dim array submodule; exports dense/sparse and mutable/immutable array classes along with `tensorproduct`, `tensorcontraction`, `derive_by_array`, and `permutedims`. Defines the convenience alias `Array = ImmutableDenseNDimArray`. Also contains the module-level docstring with comprehensive tutorial-style documentation covering: array construction modes (both nested-list shape inference and the alternative flat-iterable-with-explicit-shape-tuple pattern, e.g. `Array(range(12), (3, 4))`), slicing, elementwise differentiation, `applyfunc`, `tolist`/`tomatrix` conversion, products and contractions (including how standard matrix multiplication equals an outer product of two rank-2 arrays followed by contraction/summation over specific axes, and how trace equals contraction of both axes), and derivatives by array — this conceptual/explanatory documentation and the public API aliases live here, not in `ndim_array.py` (which provides the internal base-class mechanics) or `arrayop.py` (which holds only the operation implementations). **This is the authoritative file for any question about how N-dim array construction works**, including how the module handles different construction inputs (flat sequence with explicit shape tuple vs. nested lists with auto-detected shape) — it documents the semantics, shows worked examples of each construction mode, and defines the public `Array` entry point. Questions about construction behavior, usage patterns, or what happens when specific argument combinations are passed should always resolve here, not in `ndim_array.py` (which only contains the low-level internal dispatch helper `_handle_ndarray_creation_inputs` without the user-facing documentation). |
| `array/ndim_array.py` | Defines the `NDimArray` base class with internal/common functionality for **concrete numeric** N-dimensional arrays such as indexing, shape validation, arithmetic (including element-wise division), and conversion utilities. Its `_parse_index` validates element access on already-constructed arrays — for rank-mismatch validation on **symbolic** array bases (before any numeric data exists), see `IndexedBase.__getitem__` in `indexed.py`. Contains `_handle_ndarray_creation_inputs`, an internal-only dispatch helper that normalizes constructor arguments into a flat list and shape tuple — this does NOT convert data to numpy ndarrays, does NOT detect callable elements, and does NOT use `numpy.fromfunction`; for that special callable-as-first-element data-parsing behavior see `_TensorDataLazyEvaluator.parse_data` in `tensor.py`. This is a low-level implementation detail, not the place to understand construction semantics or behavior (for that, see the documented construction patterns and examples in `array/__init__.py`). Also contains `_scan_iterable_shape` which recursively walks nested sequences to determine their rectangular shape, raising `ValueError` on ragged input. For the public `Array` alias, tutorial-style usage examples, and high-level API documentation see `array/__init__.py`; for concrete dense/sparse subclass implementations see `dense_ndim_array.py` and `sparse_ndim_array.py`. This is for concrete numeric arrays — for abstract tensor algebra division/arithmetic see `TensMul` in `tensor.py`. |
| `array/dense_ndim_array.py` | Implements `ImmutableDenseNDimArray` and `MutableDenseNDimArray`, which store all elements in a flat list for dense N-dimensional array representations. |
| `array/sparse_ndim_array.py` | Implements `ImmutableSparseNDimArray` and `MutableSparseNDimArray`, which store only non-zero elements via a dictionary-backed sparse representation. Includes `tomatrix` for converting rank-2 arrays to `SparseMatrix` (raises `ValueError` for rank ≠ 2) — for converting abstract tensor expressions to `Matrix` see `TensExpr.get_matrix` in `tensor.py`. |
| `array/arrayop.py` | Provides symbolic array-level operations on `NDimArray` objects: `tensorproduct`, `tensorcontraction` (contracts specified axis pairs using `itertools.product` loops — purely symbolic, does NOT use numpy or any numerical library; when **all** axes are consumed by contractions the function returns a **plain scalar** value rather than a zero-dimensional array), `derive_by_array` (elementwise differentiation), and `permutedims` (axis permutation). Important: for **numerical** Einstein-summation contraction that uses `numpy.tensordot` on raw ndarrays (identifying matching covariant/contravariant index pairs across free-index lists when multiplying two multi-indexed tensor quantities), see the lazy-evaluation layer (`_TensorDataLazyEvaluator`) in `tensor.py`; for abstract tensor product/sum algebra and equality comparison see `TensMul`/`TensAdd` in `tensor.py`. |
| `array/mutable_ndim_array.py` | Defines the `MutableNDimArray` base class that serves as the mixin for mutable N-dimensional arrays. |
